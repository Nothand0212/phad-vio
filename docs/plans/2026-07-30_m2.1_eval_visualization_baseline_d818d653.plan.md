# M2.1 评估与可视化底座实施计划

- 日期：2026-07-30
- 里程碑：M2.1（见[实现里程碑与验收标准](../roadmap.md)）
- 计划 id：`d818d653`
- 跟踪 issue：[#18](https://github.com/Nothand0212/phad-vio/issues/18)

M2.1 的目标是在第一条估计轨迹出现之前就把「这次改动让系统变好还是变坏」
变成可回答的问题。它的产物是真值加载、轨迹导出、指标计算和可观察面板，
不包含任何估计逻辑。

## 切片划分

| Slice | 内容 | 可观察行为 |
|---|---|---|
| ① | 真值加载、TUM 读写、时间关联、SE3 对齐、ATE、离线 CLI | `MH_01_easy` 真值自比 ATE 为 0；导出文件可被 `evo` 读取 |
| ② | 固定时间间隔 RPE | 同一对轨迹给出 RPE 数字 |
| ③ | `phad::viz` 实时 2D 面板、Python 离线绘图 | 回放 `MH_01_easy` 时面板显示真值轨迹与当前图像 |

## 已对齐的决策

| 决策点 | 结论 |
|---|---|
| 真值加载归属 | `phad::io::dataset::euroc::openGroundtruth()`，产出与格式无关的 `common::Trajectory` |
| 真值字段范围 | 只取 timestamp 与 pose，velocity/bias 列校验列数后忽略；M4 需要时再扩展 |
| 位姿表示 | `Eigen::Isometry3d` + `common::Timestamp`；不改 `sensor::RigidTransform`，不提前引入 GTSAM |
| 指标 | ATE 平移 RMSE 为主，附 mean/median/std/max；旋转误差以 deg 单列；RPE 先只做固定时间间隔 1 s |
| 关联阈值 | 最近邻，默认最大时间差 2.5 ms（真值周期一半），CLI 可覆盖 |
| 未匹配样本 | 丢弃并显式报告数量与比例，匹配率低于阈值才判评估失败 |
| CLI 输入 | 估计侧收 TUM 文件；真值侧接受 TUM 文件或 EuRoC 序列目录 |
| 可视化 | `phad::viz` 面板组件由 `phad_euroc_runner` 调用；GFTT 探针留到 M2.2 |
| Python 脚本 | `scripts/` + `requirements.txt` + venv，不进 CI |
| 数据集范围 | 只支持 EuRoC 真值；TUM VI 的 `mocap0` 是 `T_W_marker` 而非 `T_W_B`，延后 |

## Slice ①

### 通用轨迹类型

新增 `phad/common/trajectory.hpp`，header-only，`phad::io` 与 `phad::eval`
都能依赖而不产生反向依赖：

```cpp
struct TimedPose
{
  Timestamp         timestamp;
  Eigen::Isometry3d T_W_B;
};

class Trajectory
{
public:
  [[nodiscard]] static TrajectoryResult<Trajectory> create(
      std::vector<TimedPose> poses );
  [[nodiscard]] const std::vector<TimedPose>& poses() const noexcept;
};
```

`create()` 是唯一入口，校验非空、时间戳严格递增、平移有限、旋转正交。
错误类型仿 `sensor::CalibrationError` / `CalibrationResult` 的既有形状，由
调用方映射为 `DatasetError` 或 `EvalError`。集中校验一次，因为时间关联与
RPE 都直接依赖「严格递增」这一不变量。

### EuRoC 真值加载

新增 `phad/io/dataset/euroc/euroc_groundtruth.{hpp,cpp}`：

```cpp
[[nodiscard]] DatasetResult<common::Trajectory> openGroundtruth(
    const std::filesystem::path& sequence_root );
```

行为：

- 校验 `mav0/state_groundtruth_estimate0/{sensor.yaml,data.csv}` 存在；
- 读 `sensor.yaml` 的 `T_BS`，非 identity 时报 `kUnsupportedImuExtrinsics`，
  与既有 IMU 分支一致，把「真值 S 帧就是 body」从隐含假设变成显式断言；
- 解析 CSV 的 timestamp、`p_RS_R_{x,y,z}`、`q_RS_{w,x,y,z}`，其余列只校验
  列数；四元数非单位（容差 1e-6）报 `kInvalidField` 并带字段名；
- 时间戳严格递增复用既有 `checkIncreasing`。

支撑改动：把 `dataset_adapter_utils.cpp` 匿名 namespace 中的
`removeCarriageReturn`、`splitCsv`、`parseTimestamp`、`parseFiniteDouble`、
`checkIncreasing` 提升为 `internal` 声明；把 `euroc_dataset.cpp` 的
`parseTransform` / `transformSourceField` 移到
`phad/io/dataset/euroc/internal/euroc_yaml.{hpp,cpp}` 供两个 EuRoC 解析器
共用。两处都是在第二个真实用例出现后才做的提取，不新增抽象层。

CSV header 常量先对着本地 `MH_01_easy` 的实际文件核对再写死。

### `phad::eval` 模块

新增 `phad/eval/`，只依赖 Eigen，不 link OpenCV，保证无 GUI 环境可测：

- `eval_error.hpp`：`EvalErrorCode`、带 `describe()` 的 `EvalError`、形状与
  `DatasetResult` 一致的 `EvalResult<T>`；
- `tum_io.{hpp,cpp}`：无 header、空格分隔、`timestamp tx ty tz qx qy qz qw`；
  时间戳按整数秒加 9 位定点小数输出。**读取时按 `'.'` 拆整数秒与小数位解析
  为纳秒，不经过 `double`**：EuRoC 量级（约 1.4e9 秒）的浮点秒无法承载纳秒
  精度，经 `double` 会被量化到约 100 ns；
- `associate.{hpp,cpp}`：二分最近邻，默认阈值 2.5 ms，返回匹配对与
  `dropped_out_of_range` / `dropped_over_threshold` 计数；零重叠、匹配数
  少于 3、匹配率低于阈值（默认 0.5）分别报错；
- `align.{hpp,cpp}`：固定 scale = 1 的 Umeyama/Kabsch，用 `H` 的奇异值比
  判退化（单点或共线报 `kDegenerateAlignment`）。真值自比时点集重合但不
  共线，奇异值正常、`R = I`，不会误判；
- `ate.{hpp,cpp}`：`AteReport { AteStats trans_m; AteStats rot_deg;
  Eigen::Isometry3d T_align; Association association; }`。

### 离线 CLI

- `phad_euroc_gt_export --seq <root> --out <gt.tum>`；
- `phad_traj_eval --est <est.tum> (--gt <gt.tum> | --gt-euroc <seq_root>)
  [--max-dt-ms 2.5] [--min-match-rate 0.5] [--errors-csv <path>]`。

退出码沿用现有 apps 的 0 / 1 / 2（成功 / 运行失败 / 用法错误）。
`--errors-csv` 的列是
`timestamp_ns,dt_ns,err_trans_m,err_rot_deg,est_x,est_y,est_z,gt_x,gt_y,gt_z`，
作为 Slice ③ Python 脚本的输入合同。

### 测试

`tests/eval/` 全部使用合成轨迹 fixture，不依赖数据集：

- `trajectory_test.cpp`：空、非单调、重复时间戳、非有限、非正交旋转被拒；
- `tum_io_test.cpp`：EuRoC 量级时间戳写读纳秒无损往返、四元数顺序、坏行；
- `associate_test.cpp`：完全对齐、阈值内抖动、超阈值丢弃计数、部分超出真值
  时间范围、零重叠、匹配率不足；
- `align_test.cpp`：已知 SE3 扰动被精确恢复、共线与少于 3 点报错；
- `ate_test.cpp`：真值自比 ATE 为 0、施加已知 SE3 后 ATE 回 0 且恢复该变换、
  已知常量偏移下 RMSE 等于偏移量。

`PHAD_ENABLE_MH01_TESTS` 下新增 `tests/eval/euroc_mh01_groundtruth_test.cpp`，
沿用 `PHAD_EUROC_MH01_PATH` 与 `GTEST_SKIP` 模式：真值加载成功、时间单调、
导出到 TUM 后读回自比 ATE 为 0。

## evo 交叉验证（手工执行，不进 CI）

```bash
phad_euroc_gt_export --seq "$PHAD_EUROC_MH01_PATH" --out /tmp/mh01_gt.tum
evo_traj tum /tmp/mh01_gt.tum
phad_traj_eval --est /tmp/mh01_gt.tum --gt /tmp/mh01_gt.tum
```

自比给出的是 0，只能证明读写与关联自洽，不能验证对齐与统计的算法。因此
交叉验证要在一条**非刚体扰动**的轨迹上做：给导出的真值加上随位置变化的
偏移，再比较两个实现。

MH_01 上的实测结果（2026-07-30）：`evo_ape tum gt.tum perturbed.tum -a` 与
`phad_traj_eval` 的 rmse/mean/median/std/max 在六位有效数字上完全一致
（rmse 0.0938128 m）。后续如出现差异，先定位关联阈值与对齐实现，不调整
容差掩盖差异。

## Slice ② / ③ 概要

- **RPE**：`phad/eval/rpe.{hpp,cpp}`，固定 1 s 时间间隔，复用同一
  `Association`；用已知恒定漂移轨迹验证解析值。
- **实时面板**：新增 `phad_viz`（link `opencv_highgui`、`opencv_imgproc`），
  提供图像窗口与俯视 x-y 轨迹面板，由 `apps/phad_euroc_runner.cpp` 调用。
- **Python 绘图**：`scripts/` 加 `requirements.txt`，消费 `--errors-csv` 与
  TUM 文件，产出 3D 轨迹与误差随时间曲线，README 记录用法。
