# M4.4 gyro fixed-lag contract probe 实施计划

设计：
[`m4.4-gyro-fixed-lag-contract-probe-design.md`](../research/m4.4-gyro-fixed-lag-contract-probe-design.md)

一手资料：
[`m4.4-gyro-fixed-lag-reference.md`](../research/m4.4-gyro-fixed-lag-reference.md)

本文档描述当前约定，不是绝对约束，会随项目开发修订。

## 1. Vertical slice

本片是用户确认 A→B 后的 B/P0。只把本机临时实验提升为仓库内可回归 contract tests，
不触碰 `StereoVoEstimator`、apps、CLI、配置、CSV 或 trajectory。

本片完成的定义是：五类 fixed-lag lifecycle 合同在实际链接的 GTSAM 上均有自动测试，
且完整 estimator/unit 回归不退化。本片不跑 EuRoC、不比较 ATE/RPE，也不把 smoother
estimate 交给产品。

## 2. 实施步骤

### 2.1 测试 fixture

新增 `tests/estimator/fixed_lag_contract_test.cpp`：

- 只 include 稳定 `gtsam/nonlinear` 头；
- 用 `X/B` symbol、`Point2`、prior/between factors 建最小线性 graph；
- fixture helper 每次显式构造 `newFactors/newValues/timestamps`；
- test-local ledger 记录用户 factor slot owner，不记录 internal marginal factor；
- 断言读 `timestamps()`、`valueExists()`、`getFixedVariables()`、`getFactors()` 与
  `newFactorsIndices`，不读取占位 `Result::error`。

### 2.2 五类合同

按设计稿逐项实现：

1. lag cutoff 严格 `<` 与 exact newest key；
2. shared key 只刷新 timestamp，跨 lag 存活但成为 fixed variable；
3. factor slot 的插入顺序、删除与空 slot 复用；
4. 删除最后 factor 后的 timestamp orphan 及到期异常；
5. smoother + ledger accepted snapshot 在 candidate 失败后的继续更新。

若 installed behavior 与一手源码结论冲突，保留红测试并先查 revision/linkage；不写双语义
兼容断言。

### 2.3 CMake

仅把新测试源加入既有 `phad_estimator_tests` source list。该 target 已链接 `gtsam`；不得
新增 `gtsam_unstable`、新 library、compile definition 或 runtime flag。

## 3. 验证命令

```bash
cmake -S . -B build -DCMAKE_EXPORT_COMPILE_COMMANDS=ON
cmake --build build --target phad_estimator_tests -j2
build/phad_estimator_tests --gtest_filter='FixedLagContractTest.*'
build/phad_estimator_tests
ctest --test-dir build --output-on-failure -L unit -j2
git diff --check
```

只报告实际执行结果。若完整 unit 因与本片无关的既有环境条件跳过，分别报告 PASS/SKIP，
不将 SKIP 写成 PASS。

## 4. P1 go/no-go

- 五类合同、estimator suite 与 unit 回归全通过：P0 完成，另写 P1 shadow 设计/计划；
- 任一 fixed-lag 合同失败：P0 blocked，先更新 revision/API 证据；
- orphan 或 rollback 无法被显式观察：禁止进入 P1；
- P0 无论结果如何都不改变当前 B3 production 路径，M4.4 继续保持未完成。

## 5. 实际结果

- `FixedLagContractTest.*`：`5/5 PASS`；
- `phad_estimator_tests`：`100/100 PASS`；
- `ctest --test-dir build --output-on-failure -L unit -j2`：`398/398 PASS`，3 项既有
  `SKIP`，0 failure；
- `git diff --check` 及新增 P0 文件的 `git diff --no-index --check`：无空白诊断；
- production runtime/config/schema 未修改，未执行 EuRoC run。

P0 判定为 GO；后续工作进入独立 P1 shadow 设计与计划。
