# M4.4 Rule 4 IMU 去旋转实施计划

Issue：[#34](https://github.com/Nothand0212/phad-vio/issues/34)（part of
[#30](https://github.com/Nothand0212/phad-vio/issues/30)）
设计：
[`m4.4-rule4-imu-rotation-design.md`](../research/m4.4-rule4-imu-rotation-design.md)
一手资料：
[`m4.4-rule4-imu-rotation-reference.md`](../research/m4.4-rule4-imu-rotation-reference.md)

本文档描述当前约定，不是绝对约束，会随项目开发修订。

## 1. 切片划分

- **Slice ①（主实现）**：保持 `30 px + cooldown off + mean aggregate`，只把
  Rule 4 rotation source 从 BA/PnP pose 换成 last accepted KF → current gyro
  preintegration；补 estimator helper、`KeyframeGate`、config、diag 与测试。
- **Slice ②（单变量 A/B）**：主实现通过 MH_01 后，独立评估 cooldown off/5，
  再独立扫 `10/15/30 px`。
- **Slice ③（条件 full-suite）**：只扩通过 sentinel 的非支配候选；无胜者保留
  `30 px + off`，不为完成 M4.4 强行改默认。

## 2. 已对齐决策

| 决策点 | 结论 |
|---|---|
| module | apps 中单一事务型 `KeyframeGate`；caller/tests 共用其 interface |
| estimator seam | GTSAM 保持 PRIVATE；gyro rotation helper 只暴露 Eigen/POD |
| interval | last accepted KF → current；每帧判定前追加 adjacent packet |
| bias | 用当前帧前最新 `kOk` gyro bias，每帧重建完整 raw segment |
| commit | 仅 `selected && kOk` 推进 KF pixel/timestamp baseline 并 reset |
| invalid | IMU-on Rule 4 unavailable 且无 BA fallback；Rules 0–3 继续 |
| IMU-off | 明确 `pose_fallback`，保持现有视觉模式行为 |
| diag | 现有 `diag.csv` 尾部追加，不新增 sidecar，不在 Slice ①扩 summary |
| cooldown | 只节流 Rules 3/4；N=5 为严格 `frames_after_kf > 5` |
| config | `session.keyframe_parallax_px=30.0`、`session.keyframe_min_frames_after_kf=0`；均进 run identity |
| source gate | MH_01 相对修改前 control 不劣化；原 `ATE <= 0.100 m` 独立记账 |
| optional default | per-sequence 保守 Pareto；无胜者保持 `30 px + off` |

## 4. 步骤 2：estimator gyro rotation helper

预计改动：

- 新增 `phad/estimator/imu_rotation.hpp/.cpp`；
- `CMakeLists.txt` 把 implementation 纳入 `phad_estimator`；
- 新增 `tests/estimator/imu_rotation_test.cpp`。

interface 只接受 raw `ImuMeasurement` segment 与 absolute `bias_gyr`，返回：

```text
valid / invalid_reason
R_Bi_Bj
t_i / t_j / dt_s / angle_rad
```

实现要求：

- GTSAM `deltaRij = R_W_Bi^T * R_W_Bj`；
- absolute bias 作为 integration `biasHat`，不用 increment correction interface；
- 拒绝样本不足、非严格递增 timestamp、非有限输入和非有限输出；
- public header 不出现任何 GTSAM 类型；
- 与现有 estimator 相邻段积分保持同一“左样本覆盖 dt，右端不积分”合同。

定向测试：identity、恒角速度、非零 bias、分段拼接/整段等价、无序/重复/nonfinite
与角度诊断。

## 5. 步骤 3：事务型 `KeyframeGate`

预计新增：

- `apps/keyframe_gate.hpp/.cpp`；
- 改写 `tests/apps/keyframe_selection_test.cpp`，删除复制的生产 selector；
- `CMakeLists.txt` 把 gate implementation 纳入 `phad_offline_vo_session`。

`KeyframeGate` 持有：

- last accepted KF pixels/timestamp；
- last accepted pose（仅 IMU-off fallback）；
- 最新 causal `bias_gyr`；
- last-KF→current raw IMU samples 与 sticky gap；
- accepted KF 数、`frames_after_kf`、单个 pending ticket。

每帧：

```text
decide(input)
  append packet -> rebuild rotation -> compute all rule facts
  -> apply priority + optional cooldown -> ticket/decision

estimator.update(..., decision.selected)

resolve(ticket, feedback)
  selected && kOk -> commit KF baseline + reset segment/counter
  !selected && kOk -> refresh pose/bias + counter
  rejected/failed -> retain raw time evidence, otherwise no commit
```

ticket mismatch、double resolve、unresolved 时再次 decide 抛 `std::logic_error`；不能
静默覆盖 pending transaction。

相机去旋转：

```text
R_Ccur_Clkf = R_B_Crect^T * R_Bkf_Bcur^T * R_B_Crect
```

合成测试必须使用 non-identity `T_B_left_rectified`，覆盖纯旋转近零补偿视差、旋转+
平移保留视差、transpose/共轭、multi-packet、bias 更新、reject/failed 不 reset、
IMU-on invalid 与 IMU-off fallback。

## 6. 步骤 4：session、配置与诊断

### 6.2 `diag.csv`

```text
kf_rule,kf_cooldown_suppressed,kf_frames_after_last,

```

unavailable 数值写 0，不写 NaN；source/reason/count 消歧。`is_keyframe + status`
联合表示实际接受，无需再加 accepted 列。

- GTSAM direction、absolute bias、sample validation；
- non-identity extrinsic；
- first/low-tracks/timeout 与 Rule 3/4 优先级；
- IMU invalid 不 fallback；
- ticket transaction 与 raw segment 保留；
- cooldown Rule 3/4-only、严格 `>5` 与 failed 不计数；
- CLI/config hash/meta/CSV schema。

## 8. 步骤 6：source-only MH_01 门

固定：IMU-on、`keyframe_parallax_px=30.0`、
`keyframe_min_frames_after_kf=0`。与步骤 1 control 配对：

| 项 | 门 |
|---|---|
| ATE | candidate `<=` control |
| completion | 不降低 |
| segments/reanchors/failed | `1/0/0` |
| rotation source | 建立首个 accepted KF 后且无 gap 的 Rule 4 为 `imu`，不得 fallback/unavailable |

| 原 M4 绝对门 | `<=0.100 m` 独立 PASS/FAIL 记录 |

若 source-only 未过，先从 `kf_rotation_source/reason/dt/angle`、raw/compensated
parallax、rule timeline 定位区间/方向/bias/外参问题；不进入 cooldown/threshold。

执行结果（2026-08-09）：

- run：`7f102cb_dirty/m44_source_imu30_5b289f7d`；配置明确为
  `keyframe_parallax_px=30`、`keyframe_min_frames_after_kf=0`；
- completion/coverage 与 control 完全相同（`0.879957 / 0.879924`），
  segments/reanchors/failed=`1/0/0`，RPE `0.0228335 m` 略优于 control
  `0.0229568 m`；
- ATE `0.138622 m`，劣于 control `0.122337 m`（约 `+13.3%`），故
  **source-only gate FAIL**；原 M4 `<=0.100 m` 绝对门同样 FAIL；
- 首个 accepted KF 后 3239/3239 行均为 `rotation_source=imu`、`reason=none`，
  `dt>0` 且有可用 parallax tracks；没有 fallback/unavailable，未发现区间中断；
- accepted KF 从 control `518` 降到 `320`：source run 中 timeout `258`、
  low-survival `18`、Rule 4 `42`（另有前两个 accepted KF）；80.6% accepted KF
  已由 timeout 触发；
- compensated parallax 的 p50/p95/p99 为 `6.683/24.737/30.910 px`，仅 52 个
  accepted-frame timeline 样本高于 30 px；而 raw parallax 高于 30 px 有 788 个。
  结合 direction/bias/extrinsic 合成测试，当前证据更支持“完整 IMU 去旋转后旧 30px
  阈值过疏”而非已观察到的公式/区间错误；但没有逐像素 ground-truth oracle，这仍是
  基于测试与运行诊断的推断。

按原门，本步骤停在 FAIL，不自动进入 cooldown。用户于 2026-08-09 选择方案 A，
显式批准把 source gate 修订为诊断性恢复刀：保持同一代码、IMU-on 与 cooldown off，
先跑 15px；若仍不恢复 control，再跑 10px。任一阈值仍须满足原 MH_01
ATE/completion/segments/reanchors/failed 门，且诊断须证实 Rule 4/KF 密度按预期恢复；
未通过者不进入 sentinel。该修订不授权提前评估 cooldown。

修订门执行结果：

| rotation / threshold | config hash | ATE m | RPE m | completion | accepted KF | Rule 4 |
|---|---:|---:|---:|---:|---:|---:|
| control BA-pose / 30px | `d70e45aa` | 0.122337 | 0.022957 | 0.879957 | 518 | 未记录 |
| IMU / 30px | `5b289f7d` | 0.138622 | 0.022834 | 0.879957 | 320 | 42 |
| IMU / 15px | `4018fae4` | 0.155501 | 0.022261 | 0.879957 | 406 | 231 |
| IMU / 10px | `11639aad` | 0.132913 | 0.022122 | 0.879957 | 533 | 409 |

- 15px、10px 均未恢复 control ATE，故修订后的 source gate 仍 FAIL；三条 IMU
  候选的 completion/coverage 与 segments/reanchors/failed 均保持不变，RPE 均略优；
- 10px 已把 accepted KF 数恢复至 control 附近（533 vs 518），但两者只有 133 个
  accepted KF timestamp 精确重合；mean gap 也接近（0.3042s vs 0.3131s）。因此
  “总 KF 太少”已被证伪，差异集中在选帧时刻/窗口内容；
- 以 EuRoC GT 最近邻（`<=2.5ms`）只读核对 3217 个区间：IMU rotation angle
  绝对误差 p95 为 30/15/10px 下 `0.001710/0.001454/0.001263 rad`，causal gyro
  bias 与 GT bias 的范数误差均值约 `0.0030 rad/s`。该证据削弱 bias/区间角度错误
  假设；它只验证 angle magnitude，不替代 axis/像素级 oracle，后者仍由合成测试覆盖；
- 不继续试 5px、动态阈值或 cooldown，也不扩 sentinel/full-suite。用户选择
  `A->B`：先撤回 failed production candidate，再设计约束关键帧选择时序的
  successor。
