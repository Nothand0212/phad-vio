# M3.3 V1_02 回归归因: ⑤c 关键帧策略 + ⑥ 前端加固

日期: 2026-08-07
状态: **已批准**（plan mode 审批通过 2026-08-07）
关联: issue [#27](https://github.com/Nothand0212/phad-vio/issues/27)
前提分析: [m3.3-slice5-full-suite-results](../research/m3.3-slice5-full-suite-results.md)
（§6-6c,CV 链污染机制）

## 1. Context

V 系列立体 VO 的质量是当前主要差距(MH 组 3–6× vs ORB-SLAM3,V 组 20–80×)。
在规划下一步路线之前,需要理解 V1_02 在三个连续切片上的 ATE 轨迹:

| 切片 | V1_02 ATE | segments | reanchors | 变更 |
|---:|---:|---:|---:|---|
| baseline (afe3829) | **0.768** | 1 | 0 | PnP stereo 仲裁后,全关键帧,无关键帧策略 |
| ⑤c (86212e0) | **2.617** (+241%) | 2 | 1 | Basalt 7KF+3temporal 窗口结构,关键帧 30px 阈值 |
| ⑥ (167478e) | **2.026** (-23% vs ⑤c) | 2 | 1 | 前端 5 项(CLAHE/中值流/F-RANSAC/quality 0.003/pyramid 4) |
| ⑦ (e77ee5d) | **0.522** (-74% vs ⑥) | 1 | 0 | glue 通道(零视差悬挂存活)——re-anchor 归零,彻底修复 |

**核心事实**: 回归在 ⑤c(关键帧策略)触发,⑥ 部分修复但 2-segment 结构未破,
⑦ 以 glue 通道消除 re-anchor 后修复。{⑤c,⑥} 都跑了全序列,diag.csv 已存在,
**不需要额外跑实验即可完成 Level A 归因**。Level B 需要少量 A/B 实验。

**已有机制假说**(来自 `m3.3-slice5-full-suite-results.md` §6-6c):
非关键帧 PnP 失败 → 恒速(CV) guess 不经质量门控推进 last/prev 链
→ 旋转段 CV delta 冻结在旋转前的值,无法跟踪实际运动
→ num_shared 继续下降 → overlap_broken → re-anchor 用陈旧 CV guess 作 anchor
→ 永久轨迹偏移,BA 无法修复

本计划的目的是**用数据验证/修正这条假说**(Level A),
并**量化 ⑥ 前端 5 项改动各自贡献**(Level B)。

## 2. Level A: ⑤c 关键帧策略归因

### 2.1 变更边界

⑤c `86212e0` 只改窗口结构,前端与 baseline 逐位相同:
- 窗口从全关键帧改为 7KF+3temporal(非关键帧进 BA 但驱逐优先)
- 关键帧由 30px 视差阈值决定
- **前端参数不变**: min_disparity=0.5, max_depth=40, quality=0.01, pyramid=3,
  无 CLAHE/F-RANSAC/中值流
- **estimator 参数不变**: 42 键 config hash = `773ea011`(与 baseline 相同)

### 2.2 唯一对照: V1_01

V1_01 是关键的对照: 同为 V1 旋转序列,⑤c 下 **V1_01 虽然 ATE 退化(0.173→0.514)
但没有 re-anchor**(segments=1, reanchors=0)。方法: 对比 V1_01 vs V1_02 的
diag.csv,找出构成 re-anchor 的临界条件。

### 2.3 用已有 diag.csv 验证的 4 个具体断言

若 slice5-full-suite-results §6-6c 的假说正确,以下 4 个断言应全部被数据支持:

**断言 1: PnP 成功率下降触发链**
- 预测: ⑤c 下的非关键帧(is_keyframe=0)应该有大量 `pnp_success=0` 帧,
  集中在 re-anchor 前的连续几秒内
- 验证: 加载 ⑤c diag.csv,过滤 `is_keyframe=0`,统计 `pnp_success`
  在 segment_id 跳变前的时序。若 PnP 失败帧在 re-anchor 前连续出现(>3 帧),
  且 `num_shared` 同时递减,成立

**断言 2: reproj RMS 在 PnP 失败段上升**
- 预测: pnp_success=0 帧的恒速 guess 不经优化,其 `reproj_rms_after_px`
  应在连续 PnP 失败段递增(guess 位姿与真实位姿差距扩大→重投影散开)
- 验证: 画 `reproj_rms_after_cull_px` 时序,标出 PnP 失败段。若递增,成立

**断言 3: 重锚 posterior 段(segment_id=1)的 ATE 由 anchor 偏差决定**
- 预测: 若 re-anchor 的 `prior_key` 位姿已经偏了,新 segment 的整个轨迹
  会有近乎常数的偏移,`max_window_pose_shift_m` 在新 segment 开头很小
  (prior 紧)然后随 BA 收敛逐渐变大
- 验证: diag.csv `segment_id=1` 起始段的 `max_window_pose_shift_m` 趋势 +
  `reproj_rms_before_px` 起始值。若起始 RMS 高(>5px)但 BA 迅速收敛↓,
  说明 anchor 位姿偏但 BA 在硬扯,成立

**断言 4: V1_01(无 re-anchor)缺少这些信号**
- 预测: V1_01 的 ⑤c diag.csv 不应有连续 PnP 失败段、不应有递增 reproj RMS 段
- 验证: 同样分析 V1_01 ⑤c diag.csv。若都干净,成立
- 然后可以追问: V1_01 和 V1_02 的旋转强度差异有多大?
  用 GT pose 计算每帧角速度——若 V1_02 的峰值角速度显著 > V1_01,
  那就是"旋转强度超过 PnP+tracker 承受能力"的临界点

### 2.5 Level A 验收标准

## 3. Level B: ⑥ 前端 5 项改动逐项归因

### 3.1 变更内容

⑥ `167478e` 在 ⑤c estimator 上加 5 个纯前端改动(min_disparity 和 max_depth
未变,仍为 0.5/40):

| # | 改动 | 参数 | 代码位置 |
|---|---|---|---|
| B1 | CLAHE 预处理 | clip 2.0, tile 16×16 | `stereo_tracker.cpp:621` |
| B2 | LK 中值流初始猜 | OPTFLOW_USE_INITIAL_FLOW, 中值流≥5 survivors | `stereo_tracker.cpp:650-668,756-775` |
| B3 | F 矩阵 RANSAC | 3.0px, 0.99, min 8 pts | `stereo_tracker.cpp:717-753` |
| B4 | GFTT quality_level | 0.01→0.003 | `stereo_tracker.hpp:50` |
| B5 | LK 金字塔层数 | 3→4 | `stereo_tracker.hpp:54` |

**管线顺序**: CLAHE → LK(with B2)→ FB → B3 → GFTT top-up(with B4) → matchRight

### 3.2 关于"中值流有害"假说

V1 序列的旋转段中,刚体流场是辐射状的——所有像素的位移方向不同,统一中值流
≈(0,0)→ prediction = no prediction → LK 从 `prev_pts + (0,0)` = `prev_pts` 起步,
与关中值流完全等价。**所以在纯旋转段,中值流不会主动伤害——它只是"不起作用"**。

那"中值流有害"只能来自另一种机制: 旋转段的前后几帧有大的平移分量(混合运动),
中值流给了错误的平移预测,使 LK 初始猜偏离了正确收敛域。这需要数据验证。

### 3.3 实验设计

**原则**: 与 Level A 的分析结果联动——如果 Level A 确认 PnP 失败是主因,
Level B 的指标就以 `pnp_success` 率和 `num_shared` 中位数为核心。

**必须跑**:

| 实验 | 内容 | CLI 支持 | 动机 |
|---|---|---|---|
| E0 | 等效⑤c = 关 B1+B2+B3 + B4=0.01 + B5=3 | 需三个临时 flag(见 §4) | 复现 ⑤c,作为 Level B 基准 |
| E4 | quality 0.003→0.01 | `--tracker-quality-level 0.01` | 量变项,已有 CLI |
| E5 | pyramid 4→3 | `--tracker-lk-pyramid-levels 3` | 量变项,已有 CLI |
| E6 | E4+E5 同时 | 两者 CLI | 量变叠加,最接近 ⑤c 的两项 |
| E7 | 关 B2+关 B3 | 需两个临时 flag | 关闭两机制,最接近 ⑤c 前端 |

**选跑**(仅当 E4-E7 的结果不清):

| 实验 | 内容 | 时机 |
|---|---|---|
| E1 | 关 CLAHE | 若 E7(关中值流+关 F-RANSAC)仍然与 ⑤c 有显著差异 |
| E2 | 关中值流 | 若 E0 和 E7 的差异主要由中值流驱动(非 F-RANSAC) |
| E3 | 关 F-RANSAC | 若 E7 与 E0 差异不大,但单独关中值流差异大(证伪) |

**跑哪些序列**: V1_02(主靶)+ MH_01(硬门 0.0988)+ V1_01(旋转对照组)。

**不跑**:
- quality=0.001(Kimera)或 0.005(中间值)——参数微调,根因摸清前不追
- pyramid=5(超出 Kimera 参考)
- V1_03(太重,且 V1_03 有显著光照问题,不是前端参数的纯测试案例)

### 3.4 数据分析

对每组实验,从 diag.csv 提取:
1. `pnp_success=0` 帧数(整体 + segment_id=0 仅)
2. `num_shared` 中位数和 <10 占比
3. `segment_id` 跳变次数和位置
4. `status=rejected` 帧数
5. `reproj_rms_after_cull_px` 中位数
6. ATE trans RMSE (从 summary.json)

判断:
- E4/E5/E6 与 E0 对比 → 量变项贡献
- E7 与 E0 对比 → 机制项(B2+B3)贡献
- E1 与 E7 对比(若跑)→ CLAHE 贡献
- E2/E3 单独(若跑)→ 中值流 vs F-RANSAC 各自贡献

### 3.5 Level B 验收标准

- 5 项改动中至少明确 3 项的 V1_02 收益/伤害方向
- 确认中值流在 V1 旋转段是否有净负收益
- 确认 F-RANSAC 的 FB 幸存 track 误杀率
- MH_01 硬门不回归
- 输出推荐配置

## 4. 一次性代价: 临时 CLI flag
