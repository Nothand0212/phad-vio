# M4.4 gyro fixed-lag read-only shadow 实施计划

设计：
[`m4.4-gyro-fixed-lag-shadow-design.md`](../research/m4.4-gyro-fixed-lag-shadow-design.md)

结果：
[`m4.4-gyro-fixed-lag-shadow-result.md`](../research/m4.4-gyro-fixed-lag-shadow-result.md)

本文档描述当前约定，不是绝对约束，会随项目开发修订。

## 1. Vertical slice

本片只增加显式 probe path。shadow 消费 production post-cull graph events，但不反馈 pose、
bias、landmark、status、schedule 或下一帧初值。默认 path 为空时不得构造 smoother，主路径
保持 B3。

本片输出是一个独立 CSV 与 canonical JSON 分析；不把 shadow pose 拼接成“反事实 ATE”，
不改变 config hash，不新增 runtime selector/mode/fallback。

## 2. 实施顺序

1. 先扩展 public POD diagnostics 与 public-seam tests，观察 shadow 字段/行为尚不存在；
2. 在 estimator PIMPL 内实现 bootstrap、add-only factors、dynamic lag、generation 与
   candidate snapshot；
3. 通过长序列测试锁定 bounded state、fixed bias、zero orphan/missing slot 与 on/off
   production equality；
4. 实现独立 writer 与 session/CLI wiring，open writer 后才打开 estimator shadow option；
5. 写 analyzer 与 synthetic CSV tests；
6. 定向/完整回归通过后跑一次 MH_01，不先扩其他序列。

## 5. MH_01 停止条件

- main artifact/config byte gate 任一失败：先定位行为污染，不解释 shadow delta；
- orphan/missing slot/pose-set mismatch/exception 任一非零：P1 FAIL，停在首个坏 epoch；
- state 数无界：P1 FAIL，不以完整 run “跑完了”冒充成功；
- 结构门全部通过：记录 delta 分布与 cull retirement 规模，再设计单路径 handoff；
- P1 不运行 MH_05/11，也不改变 M4.4 未完成状态。

## 6. 实际结果

- P0 installed-library contract `5/5 PASS`；P1 estimator lifecycle `4/4 PASS`、
  writer/session/CLI `8/8 PASS`、Python analyzer `4/4 PASS`；
- 完整 unit `410/410`、0 fail（407 PASS + 3 个既有 dataset SKIP）；
- MH_01 sidecar `3681` 行，其中 inactive/active=`2001/1680`；bootstrap=`1`、
  segment reset=`0`、missing slot/orphan=`0/0`，pose count 最大值与 batch 同为 `10`；
- `est.tum/kf.tum/diag.csv` 与 recovery 逐字节相同，config hash 保持 `f6808356`；
- shadow-vs-batch translation delta p50/p95/max=`0.208/0.606/0.643 m`，rotation
  p50/p95/max=`0.0310/0.0554/0.0620 rad`；P1 结构门通过，但 direct handoff 无授权；
- 下一片尚待用户在 candidate-owned closed-loop shadow、直接 handoff 或停止
  fixed-lag 三者中确认；未扩 MH_05/11，M4.4 未完成。
