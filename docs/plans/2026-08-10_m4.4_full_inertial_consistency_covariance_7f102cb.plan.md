# M4.4 full-inertial consistency covariance 实施计划

设计：
[`m4.4-full-inertial-consistency-covariance-probe.md`](../research/m4.4-full-inertial-consistency-covariance-probe.md)

本文档描述当前约定，不是绝对约束，会随项目开发修订。

## 1. Vertical slice

本片验证：复用 alignment 已计算的 held-out position RMS，在标准 GTSAM
`ImuFactor` 的 PIM covariance 上增加固定公式的 rotation/position/velocity effective
discrepancy，并把实际 sigma 写入只读 sidecar。MH_01 单臂未通过精度门，因此该
production 行为按计划撤回；只保留不改变 estimator 数值行为的诊断与解析修复。

不改 residual、sensor noise density、bias/prior、window、keyframe、frontend、eval；
不新增 amplitude/config/CLI knob，不实现 marginalization。

## 2. 小步顺序

1. 为 covariance 纯函数写 red tests：block layout、cross-covariance、zero/invalid；
2. 实现 helper，并通过标准 `ImuFactor::cloneWithNewNoiseModel()` 替换 noise；
3. 为 alignment RMS 的 commit/demotion/rollback 写 lifecycle red tests；
4. 接 state 与 graph，检查 factor count/type/residual 不变；
5. 为 sidecar 新列与 full/non-full 有效性写 red tests并实现；
6. 定向 tests → 完整 unit/Python → MH_01 单臂 run；
7. MH_01 任一门失败即记录并恢复该臂；通过才继续 MH_05。

## 5. 真实运行与停止条件

- candidate runtime snapshot 必须来自 `meta.json.config/config_canonical_text`；由于没有
  新 config，hash 应保持 B5 的 `865fa580`；
- 先核对 activation epoch 与 pre-full trajectory，再算全程及 full suffix exact-common；
- MH_01 ATE/RPE 任一不严格优于 paired VO：不跑 MH_05，不扫 scale；
- MH_01 通过后 MH_05 任一门失败：保存失败分解，不扩 11/11；
- 只有 required scope 全部严格 `VIO < VO` 且健康门通过，才可更新 M4.4 完成状态。

## 6. 执行结果

- TDD 与完整 unit/Python 验证通过；
- MH_01 candidate 全程 ATE/RPE=`0.0963460/0.0181547 m`，paired VO=
  `0.0809641/0.0177812 m`；full suffix 亦双门失败；
- factor-cost 显示 normalized IMU cost 已回到一致性量级，故失败不能归因于实验 factor
  未生效；
- 按停止条件未运行 MH_05、未扩 11/11、未扫参数，并恢复 raw factor covariance；
- 后续转入 activation phase/window-history 的 no-write 诊断。
