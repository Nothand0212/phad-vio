# M4.4 VIO bias transition 合同修复实施计划

设计：
[`m4.4-vio-bias-transition-design.md`](../research/m4.4-vio-bias-transition-design.md)

本文档描述当前约定，不是绝对约束，会随项目开发修订。

## 1. 切片边界

- **A（本次）**：共同 support/bias probes + 删除重复 bias `BetweenFactor` + 单次
  MH_01 A/B。
- **B（条件后续）**：A 未达 VIO>VO 出口时，先另起 PIM prediction/posterior
  只读探针；没有状态证据前不实现 fixed-lag/marginalization。

## 2. 已对齐决策

| 决策点 | 结论 |
|---|---|
| 比较 support | VIO/VO exact timestamp intersection |
| 质量出口 | ATE、RPE translation RMSE 均严格低于 VO |
| factor 合同 | `CombinedImuFactor` 单独拥有 bias evolution |
| 配置 | 不加开关、不改 config hash、不扫参数 |
| 失败处理 | 记录真实结果；不靠噪声调参补救 A |

## 3. 实施步骤

1. 给 `scripts/vio_vo_common_support.py` 补 synthetic/contract tests，并把两个 probe
   的用法写入 `scripts/README.md`。
2. 在 `stereo_vo_estimator.cpp` 删除：
   - `#include <gtsam/slam/BetweenFactor.h>`；
   - `dt`、`gyr_rw_sigma`、`acc_rw_sigma`、`bias_sigmas`；
   - `BetweenFactor<ConstantBias>`。
3. 确认连续 interval 仍创建一个 `CombinedImuFactor`，gap weak-prior 分支不变。
4. 格式化受影响 C++，运行定向与 unit tests。
5. 跑唯一一次 MH_01 默认参数实验，随后运行共同 support 与 bias probes。
6. 按预注册门判定 A：达 VIO>VO 则进入扩展验证；仅改善则进入 B 设计；恶化则撤销
   生产刀并记录失败，再进入 B。

## 7. 执行结果（2026-08-10）

- Python probes `7/7`；estimator `84/84`；apps `34 PASS + 3 SKIP`；完整 unit
  `361 PASS + 3 SKIP`，0 fail；
- 唯一生产修改为删除额外 bias `BetweenFactor` 及其 sigma 构造；
- MH_01 candidate 相对 control 的 ATE/RPE 分别改善
  `1.2704385e-6 / 1.2335049e-7 m`，schedule 与完整性不变；
- 相对共同 support VO 仍差 `0.0391486 / 0.0046226 m`，M4.4 出口 FAIL；
- acc bias RMS error 略增，未证明 duplicate factor 是主要精度根因；
- A 按预注册可保留门保留，后继改为只读 PIM/posterior state probe，不直接实现
  fixed-lag。
