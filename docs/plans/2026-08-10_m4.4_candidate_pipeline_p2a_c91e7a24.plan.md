# M4.4 candidate-owned pipeline P2a seam tracer 实施计划

设计：
[`m4.4-candidate-pipeline-design.md`](../research/m4.4-candidate-pipeline-design.md)

一手资料：
[`m4.4-candidate-owned-shadow-reference.md`](../research/m4.4-candidate-owned-shadow-reference.md)

Issue：[#34](https://github.com/Nothand0212/phad-vio/issues/34)

本文档描述当前约定，不是绝对约束，会随项目开发修订。

## 1. 本片唯一目标

P2a 证明以下反事实 seam 可信：同一份不可变 rectified stereo 与 IMU interval 同时送入
production 和 candidate；candidate 自己拥有 tracker、ID allocator、KF transaction、
estimator、landmark/cull/drop、reset、diagnostics 与 trajectory，且绝不反馈 production。

本片 candidate 暂时使用第二套现行 concrete `StereoVoEstimator`。其唯一用途是制造应当
等价的 batch twin，从而验证 ownership。P2a：

- 不接 `IncrementalFixedLagSmoother`；
- 不计算或宣称新的 VIO 精度；
- 不公开 backend enum/factory/`IOptimizer`；
- 不保留 production fallback、silent reset 或混合 trajectory；
- 不跑 MH_05/11。

## 2. Public seam

新增 `apps/candidate_pipeline.hpp/.cpp`，move-only + PIMPL：

```cpp
CandidateCreateResult CandidatePipeline::create(
    camera::RectifiedStereoCalibration calibration,
    CandidatePipelineOptions options );

CandidateProgress CandidatePipeline::process(
    const CandidateFrameInput& input );

CandidateRunResult CandidatePipeline::finish() &&;
```

`CandidateFrameInput` 只借用本次调用的 rectified frame/IMU span；implementation 不保留
alias。`finish() &&` 统一构造 trajectory/KF trajectory、diagnostics、counts 与 terminal
error。GTSAM/OpenCV implementation types 不进 public header。

## 3. TDD vertical cycles

### Cycle ①：完整最小闭环

先新增 `tests/apps/candidate_pipeline_test.cpp` 的一条 public-seam test：用
`tests/frontend/synthetic_stereo.hpp` 的静态双目点阵、首帧零段和合法静止 IMU 区间，
断言输入 bytes 不变、candidate 有 accepted finite identity-gauge `T_W_B`、trajectory 非空且
严格单调。先构建并保存缺 interface/行为的 RED 输出，再实现最小 GREEN。

### Cycle ②：ownership

两个独立 candidate 实例消费相同序列，结果完全一致；只改变其中一个实例的一帧输入，
允许它后续分叉，但另一实例保持 reference。测试不 mock tracker/gate/estimator，不读取
private state。

### Cycle ③：错误

逐条覆盖：逆序 timestamp、错误 `t_prev`、非-gap IMU 端点/顺序错误 → typed terminal；
transaction rollback 成功的 frame `kFailed` 可继续；terminal run 保留 diagnostics/error、
不返回 trajectory。

### Cycle ④：session 与 artifacts

`OfflineVoSession` 在 production frame 完整处理后再调用 candidate；candidate terminal 只停止
candidate。bench 写独立 candidate TUM/KF/diagnostics，candidate path/flag 不进 production
config hash。writer/analyzer 错误升级为 session/bench error，不混入 estimator transaction。

## 6. MH_01 硬门

reference：

```text
run         m44_gyro_only_recovery_b3a1c0de
config_hash f6808356
production  poses=3681, failed=0, segments/reanchors=1/0
```

candidate on 后必须：

1. production `est.tum`、`kf.tum`、`diag.csv` 与 reference 逐字节相同，config hash 不变；
2. candidate `est.tum`/`kf.tum` 与同 run production 逐字节相同；
3. frame status、KF selected/commit/epoch、`T_W_B`、bias、segment、cull/drop 映射逐行相同；
4. `ownership=full_pipeline`，candidate input rows 完整，terminal=`0`、failed=`0`；
5. candidate timing 单独报告，不污染 production frontend/estimator stage timing。

任一失败即 P2a FAIL；不接 P2b、不放宽 schema/byte gate、不把差异解释成 fixed-lag 行为。

## 7. P2a 出口

P2a 全部门通过后：

- 写结果文档与可复现 runtime snapshot；
- 把临时 batch candidate 标为待 P2b 删除；
- 重新基于 P2a 日志审计第一处分叉风险；
- 另写 P2b 设计/计划，用唯一 concrete fixed-lag implementation **替换** batch twin。

M4/M4.4 在 P2a 后仍是未完成；只有 P2b 及最终 EuRoC 11/11 paired exact-common
ATE/RPE 双指标严格 `VIO < VO` 才能完成。
