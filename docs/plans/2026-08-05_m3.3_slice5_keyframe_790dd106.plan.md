# M3.3 Slice ⑤ 关键帧策略

**Goal:** 引入关键帧选择策略，使 estimator 滑窗只包含稀疏关键帧，延长窗口时间跨度，
缓解 V1_03/V2_02 前端重置问题，为 M4 IMU 预积分预备帧边界。

**Architecture:** 关键帧选择逻辑放在 apps/session 层（`isKeyframe()` 判断），
estimator `update()` 新增 `bool keyframe = true` 参数——非关键帧时跳过
window/landmark/graph 修改和 LM 优化，仅做 PnP 位姿估计 + 更新 last/prev。
这避免了从 `update()` 中提取共享 helper 的大范围重构，所有改动集中在单一
方法的条件分支上。窗口管理（`push_back`/`pop_front`/`buildGraph`）不变，
只是 session 只在关键帧时触发 BA 路径。

**Tech Stack:** 既有 C++20 / Eigen / OpenCV / GTSAM / GTest / `phad_vo_bench`；
无新依赖。

Issue：[#23](https://github.com/Nothand0212/phad-vio/issues/23)（M3.3 总图）。

## 已对齐的决策

| 决策点 | 结论 |
|---|---|
| 关键帧选择标准 | 组合：视差 > 30 px OR track 存活率 < 60% OR 时间 > 0.5s |
| 非关键帧处理 | Track-only：PnP 估计位姿，不进窗口 BA，不 seed 新 landmark |
| IMU 预积分边界 | 关键帧 = 边界；非关键帧 IMU 在 M4 merge 进上段 |
| 窗口管理 | `window_size=10` 不变，但窗口只含关键帧 |
| 前置关键帧数 | 前 2 帧总是关键帧 |
| 阈值 visibility | 不进 config_hash（session 常量，不作为 estimator 配置项） |
| 轨迹输出 | est.tum 逐帧（含非关键帧 PnP 位姿）；新增 kf.tum 只存关键帧优化位姿 |
| 非目标 | 不改 PnP/cull/reopt/reanchor 逻辑；不改 frontend；不实现 IMU 代码 |

## Task 1：实现关键帧判断函数

修改 `apps/offline_vo_session.hpp`（新增 session 成员）和
`apps/offline_vo_session.cpp`（新增 `isKeyframe()` 函数）。

### 1.1 Session 新增成员

```cpp
// keyframe selection (Slice ⑤)
struct KeyframeSelectorState {
  std::unordered_map<common::LandmarkId, Eigen::Vector2d> last_kf_pixels;
  common::Timestamp last_kf_timestamp{0};
  std::uint32_t total_keyframes = 0;
};
KeyframeSelectorState kf_state_;
```

### 1.2 isKeyframe() 函数

```cpp
bool isKeyframe(const frontend::FrameTracks& tracks,
                common::Timestamp current_ts) {
  // Rule 1: first 2 frames always keyframes
  if (kf_state_.total_keyframes < 2) return true;

  // Rule 2: time fallback (> 0.5s)
  if (common::durationSec(current_ts, kf_state_.last_kf_timestamp) > 0.5)
    return true;

  // Rule 3: track survival ratio
  std::size_t common_count = 0;
  for (const auto& track : tracks.tracks()) {
    if (kf_state_.last_kf_pixels.count(track.id) > 0) ++common_count;
  }
  double survive_ratio = static_cast<double>(common_count) /
                         std::max(kf_state_.last_kf_pixels.size(), 1ul);
  if (survive_ratio < 0.6) return true;

  // Rule 4: average parallax
  double parallax_sum = 0.0;
  std::size_t parallax_count = 0;
  for (const auto& track : tracks.tracks()) {
    auto it = kf_state_.last_kf_pixels.find(track.id);
    if (it == kf_state_.last_kf_pixels.end()) continue;
    double dx = track.left_pixel.x() - it->second.x();
    double dy = track.left_pixel.y() - it->second.y();
    parallax_sum += std::sqrt(dx * dx + dy * dy);
    ++parallax_count;
  }
  if (parallax_count > 0 &&
      (parallax_sum / parallax_count) > 30.0)
    return true;

  return false;
}
```

### 1.3 关键帧快照更新

每次关键帧通过 `update()` 后调用：

```cpp
void updateKeyframeSnapshot(const frontend::FrameTracks& tracks,
                            common::Timestamp ts) {
  kf_state_.last_kf_pixels.clear();
  for (const auto& track : tracks.tracks())
    kf_state_.last_kf_pixels[track.id] = track.left_pixel;
  kf_state_.last_kf_timestamp = ts;
  ++kf_state_.total_keyframes;
}
```

## Task 2：estimator update() 增加 keyframe 参数

修改 `phad/estimator/stereo_vo_estimator.hpp` 和
`phad/estimator/stereo_vo_estimator.cpp`。

### 2.1 方案：`bool keyframe` 参数

不在 estimator 新增独立 method。改为在现有 `update()` 方法签名增加参数：

```cpp
// stereo_vo_estimator.hpp:
VioUpdateResult update(const KeyframeMeasurement& measurement,
                       bool keyframe = true);
```

`keyframe=false` 时，`update()` 在正常流程的特定点提前返回：

```
update(measurement, keyframe):
    // 1. validation（共享）
    validate measurement (non-finite pixel, disparity, timestamp)

    // 2. shared counting（共享）
    count num_shared against landmarks_W

    // 3. reanchor / first-frame check —— only for keyframe
    if keyframe && overlap_broken && can_seed:
        seedSegment(...); return  ← 只有关键帧可 reanchor
    if keyframe && first_frame && can_seed:
        seedSegment(...); return

    // ↓ 以下 keyframe 和 non-keyframe 共享 ↓

    // 4. PnP init + stereo arbitration（共享）
    guess = poseInitialValue()
    if shared >= min_pnp_inliers:
        pnp = tryPnpInit(measurement, guess)
        if pnp passes arbitration:
            candidate.T_W_B = pnp.pose
            apply PnP mask

    // 5. non-keyframe: early return after PnP
    if !keyframe:
        update last/prev_accepted ← candidate.T_W_B (or guess if PnP failed)
        diagnostics: segment_id, pnp_success/inliers, num_shared only
        return kOk (or kRejected if shared < min_pnp_inliers)
        // ── NO window push, NO landmark backproject, NO buildGraph, NO LM ──

    // 6. keyframe: continue with full pipeline（现有逻辑不变）
    backproject new landmarks → push window → pop oldest → buildGraph → LM
    → cull → reopt → dropCheirality → diagnostics → return
```

### 2.2 关键实现细节

**PnP guess 来源**：`poseInitialValue()`（恒速预测，与 keyframe 路径完全相同）。

**PnP 仲裁保留**：`tryPnpInit()` + stereo RMS 仲裁在非关键帧路径**也运行**。
非关键帧的 PnP proposal 仍需通过仲裁才能被采用；被拒绝时回退恒速 guess。
这保证 `last_accepted` 不被错误 proposal 污染。

**非关键帧 shared < min_pnp_inliers**：返回 `kRejected`，**不更新**
`last/prev_accepted`。恒定速度链保持上一个有效位姿不变。关键帧到来时
`poseInitialValue()` 从该位姿出发计算初始猜测。

**代码复用**：此方案避免了 ~100 行重复代码。所有共享逻辑（validation、
PnP init、仲裁）只写一次。新增的 `if (!keyframe)` 分支约 10 行。

### 2.3 Reanchor 后的空窗期（有意设计）

Reanchor（`seedSegment`）只在关键帧发生。Reanchor 后 `landmarks_W` 只含
anchor 帧的 landmark，下一关键帧之前的所有非关键帧都可能因 shared 不足
而 rejected。示例：

```
K_i:   shared=0 → reanchor, landmarks_W 重建（anchor 帧的 landmark）
NK_1:  shared 可能 >0（如果前端 track 匹配 anchor 帧的 id）→ PnP ok
NK_2:  shared 同上
NK_3:  前端 track 全部刷新 → shared=0 → rejected
NK_4:  shared=0 → rejected
K_{i+1}: shared=0 → reanchor（下一个 segment）
```

这与**当前**每帧-reanchor 的循环对比：

```
当前系统：
F_1: shared=0 → rejected（enable_reanchor=false 时）或 reanchor（enable_reanchor=true 时）
F_2: reanchor → 1 帧 segment
F_3: shared=0 → reanchor → 1 帧 segment
F_4: shared=5 → 勉强跟踪
...
```

关键帧化后，非关键帧期间的前端重置被"压缩"到一个 KF 周期——只有下一个
关键帧才触发一次 reanchor，而非每帧触发。V1_03 se=15→预期下降到 3-5。

**这不是 bug**。如果 reanchor 后首个 KF 周期非关键帧全部 rejected，说明
前端仍未恢复，下一关键帧应当 reanchor。这比当前 14 个 1-3 帧 segment
要健康得多。

## Task 3：集成 session processFrame()

修改 `apps/offline_vo_session.cpp` 的 `processFrame()`。

### 3.1 流程

```text
FrameTracks from frontend
        │
        ▼
   isKeyframe(tracks, ts)
        │
    ┌───┴───┐
   YES      NO
    │        │
    ▼        ▼
estimator   estimator
::update(   ::update(
  meas,       meas,
  true)       false)
    │        │
    ▼        ▼
full BA    PnP only
+ window   + update
+ est.tum  last/prev
+ kf.tum   + est.tum (PnP pose)
    │        │
    ▼        ▼
updateKeyframeSnapshot(tracks, ts)
── NOTE: tracks = original FrameTracks, BEFORE PnP mask
          (session has the unfiltered FrameTracks;
           estimator's PnP mask is internal to update())
```

关键：`updateKeyframeSnapshot()` 保存的是**原始的** `FrameTracks` 左目像素，
未经 estimator 内部的 PnP mask 过滤。这保证 `last_kf_pixels` 包含所有前端
track，而非只包含 PnP inlier——下一帧的 track 存活率计算不会因为 PnP mask
而被人为压低。
