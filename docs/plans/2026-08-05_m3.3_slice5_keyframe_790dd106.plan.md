# M3.3 Slice ⑤ 关键帧策略

**Goal:** 引入关键帧选择策略，使 estimator 滑窗只包含稀疏关键帧，延长窗口时间跨度，
缓解 V1_03/V2_02 前端重置问题，为 M4 IMU 预积分预备帧边界。

**Architecture:** 关键帧选择逻辑放在 apps/session 层（`isKeyframe()` 判断），
estimator 新增轻量 `trackOnly()` public method 用于非关键帧的 PnP-only 位姿更新。
窗口管理（`push_back`/`pop_front`/`buildGraph`）不变，只是 session 只在关键帧时
调用 `update()`，降低了窗口推入频率。

**Tech Stack:** 既有 C++20 / Eigen / OpenCV / GTSAM / GTest / `phad_vo_bench`；
无新依赖。

Issue：[#23](https://github.com/Nothand0212/phad-vio/issues/23)（M3.3 总图）。

## 已对齐的决策

| 决策点 | 结论 |
|---|---|
| 关键帧选择标准 | 组合：视差 > 30 px OR track 存活率 < 60% OR 时间 > 0.5s |
| 非关键帧处理 | Track-only：PnP 估计位姿，不进窗口 BA，不 seed 新 landmark |
| IMU 预积分边界 | 关键帧 = 边界；非关键帧 IMU 在 M4 merge 进上段 |
| 窗口管理 | `window_size=10` 不变，但窗口只含关键帧 |
| 前置关键帧数 | 前 2 帧总是关键帧 |
| 阈值 visibility | 不进 config_hash（session 常量，不作为 estimator 配置项） |
| 轨迹输出 | 非关键帧不写 `est.tum`——只输出关键帧优化位姿 |
| 非目标 | 不改 PnP/cull/reopt/reanchor 逻辑；不改 frontend；不实现 IMU 代码 |

## Task 1：实现关键帧判断函数

### 1.1 Session 新增成员

```cpp
// keyframe selection (Slice ⑤)
struct KeyframeSelectorState {
  std::unordered_map<common::LandmarkId, Eigen::Vector2d> last_kf_pixels;
  common::Timestamp last_kf_timestamp{0};
  std::uint32_t total_keyframes = 0;
};
KeyframeSelectorState kf_state_;
```

### 1.2 isKeyframe() 函数

```cpp
bool isKeyframe(const frontend::FrameTracks& tracks,
                common::Timestamp current_ts) {
  // Rule 1: first 2 frames always keyframes
  if (kf_state_.total_keyframes < 2) return true;

  // Rule 2: time fallback (> 0.5s)
  if (common::durationSec(current_ts, kf_state_.last_kf_timestamp) > 0.5)
    return true;

  // Rule 3: track survival ratio
  std::size_t common_count = 0;
  for (const auto& track : tracks.tracks()) {
    if (kf_state_.last_kf_pixels.count(track.id) > 0) ++common_count;
  }
  double survive_ratio = static_cast<double>(common_count) /
                         std::max(kf_state_.last_kf_pixels.size(), 1ul);
  if (survive_ratio < 0.6) return true;

  // Rule 4: average parallax
  double parallax_sum = 0.0;
  std::size_t parallax_count = 0;
  for (const auto& track : tracks.tracks()) {
    auto it = kf_state_.last_kf_pixels.find(track.id);
    if (it == kf_state_.last_kf_pixels.end()) continue;
    double dx = track.left_pixel.x() - it->second.x();
    double dy = track.left_pixel.y() - it->second.y();
    parallax_sum += std::sqrt(dx * dx + dy * dy);
    ++parallax_count;
  }
  if (parallax_count > 0 &&
      (parallax_sum / parallax_count) > 30.0)
    return true;

  return false;
}
```

### 1.3 关键帧快照更新

每次关键帧通过 `update()` 后调用：

```cpp
void updateKeyframeSnapshot(const frontend::FrameTracks& tracks,
                            common::Timestamp ts) {
  kf_state_.last_kf_pixels.clear();
  for (const auto& track : tracks.tracks())
    kf_state_.last_kf_pixels[track.id] = track.left_pixel;
  kf_state_.last_kf_timestamp = ts;
  ++kf_state_.total_keyframes;
}
```

## Task 2：实现 estimator trackOnly()

修改 `phad/estimator/stereo_vo_estimator.hpp`（public API）和
`phad/estimator/stereo_vo_estimator.cpp`（PIMPL 实现）。

### 2.1 Public API

```cpp
// In stereo_vo_estimator.hpp:
VioUpdateResult trackOnly(const KeyframeMeasurement& measurement);
```

### 2.2 PIMPL 实现

`trackOnly()` 是 `update()` 的严格子集：

1. 校验 measurement（non-finite pixel、non-positive disparity）
2. 计算 `num_shared`（与 landmarks_W 比较）
3. 若 `shared < min_pnp_inliers` → `kRejected`，返回
4. 运行 `tryPnpInit()` → PnP 位姿
5. 若 PnP 失败 → 回退恒速 guess
6. 更新 `last_accepted_T_W_B` / `prev_accepted_T_W_B`
7. 返回 `kOk`，diagnostics 仅填 `segment_id`、`pnp_success/inliers`、`num_shared`
8. **不** modify `window`、`landmarks_W`、`track_times`、`culled_ids_`
9. **不** run `buildGraph()` / GTSAM optimization

> 注意：`trackOnly()` 复用现有的 `tryPnpInit()` + stereo RMS 仲裁逻辑，
> 不绕过 PnP 的安全性检查。非关键帧的 PnP proposal 仍需通过仲裁才能被采用。

### 2.3 非关键帧 rejected 的边效

若 `trackOnly()` 返回 `kRejected`（shared 不足或 PnP 失败），session 应：
- 不更新 `last/prev_accepted`（恒速预测链不断）
- 在 diag.csv 中该帧 `status = rejected`、`is_keyframe = 0`
- 继续处理下一帧（无论其是否关键帧）
