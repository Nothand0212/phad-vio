## 1. 本片唯一目标

P2b 证明固定滞后生命周期的结构性健康：candidate 拥有 pose/bias/landmark 的
key、timestamp、factor slot 与 marginal prior 生命周期；active 量有界；
异常/孤儿/rollback 失败是 typed terminal error；MH_01 一次结构门通过。
**不计算或宣称新的 VIO 精度**；最终精度门以 `docs/roadmap.md` 为准。

- 不保留 backend switch/fallback/兼容路径；删除 batch twin 临时代码；
- 不公开 backend enum/factory/`IOptimizer`；GTSAM 类型不越过 public seam；
- production 三主产物与 config hash 不受影响；`--candidate` 仍 CLI-only。

## 2. Public seam（不变）

```cpp
CandidateCreateResult CandidatePipeline::create(calibration, options);
CandidateProgress     CandidatePipeline::process(const CandidateFrameInput&);
CandidateRunResult    CandidatePipeline::finish() &&;
```

GTSAM/OpenCV implementation types 不进 public header；`CandidateGraphDiagnostics`
由恒空改为真实计数（存量 active / 增量 marginalized/retired，不暴露 keys/slots）。

## 3. TDD vertical slices

### Slice ① P0 contract probe

新增 `tests/estimator/fixed_lag_contract_test.cpp`（经稳定头 + `gtsam` target，
不改产品输出），六项 installed-library 合同：

1. cutoff 严格 `<`，恰在 cutoff 的 key 保留；
2. 已有 shared key 只刷 timestamp 不重复插 value 可跨 lag 存活；
3. 首次 pose 边缘化后幸存 key 进入 `getFixedVariables()`；
4. `newFactorsIndices` 与插入顺序对应、空 slot 可复用；
5. 删最后 factor 后 `timestamp present && !valueExists`，下次到期显式失败；
6. 人工制造 update 异常，恢复 smoother + ledger snapshot 后下一合法 update 成功。

### Slice ② fixed-lag 骨架

`apps/candidate_pipeline.cpp` 的 `Impl::estimator` 成员从 batch
`StereoVoEstimator` 替换为新建 concrete `CandidateFixedLagEstimator`
（PIMPL 内私有类，先只做 pose-only 图）：

- 每 accepted KF 一个 `X(frame_index)`（timestamp = accepted frame_index
  double）；cutoff 严格 `<` 由 lag 计算保证；
- 每帧 `update()` 前 snapshot 整个 smoother + timestamp/slot 账本；异常恢复
  snapshot 后返回 `kEstimatorInvariant` terminal；
- slot 账本：`newFactorsIndices` 记录、删除前 `exists(slot)` 校验；
- segment reset = 显式重建（`reset_reason` 记录），不是静默 fallback。

RED→GREEN：先写 synthetic 序列的候选门测试（有界、terminal=0、failed=0、
reset 声明正确、candidate enabled/failed 不影响 production 三主产物回归），
再最小实现。

### Slice ③ landmark 生命周期

- `L(id)` key（candidate tracker 全局递增 `LandmarkId`，无 rebirth）；
- 进图前重投影 gating（阈值初始值复用 production 的 reprojection 语义）；
- 窗口自然退休：最后观测 pose 出窗后删 factor/value，`retired_landmark_count`
  增量；zero-disparity 不建 factor 不刷 timestamp；
- cull/drop 反馈与 P2a 对齐（gating 拒收 → tracker 侧仍可 dropTracks）。

### Slice ④ per-KF bias 链

- `B(frame_index)` per accepted KF + 相邻 KF random-walk edge
  （σ_rw 来自标定参数）；
- gyro BetweenPose3 因子复刻 production 的 gyro factor 构造（不改因子语义）；
- 旧 bias 随旧 pose 边缘化；不做 shared frozen bias。

### Slice ⑤ 非 KF 帧 PnP + 诊断 + artifacts

- 非 KF 帧用 candidate landmarks PnP → trajectory pose；失败 → `kRejected`
  （非 terminal）；
- `CandidateGraphDiagnostics` 真实计数；`candidate_artifacts`/analyzer 扩展
  graph 计数校验（`scripts/candidate_pipeline_probe.py`）；
- diagnostics 行数 = 送入帧数、ts 递增、graph 计数与账本一致。

### Slice ⑥ MH_01 结构门

- synthetic 全绿后跑一次 MH_01（`--candidate`）：
  terminal=0、failed=0、finite、无未声明 reset；
  completion/coverage 不低于 paired VO（`--no-imu` 同 run）；
  active state/factor 有界；candidate artifacts 完整；
- 删除 batch twin 临时代码（`StereoVoEstimator` 从 candidate 移除）；
- 写结果文档 + 可复现 runtime snapshot；P2b 精度结论不宣称。

任一 slice 的结构门失败 → 停在对应诊断，不扫 lag/threshold 参数、不扩序列。

## 6. MH_01 结构门

reference：P2a 的 `m44_p2a_candidate_v2`（config_hash `f6808356`）。

candidate on 后必须：

1. production `est.tum`、`kf.tum`、`diag.csv` 与 P2a run 逐字节相同，config
   hash 不变；
2. candidate terminal=0、failed=0、estimate 全 finite、无未声明 reset；
3. active pose/factor/landmark 有界（≤ 窗口上界 + 常数），
   timestamp/valueExists 无孤儿；
4. completion/coverage 不低于 paired VO（`--no-imu`）；
5. candidate artifacts 完整（analyzer 含 graph 计数校验）、timing 单独报告。

任一失败即 P2b FAIL；不接精度调参、不跑 MH_05/11、不放宽结构门。

## 7. P2b 出口

结构门通过后：

- 写结果文档与可复现 runtime snapshot；
- 把 P2b 结果与 P2a 日志合并审计第一处分叉风险；
- 精度晋级（VIO < VO）是 roadmap 最终出口，需后续独立 slice 调 lag/
  threshold/iSAM2 参数并逐序列验证；在达到前 M4/M4.4 仍标记未完成。
