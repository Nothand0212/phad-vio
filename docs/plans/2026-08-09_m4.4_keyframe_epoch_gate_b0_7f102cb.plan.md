# M4.4 successor B0：Keyframe Epoch Gate 实施计划

Issue：[#34](https://github.com/Nothand0212/phad-vio/issues/34)（part of
[#30](https://github.com/Nothand0212/phad-vio/issues/30)）
设计：
[`m4.4-keyframe-epoch-gate-design.md`](../research/m4.4-keyframe-epoch-gate-design.md)
调研：
[`m4.4-keyframe-schedule-guard-reference.md`](../research/m4.4-keyframe-schedule-guard-reference.md)
探针：
[`m4.4-keyframe-schedule-probe.md`](../research/m4.4-keyframe-schedule-probe.md)

本文档描述当前约定，不是绝对约束，会随项目开发修订。

## 1. 范围与出口

B0 只做行为保持的 module seam：

- 新增 `apps::KeyframeEpochGate`；
- 把 evidence、rule priority 与 accepted-KF commit 变成 production interface；
- session 通过 `decide -> estimator.update -> resolve` 使用该 interface；
- 测试不再复制 production selector；
- 不改 config、CLI、`config_hash`、CSV schema、threshold、rotation source 或 estimator。

B0 的完成出口不是 ATE 改善，而是 MH_01 下以下三份文件逐字节一致：

```text
est.tum  93318dc194cf1be06f580d2ef55188aa
kf.tum   261664a00835a97ff368ec96037caa6d
diag.csv 71bdff9377e4c0073bd7127fed032581
```

若字节门失败，B0 未完成；不进入 B1。

## 2. 步骤 1：新增 production gate

新增：

- `apps/keyframe_epoch_gate.hpp`
- `apps/keyframe_epoch_gate.cpp`

修改 `CMakeLists.txt`，把 `.cpp` 纳入 `phad_offline_vo_session`。不新增 target 或
依赖。

public interface 包含：

- `KeyframeRule` 与完整 `KeyframeTriggers`；
- `KeyframeEvidence`；
- `KeyframeDecision(ticket, selected, rule, evidence)`；
- `KeyframeFeedback(status, optional R_W_B)`；
- `KeyframeEvent(epoch_committed, epoch)`；
- move-only `KeyframeEpochGate::decide/resolve`。

implementation 内部：

1. `EvidenceBuilder` 计算 obs/common/parallax、survival、dt 与所有 trigger；
2. `EpochScheduler` 按当前 Rules 0–4 的严格比较和优先级返回 reason；
3. gate 保存 last-KF pixels/timestamp、`last_accepted_rotation`、
   `last_kf_rotation`、accepted epoch、ticket 和 pending snapshot；
4. `resolve(selected && kOk)` 必须先把旧 `last_accepted_rotation` 写入
   `last_kf_rotation`，再应用当前 feedback pose；
5. wrong/double/unresolved transaction 抛 `std::logic_error`。

不在本步添加 IMU sample/bias、cooldown、运行时 source switch、日志 writer 或配置。

## 3. 步骤 2：接入 OfflineVoSession

修改 `apps/offline_vo_session.cpp`：

1. 删除匿名 namespace 中 `KeyframeSelectorState`、`isKeyframeImpl()`、
   `updateKeyframeSnapshotImpl()` 与 selector lambdas；
2. rectified calibration 创建成功后构造唯一 `KeyframeEpochGate`；
3. 每帧调用 `decision = gate.decide(tracks)`；
4. 保持 measurement/dropout/IMU packet 与 `estimator.update()` 顺序不变，只把
   `is_kf` 替换为 `decision.selected`；
5. update 返回后无条件用同一 ticket 调用 `resolve()`；feedback rotation 仅在
   `status==kOk && estimate` 时有值；
6. 保持后续 result count、trajectory、dropTracks 与 writer 逻辑不变。

session 不读取 evidence 来改变业务行为。B0 interface 的可观测字段只供 tests 和
下一轮 shadow probe 使用。

## 4. 步骤 3：生产 interface tests

改写 `tests/apps/keyframe_selection_test.cpp`，删除：

- 测试专用 selector state；
- `isKeyframeTest()`；
- `updateKeyframeSnapshotTest()`。

所有用例直接构造 `KeyframeEpochGate`。用 helper 只生成 calibration、tracks 与
feedback，不复制业务规则。

定向用例：

1. empty veto；
2. bootstrap 只按 accepted epoch 计数，reject 不推进；
3. `<10` low-tracks；
4. timeout 严格 `>500'000'000 ns`；
5. survival 严格 `<0.6`；
6. compensated parallax 严格 `>30 px`；
7. 完整 trigger mask 与 selected reason priority；
8. pure rotation compensation；
9. selected accept 的旧 pose snapshot 顺序；
10. non-KF `kOk` 更新 causal pose；
11. rejected/failed 不更新；
12. unresolved decide、ticket mismatch、double resolve。

现有测试中有价值的几何场景复用输入数据，不复用 selector implementation。

## 5. 步骤 4：静态检查、构建与 unit

按小到大执行：

```bash
clang-format -i \
  apps/keyframe_epoch_gate.hpp \
  apps/keyframe_epoch_gate.cpp \
  apps/offline_vo_session.cpp \
  tests/apps/keyframe_selection_test.cpp

cmake -S . -B build -DCMAKE_EXPORT_COMPILE_COMMANDS=ON
cmake --build build --target \
  phad_apps_tests phad_vo_bench phad_stereo_vo_probe -j2

./build/phad_apps_tests \
  --gtest_filter='KeyframeEpochGateTest.*'
./build/phad_apps_tests
ctest --test-dir build --output-on-failure -L unit
```

实际并行度按机器负载调整。构建必须无新增 warning；测试失败先定位根因，不用放宽
断言或保留旧 selector 绕过 production interface。

## 7. 步骤 6：B1 shadow probe，而非直接上 guard

只有 B0 byte gate PASS 后才开始：

1. 固定 B0 production decision 和 accepted epoch，不改变 estimator 输入；
2. 记录每帧 evidence、trigger mask、selected reason、resolve outcome；
3. 对候选 guard 只做 shadow counterfactual，明确首次 veto、连续 veto、max-gap
   bypass 与相对 control schedule；
4. 先跑 MH_01 诊断，再依据失败模式决定是否需要 sentinel；
5. 写 B1 独立设计与实施计划后才改 production policy。

当前无证据晋级 `N=5`、two-hit、hysteresis 或 trace match-rate 中的任何一个。

## 8. 回滚与非目标

B0 修改集中在独立 gate、session 接线、CMake 与 tests；若 byte gate 失败，修正提取
语义，不在错误 seam 上继续堆 guard。未经用户明确要求不执行 commit、merge、push
或 issue 状态修改。

B0 不声称改善精度，不运行 EuRoC full-suite，也不满足最终“VIO 优于 VO”目标。
