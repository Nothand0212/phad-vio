## 1. 决策背景与目标

### 1.1 已证事实

直接把 Rule 4 的旋转来源从 BA/PnP pose 换成 last-KF→current gyro
preintegration 后，MH_01 的三个候选均未通过相对 control ATE 门：

| 路径 | parallax threshold | accepted KF | ATE / RPE (m) |
|---|---:|---:|---:|
| 当前 control | 30 px | 518 | 0.122337397 / 0.022956790 |
| IMU rotation | 30 px | 320 | 0.138622478 / 0.022833546 |
| IMU rotation | 15 px | 406 | 0.155501216 / 0.022261365 |
| IMU rotation | 10 px | 533 | 0.132913217 / 0.022121573 |

三条 candidate 与 control 使用完全相同的 3682 帧 timestamp axis，但首次
accepted-KF 分叉后 schedule 会持续级联。即使 IMU10 的总量和 gap 中位数接近
control，其 exact accepted-event overlap 仍只有 133 个，10-frame rolling count
最大差为 5。因此“调回相同 KF 总量”不是时序正确性的充分条件。

上游固定 revision 对照没有提供可直接迁移的 two-hit、固定 trace conformance 或
schedule-independent selector。Basalt 的 `frames_after_kf > 5` 会触及 control 的
296/517 个现有间隔，不是只抑制少量离群分叉的最小刀。B1 的 guard 必须由本仓库
固定-baseline shadow evidence 决定，不能从上游阈值反推。

### 1.2 本设计目标

把当前匿名 selector 演进成一个事务型、可观测的深模块，显式分开：

1. frame evidence 的构造；
2. evidence 到 candidate decision 的纯 policy；
3. estimator 返回后的 accepted-KF epoch commit。

演进按三个可独立归因的 vertical slice 进行：

- **B0：行为保持 seam。** 继续使用当前 `pose_lag` evidence 与当前 Rules 0–4，
  提取 `KeyframeEpochGate`，生产输出必须逐字节一致；
- **B1：只改 schedule policy。** evidence source 仍为 `pose_lag`，根据 B0 shadow
  日志选择一个 guard；
- **B2：只改 rotation evidence。** 删除 BA `pose_lag` 实现，换成唯一 IMU
  last-KF→current evidence 路径。

B0 是后续实验的可观测 seam，不是 M4.4 或 VIO 精度目标的完成条件。

### 1.3 最终产品出口

当前纯 VO 锚来自 M3.3 Slice ⑦，且在 M4.3 IMU-off 精确复现：MH_01
ATE=`0.080964 m`、RPE=`0.017781 m`、completion=`0.999728`、coverage=`1.0`。

最终默认 VIO 至少需要：

1. MH_01 ATE **严格小于** `0.080964 m`，RPE **严格小于** `0.017781 m`；
2. completion/coverage 不低于开工前 VIO control
   `0.879956545 / 0.879923934`，且 `segments/reanchors/failed=1/0/0`；
3. 因 VO/VIO 当前输出时间覆盖不同，另在共同 timestamp support 上做成对评估，
   VIO 仍须同时胜过 VO；
4. 通过 MH_01 后再按同一评价合同扩到 EuRoC 11/11，不能用单序列结果宣称
   “VIO 优于 VO”。full-suite 的序列级晋级规则在出现通过 MH_01 的候选后单独对齐。

旧的 `ATE <= 0.100 m` 只保留为中间债务门，不能替代上述 VO 对照出口。

## 2. 模块边界

### 2.1 唯一外部 seam

新增 `apps::KeyframeEpochGate`，由 `OfflineVoSession` 独占：

```text
StereoTracker -> FrameTracks
                    |
                    v
            KeyframeEpochGate.decide
                    |
                    v
       StereoVoEstimator.update(selected)
                    |
                    v
            KeyframeEpochGate.resolve
```

`apps` 继续承担 composition root；gate 不进入 frontend 或 estimator。B0 不新增
runtime source switch、虚基类、policy hierarchy、配置项或兼容路径。测试与生产 caller
必须使用同一个 public interface，删除测试中的 selector 副本。

gate implementation 内部只有两个具体协作者：

- `EvidenceBuilder`：从当前 tracks、已提交 epoch state 和 calibration 构造事实；
- `EpochScheduler`：无状态地按固定优先级把事实映射成 selected rule。

两者留在 `.cpp`，不成为跨模块抽象。accepted epoch、pending ticket 与 causal pose
由 gate 统一拥有，避免 caller 能绕过事务更新其中一半。

### 2.2 B0 public interface

语义接口如下，实际 identifier 按 C++ naming 规则实现：

```cpp
enum class KeyframeRule : std::uint8_t
{
  kNone,
  kBootstrap,
  kLowTracks,
  kTimeout,
  kLowSurvival,
  kParallax
};

struct KeyframeTriggers
{
  bool empty;
  bool bootstrap;
  bool low_tracks;
  bool timeout;
  bool low_survival;
  bool parallax;
};

struct KeyframeEvidence
{
  common::Timestamp timestamp;
  std::uint64_t     epoch;
  std::size_t       observation_count;
  std::size_t       common_count;
  std::size_t       parallax_count;
  std::int64_t      since_keyframe_ns;
  double            survival_ratio;
  double            raw_parallax_px;
  double            compensated_parallax_px;
  KeyframeTriggers  triggers;
};

struct KeyframeDecision
{
  std::uint64_t    ticket;
  bool             selected;
  KeyframeRule     rule;
  KeyframeEvidence evidence;
};

struct KeyframeFeedback
{
  estimator::UpdateStatus        status;
  std::optional<Eigen::Matrix3d> R_W_B;
};

struct KeyframeEvent
{
  std::uint64_t           ticket;
  bool                    selected;
  estimator::UpdateStatus status;
  bool                    epoch_committed;
  std::uint64_t           epoch;
};

class KeyframeEpochGate
{
public:
  explicit KeyframeEpochGate(
      camera::RectifiedStereoCalibration calibration );

  [[nodiscard]] KeyframeDecision decide(
      const frontend::FrameTracks& tracks );

  [[nodiscard]] KeyframeEvent resolve(
      std::uint64_t ticket, const KeyframeFeedback& feedback );
};
```

public header 只暴露调用方已有的 Eigen、camera、frontend 与 estimator POD；状态和
存储隐藏在 implementation。B0 不预留 IMU samples、bias、cooldown 或 source enum；
这些只在对应 slice 确认后演进 interface。

### 2.3 为什么是 ticket + resolve

当前 estimator 可返回 `kOk`、`kRejected` 或 `kFailed`。candidate 并不等于
accepted KF：只有 `selected && kOk` 才能推进 pixel、timestamp 和 rotation
baseline。`decide()` 必须保存待提交 snapshot，`resolve()` 再根据同一 ticket 原子地
提交或丢弃。

同一 gate 同时最多一个 unresolved ticket。以下均为 caller 编程错误并抛
`std::logic_error`：

- unresolved 时再次 `decide()`；
- ticket 不匹配；
- double resolve。

不提供 silent overwrite、implicit reject 或析构时 commit。

## 3. 数据流与状态语义

### 3.1 B0 evidence

B0 固定以下常量和规则，不进入配置：

```text
min PnP tracks       = 10
timeout              > 0.5 s
minimum survival     < 0.6
mean parallax        > 30 px
```

`EvidenceBuilder` 对当前帧一次构造完整事实：

1. `observation_count`；
2. 当前 observations 与 last accepted KF pixel map 的 `common_count`；
3. `common_count / max(last_kf_pixels.size(), 1)`；
4. raw mean pixel flow；
5. 使用现有 `pose_lag` rotation 的 compensated mean pixel parallax；
6. 所有 trigger booleans。

完整 trigger mask 与 selected reason 都从生产对象返回，后续 shadow probe 可以区分
“evidence 变化”与“policy 变化”。B0 不把这些字段写进现有 `diag.csv`，所以 benchmark
schema 和文件字节保持不变。

### 3.2 B0 的 `pose_lag` 必须原样保留

现有 session 的事实顺序是：

```text
selected && kOk:
  last_kf_rotation = last_accepted_rotation
  commit pixels/timestamp/count

kOk && estimate:
  last_accepted_rotation = current estimate rotation
```

因此，接受当前 KF 时 snapshot 的 rotation 是**本帧 estimator.update 之前最近一次
接受 pose**，不是当前 KF 优化后的 pose。后续 Rule 4 使用：

```text
R_kf_to_cur = last_accepted_rotation.transpose() * last_kf_rotation
```

这是一条 causal `pose_lag` 路径。它可能不是理想的物理 last-KF pose，但 B0 必须先
忠实提取：`resolve()` 先 commit KF snapshot，再更新 feedback 中的当前
`R_W_B`。在 B0 “顺手修正”顺序会同时改变 schedule，违反行为保持门。

### 3.3 Rule priority

`EpochScheduler` 保持当前短路优先级：

1. observations 为空：`kNone`，即使其他 trigger 为真也不选；
2. 已接受 KF 数 `<2`：`kBootstrap`；
3. observations `<10`：`kLowTracks`；
4. 距 last accepted KF `>0.5 s`：`kTimeout`；
5. survival `<0.6`：`kLowSurvival`；
6. compensated mean parallax `>30 px`：`kParallax`；
7. 否则 `kNone`。

比较符号、分母、`z <= 1e-6` skip、normalized-ray projection 和 mean aggregate 均不
改变。相同 `LandmarkId` 的异常重复 observation 也沿用当前计数/最后写入语义；B0
不夹带输入清洗。

### 3.4 resolve transaction

pending decision 保存当前 timestamp 与 selected 帧 pixel snapshot。resolve 行为：

| decision / feedback | KF epoch | causal pose |
|---|---|---|
| selected + `kOk` | 先提交 pixels/timestamp/旧 causal pose，epoch +1 | 有 pose 则随后更新 |
| non-selected + `kOk` | 不提交 | 有 pose则更新 |
| 任意 + `kRejected` | 不提交 | 不更新 |
| 任意 + `kFailed` | 不提交 | 不更新 |

`kOk` 不带 estimate 时仍按旧行为提交 selected KF snapshot，但不更新 causal pose。
gate 不虚构 estimate，也不把 reject/failed 当成成功。

## 4. 错误与诊断

### 4.1 错误边界

B0 只新增事务 misuse 错误。calibration 由既有 validated type 提供；estimator pose
继续沿用当前信任边界，不在行为保持重构中增加新的 runtime rejection。

数值计算继续遵守当前合同：共同 track 为 0 时 parallax mean 为 0；旋转后 ray 的
`z <= 1e-6` 不进入 aggregate。没有可用 parallax sample 时 Rule 4 不触发。不得用
NaN、异常或默认 selected 掩盖 ticket 错误。

### 4.2 可观测性分层

- **B0 production output**：CSV、summary、config、hash 全部不变；以文件 MD5 对拍；
- **B0 interface/test**：decision 暴露 evidence、trigger、reason、epoch，resolve
  暴露 commit outcome；
- **B1 shadow probe**：在 B0 后新增明确的 sidecar/离线 probe，固定 production
  schedule 同时记录 guard 反事实；它不能改变 estimator 输入；
- **B2 diagnostics**：只有 IMU evidence slice 定案后才加入 rotation source、区间、
  angle、invalid reason 与 bias 等字段。

frozen control trace 只能作为本地回归 oracle，不能变成运行时产品依赖或未经证实的
match-rate 常量。

### 5.4 B1/B2 晋级边界

B0 通过后才写固定 production schedule 的 shadow probe。B1 只能选择一个由日志
支持的 policy 单变量；当前明确不默认：

- Basalt-family `frames_after_kf > 5`；
- two-hit confirmation；
- 任意 hysteresis enter/exit threshold；
- frozen trace 的任意 match-rate 门。

B1 必须先胜过当前 VIO control，再进入 B2。B2 只替换 evidence source并删除
`pose_lag` production implementation，不保留双 selector 或 BA fallback。最终是否完成
仍由“VIO 严格优于 VO”的第 1.3 节出口决定。

执行结果（2026-08-09）：fixed-production-epoch sidecar 通过 byte/axis/transaction
硬门，但 10/15px hit 以连续 motion run 为主，Basalt-family hard gap 与
pose/IMU agreement veto 都会影响数百个事件。当前日志没有支持 two-hit、
hysteresis、cooldown 或 dual-evidence guard 的局部机制证据，因此没有 B1 live
候选可执行，“B1 先胜 control”的前提未满足。B2 不自动启动；下一刀须根据
[`m4.4-keyframe-shadow-probe.md`](m4.4-keyframe-shadow-probe.md) 第 6 节重新对齐。

## 6. 非目标与已知风险

- B0 不修复 static-init scale/tilt、accel-bias walk 或 estimator graph；
- B0 不改变 tracker、landmark lifecycle、window/marginalization 或 IMU factor；
- B0 不新增用户配置和 benchmark schema；
- accepted-KF schedule 只是精度影响路径之一；即使后续 schedule 受控，也不能据此
  假定 ATE 必然优于 VO；
- 当前 schedule 探针只覆盖 MH_01，B1 候选不能未经 sentinel/full-suite 验证外推到
  其他 EuRoC 序列。
