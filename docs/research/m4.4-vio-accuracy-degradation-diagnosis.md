# M4.4 P2b VIO 精度退化因果诊断

日期：2026-08-11
状态：诊断完成；尚未实施 production 修复
范围：EuRoC `MH_01_easy`，P2b fixed-lag candidate 与 paired production VO

本文区分三类陈述：**事实**来自代码、artifact、复现实验或一手资料；
**推断**由多项事实共同支持但尚未由单一实验完全隔离；**待确认**表示当前产物缺少
必要诊断字段。外部模型/API 对照见
[`m4.4-vio-accuracy-degradation-primary-reference.md`](m4.4-vio-accuracy-degradation-primary-reference.md)。

## 1. 结论先行

1. P2b 的 `candidate 0.2313/0.2746` 对 `production VO
   0.0810/0.0178` **不是“同一估计器只增加 IMU”的 A/B**。两侧同时改变了
   estimator、KF schedule、视觉观测入图方式、PnP 门限、landmark/outlier lifecycle
   和 fixed-lag marginalization。该数字不能证明 IMU 是退化原因。
2. 两个 candidate 系统级单开关实验都得到 **IMU on 更好**：
   保留 bias 链而只删除 AHRS factor 时，common support 上由
   `0.0549/0.0402` 恶化为 `0.8728/0.9909`；修正 KF epoch 后，IMU on/off 为
   `0.4010/0.5059` 对 `0.5033/0.7002`。当前证据反而否定“AHRS factor 是
   0.231/0.081 主因”。
3. 对现有全轨迹指标影响最大的是 candidate PnP：GT support 内 5 个 PnP-only
   单帧跳变达到 3.5--6.3 m、最高 156.7°，下一帧立即恢复。后验剔除这 5 个 timestamp
   后，candidate 从 `0.2313/0.2746` 降到 `0.1241/0.0279`；但仍差于 VO，说明
   fixed-lag candidate 的视觉信息集与生命周期还贡献了剩余退化。
4. IMU 实现仍有真实且必须修复的建模错误：raw gyro 未对齐就启用、root bias 以
   `sigma=1e-6` 锁在零、bias RW 错用 gyro white-noise density、AHRS covariance
   未包含 alignment/model discrepancy。GT-bias oracle 在前 1000/3000 帧显著改善，
   证明这些问题会造成局部精度损失；但后段被 PnP/图生命周期失稳淹没，故不是当前
   full-run 的唯一主因。
5. 还确认了 lag 时间单位、常速初值方向、selected-KF 降级提交、异常后继续使用可能
   部分更新的 smoother、诊断字段失真等 bug。它们共同使“结构门 PASS”高估了图的
   健康程度。

因此，[P2b 结果文档](m4.4-candidate-pipeline-p2b-result.md)中的“精度劣化为
fixed-lag 近似的固有代价”也超出了证据：现在能确认的是**当前 candidate 实现退化**，
不能把它归为 fixed-lag 理论的固有代价，更不能归因于 IMU 本身。

崩溃与 candidate 的 fixed-lag timestamp/elimination lifecycle 有关，而不是数据读入。

## 4. 按观测影响排序的原因

### 4.1 P0：PnP 将灾难性单帧 pose 写成 `kOk`（极高影响，已确认）

**事实。** GT support 内 frame `1894/3140/3394/3463/3548` 均出现 3.5--6.3 m
相邻跳变、最高 156.7°，下一帧立即恢复；它们全部是 non-KF PnP-only 输出。另有 frame
`3668` 的约 4.9 m 跳变位于 GT support 外。candidate 将配置的
`min_pnp_inliers=10` 强制降为 4，见
[`candidate_fixed_lag_estimator.cpp`](../../apps/candidate_fixed_lag_estimator.cpp#L502)，
且当前帧 PnP 只验证左目 2D residual，没有 production 的 cull/reopt 与完整诊断。

剔除五帧后，约 71% 的 ATE 均方能量和约 99% 的 RPE 均方能量消失。因此这是 headline
RPE 的第一直接来源。单独改回 10 虽清除了原五帧，却在 frame 169、390--398、2199
附近形成新跳变，说明问题不是一个阈值数字，而是 PnP 结果参与后续初值/地图的闭环，却
没有可靠的 stereo、reprojection 和 motion plausibility 仲裁。

**修复。**

1. 尊重 `enable_pnp_init` 和 `min_pnp_inliers`，不再在 estimator 内偷偷 clamp 为 4；
2. 输出 `pnp_attempted/correspondences/inliers/reproj_rms/init_source`，并在 current-frame
   左右目一致性、RANSAC inlier residual 和相对运动均通过后才返回 `kOk`；
3. PnP 未通过时返回可区分的 `kRejected`，不得把未验证 pose 写入轨迹或 KF feedback；
4. 用上述六个已知 timestamp 做回归，但验收还必须禁止任何新 `>1 m` 瞬时跳变，不能
   只针对旧样本打补丁。

### 4.2 P1：candidate 丢失 production 的视觉信息与 robust lifecycle（高影响，已确认结构；剩余精度影响为强推断）

MH_01 的 3682 帧中约 71% 是 non-KF；这些帧完全不进图，只做 PnP。KF 路径也与
production 不等价：

- 新 landmark 的“延迟初始化”只保存 `observed_once` id；第二次观测时才创建 `L`，
  但首观测 factor/几何并未保留，所以它仍不是两视图联合初始化，见
  [`collectLandmarkFactors()`](../../apps/candidate_fixed_lag_estimator.cpp#L328)；
- estimator 从不填写 `culled_landmark_ids/outliers_culled`，使
  [`candidate_pipeline.cpp`](../../apps/candidate_pipeline.cpp#L232) 的 tracker feedback
  恒空；也没有 production 的 mean-reprojection cull/reopt；
- KF PnP/degrade、gating 100 px、anchored landmark clamp 到 4，以及 150 ms schedule
  都改变了 production 的观测集合和优化路径。

五个跳变剔除后 candidate 仍为 `0.1241/0.0279`，显著差于
`0.0809/0.0177`；而关闭 AHRS 会使这个弱视觉图更差。这两项共同支持：剩余差距首先
来自 candidate visual backend/lifecycle，而非 IMU factor。

**修复。** 先建立视觉等价的 shadow：固定/replay 同一 KF schedule、同一 frontend
observations 和 cull decisions，再仅切 AHRS factor。产品路径要么把 non-KF pose/视觉
约束纳入后验，要么只在共同 KF 上作算法比较；不能继续把混合的 KF posterior + non-KF
PnP 全轨迹称为 IMU A/B。

### 4.3 P2：lag 的时间单位和状态生命周期违反设计合同（高影响，已确认）

`IncrementalFixedLagSmoother(lag=window_size=10)` 使用 caller timestamp 的单位；代码却
每个图像帧递增 `frame_count`，并在 non-KF 上把最新 `X` 刷到该值，见
[`candidate_fixed_lag_estimator.cpp`](../../apps/candidate_fixed_lag_estimator.cpp#L658)。
因此“10 个 accepted KF”实际变成“最近 10 个图像帧”：artifact 的 active pose 均值
3.889，绝大多数只有 3--4，只有 2 帧达到 11。

同时 non-KF aging 只刷新 `X(last)`，不刷新 `B(last)`；后续若 B 已出窗，代码捕获异常并
静默跳过 AHRS factor。aging/update 的内层 catch 还明确承认 GTSAM update 可能已经部分
修改 smoother，却不恢复外层 snapshot，随后继续 `retireExpiredLandmarks()`，见
[`candidate_fixed_lag_estimator.cpp`](../../apps/candidate_fixed_lag_estimator.cpp#L673)。
原 no-IMU 在第 533 帧的 `marginalizeLeaves` 崩溃是该风险的直接表现。

accepted-KF epoch 实验把 active pose 恢复到 median/max `12/12`，并消除了该崩溃；但
完整精度仍差、ok 数降到约 1710，说明一行 timestamp 修正只恢复了合同，长窗下的
landmark separator、线性化点与跟踪稳定性仍未解决。

**修复。** graph epoch 只在 graph KF 真正提交时推进；同一个 KF 的 `X/B/L` 使用一致
timestamp，non-KF 不驱动 graph cutoff。任何 `smoother.update()` 异常必须回到完整 snapshot
或终止该 candidate，不得在未知的部分更新状态上继续。增加 marginalization 前后共同变量
posterior/cost 连续性检查，并明确长寿命 `L` 的 generation/退休策略；不要以 active count
有上界代替正确性。

### 4.4 P3：gyro bias 初始化、RW 与 covariance 不一致（局部高影响，full-run 次级，已确认）

candidate 明确没有 production gyro-visual alignment，却从第一条可积分边启用 raw gyro。
每个 `B(k)` 初值为零，root prior 中心也为零、`sigma=1e-6`，见
[`candidate_fixed_lag_estimator.cpp`](../../apps/candidate_fixed_lag_estimator.cpp#L842)。
MH_01 GT 起始 gyro bias 约为
`(-0.003172, 0.021267, 0.078502) rad/s`；仅 z bias 在 150 ms edge 上就产生
约 0.0118 rad 假旋转，而 white-noise PIM rotation sigma 约 `6.6e-5 rad`，量级约
180 sigma。AHRS factor 又只用 `preintMeasCov()`，没有 alignment residual/model
discrepancy，见
[`candidate_fixed_lag_estimator.cpp`](../../apps/candidate_fixed_lag_estimator.cpp#L100)。

此外 bias BetweenFactor 用 `imu_gyr_noise_nd * sqrt(dt)`；这把 gyro white-noise
density `1.6968e-4` 错当成 EuRoC bias random walk `gyr_rw=1.9393e-5`，量纲错误且使
bias 演化 sigma 约放宽 8.75 倍。candidate 当前构造接口甚至没有传入 `gyrRw()`。

GT-bias oracle 的前 1000 帧从 `0.05597/0.04092` 改善到
`0.01793/0.00875`，验证了零 bias 的实际伤害；full-run 后段发散则验证它不是唯一问题。
GTSAM 官方 `AHRSFactor` 实现与本地非零 bias 单测均表明 factor 的 bias key 表示 absolute
bias，内部以 `bias-biasHat` 做一阶修正；未发现“双重减 bias”的 API 误用。该 API 对照见
[GTSAM `AHRSFactor.cpp`](https://github.com/borglab/gtsam/blob/develop/gtsam/navigation/AHRSFactor.cpp)。

需要注意：现有 `diag.csv` 的 bias 3681 行全为零，是因为 candidate 从未把 posterior
`B(k)` 写回 diagnostics，**不能据此断言优化器中的 bias 始终为零**。

**修复。** 复用 production 已验证的 staged visual-gyro alignment：ready 前不建 AHRS
factor；以对齐 bias 为 root prior 中心；将 alignment RMS/model discrepancy 合理传播到
factor covariance。通过 `ImuParameters::gyrRw()` 显式传递真实 RW，禁止复用 `gyr_nd`。
同时记录每个 KF 的 posterior bias、AHRS raw/whitened residual 和 covariance eigenvalues。
不采用 GT bias 或任意 covariance inflation 作为产品兜底。

### 4.5 P4：常速初值方向反了（明确 bug，当前指标影响较低）

当前写法是 `last_pose->between(prev_pose)` 后 compose 到 `last_pose`，得到反向运动；
正确式为 `prev_pose->between(last_pose)`，与 production 的
`T_prev * (T_prevprev.inverse() * T_prev)` 一致，见
[`candidate`](../../apps/candidate_fixed_lag_estimator.cpp#L423) 与
[`production`](../../phad/estimator/stereo_vo_estimator.cpp#L1004)。

单变量修正后全轨迹反而小幅变差且 KF 数从 1068 变为 1065。这不是保留 bug 的理由，
而是说明非线性闭环目前会把正确初值导向另一组 PnP/KF 失败。应先加“PnP 强制失败的三帧
匀速平移+转动”单测，再与 P0--P3 一起修复并重跑，不能用一次总 ATE 判断公式正误。

### 4.6 P5：结构门与 diagnostics 存在盲区（不直接制造 pose，但严重妨碍归因）

- `fusion_mode` 从 `last_fusion_mode` 继承，2614 个 non-KF PnP-only 帧仍被标成
  gyro-visual；
- `bias_gyro` 未写 posterior，PnP inliers/RMS、IMU segment endpoints、实际 AHRS factor
  数均未落盘；
- selected KF 若 graph update 降级，但 PnP 返回 `kOk`，`KeyframeEpochGate::resolve()`
  仍提交 epoch。baseline 的 frame 378 和 3668 都是 `selected=1, committed=1,
  landmark_count=0`；后者还是巨幅跳变；
- `ledger` 只 append、不用于验证/删除，并把同次 update 的所有新 factor 粗略标成
  `pose_prior` 或 `between`；`active_factor_count=getFactors().size()` 也没有排除 removed
  slot。因而 bounded count 不能证明无 orphan 或 factor lifecycle 正确。

修复方向是让“selected / graph_committed / output_ok”成为三个独立事实；只有 graph 真正
提交才推进 KF epoch。结构 analyzer 应按 live keys/factors 和 endpoint 存在性验账，而不是
只看容器 size、terminal 和 coverage。

### 4.7 P6：当前只是 gyro-aided pose VO，不是能直接改善 translation 的 full VIO（设计边界）

candidate 只有 pose、landmark、gyro bias 和 AHRS rotation factor，没有 velocity、gravity、
accelerometer bias 或 accelerometer factor。因此 gyro 只能通过 stereo 的 rotation/translation
耦合间接影响平移 ATE。[production B3](../benchmark/m4.4/README.md)
的实测也呈混合结果：VIO
`0.083321/0.0168992` 对 VO `0.0809641/0.0177812`，即 ATE 略差而 RPE 略好。
这类变化不能概括为“IMU 让 VO 变差”，也不能期待调 AHRS 权重直接解决平移模型缺失。

## 5. 已排除或降级的假设

| 假设 | 证据 | 当前判断 |
|---|---|---|
| 评估 timestamp 混杂 | exact-common 使用严格整数 ns；3681 common、3637 GT matched，三次结果一致 | 已排除 headline 的近邻匹配假象 |
| paired VO 基线污染 | 干净 M3 重跑与 paired VO ATE/RPE 完全一致 | 已排除 |
| MH_01 原始 IMU 漏样/乱序 | camera/IMU 各自严格递增；每个 50 ms camera interval 有 11 个 IMU 点、两端精确命中；最大 IMU gap 5.000192 ms | 无支持证据 |
| replay 同 stamp 顺序错误 | 实现顺序为 IMU→Left→Right；sync 区间为 `[t_prev,t_cur]` | 无支持证据 |
| `T_BC/T_CB` 或 body frame 反用 | 项目 `T_W_B`、`T_B_left_rectified` 与 PnP 回算一致；EuRoC adapter 的 body=IMU 合同成立 | 静态审计未发现错误 |
| gravity/NavState 符号错误 | candidate 根本没有 gravity、velocity、accel factor | 不适用于当前 candidate |
| GTSAM AHRS bias 是 increment 而代码传 absolute | 官方实现和本地非零 bias test 均为 absolute-bias 合同 | 已排除 |

这些结论不等于以后无需做 runtime segment/frame assertion；只是它们无法解释当前

## 6. 修复与验证顺序

### Slice A：先建立可信的因果基线

1. 修复 no-IMU 在 frame 533 的 fixed-lag crash；禁止异常后继续使用可能部分更新的图；
2. 引入实验专用 AHRS-factor switch，但保持 X/B/L keys、timestamps、KF schedule 和
   frontend observations replay 不变；
3. 分别报告 all-frame、KF-only、non-KF-only 和 KF/non-KF 边界 RPE；
4. 将 P2b 结果文档中的“固有代价”改为非因果的 system comparison 描述。

验收：完整 MH_01 的 candidate on/off 均 terminal=0；schedule/observations 逐帧一致；
exact-common on/off 才作为 IMU 增量结论。

### Slice B：关闭 PnP 灾难输出

先补 adversarial PnP 测试和六个已知 timestamp 回归，再恢复配置门限、左右目/reprojection
诊断与 fail-closed 仲裁。验收同时要求：没有新的 `>1 m` 单帧跳变；`kOk` pose 均有明确
来源和质量证据；selected graph failure 不提交 KF epoch。

### Slice C：修复 fixed-lag 合同与视觉后验

用 accepted-KF epoch、X/B 同寿命、可回滚 update、live factor endpoint invariant 收口
lifecycle；再决定 non-KF pose 入图或仅 KF 输出的产品合同。对“3 个 non-KF 后 1 个 KF”
合成序列断言稳定保留目标 KF 数，并在 frame 532 前后加入回归。

### Slice D：修复 gyro 模型

复用 production alignment，接通 `gyrRw()`，记录 posterior bias 与 factor residual；增加
非零已知 bias、真实 EuRoC noise scale、gap 与 re-preintegration 测试。先看
visual-init/PIM-predict/posterior 三态，再决定 robust kernel 或 covariance；禁止先扫一个
任意 scalar 来掩盖模型错误。

### Slice E：独立修 correctness 与 diagnostics

live factor/slot diagnostics。只有 A--E 在 MH_01 同时通过后，才按仓库约定跑 MH_05，
再扩 EuRoC 11/11。若最终目标需要 IMU 直接改善 translation，再另开 full inertial
`V/gravity/ba` vertical slice，不把它混入本轮修复。
