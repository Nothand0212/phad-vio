# M4.4 PIM prediction / posterior 双轨探针设计

日期：2026-08-10
状态：**已实现并完成 MH_01 行为隔离与选刀；结果见
[`m4.4-vio-state-probe.md`](m4.4-vio-state-probe.md)**
前置：Combined-only A 已保留，但共同 support VIO>VO 仍 FAIL

本文档描述当前约定，不是绝对约束，会随项目开发修订。

## 1. 要回答的问题

当前只知道 posterior trajectory 与 posterior bias；不知道同一帧在视觉/图优化前的
one-step PIM prediction 是否更接近 GT。B 只回答：

```text
上一 accepted posterior + 当前 IMU interval
  → one-step PIM prediction
  → 加入视觉/窗口图后的 posterior

谁先偏离 GT？posterior correction 是改善还是恶化？
```

这里的 PIM trajectory 是“每步从上一 posterior 外推”的 prediction trace，不是从
初始状态递归到底的纯惯导轨迹。它能隔离本帧 optimizer correction，不能单独证明长期
IMU-only drift。

## 2. 模块与 interface

### 2.1 estimator state snapshot

`phad::estimator` 在已有 `UpdateDiagnostics` 中增加一个可选 POD：

```cpp
struct NavStateDiagnostics
{
  std::uint64_t    state_key;
  std::uint32_t    imu_sample_count;
  std::int64_t     imu_t_i_ns;
  std::int64_t     imu_t_j_ns;
  double           imu_dt_s;
  bool             prediction_valid;
  Eigen::Isometry3d predicted_T_W_B;
  Eigen::Vector3d   predicted_velocity_W;
  Eigen::Vector3d   prediction_bias_gyro;
  Eigen::Vector3d   prediction_bias_acc;
  Eigen::Vector3d   posterior_velocity_W;
};

std::optional<NavStateDiagnostics> nav_state;
```

interface 只含 Eigen/POD；GTSAM `NavState`、PIM 与 factor graph 继续藏在 estimator
PIMPL implementation 后。`nav_state` 只在 `enable_imu && status=kOk` 时存在；
`prediction_valid=false` 显式表达 gap/不可预测，不能用零值冒充有效 prediction。

### 2.2 apps sidecar module

在 apps composition root 新增深 module：

```cpp
class VioStateProbe
{
public:
  explicit VioStateProbe( const std::filesystem::path& path );
  void write( bool is_keyframe,
              const estimator::VioUpdateResult& update );
};
```

caller 只知道路径和每帧 update；CSV schema、finite/unit-quaternion 校验、状态事务、
浮点精度和 I/O error 都隐藏在 implementation 内。只有一个文件 adapter，不引入
interface hierarchy。

`OfflineVoSessionOptions::vio_state_probe_path` 与 bench
`--vio-state-probe <csv>` 是 CLI-only seam；空路径完全关闭，不进入 config/hash。
IMU-off 与该 flag 同时出现是显式参数错误。

### 2.3 offline analyzer module

```text
python3 scripts/vio_state_probe.py \
  <sidecar.csv> <euroc-sequence> \
  [--traj-eval build/phad_traj_eval] \
  [--bucket-poses 100] [--output buckets.csv]
```

analyzer 隐藏 strict CSV parsing、pred/post exact timestamp support、临时 TUM 和两次
`phad_traj_eval` 调用。它输出 full 与固定 bucket 的 prediction/posterior ATE/RPE、
posterior-minus-prediction delta，以及 pose/velocity/bias correction 分布。

## 3. 数据流

### 3.1 snapshot 时点

```text
accepted state i-1 (posterior X/V/B)
  + pending raw IMU [ti-1, ti]
  → rebuildPreintegration(biasHat = B i-1)
  → preint.predict()                       [snapshot prediction]
  → candidate initial X/V/B
  → build graph + LM + optional cull reopt
  → window.back final X/V/B                [snapshot posterior]
  → VioUpdateResult
  → VioStateProbe CSV                      [write-only sidecar]
```

- prediction 必须在任何本帧 LM/PnP 修改前保存；
- posterior 必须在最后一个成功 reopt/rollback 决议后保存；
- first seed 使用 `init_T_W_I0/init_bias0` 的 PIM prediction，也按同一 schema 记录；
- re-anchor/gap 若没有 PIM prediction，row 保留但 `prediction_valid=0`；
- sidecar 不回写 estimator、gate、tracker 或 session result。

### 3.2 CSV schema

每个 `status=kOk` state 一行：

- identity：timestamp ns、state key、prior key、window size、is-keyframe；
- IMU interval：sample count、起止 ns、duration、prediction valid；
- prediction：pose `p/q`、velocity、biasHat gyro/acc；
- posterior：pose `p/q`、velocity、gyro/acc bias。

quaternion 固定 `qx,qy,qz,qw`，writer 以 `max_digits10` 输出。correction 不在 C++
重复派生，由 analyzer 单点计算，保持 raw sidecar 可复算。

### 3.3 analyzer 比较口径

只取 `prediction_valid=1` rows；prediction 与 posterior 使用完全相同 timestamp：

1. 分别生成 TUM，但两者 support 恒等；
2. 同一个 `phad_traj_eval`、同一个 EuRoC root、SE(3) alignment、禁止 scale；
3. 报告 `post_metric - pred_metric`；
4. 100-pose bucket 独立对齐并计算 1 秒 RPE；不足 22 poses 的尾桶只报告 correction，
   不伪造轨迹 metric。

两条轨迹分别拟合 SE(3)，因此该首片比较 shape/local drift，不回答绝对 gravity tilt；
初始化绝对误差留给后续 init probe。

## 4. 错误与诊断

- writer open/header/write/flush 失败：session 明确失败，不静默丢 sidecar；
- `kOk` 缺 estimate/nav_state、非有限向量/pose、非单位 quaternion、timestamp/state key
  非单调：writer 抛出带上下文错误；
- non-ok update 不写 row；
- `prediction_valid=0` 时 prediction 数值只是缺省，不参与 analyzer；invalid 数量单列；
- analyzer schema/列数/finite/单调/单位 quaternion/interval 不变量失败返回 2；
- evaluator 失败或输出缺字段返回 2；
- probe off/on 的 `est.tum`、`kf.tum`、`diag.csv` 必须 `cmp=0`，否则先修隔离；
- raw run 保留 dirty identity，不描述成 formal baseline。

## 5. 测试与验收

### 5.1 tests

1. estimator IMU synthetic：prediction snapshot valid、timestamp/sample interval 正确，
   posterior velocity/bias 与结果一致；IMU-off 不产生 snapshot；
2. writer synthetic：header/row、rejected skip、quaternion/finite/transaction 与 I/O failure；
3. CLI：usage、缺值、`--no-imu` 冲突、path 不改变 config hash；
4. Python：strict load、pred/post TUM、metric parsing、bucket correction 与 malformed cases；
5. affected targets + `ctest -L unit` 0 fail。

### 5.3 选刀规则

- prediction 与 posterior 都明显劣于 VO，且 post-pred delta 小：优先初始化/IMU model；
- prediction ATE/RPE 都优于 posterior：优化 correction 使轨迹恶化，转视觉/window；
- 只在固定坏窗 posterior 变差，且 correction/prior-key 同步：再补 prior-target/factor
  cost probe，仍不直接宣称 marginalization 因果；
- prediction/posterior 方向混合：按预注册 bucket 查首个分叉，禁止用单一 headline
  选结论；
- 无论哪种结果，本 probe 本身不改变 production estimator 策略，也不完成 M4.4。

## 6. 非目标

- 不实现 fixed-lag smoother/marginalization；
- 不改初始化、noise/RW/prior、keyframe schedule；
- 不运行第二个 optimizer 或递归 IMU-only trajectory；
- 不在本片记录 factor residual/cost 或 posterior covariance；
- 不运行 sentinel/11/11，直到日志选出并验证下一个 production fix。

## 7. 实施后合同修订

MH_01 首次离线分析暴露了一个设计边界：accepted rows 的尾部 22 帧超过 EuRoC
ground-truth 时间范围。最终 analyzer 先以 `2.5 ms` tolerance 过滤 evaluator 可比较
support，并分别报告 `accepted`、`prediction_valid`、`evaluation` 与
`outside_groundtruth`；它不截断原始 sidecar，也不把范围外帧冒充 evaluator 匹配。
本次为数据合同修正，不改变 estimator、session 或生产轨迹。
