## 4. 过程记录：第一处分叉与修复

首跑（`m44_p2a_candidate`）门 1/4 过、门 2 FAIL：candidate 与 production 的
trajectory 在前 1215 行一致后分叉。根因：**candidate 未消费 estimator cull 反馈**——
production 每帧对 `culled_landmark_ids` 执行 `dropTracks`（默认 `drop_culled_tracks`），
candidate tracker 从不 drop（MH_01 上 candidate track_count 恒 200 满，production 在
cull 帧后 196-199）。track 集合分叉 → 后续估计分叉。

修复：`apps/candidate_pipeline.cpp` 消费 `CandidateTrackPolicy`，实现与 production
同构的 cull/drop/zombie 反馈：

- zombie-age 推进在 `tracker.process` 之后（present → age++ / absent → erase，
  age ≥ `zombie_drop_age` 时 drop）；
- `estimator.update` 后：`outliers_culled ≥ skip_drop_min_culled` 时 skip（记入
  zombie_age，age=1），否则 `dropTracks(culled)`；
- `diagnostics.dropped_track_count` 记录本帧实际 drop 数。

复跑（`m44_p2a_candidate_v2`）门 2 PASS（est.tum/kf.tum 逐字节相同）。analyzer 首跑
bias 列误报（production fixed 6 位 vs candidate 9 位有效数字，差值 ~2e-7）→ 容差改
1e-6；并补 culled_count vs production outliers_culled 逐行映射。

## 5. 遗留（P2b 前已知边界）

- `CandidatePipeline` 仍缺：tracker/gate/estimator exception → typed terminal 映射、
  estimate finite/SE(3) invariant、`finish()` cross-check（设计 §8.4）、
  `CandidateGraphDiagnostics` 恒空（batch twin 无 fixed-lag graph，P2b 替换后才有值）。
- TinyEurocFixture（均匀灰度）下 candidate `finish()` 报 `kTrajectoryInvariant`
  （"trajectory must contain at least one pose"），与 production "no accepted poses"
  同命运——设计行为。
- 临时 batch candidate code 标记为待 P2b 删除；P2b 不保留 backend switch/fallback/
  兼容路径。
