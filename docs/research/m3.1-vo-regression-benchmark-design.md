# M3.1 VO 回归 Benchmark 设计

日期：2026-07-31  
状态：二轮审阅已定稿，决策见 §2  
相关：[roadmap M3.1](../roadmap.md)、[architecture](../architecture.md)、[M2.3 VO 后端设计](m2.3-vo-backend-design.md)、issue [#21](https://github.com/Nothand0212/phad-vio/issues/21)

## 1. 目标与非目标

### 目标

在 M3 算法加固之前，建立**可复现的算法回归表**：同一序列上，按
`(sequence, git_commit, config_hash)` 对比 ATE / RPE / 完成率 / RTF，使后续
「优化或退化」有对标数字，而不是口头判断。

v1 只钉 `MH_01_easy`，把合同与工具跑通；多序列矩阵留到 M3.2+。

「一键对照」由两部分构成：`phad_vo_bench` 负责单次 run 的可复现落盘，
`scripts/bench_table.py` 负责把 `bench_root` 下的多个 `summary.json` 拼成
对比表。

### 非目标

- Docker 集群 / SLAM Hive 式参数扫掠
- CPU% / RSS 跨机公平竞技（同机 timing 仅作附带）
- 距离间隔 RPE、Sim3 对齐、NEES（滤波器语义）
- 自动发散判定（末段 ATE 阈值）——可后加
- 把 `phad_euroc_runner`（GUI）强制迁到 session
- 在 `phad::frontend` / `phad::estimator` 内注入 bench hooks
- 非 EuRoC 数据集（v1 session 只支持 EuRoC）

### 为何独立成 M3.1

M2.3 已给出第一条 MH_01 基线（ATE translation RMSE ≈ 0.150 m），但缺少：

- 固定落盘合同与 run 身份（代码版本 + 参数指纹）；
- 可复用的离线编排（probe 与回归入口共用）；
- 「改动前后」一键对照的入口。

没有这些，M3 的几何验证 / 关键帧 / landmark 生命周期改动无法证明变好或变坏。
因此 **benchmark 先于加固**。

## 2. 已锁定决策

| 项 | 决策 |
|---|---|
| 首要用途 | 算法回归表（非性能剖析竞技场、非论文多算法对比） |
| v1 序列 | 仅 `MH_01_easy`；session 只支持 EuRoC，格式选择留 M3.2+ |
| 交付形态 | 纯逻辑库 `phad::bench`（`phad/bench`，含 README）+ 独立 app `phad_vo_bench`（composition root） |
| 目标命名 | 库 target `phad_bench`；app 改名 `phad_vo_bench` 以避开同名冲突 |
| Session | 抽出 `apps/offline_vo_session`，编成静态库 target `phad_offline_vo_session`；**probe 与 bench 同时迁入** |
| Session 边界 | 只跑 pipeline（replay→rectify→track→glue→estimate）；**不落盘**、**不算** ATE/RPE |
| 结果交付 | `OfflineVoSessionResult` 直接携带 `common::Trajectory`、diag 行、时间跨度与 timing；写文件由调用方决定 |
| bench 库边界 | 只做 run 身份、config 快照与 hash、路径模板、summary schema 与 JSON 序列化；**不认识** frontend / estimator / eval 类型 |
| 评估归属 | `phad_vo_bench` 调用 `phad::eval`；session 与 `phad::bench` 都不依赖 eval |
| 依赖方向 | `phad::bench` 零 `phad::*` 依赖；session → `{io_dataset, camera, frontend, estimator, common}`；app → `{bench, session, eval, io_dataset}` |
| 注入含义 | app 向下组装模块；**禁止** estimator/frontend 反向依赖 bench |
| 虚接口 | v1 不引入 `IFrontend` / `IEstimator` |
| JSON | `find_package(nlohmann_json 3.11)`，只给 app 与 `phad_bench` **PRIVATE**；public header 不出现 json 类型 |
| config_hash | 规范化文本（key 字典序、浮点 `%.17g`）过 FNV-1a 64，取前 8 hex |
| 目录段 | `<config_label>_<config_hash8>`，`--config-label` 缺省 `default` |
| 路径模板 | `<bench_root>/<sequence>/<commit_short>[_dirty]/<label>_<hash8>/` |
| 覆盖策略 | clean 树默认拒绝覆盖（`--force` 才写）；dirty 树默认覆盖并警告 |
| Run 身份 | 运行时调 `git`：`rev-parse HEAD` 取 commit，`diff --quiet HEAD` 判 dirty（**只看 tracked**，忽略 untracked） |
| 完成度指标 | `completion_rate = ok_frames / image_frames`，并列 `coverage_rate = 轨迹时间跨度 / 图像时间跨度` |
| 主表键 | `(sequence, git_commit, config_hash)`；dirty 树不宜作正式基线 |
| 汇总 | `scripts/bench_table.py` 扫 `bench_root` 拼 Markdown/CSV 表；不进 CMake / CI |
| probe 迁移验收 | 迁移前后 `est.tum` 与 `diag.csv` **逐字节相同** |

## 3. 开源对照（摘要）

| 来源 | 借鉴 |
|---|---|
| Sturm / TUM RGB-D、[evo](https://github.com/MichaelGrupp/evo) | ATE + RPE；SE3 对齐；多统计量（rmse/mean/median/max） |
| [OpenVINS eval](https://docs.openvins.com/evaluation.html) | 组件级 timing CSV；回归关心 mean/p95/max；评估与估计分离 |
| [SLAM Hive](https://ar5iv.labs.arxiv.org/html/2303.11854) / SLAMBench | 准确性 + 资源；v1 只取「结果可复现落盘」，不做集群 |
| [TUM VI](https://ar5iv.labs.arxiv.org/html/1804.06120) | 完成/发散标记思路；v1 用 completion/coverage + status，不做自动发散阈值 |
| 本仓库 M2.1–M2.3 | `phad_traj_eval`、frontend frames-csv、VO diag-csv、MH_01 基线数字 |

不借鉴：把评估嵌进估计器；为单一实现预建插件虚基类。

## 4. 模块边界

```text
phad::io / camera / frontend / estimator / eval / common      phad::bench
        ▲                                                          ▲
        │ 单向依赖（只向下）                                        │ 纯逻辑，零 phad 依赖
        │                                                          │
apps/
├── stereo_vo_glue.hpp              # 已有：FrameTracks → KeyframeMeasurement
├── offline_vo_session.hpp/.cpp     # 新增：离线 VO 编排（静态库）
├── phad_stereo_vo_probe.cpp        # 迁到 session；诊断 / 人读
├── phad_vo_bench.cpp               # 新增：session + eval + bench 落盘
└── phad_euroc_runner.cpp           # v1 不强制迁
```

| 模块 | 做 | 不做 |
|---|---|---|
| `phad::bench` | run 身份（git）、config 快照与 hash、路径模板、summary schema、JSON 输出 | 认识任何 pipeline 类型、跑 pipeline、算指标 |
| `OfflineVoSession` | 打开序列、校正、跟踪、glue、估计；产出轨迹、diag 行、计数、时间跨度、阶段 timing | ATE/RPE、写文件、结果目录约定、git、多序列调度、开窗 |
| `phad_stereo_vo_probe` | CLI + session + 写 tum/diag + 人读 stdout | 回归表、`summary.json` |
| `phad_vo_bench` | CLI + session + eval + `meta`/`summary` + 路径模板 | 重写 pipeline |

`phad::bench` 之所以不认识 `StereoTrackerOptions` / `EstimatorOptions` /
`AteOptions`，是为了不让它变成横切所有模块的顶层库：它只收有序的
key→scalar，展平由知道这些类型的 apps 侧完成。

### Session 深接口

```cpp
namespace phad::apps
{

  struct OfflineVoSessionOptions
  {
    std::filesystem::path          sequence_root;   // v1：EuRoC 序列根
    frontend::StereoTrackerOptions tracker;
    estimator::EstimatorOptions    estimator;
    std::optional<std::uint64_t>   max_frames;      // 冒烟用，缺省跑完
    bool                           collect_timing = true;
  };

  struct OfflineVoSessionResult
  {
    std::optional<common::Trajectory> trajectory;    // 无 kOk 帧时为空
    std::vector<VoDiagRow>            diag;          // 列同 M2.3 probe
    FrameCounts                       counts;        // frames/ok/rejected/failed/...
    common::Timestamp                 first_image_ts;
    common::Timestamp                 last_image_ts;
    double                            wall_s = 0.0;  // 仅 pipeline 循环
    StageTimings                      timings;       // rectify/frontend/estimator/total
    ReprojSummary                     reproj;        // after 的 median / p95
    std::optional<SessionError>       error;
  };

  [[nodiscard]] OfflineVoSessionResult runOfflineVoSession(
      const OfflineVoSessionOptions& options );

  /// probe 与 bench 共用，保证 diag.csv 逐字节一致。
  [[nodiscard]] std::optional<SessionError> writeDiagCsv(
      const std::filesystem::path& path, const std::vector<VoDiagRow>& rows );

}  // namespace phad::apps
```

`result` **不含** ATE/RPE。`wall_s` 只覆盖 pipeline 循环（含解码与校正），
不含 eval 与落盘。

### bench 库接口草图

```cpp
namespace phad::bench
{

  class ConfigSnapshot
  {
  public:
    void set( std::string key, std::string value );
    void set( std::string key, double value );
    void set( std::string key, std::int64_t value );
    void set( std::string key, bool value );

    /// key 字典序、浮点 "%.17g"、每行 "key=value"。
    [[nodiscard]] std::string canonicalText() const;
    /// canonicalText 的 FNV-1a 64，前 8 位 hex。
    [[nodiscard]] std::string hash8() const;
    [[nodiscard]] std::string toJson() const;
  };

  struct CodeIdentity
  {
    std::optional<std::string> git_commit;                 // 40 hex
    std::string                git_commit_short = "unknown";
    bool                       git_dirty        = false;
    std::optional<std::string> git_branch;
  };

  /// 运行时调用 git；失败时返回默认值并附 warning，不抛异常。
  [[nodiscard]] CodeIdentity queryGitIdentity(
      const std::filesystem::path& repo, std::vector<std::string>& warnings );

  [[nodiscard]] std::filesystem::path composeRunDir(
      const std::filesystem::path& bench_root, std::string_view sequence,
      const CodeIdentity& code, std::string_view config_label,
      std::string_view config_hash8 );

}  // namespace phad::bench
```

`queryGitIdentity` 是本库唯一有副作用的部分，单独放一个 TU，让路径与 hash
的单测不触碰进程调用。默认查询的仓库路径由 CMake 定义 `PHAD_SOURCE_DIR`
给出，`--repo` 可覆盖。

## 5. 分层指标

| 层 | 内容 | v1 主表 |
|---|---|---|
| L0 | sequence、code、config、config_hash、paths、status | 键与过滤 |
| L1 | ATE trans RMSE、RPE(1 s) trans RMSE、completion_rate、coverage_rate、wall_s/RTF | ★ 必进 |
| L2 | rejected/failed、low_connectivity、cheirality | 恶化时展开 |
| L3 | rectify/frontend/estimator/total 的 mean·p95·max | 附带 |
| L4 | frontend valid/track 长度（沿用 probe CSV） | 不强制进 bench summary |
| L5 | reproj after median/p95、窗口 landmark | 附带 robustness |

定义：

- `completion_rate = ok_frames / image_frames`；
- `coverage_rate = (last_pose_ts − first_pose_ts) / (last_image_ts − first_image_ts)`，
  用于抓「总接受率好看但后半段全挂」；
- `RTF = 序列图像时间跨度 / wall_s`；
- 对齐固定尺度 **SE3**（双目），RPE 默认 **1 s**（与现有 eval 一致）。

## 6. 数据流与落盘合同

```text
sequence_root
    → runOfflineVoSession
         → OfflineVoSessionResult（Trajectory + diag 行 + 计数 + timing）
    → phad_vo_bench
         → phad::eval (ATE/RPE)
         → phad::bench (identity / config_hash / 路径 / summary)
         → output_dir/{meta,summary,est,diag[,errors]}
```

### 路径模板

```text
<bench_root>/
  <sequence>/                      # 如 MH_01_easy
    <git_commit_short>[_dirty]/    # 未知则 unknown
      <config_label>_<hash8>/      # 如 default_9f2ab41c
        meta.json
        summary.json
        est.tum
        diag.csv
        errors.csv                 # 可选
```

- `bench_root`：`--bench-root` 或环境变量 `PHAD_BENCH_ROOT`；**不写入仓库**。
- `<sequence>`：默认取 `weakly_canonical(sequence_root)` 的 basename；为空或
  等于 `mav0` 时报错，要求显式 `--sequence-name`。
- clean 树：目标已有 `summary.json` 时失败（exit 3），`--force` 才覆盖。
- dirty 树：默认覆盖并警告「非正式基线」。
- `--out` 可覆盖模板路径；`meta.paths.layout_template` 标 `override`。
- 写入顺序：先建目录写 `meta.json`，跑完再写 `est.tum` / `diag.csv`，
  `summary.json` **最后**写，使其成为「这个目录已被占用」的哨兵。

### `meta.json`（身份）

- `schema_version`、`sequence`、`sequence_root`、`created_utc`
- `code`：`git_commit`、`git_commit_short`、`git_dirty`、可选 `git_branch`
- `config`：完整可复现快照（estimator / tracker / session 策略 / eval 选项）
- `config_label`、`config_hash`、`config_canonical_text`（碰撞时可人工判别）
- `paths`：`bench_root`、`output_dir`、`layout_template`
- `warnings[]`

**规则：** config 必须从即将使用的 options **生成再 hash**；禁止手写 hash。
等价软件版本：`git_commit` 相同且 `git_dirty == false`。

### `summary.json`（回归主合同，schema_version=1）

含：`status`、`code`（短）、`config_label`、`config_hash`、`trajectory`
（image_frames / poses_written / ok/rejected/failed / completion_rate /
coverage_rate）、`ate`、`rpe`、`robustness`、`timing`（含 `wall_s`、`rtf`）。
完整 `config` 只在 `meta.json`；summary 保持小以便拼表。

`diag.csv` 列保持 M2.3 probe 合同；`errors.csv` 与
`phad_traj_eval --errors-csv` 同列。

## 7. 错误与诊断

| `status` | 含义 |
|---|---|
| `completed` | session + eval 成功，无警告 |
| `completed_with_failures` | 有 `kFailed` 帧，仍写出数字 |
| `completed_with_warnings` | 无失败帧但有警告（dirty 树、git 不可用、RPE 样本不足等） |
| `eval_failed` | session 有输出但关联或指标失败；`ate`/`rpe` 为 null，不写假 0 |
| `failed` | session 无法完成有意义输出 |

`completed_with_failures` 优先于 `completed_with_warnings`。

Exit code：`0` 完成（可带 warning）；`1` session/eval 失败；`2` CLI 用法；
`3` 目录占用未 `--force`。

- 拒帧（`kRejected`）不计为进程失败（与 M2.3 一致）。
- `status = failed` / `eval_failed` 的 run **仍写 `summary.json`**：回归表要
  能看到「这次跑挂了」。代价是同一 clean 目录重跑需 `--force`。
- git 不可用 → `git_commit = null`，路径段 `unknown`，仍可跑并 warning。
- dirty → 路径 `_dirty` + 警告「不宜作正式基线」。
- Timing：`steady_clock`；采集失败不令 run 失败。

主表信任序：`status` / `completion_rate` / `coverage_rate` → 再看 RMSE。

## 8. 测试与验收

### 组件（`tests/bench`、`tests/apps`，label `unit`）

- `ConfigSnapshot`：key 顺序无关性、浮点格式固定、同内容同 hash、
  改一个字段 hash 必变。
- 路径模板：clean / dirty / unknown commit、`--sequence-name` 覆盖、
  basename 为 `mav0` 时报错。
- 目录占用：有 `summary.json` 且 clean 时拒绝，`--force` 通过，dirty 直接通过。
- `summary.json` / `meta.json` 序列化字段齐全，`ate`/`rpe` 缺失时为 null。
- session 计数汇总：用合成序列或 `max_frames` 验证计数与 coverage 计算。
- CMake/约定：`phad_bench` 不链接 `phad_eval`；session 不链接 `phad_eval`。

### Probe 迁移

- CLI 与 diag 列不变。
- 迁移前在当前 commit 跑一遍 MH_01，把 `est.tum` / `diag.csv` 存到仓库外作
  参考产物；迁移后 `diff` 必须为空。不同则视为重构引入行为变化，须定位。

### Bench E2E（本地 MH_01，人工执行）

- 模板路径下四件套齐全；`meta` 含 code / config / config_hash。
- L1 字段有限；与 `phad_traj_eval` 交叉验证（可选再对 evo）。
- clean 树无 `--force` 二次运行 exit 3；有 `--force` 覆盖成功。
- `scripts/bench_table.py` 能把两次 run 拼成一张表。

### 失败抽检

坏 `sequence_root`、关联失败（`eval_failed` 且 ate 为 null）、dirty 路径标记、
`git` 不可用时的 `unknown` 段。

### v1 出口清单

- [ ] `phad::bench` 库落地（含 README），零 `phad::*` 依赖
- [ ] `OfflineVoSession` 抽出为静态库；probe 与 `phad_vo_bench` 共用
- [ ] session 与 `phad::bench` 都不依赖 `phad::eval`
- [ ] 路径模板 + clean 拒绝覆盖 / dirty 覆盖并警告
- [ ] `meta`：`code` + `config` + `config_hash`；`summary.json` schema_version=1
- [ ] probe 迁移前后 `est.tum` / `diag.csv` 逐字节相同
- [ ] MH_01 跑通，ATE 与 M2.3 基线一致（≈ 0.150 m）
- [ ] `scripts/bench_table.py` 可拼表
- [ ] 本文档与 roadmap M3.1、issue #21 一致

### v1 不做

MH_02–05 矩阵、CI 强制 mh01 gate、runner 迁 session、CPU/RSS、自动发散标签、
非 EuRoC 数据集。

## 9. 实施切片
