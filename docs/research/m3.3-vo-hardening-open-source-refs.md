## 1. 核心问题

本仓库的失败模式是：**前端 track 全部丢失 → 重新检测发放全新 landmark id →
固定窗口与新帧交集为空 → 永久拒帧**。要回答的是：其他系统在同一处怎么做，
断裂两侧的 gauge 怎么接。

## 2. 逐项目结论

### 2.1 Basalt（架构最接近本仓库的答案）

零重叠不是异常，而是**关键帧触发条件**：

```cpp
// basalt/src/vi_estimator/sqrt_keypoint_vo.cpp
if (Scalar(connected0) / (connected0 + unconnected_obs0.size()) <
    Scalar(config.vio_new_kf_keypoints_thresh) &&      // 默认 0.7
    frames_after_kf > config.vio_min_frames_after_kf)  // 默认 5
  take_kf = true;
```

`connected0` 是已在 landmark 数据库中的观测数。全丢失时 `connected0 == 0`，
比值为 0 → **强制开关键帧**，把新 id 三角化进同一窗口。`measure()` 无最小观测门限，
永远返回 `true`；没有任何 reject 状态。gauge 由 sqrt marginalization prior 承接
（`vio_init_pose_weight = 1e8`），**单一连续 gauge，无分段**。

边缘化策略：`vio_max_kfs = 7`，优先边缘化 `num_points_connected / num_points_kf
< vio_kf_marg_feature_ratio (0.1)` 的最老关键帧。

数值失败时是 `std::abort()`，没有优雅恢复。

### 2.2 VINS-Fusion（后端根本不设门）

失败检测被**源码写死关闭**：

```cpp
// vins_estimator/src/estimator/estimator.cpp:955
bool Estimator::failureDetection()
{
  return false;
```

之后的判据（`Bas.norm() > 2.5`、`Bgs.norm() > 1.0`、位移跳变 > 5 m、
旋转跳变 > 50°、`last_track_num < 2`）全是不可达代码，其中多条本来也是注释掉的。
`double2vector()` 里有一段本意是「失败后锚回失败前 frame-0」的代码
（`failure_occur → origin_R0 = R2ypr(last_R0)`），但 `clearState()` 会先把
`failure_occur` 清零，且该逻辑只在 `USE_IMU` 分支内——**纯双目路径下是死代码**。

实际运行时的行为：后端从不因 landmark 重叠为零而拒帧；PnP 失败就沿用上一帧
（`Ps[WINDOW_SIZE] = Ps[WINDOW_SIZE - 1]`）；新 id 当作新 landmark 三角化；
`last_track_num < 20` 时**每帧强制关键帧**。前端 `n_id` 单调递增、`clearState()`
也不重置，无任何 id 重映射。

`rejectWithF()`（`findFundamentalMat`，`F_THRESHOLD = 1.0 px`，置信度 0.99）
在热路径里被 `//rejectWithF();` 注释掉了。后端 `outliersRejection()` 按平均重投影
误差 `> 3 px` 等效阈值剔除，并同步从前端 track 表里删除，是永久的。

关键帧判据（`addFeatureCheckParallax`）：`frame_count < 2 || last_track_num < 20
|| long_track_num < 40 || new_feature_num > 0.5 * last_track_num` 任一成立即
关键帧；否则按平均视差 `>= keyframe_parallax / FOCAL_LENGTH`（EuRoC 为 10 px / 460）。

### 2.3 Kimera-VIO（前端不喂后端）

KLT 全灭时前端直接跳过关键帧，**后端不被调用**：

```cpp
// StereoVisionImuFrontend.cpp:312
if (left_frame_k->keypoints_.size() == 0) {
  feature_detector_->featureDetection(left_frame_k, stereo_camera_->getR1());
  ...
  StereoMeasurements smart_stereo_measurements;   // 空
  return std::make_shared<StatusStereoMeasurements>(...);
}
```

部分退化用 `TrackingStatus`（`VALID / LOW_DISPARITY / FEW_MATCHES / INVALID /
DISABLED`）表达，阈值 `minNrMonoInliers_ = 10`、`minNrStereoInliers_ = 5`、
`disparityThreshold_ = 0.5`。后端按状态决定加哪些因子：`LOW_DISPARITY` 时跳过视觉
landmark，改加 zero-velocity + no-motion 因子；视觉失败时位姿初值退回 IMU
（`"Using IMU for pose guess"`）。IMU 预积分因子**总是**加，所以状态永远前进。

`IncrementalFixedLagSmoother`，prior 只在 bootstrap 打一次
（`addInitialPriorFactors`）。`IndeterminantLinearSystemException` 的处理是：在
首个状态与失败点附近加紧 prior（0.01 rad / 0.1 m）、从备份还原 smoother、重试一次，
再失败就 `return false` → 整个 backend `shutdown()`。**没有 reset / 重开 gauge 的概念**；
`ReinitPacket` 存在但从未被消费。

### 2.4 SVO Pro（双目从不宣告失败）

双目路径的 `processFrameBundle()` 只处理 `kTracking` 与 `kInitializing`，
**没有 `kRelocalization` 分支**。特征不足时不返回失败，而是强制建关键帧重新三角化：

```cpp
// svo/src/frame_handler_stereo.cpp:100
if(n_tracked_features < options_.quality_min_fts)   // 默认 50
{
  return makeKeyframe();   // force stereo triangulation to recover
}
```

单目才走 relocalization：以**上一个关键帧**为参考（`relocalizeFrame(Transformation(),
reloc_keyframe_)`），失败时把位姿贴回该关键帧的位姿（不跳世界系）；试满
`relocalization_max_trials`（`vio_stereo.yaml` 为 5）才整体 reset，reset 后世界系
回到 identity。

### 2.5 ORB-SLAM3（唯一走分段的）

纯双目的状态机：`TrackLocalMap()` 失败 → `RECENTLY_LOST`（前提
`KeyFramesInMap() > 10`，否则直接 `LOST`）→ 每帧尝试 `Relocalization()`
（BoW 检索 + `MLPnPsolver` RANSAC，`SetRansacParameters(0.99, 10, 300, 6, 0.5, 5.991)`）
→ 超过 **3.0 s** 仍失败则 `LOST` → `CreateMapInAtlas()`。

`time_recently_lost = 5.0 s` 只对 IMU 生效；纯双目是硬编码 3.0 s。
`RECENTLY_LOST` 期间 `TrackLocalMap` 的内点门限从 30 放宽到 **10**，投影搜索半径
从默认放大到 `th = 15`。

新地图的原点是 **identity**（`mCurrentFrame.SetPose(Sophus::SE3f())`），速度清零，
`mpLastKeyFrame / mpReferenceKF` 置空，**不保存新旧地图之间的变换**。
`SaveTrajectoryEuRoC()` 默认**只导出关键帧最多的那张地图**，其余地图的帧被
`pKF->GetMap() != pBiggerMap → continue` 跳过。也就是说：分段之后，未被 loop merge
接回的段在评估里直接消失。

ORB-SLAM2 没有 Atlas：任何失败都是 `LOST`，之后无限次 relocalization，
`KeyFramesInMap() <= 5` 才整体 `Reset()`。

### 2.6 lk-vio（本仓库形态的来源）

`FrontendStatus{ INITING, TRACKING_GOOD, TRACKING_BAD, LOST }`，按 pose-only BA
内点数分档：`> 50` good、`> 10` bad、否则 LOST。而 LOST 的处理是空的：

```cpp
// src/lk_vio/frontend.cpp:68
case FrontendStatus::LOST:
{
  /// TODO
  break;
}
```

全仓库没有 `Reset()`。进入 LOST 后 `Track()` 再也不被调用，位姿保持默认构造的
identity 并照常发布——**和本仓库同型的吸收态，只是它连拒帧诊断都没有**。
唯一的恢复带是 `TRACKING_BAD`（10–50 内点）：每帧重新检测 + 三角化 + 插关键帧，
**不清空后端窗口**。滑窗 BA 里没有 `setFixed(true)`、没有 prior、没有边缘化，
gauge 只靠初始化时首关键帧在 identity 隐式确定。

## 3. 对照汇总

| 项目 | 零重叠时的动作 | 是否有 reject 门 | gauge 连续性 | 断裂是否可观测 |
|---|---|---|---|---|
| Basalt | 强制关键帧，新 id 进同一窗口 | 无 | 连续（marg prior） | 仅 debug 输出 `connected0` |
| VINS-Fusion | 照常优化，PnP 失败沿用上一帧 | 无 | 连续（marg prior） | 无（自动重启已关闭） |
| Kimera-VIO | 前端不产关键帧，后端不被调用 | 前端侧有 | 连续（IMU 撑住） | frontend stats CSV 有 `TrackingStatus` |
| SVO Pro（双目） | 强制关键帧重新三角化 | 无 | 连续（同一 map frame） | `trace_statistics` 的 stage / quality |
| ORB-SLAM3 | 先 relocalize 3 s，再开新地图（identity 原点） | 有（状态机） | **分段** | 有（stage），但导出只留最大地图 |
| lk-vio | 空 stub | 有（LOST 分档） | 无（死态） | 仅一条日志 |

**没有任何项目在做「失败检测 + 以最后位姿重锚」。** 主流答案是**不设重叠门**，
让新 id 直接进窗口，gauge 交给 marginalization prior 或 IMU 承接。

## 4. 对本仓库的取舍

1. **不能照抄字面做法**：Basalt / VINS / Kimera 的连续性都来自
   marginalization prior 或 IMU 因子，本仓库是「固定窗口 batch BA + 最老帧硬
   prior、窗口滑出即丢弃」（M6 才做边缘化，M4 才有 IMU）。零重叠时新帧与旧窗口
   之间**没有任何约束**，所以「不设门」在我们的架构里必然落地为「新窗口的 prior
   打在最后一个被接受的位姿上」。这不是发明，而是同一原则在无 marg prior 架构下的
   唯一单轨迹实现。
2. **不采用 ORB-SLAM3 的分段**：它的前提是 BoW place recognition 能把段接回来
   （本仓库要到 M8），且其评估路径靠丢弃未 merge 的段来回避 gauge 问题——在
   evo 单次 SE3 对齐下，未闭合的分段轨迹不可评估。
3. **采纳「零重叠触发新窗口种子」而非「检测失败再重启」的触发形式**（Basalt 路线），
   实现上不引入失败检测器与计时器。
4. **采纳最小观测数门限**：Kimera 的 `minNrStereoInliers_ = 5`、SVO 的
   `quality_min_fts = 50`、VINS 的 `last_track_num < 20`、lk-vio 的 `track_good = 50`
   量级不一，但都存在；本仓库现有 `min_shared_landmarks = 10` 只是诊断 flag，
   应升格为 seed 门限（初始化与 re-anchor 共用）。
5. **断裂必须进产物**：只有 Kimera 与 ORB-SLAM3 把状态写进离线可读的输出。
   本仓库有 bench 对照表，若断裂不可观测就分不清「算法变好」与「re-anchor 变多」，
   因此比参考实现更需要 `segment_id` / `reanchor` 这类列。
6. **后续切片的参考点**：几何验证阈值（VINS `F_THRESHOLD = 1.0 px`、Kimera
   `ransac_threshold_stereo_ = 1.0`）、chi2 外点剔除（ORB-SLAM3 stereo 7.815 /
   mono 5.991，4 轮 × 10 次迭代，第 3 轮后去掉 Huber；lk-vio 前端 5.991、后端
   5.891）、关键帧判据（见 2.2 / 2.5）。
