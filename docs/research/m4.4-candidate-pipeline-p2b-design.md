# M4.4 P2b fixed-lag candidate 设计

- 状态：设计草案，待确认（模块边界 → 数据流 → 错误与诊断 → 测试与验收 已逐段对齐核心决策）

- 一手资料：`docs/research/m4.4-gyro-fixed-lag-reference.md`、`docs/research/m4.4-candidate-pipeline-design.md` §9.4/§9.5

本文档描述当前约定，不是绝对约束，会随项目开发修订。

## 1. 目标与边界

P2b 把 candidate PIMPL 内的临时 batch `StereoVoEstimator` **替换**为唯一 concrete
fixed-lag implementation（`IncrementalFixedLagSmoother` + candidate-owned 账本）。
P2b 是生命周期/结构 slice，不产生精度晋级结论：

- 不保留 backend switch/fallback/兼容路径；删除 batch twin 代码；
- production 三主产物与 config hash 不受影响；`--candidate` 仍 CLI-only；
- public seam `CandidatePipeline::create/process/finish` 不变；
- structural gate（设计 §9.4）通过后才跑一次 MH_01；精度门（§9.5）是最终出口，
  P2b 的 MH_01 只做结构验收（terminal=0/failed=0/finite/有界/无未声明 reset/
  coverage 不低于 paired VO）。

## 2. 状态模型（已确认决策）

### 2.1 图粒度：KF-only + 非 KF 帧 PnP

- 只有 accepted keyframe 进入 fixed-lag 图：pose key `X(frame_index)`，
  timestamp = accepted `frame_index`（double，非 wall-clock 秒）；cutoff 严格 `<`；
- 非 KF 帧：用 candidate 自有的 landmark 集合做 PnP 得 pose，只写 trajectory 与
  diagnostics，不进图、不推进 graph epoch；PnP 失败 → 该帧 `kRejected`（非
  terminal），与 production 的 rejected 语义一致；
- rejected/failed 帧不推进 graph epoch，不产生 pose key。

### 2.2 gyro bias：每 KF bias 链 + random-walk edge

- 每个 accepted KF 一个 gyro-bias key `B(frame_index)`；
- 相邻 KF 用 random-walk edge：`B(i-1) - B(i) ~ N(0, σ_rw² Δt)`（σ_rw 来自
  `EstimatorOptions.imu_gyr_noise_nd` / random-walk 标定）；
- 旧 bias 随旧 pose 一起边缘化，不依赖 `fixedVariables_` 存活；
- 不做 shared global bias key（reference §4.2 的固定线性化点陷阱）。

### 2.3 landmark：进图前 gating + 窗口自然退休

- landmark key `L(id)`（id 为 candidate tracker 的全局递增 `LandmarkId`，
  无 rebirth，无需 generation 后缀）；
- 进图前 gating：新观测相对当前 estimate 的重投影残差超阈值的观测不入图
  （VINS/Basalt 的 pre-marginalization residual 选择）；gating 是 candidate
  自己的决策，不读 production graph events；
- 自然退休：landmark 的最后一个观测 pose 被边缘化/出窗后，删除其 factor 与
  value，retire 计数 +1；被边缘化 prior 中的历史贡献不可逆（接受的固有语义）；
- zero-disparity 观测不创建 stereo factor，也不刷新任何 graph timestamp
  （reference §6.3 的「假存活」禁令）。

### 2.4 KF 选择与 reset

- KF 选择复用 candidate 自己的 `KeyframeEpochGate`（P2a 已有）；
- segment seed / re-anchor：显式 graph reset event——重建新 smoother 与全部
  账本（pose/bias/landmark/slot），记录 `reset_reason`；这是 domain lifecycle，
  不是出错后的静默 fallback；
- fixed-lag 窗口：`smootherLag = current_frame_index - oldest_in_window_index`，
  窗口 = 最近 N 个 accepted KF（初始 N 对齐 production `window_size` 语义，
  structural gate 后按观测调参，不进 config_hash 的默认先固定）。

## 3. 数据流（每帧 `process()`）

```text
tracker.process(rectified)
  → zombie-age / cull 反馈（P2a 已有，图侧改为 retire 语义）
  → keyframe_gate.decide(tracks)
  → [KF 帧] 观测 gating（重投影阈值）
      → 构造 factors：
          stereo 观测 factors（含 bias prior 语义不变）
          gyro BetweenPose3（相邻 KF，复刻 production 的 gyro factor 构造）
          bias random-walk edges
      → snapshot smoother + ledger（强异常保证）
      → smoother.update(newFactors, newTheta, timestamps, factorsToRemove)
      → 回写：活动窗口 pose/bias/landmark、newest estimate、diagnostics
  → [非 KF 帧] PnP（candidate landmarks）→ trajectory pose 或 rejected
  → 自然退休检查（landmark 最后观测出窗 → 删 factor/value）
```

- 每次 `update()` 前完整备份 smoother + timestamp/ledger；任何异常恢复
  snapshot 并返回 `kEstimatorInvariant` terminal error（reference §3.4）；
- `newTheta` 只含本次新 key 的初值；已有 key 只刷 timestamp 不重复插 value；
- factor slot 账本：按 `getISAM2Result().newFactorsIndices` 记录每个自有
  factor 的真实 slot，删除前验证 `getFactors().exists(slot)`；
- 拒绝/失败帧不推进 graph epoch（与 production 的 accepted epoch 语义一致）。

## 4. 错误与诊断

| 条件 | 结果 |
|---|---|
| slot missing（账本持有但 `exists` 假） | `kEstimatorInvariant` terminal |
| timestamp orphan（timestamp 表有 key 但 `!valueExists`） | `kEstimatorInvariant` terminal |
| `update()` 异常 / rollback 失败 | 恢复 snapshot 后 `kEstimatorInvariant` terminal |
| non-finite estimate / pose / bias | `kEstimatorInvariant` terminal |
| 输入合同违约（P2a 已有） | `kInputContract` terminal |
| PnP 失败（非 KF 帧） | `kRejected` 帧级（继续） |
| segment reset | 显式 reset event + `reset_reason` |

`CandidateGraphDiagnostics` 由恒空改为真实值：
`active_pose_count`（窗口内 pose key 数）、`active_factor_count`（smoother 内
factor 数）、`marginalized_pose_count`（本帧新增边缘化 pose 数）、
`retired_landmark_count`（本帧自然退休 landmark 数）——仍是存量/增量计数，
不公开 factor keys/slots/landmark values（设计 §8.3 合同不变）。

## 5. 测试与验收

### 5.1 P0 contract probe（reference §8.1，第一个 slice）

经仓库 C++ test target 与稳定头验证 installed-library 合同（不改产品输出）：

1. cutoff 严格 `<`，恰在 cutoff 的 key 保留；
2. 已有 shared key 只刷 timestamp 不重复插 value 可跨 lag 存活（回归记录；
   P2b 用 per-KF bias 不依赖它）；
3. 首次 pose 边缘化后幸存 key 进 `getFixedVariables()`；
4. `newFactorsIndices` 与插入顺序对应、空 slot 可复用；
5. 删最后 factor 后复现 `timestamp present && !valueExists`，下次到期显式失败；
6. 人工制造 update 异常，恢复 smoother + ledger snapshot 后下一合法 update 成功。

### 5.2 synthetic structural gate

synthetic 序列（复用 `SyntheticEurocFixture` 扩展 + 静止/运动/丢帧场景）：

- terminal error=0、failed=0、全部 estimate finite；
- active pose/factor/landmark 数有界（≤ 窗口上界 + 常数）；
- cutoff 严格 `<` 保持；timestamp/valueExists 无孤儿；
- reset（segment）显式声明且计数正确；
- candidate enabled/failed 都不改变 production 三主产物/config hash（回归）；
- candidate diagnostics 行数 = 送入帧数，graph 计数与账本一致。

### 5.3 MH_01 结构门（只跑一次）

- terminal=0、failed=0、finite、无未声明 reset；
- completion/coverage 不低于 paired VO（`--no-imu` 同 run 比较）；
- active state/factor 有界；candidate artifacts 完整（analyzer 扩展 graph
  计数校验）。

不要求 ATE/RPE 严格优于 VO——精度结论留最终出口；若结构门失败，停在 MH_01
诊断，不扫 lag/threshold 参数。

## 6. vertical slice 草案（写实施计划时细化）

1. **P0 contract probe**（5.1 六项，仓库测试）；
2. **candidate fixed-lag 骨架**：PIMPL 内替换 estimator 为
   `IncrementalFixedLagSmoother` + pose-only 图 + snapshot/rollback + slot 账本
   （先无 bias/landmark 的纯 KF pose 链，synthetic 门）；
3. **landmark 生命周期**：`L(id)` + gating + 自然退休 + cull/drop 反馈对齐；
4. **per-KF bias 链**：`B(frame_index)` + RW edge + gyro BetweenPose3；
5. **非 KF 帧 PnP + 诊断**：trajectory 完整、`CandidateGraphDiagnostics` 真实
   计数、analyzer/artifact 扩展；
6. **MH_01 结构门** + 结果文档 + 删除 batch twin 临时代码。
