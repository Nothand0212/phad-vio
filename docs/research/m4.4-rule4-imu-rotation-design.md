## 1. 目标与非目标

### 1.1 唯一主行为

把关键帧 Rule 4 的旋转补偿来源从上一接受 BA/PnP body pose，替换为
**last accepted KF → current image** 的 gyro preintegration，并用
`T_B_left_rectified` 把 body-frame 相对旋转共轭到 rectified-left camera
frame。第一道 vertical slice 固定：

- `session.keyframe_parallax_px=30.0`；
- `session.keyframe_min_frames_after_kf=0`（cooldown 关闭）；
- mean pixel parallax 聚合不变；
- Rules 0–3 的业务语义不变。

第一刀通过后，才分别评估 Basalt-family cooldown 与 `10/15/30 px`；两项不在
第一次实现中同时改变，避免无法归因。

### 1.2 非目标

- 不修复 M4.3 已归因的 static-init scale/tilt 与 accel-bias walk；原 M4
  `MH_01 ATE <= 0.100 m` 门继续独立记账，不把 M4.4 描述成该债的修复。
- 不改变 GTSAM X/V/B 图、IMU factor、边缘化、窗口结构或 tracker。
- 不新增 BA pose 作为 IMU-on 的静默 fallback。
- 不把 VINS-Fusion 的 `10 px` 或 Basalt 的 `5` 当作可直接迁移的已验证默认。
- 不做 threshold × cooldown 的全因子矩阵；只有两个单变量候选各自成立后，才评估
  一个组合候选。

## 2. 已对齐决策

| 决策点 | 定案 |
|---|---|
| 外部 seam | apps 中单一事务型 `KeyframeGate` module |
| interface | `decide(...) -> ticket + decision`；estimator 返回后 `resolve(ticket, feedback)` |
| GTSAM 所有权 | 预积分数学留在 `phad::estimator`；public header 只暴露 Eigen/POD |
| 时间区间 | last accepted KF timestamp → current image timestamp |
| 样本生命周期 | 每帧判定前追加相邻 packet；只在 `selected && kOk` 后 reset |
| bias | 当前判定使用此前最新 `kOk` estimator gyro bias；每帧重建完整 last-KF 段 |
| 非 KF 接受 | 更新 causal bias/pose，保留 raw IMU 段，cooldown counter +1 |
| 失败/拒绝 | raw 时间证据保留；不更新 bias/pose/pixel baseline/cooldown counter，不 reset |
| IMU-on invalid | Rule 4 `unavailable`，不回退 BA；Rules 0–3 继续 |
| IMU-off | 显式 `pose_fallback`，保持视觉模式行为 |
| 诊断载体 | 在现有 `diag.csv` 末尾追加逐帧 KF 诊断，不新建 sidecar |
| 主切片 | `30 px + cooldown=off`，只替换 rotation source |
| MH_01 门 | 相对开工前同配置 control 不劣化；结构保持 `segments/reanchors/failed=1/0/0` |
| cooldown 规则 | 只节流 Rule 3（survival）与 Rule 4（parallax） |
| cooldown 边界 | Basalt 严格语义 `frames_after_kf > 5`；只计 `kOk` 非 KF 帧 |
| 配置身份 | parallax/cooldown 两键进入 `flattenConfig`、`config_hash`、`meta.json` |
| 可选默认晋级 | 保守 Pareto 门；无明确胜者就保持 `30 px + off` |

## 3. 模块 seam 与 interface

### 3.1 依赖方向

```text
phad::estimator
  raw IMU samples + gyro bias
       -> relative body rotation result (GTSAM hidden in implementation)
                         ^
                         |
apps::KeyframeGate ------+
  owns KF state / raw gyro segment / camera projection / cooldown
                         ^
                         |
apps::OfflineVoSession
  track -> decide -> estimator.update -> resolve -> diag
```

允许：

- `apps::KeyframeGate` 依赖 frontend track、camera calibration、sensor IMU 与
  estimator 的窄 rotation result；
- session 把 estimator `status`、最新 gyro bias 与接受 pose 作为 feedback；
- tests 与生产 caller 穿过同一个 `KeyframeGate` interface。

禁止：

- session 直接构造 GTSAM PIM 或复制 bias correction；
- estimator 依赖 frontend 或接管 KF policy；
- 保留匿名 namespace 中一份生产 selector、在测试中再复制一份；
- 为唯一实现增加 adapter/interface hierarchy。

### 3.2 语义 interface

下列为语义合同；实施时可按现有类型命名微调，但不得扩大 caller 需要掌握的状态：

```cpp
struct KeyframeDecision
{
  std::uint64_t ticket;
  bool          selected;
  // rule / cooldown / rotation / parallax diagnostics
};

struct KeyframeFeedback
{
  estimator::UpdateStatus          status;
  std::optional<Eigen::Matrix3d>   R_W_B;
  Eigen::Vector3d                  bias_gyr;
};

class KeyframeGate
{
public:
  [[nodiscard]] KeyframeDecision decide(
      const KeyframeInput& input );

  void resolve( std::uint64_t ticket,
                const KeyframeFeedback& feedback );
};
```

interface 的顺序不变量：

1. 同一时刻最多一个 unresolved ticket；
2. `decide()` 在计算本帧 Rule 4 前先纳入当前 packet；
3. caller 必须把同一帧 estimator 结果交给 `resolve()`；
4. ticket 不匹配、重复 resolve 或 unresolved 时再次 decide 是编程错误，必须显式
   抛出 `std::logic_error`，不能静默覆盖 pending transaction。`KeyframeInput` 只聚合
   tracks、raw IMU samples、`t_prev` 与 `imu_gap`，不让 gate 依赖图像 payload。

### 3.3 estimator rotation helper

estimator-owned helper 的输入只包含 raw samples 与 absolute gyro bias；输出至少包含：

```text
R_Bi_Bj, t_i, t_j, dt_s, angle_rad, valid, invalid_reason
```

约束：

- `R_Bi_Bj = R_W_Bi^T * R_W_Bj`，与 GTSAM `deltaRij()` 一致；
- absolute bias 只能作为 integration `biasHat`，不得传给只接受 bias increment 的
  `biascorrectedDeltaRij()`；
- samples 覆盖 `[t_i,t_j]`，左样本覆盖下一段 dt，右端样本不再积分；
- public header 不出现 GTSAM 类型。

## 4. 数据流与状态事务

### 4.1 每帧顺序

```text
StereoImuPacket + FrameTracks
        |
        v
KeyframeGate.decide
  1. append current adjacent-frame IMU segment
  2. rebuild last-KF -> current rotation with latest accepted gyro bias
  3. compute rule facts / raw and compensated parallax
  4. apply priority rules and optional cooldown
        |
        v
estimator.update(measurement, decision.selected)
        |
        v
KeyframeGate.resolve(ticket, status / pose / bias)
  - selected && kOk: commit KF pixels/timestamp, reset IMU segment/counter
  - !selected && kOk: refresh causal pose/bias, counter +1, keep segment
  - rejected/failed: keep temporal samples, rollback other pending state
```

raw IMU segment 是已发生的时间证据，不因 estimator 失败而删除；事务回滚针对
pixel/KF baseline、accepted pose、bias 与 cooldown counter。下一 packet 仍从失败帧
timestamp 开始，因此删除失败帧的 IMU 段会造成物理时间缺口。

### 4.2 bias 时效性

`KeyframeGate` 保存最近一次 `kOk` feedback 的 `bias_gyr`。当前帧 `decide()` 只能
使用上一帧结束前已接受的值，不能读取未来 estimator 结果。接受非 KF 后 bias 可在
下一帧生效；由于 gate 保存 raw samples，每帧用新 bias 重建整个 last-KF 段，而不是
把不同 bias 积分出的 delta 直接拼接。

### 4.3 坐标系与投影

采用 `R_A_B` 把 B-frame 向量变换到 A-frame。GTSAM 输出：

```text
DeltaR_ij = R_Bkf_Bcur = R_W_Bkf^T * R_W_Bcur
```

旧 KF camera ray forward-warp 到当前 camera：

```text
R_Ccur_Clkf = R_B_Crect^T * DeltaR_ij^T * R_B_Crect
```

其中 `R_B_Crect = T_B_left_rectified.rotation()`。像素先经内参变为 normalized
ray，旋转后再投回像素；`z <= 1e-6` 或非有限投影不进入 compensated aggregate。

### 4.4 Rule 顺序

现有优先级保持：

1. empty observations：不选；
2. 前两个**已接受** KF：强制选；
3. observations `< 10`：强制选；
4. 距 last accepted KF `> 0.5 s`：强制选；
5. survival `< 0.6`：候选 Rule 3；
6. compensated mean parallax `> keyframe_parallax_px`：候选 Rule 4。

cooldown 只作用于 5–6；1–4 不受其限制。

## 5. 错误与诊断

### 5.1 rotation source

`kf_rotation_source` 只有三种业务值：

- `imu`：IMU-on 且完整 last-KF segment 预积分成功；
- `pose_fallback`：仅 IMU-off 使用既有视觉 pose path；
- `unavailable`：IMU-on 但 Rule 4 无可靠 rotation。

IMU-on 的 `unavailable` 不升级成 session failure；Rule 4 本帧跳过，Rules 0–3
仍可选择 KF。不得用 BA pose 静默掩盖。

失效原因至少区分：

```text
no_accepted_kf, init_pending, imu_gap, insufficient_samples,
non_monotonic_samples, numeric_invalid
```

若 last-KF→current 之间任一 packet 有 `imu_gap`，整个累计段保持 unavailable，直到
某个由 Rules 0–3 选中的 KF 被 estimator 接受并重置 baseline。

### 5.2 `diag.csv` 追加列

保持现有 26 列及顺序不动，在末尾追加：

```text
kf_rule,
kf_cooldown_suppressed,
kf_frames_after_last,
kf_rotation_source,
kf_rotation_invalid_reason,
kf_rotation_dt_s,
kf_rotation_angle_rad,
kf_raw_parallax_px,
kf_compensated_parallax_px,
kf_common_tracks,
kf_parallax_tracks
```

约束：

- `kf_rule` 记录首个成立的候选规则；被 cooldown 抑制时仍保留 Rule 3/4，结合
  `kf_cooldown_suppressed=1` 与 `is_keyframe=0` 解读；
- 数值 unavailable 时写 `0`，不用 NaN；source/reason/count 负责消歧；
- `is_keyframe` 保持 estimator 调用时的 candidate 选择语义；是否真正接受由同一行
  `status` 联合判断；
- 不新增 `kf_diag.csv`，不在第一刀扩 `summary.json`；全序列分析从逐帧表聚合。

## 6. cooldown 与配置合同

新增正式 session 配置：

```text
session.keyframe_parallax_px=30.0
session.keyframe_min_frames_after_kf=0
```

- `keyframe_parallax_px` 必须有限且 `> 0`；
- `keyframe_min_frames_after_kf` 必须 `>= 0`；`0` 明确关闭 cooldown；
- 正数 `N` 的允许条件为 `frames_after_kf > N`；因此 `N=5` 表示已有 6 个
  `kOk` 非 KF 帧后，Rule 3/4 才可再次触发；
- `selected && kOk` 清零；`!selected && kOk` 加一；rejected/failed 不变；
- 两键由 bench/probe CLI 覆写，并进入 `flattenConfig`、`config_hash` 与
  `meta.json`；非法值在打开 dataset 前以非零状态退出。

## 7. 测试与验收

### 7.1 定向测试

测试必须调用生产 `KeyframeGate` interface，删除
`tests/apps/keyframe_selection_test.cpp` 中复制的 selector implementation。

1. 非 identity `R_B_Crect` + 纯 body rotation：raw flow 大，compensated
   parallax 近 0；能抓 transpose 与外参共轭错误。
2. 同一旋转叠加已知 camera translation：补偿后保留已知非零平移视差。
3. 非零 gyro bias：absolute bias 作为 biasHat 后补偿近 0；错误 increment 用法必须
   失败。
4. 多个 adjacent packet 与一次性整段积分一致。
5. 非 KF `kOk` 保留段并刷新下一帧 bias；selected+`kOk` reset；candidate rejected /
   failed 不推进 snapshot/counter/bias，且不丢 raw 时间段。
6. IMU-on 的 gap/样本不足/init pending/numeric invalid：Rule 4 unavailable、无 BA
   fallback、Rules 0–3 可用；IMU-off 明确 `pose_fallback`。
7. cooldown：Rule 3/4 被抑制；first/low-tracks/timeout 绕过；`N=5` 锁定严格
   `>5` off-by-one；失败帧不计数。
8. CLI / config hash / `meta.json`：默认值、覆写值、非法值与不同 run identity。
9. `diag.csv`：旧列顺序不动，新列值与 source/reason/suppressed 合同一致。

### 7.2 vertical slice 门

第一刀只运行 `IMU rotation + 30 px + cooldown off`：

1. 受影响 unit suites 与 production-interface tests 全过；
2. 以编码前相同数据、配置与工具链的 MH_01 run 为 control；新实现要求
   `ATE <= control`；
3. `segments/reanchors/failed=1/0/0`，completion 不降低；正常数据上 Rule 4 不出现
   `unavailable`（首个 accepted KF 建立前及显式 gap 区间除外）；
4. 原 M4 绝对门 `ATE <= 0.100 m` 单独报告；即使仍失败，也不能写成已修复。

### 7.3 cooldown / threshold 两级筛选

source-only 门通过后：

1. sentinel：`MH_01 / MH_05 / V1_01`；
2. 单变量 cooldown：`30 px` 下比较 off / `N=5`；
3. 单变量 threshold：cooldown off 下比较 `10/15/30 px`；
4. 只有通过 MH_01、无结构失败且诊断显示机制有效的候选，才扩 EuRoC 11/11；
5. 只有 cooldown 与 threshold 各自成立时，再在 sentinel 评估一个组合候选。

optional candidate 改默认采用保守 Pareto 门：

- MH_01 配对门通过；
- 全序列不新增 failure/re-anchor，不降低 completion/coverage；
- coverage 可比的每条序列 ATE 均不劣于 source-only `30 px + off`，且至少一条改善；
- cooldown 必须实际减少被抑制的近邻 Rule 3/4 KF 洪峰；threshold 的 KF 密度与
  parallax 分布变化必须与候选方向一致。

不满足时保留 `30 px + off`。EuRoC full-suite 数字仍全部 record-only，不把可选
候选的 Pareto 晋级门改写成 M4.4 主实现的完成条件。

## 8. 风险与证据缺口

| 风险 | 控制 |
|---|---|
| PIM 区间误用为 previous-frame→current | 多 packet 合成等价测试；diag 输出 dt |
| 旋转方向或外参共轭错误 | 非 identity 外参与纯旋转合成测试 |
| absolute bias 错当 increment | 非零 bias 定向测试 |
| failed candidate 提前 reset | ticket/resolve 事务测试 |
| IMU gap 被 BA fallback 掩盖 | source/reason 断言；IMU-on 禁 fallback |
| cooldown 差一帧 | `N=5` 的严格 `>5` 边界测试 |
| 10 px 被错误引用为上游已验证 | 一手资料已证明 VINS 当前执行 raw flow；只作本仓库 A/B |
| 单一平均 ATE 隐藏灾难 | sentinel + full-suite per-sequence Pareto；coverage 先行 |

尚无核对 revision 同时启用“IMU 去旋转 pixel aggregate → 固定 threshold → KF”
完整链路。因此公式由 GTSAM 方向合同、VINS 外参公式与 Kimera 时序共同约束；阈值、
cooldown 与默认选择必须由本仓库测试和 A/B 决定。
