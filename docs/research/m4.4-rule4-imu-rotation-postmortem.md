## 1. 结论

候选完成了数学、状态事务、生产接线和诊断的端到端实现，但没有通过 MH_01
相对 control 门。`30/15/10 px` 三个阈值的 ATE 都更差；10px 已恢复相近的关键帧
总量，仍未恢复 control。因此候选没有晋级，生产 C++、配置与 CSV schema 已完整
回退，cooldown、sentinel 与 EuRoC full-suite 未运行。

这不是“IMU rotation 公式已被证伪”。现有证据只证明：把该 rotation 直接替换进
既有 mean-pixel Rule 4，会改变关键帧时间表和 estimator 窗口内容，并在 MH_01
降低 ATE。下一刀应研究如何约束选择时序的改变，而不是继续盲扫更小阈值。

## 2. 候选做了什么

- 用 GTSAM 语义的 `R_Bkf_Bcur = R_W_Bkf^T R_W_Bcur`，按 latest accepted gyro
  bias 重建 last accepted KF → current 的完整 raw IMU 区间；
- 以 `R_Ccur_Clkf = R_B_Crect^T R_Bkf_Bcur^T R_B_Crect` 把旧 KF ray 投到当前
  rectified-left camera，保持 mean aggregate；
- 引入事务型 `decide -> estimator.update -> resolve`，只在 selected + `kOk`
  后推进 accepted-KF baseline；
- IMU-on invalid 时显式 unavailable，不静默退回 BA pose；
- 增加 source/reason/angle/raw/compensated parallax 等逐帧诊断；
- 第一刀固定 cooldown off；只在 30px 失败后按批准顺序诊断 15px、10px。

## 3. 哪些证据成立

### 3.1 实现与数据源

- estimator/apps/unit 全部通过：候选状态下 estimator **85/85**、apps
  **34 PASS + 3 SKIP**、unit **365/365**；
- 合成测试覆盖旋转 direction、非 identity camera extrinsic、absolute gyro bias、
  多 packet、失败事务与 invalid source；
- MH_01 首个 accepted KF 后 3239/3239 行为 `rotation_source=imu`，没有
  fallback/unavailable，区间 `dt>0`；
- 3217 个可匹配 GT 区间的 rotation angle 绝对误差 p95 为
  `0.001710/0.001454/0.001263 rad`（30/15/10px），causal gyro bias 对 GT bias
  范数误差均值约 `0.0030 rad/s`。

这些事实显著削弱了“候选实际上没用 IMU”“存在整段时间缺口”“rotation angle
量级错误”三类假设。GT 检查只验证 angle magnitude；axis 与像素投影由合成测试
约束，没有真实像素级 GT oracle。

### 3.2 质量结果

| source / threshold | ATE (m) | 相对 control | RPE (m) | accepted KF |
|---|---:|---:|---:|---:|
| BA-pose / 30px control | 0.122337 | — | 0.022957 | 518 |
| IMU / 30px | 0.138622 | +13.31% | 0.022834 | 320 |
| IMU / 15px | 0.155501 | +27.11% | 0.022261 | 406 |
| IMU / 10px | 0.132913 | +8.64% | 0.022122 | 533 |

四条 run 的 completion/coverage 完全相同，且
segments/reanchors/failed=`1/0/0`。所有 IMU 候选 RPE 略优而 ATE 更差，说明不能用
单一局部误差指标覆盖全局轨迹门。

## 4. 假设处置

| 假设 | 当前判定 | 证据边界 |
|---|---|---|
| 30px 对完整去旋转过高，导致 KF 总量过少 | **不足以解释，已被 10px 反例削弱** | 10px 的 accepted KF 533，接近 control 518，ATE 仍差 8.64% |
| rotation source / 区间根本无效 | **强烈削弱** | source 3239/3239 有效，GT angle 与 bias 量级合理，合成 direction/extrinsic 通过 |
| 关键帧时刻和窗口内容改变导致全局轨迹变化 | **最符合证据的推断，未建立单因果证明** | 10px 与 control 仅 133 个 accepted timestamp 重合；mean gap 接近但 schedule 不同 |
| cooldown 能修复 | **未确认** | source gate 已失败，依门禁未运行；不得从 Basalt 的独立策略外推 |
| 更小/动态阈值能修复 | **未确认且不继续盲扫** | 15px 非单调变差，10px 仍未过门；缺少可证伪的时序机制 |

目前没有逐像素真实 rotation oracle，也没有“固定同一 KF schedule，仅替换 rotation
evidence”的反事实 run，因此不能把根因写成已经证明的单一算法错误。

## 6. successor 约束

后续 B 先设计、再实施，并满足：

1. 研究对象是“关键帧 schedule 何时允许偏离已验证 control”，不是再扫一个 raw
   threshold；
2. first-KF、低观测、timeout 等安全规则保持清楚且可诊断；
3. estimator feedback 与 accepted-KF baseline 的事务边界必须显式；
4. 产品只保留一个选择路径，不复活 BA/IMU 双实现作为永久兼容层；
5. 最小验收应能区分 evidence 数值正确、schedule 改变和 estimator 窗口响应，避免
   只看 KF 总数或平均间隔；
6. 没有 MH_01 相对 control PASS 前，不进入 cooldown、sentinel 或 full-suite。
