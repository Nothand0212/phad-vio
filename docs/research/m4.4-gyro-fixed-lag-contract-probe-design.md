## 1. 目标与边界

用户已确认按 A→B 继续：A 已撤销失败的 full-B5 并恢复 B3 gyro-only 基线；B 探索
persistent joint-state / fixed-lag。调研确认本机 GTSAM 的
`IncrementalFixedLagSmoother` API 可用，但 API 可用不代表当前 estimator 的 shared bias、
explicit landmark 与 post-opt cull/rebuild 生命周期可以直接换芯。

P0 只回答一个问题：

> 本仓库实际链接的 GTSAM 是否稳定呈现后续 P1 shadow 必须依赖的 fixed-lag 生命周期
> 合同，并能否用“smoother + ledger 同一 snapshot”恢复一次失败更新？

本片不回答 fixed-lag 是否提高 ATE/RPE，也不实现 shadow graph。具体范围为：

- 通过稳定头 `<gtsam/nonlinear/IncrementalFixedLagSmoother.h>` 与现有 `gtsam` target
  编译、运行 contract tests；
- 固化 cutoff、timestamp refresh、fixed separator、factor slot、orphan 与 rollback 行为；
- 测试只拥有进程内合成 `Point2` graph，不读取 dataset，不新增产品类型；
- 不改 `StereoVoEstimator`、`EstimatorOptions`、apps、CSV/schema、config hash 或 benchmark
  产物；
- 不链接 `gtsam_unstable`，不新增 adapter/factory/config knob。

P0 通过只表示可以开始 P1 read-only shadow；绝不表示 M4.4、fixed-lag production 或
VIO<VO 精度门完成。

## 2. 模块边界与依赖

唯一新增实现位于 `tests/estimator/fixed_lag_contract_test.cpp`。测试通过现有
`phad_estimator_tests` target 链接 `gtsam`，不在 `phad/estimator` 中新增 probe class。

```text
phad_estimator_tests
  └─ FixedLagContractTest
       ├─ gtsam::IncrementalFixedLagSmoother
       ├─ gtsam::PriorFactor<Point2>
       ├─ gtsam::BetweenFactor<Point2>
       └─ test-local FactorLedger
```

`FactorLedger` 只是测试 fixture 内的 slot 所有权记录，用于证明 snapshot 边界必须同时
覆盖 smoother 与 caller ledger；它不是预先塑造的 production interface。P1 只有在真实
shadow 需求出现后再设计自己的内部账本。

## 3. 被锁定的合同

### 3.1 lag cutoff

使用 accepted epoch 同单位的整数 `double` timestamp。设 lag=`2.0`：

- current=`2` 时，epoch=`0` 恰好等于 cutoff，应仍存在；
- current=`3` 时，epoch=`0 < 1`，应被边缘化；
- newest `X(3)` 必须可按确切 key 读取，不能依赖 Values 顺序。

该测试防止后续代码把严格 `<` 误写成 `<=`，也防止把 Unix 纳秒直接 cast 到 `double`
后计算 lag。

### 3.2 shared key timestamp 与 fixed linearization

构造一个 global `B(0)`，首次插值后每个 epoch 只刷新 timestamp，不重复放进
`newTheta`。验证：

- 跨 lag 后 `B(0)` 仍有 timestamp 与 value；
- 第一个相连旧 pose 被边缘化前，`B(0)` 不在 `getFixedVariables()`；
- 边缘化后，`B(0)` 进入 fixed set。

这是事实门，不是 endorsing shared bias。P1 必须把它报告为 `bias_fixed`；未来 online
bias 仍需每状态 bias chain，而不是假定 timestamp refresh 能保持正常重线性化。

### 3.3 factor slot ownership 与复用

默认 smoother 打开 `findUnusedFactorSlots`。测试按插入顺序读取
`getISAM2Result().newFactorsIndices`，删除一个仍存在的用户 factor，再加入新 factor，
验证空 slot 被复用且 ledger 更新到新 owner。

slot 是当前 factor graph 的位置，不是永久 factor identity。测试不得硬编码由边缘化生成
的 internal linear factor slot，也不得在 `getFactors().exists(slot)==false` 时继续删除。

### 3.4 timestamp orphan 失败

插入只有一个 prior 的 key，随后用 `factorsToRemove` 删除它的最后 factor。验证
`ISAM2::valueExists(key)==false` 但 smoother `timestamps()` 仍含 key；再推进 current 使其
到期，必须观察显式异常，而不是把这一状态当成功。

该用例锁定当前 GTSAM 4.3a0（fixed-lag blobs 与 4.3a1 相同）的真实限制。P1 设计必须在
调用 update 前阻止 timestamp orphan；不能依赖一个不存在的公开 erase-timestamp API。

### 3.5 snapshot rollback

事务对象由下面两部分组成：

```text
IncrementalFixedLagSmoother + caller-owned FactorLedger
```

测试先复制 accepted snapshot，再在 candidate 上制造 orphan-expiry 异常；丢弃 candidate，
从 snapshot 继续一次合法 update。验收：合法 key 可估计、ledger 未含 candidate mutation、
accepted snapshot 与失败 candidate 不共享会被原位破坏的 Bayes-tree 状态。

这只证明整对象复制可作为 P1 的 rollback primitive；不声称任意 factor `shared_ptr` 可在
update 期间安全原位修改。P1 factor 必须 immutable。

## 4. 错误与诊断合同

- expected library failure 用 `EXPECT_THROW(..., std::exception)` 与 orphan 前置状态共同
  证明；不绑定可能随 patch release 改变的完整英文 message；
- 所有成功 update 后都检查 timestamp/value/factor slot 的实际状态，不使用占位型
  `FixedLagSmoother::Result::error`；
- contract 变化时测试应红并指出哪一条依赖失效，不添加兼容分支同时接受矛盾语义；
- P0 不 catch 后继续使用失败的 candidate smoother；rollback 用未参与失败调用的 snapshot；
- 测试使用唯一 GTSAM Symbol namespace，避免 key/type 混用掩盖 lifecycle 问题。

## 5. 测试与验收

计划新增以下测试：

| test | 核心验收 |
|---|---|
| `CutoffIsStrictAndNewestUsesExactKey` | 等于 cutoff 保留，严格早于 cutoff 删除，newest 可读 |
| `RefreshedGlobalSeparatorSurvivesAndBecomesFixed` | shared key 存活但在第一次 marginalization 后固定 |
| `NewFactorIndicesTrackReusedSlots` | slot 与插入顺序对应，删除后真实复用，ledger 换 owner |
| `RemovingLastFactorLeavesTimestampOrphanAndExpiryThrows` | timestamp/value 脱节可复现，expiry 显式失败 |
| `SnapshotRestoresSmootherAndLedgerAfterFailedCandidate` | 失败 candidate 不污染 accepted smoother/ledger |

验证顺序：

1. 重新生成 CMake，确认只使用稳定头与既有 `gtsam` target；
2. 构建并运行 `FixedLagContractTest.*`；
3. 运行完整 `phad_estimator_tests`；
4. 运行 `ctest -L unit`，确认无相关回归；
5. `git diff --check` 与目标文件格式检查。

## 6. 停止条件与 P1 入口

任一合同无法稳定复现时，停止 P1：先核对 installed GTSAM revision、链接库与实际源码，
更新调研结论，不能通过放宽断言掩盖差异。

P0 全部通过后，下一片才设计 P1 read-only shadow。P1 至少要报告 active pose/landmark
数量、cutoff、shared bias fixed 状态、owned/missing slots、timestamp orphan、marginalized
pose 数与 newest batch-vs-shadow delta；shadow 不参与 prediction、gate、LM initial value 或
返回 pose。只有 P1 在 MH_01 全程 finite、无 orphan/异常、状态有界，才讨论 production
handoff。

## 7. 实施结果

P0 只新增 `tests/estimator/fixed_lag_contract_test.cpp` 并接入既有
`phad_estimator_tests`；没有修改 estimator runtime、options、apps 或输出 schema。五项
contract tests 均在实际链接的 GTSAM 4.3a0 上通过：

```text
FixedLagContractTest.*  5/5 PASS
phad_estimator_tests    100/100 PASS
ctest -L unit           398/398 PASS, 3 existing SKIP, 0 FAIL
```

其中 shared separator 在第一次 pose marginalization 后进入 fixed set；删除最后 factor
后实际观察到 `timestamp present && !valueExists`，推进 epoch 时抛出异常；在失败调用只
发生于 candidate copy 的前提下，accepted smoother/ledger 保持可继续更新。`git diff
--check` 与四个新增 P0 文件的 `--no-index --check` 均无空白诊断。

因此 P0 的 go 条件满足。该结果只授权另写 P1 read-only shadow 设计，不授权把 fixed-lag
estimate 交给 production，也没有运行或改变任何 EuRoC accuracy 数字。
