# M2.3 VO Backend — Open Source References

日期：2026-07-31

Scope lock（本笔记仅服务 M2.3）：`Cal3_S2Stereo` + `GenericStereoFactor`（显式 landmark，非 smart factor）、`triangulatePoint3`（及等价 stereo 初值）、固定窗口 batch BA + `LevenbergMarquardtOptimizer`、滑出窗口直接丢弃（无边缘化）、单一 gauge-fixing prior、每帧都是 keyframe（前端已产出带 `LandmarkId` 的 `FrameTracks`）、出口为 MH_01_easy 轨迹文件且 meter-level ATE 即可。

Citations 使用当时 HEAD / 发布 tag 的 blob permalink；GTSAM API 同时对照仓库 vendored `thirdparty/gtsam-4.3a1`（tag [`4.3a1`](https://github.com/borglab/gtsam/releases/tag/4.3a1) = [`2f3e56c0ddbd`](https://github.com/borglab/gtsam/commit/2f3e56c0ddbd3a1aa54ed043643b553d26a069f6)）。

## Summary (for design decisions)

- **Factor stack**：直接复用 GTSAM `StereoVOExample` / `_large` 的 `GenericStereoFactor<Pose3,Point3>` + `Cal3_S2Stereo` + LM；这是 M2.3 最近邻参考。[`StereoVOExample.cpp`](https://github.com/borglab/gtsam/blob/2f3e56c0ddbd3a1aa54ed043643b553d26a069f6/examples/StereoVOExample.cpp)、[`StereoVOExample_large.cpp`](https://github.com/borglab/gtsam/blob/2f3e56c0ddbd3a1aa54ed043643b553d26a069f6/examples/StereoVOExample_large.cpp)
- **Gauge**：官方 stereo 示例用 `NonlinearEquality<Pose3>`，但注释明确会强制 QR（慢）。M2.3 / `docs/architecture.md` 已选 **`PriorFactor<Pose3>`**（强先验近似固定首帧）——与 Kimera 初始 prior 风格一致，避免 QR。[`StereoVOExample_large.cpp` L105–107](https://github.com/borglab/gtsam/blob/2f3e56c0ddbd3a1aa54ed043643b553d26a069f6/examples/StereoVOExample_large.cpp#L105-L107)、[`PriorFactor.h`](https://github.com/borglab/gtsam/blob/2f3e56c0ddbd3a1aa54ed043643b553d26a069f6/gtsam/nonlinear/PriorFactor.h)、[architecture §4](../architecture.md)
- **Landmark 初值**：单帧有效立体观测优先用 `StereoCamera::backproject(StereoPoint2)`（闭式 `Z = b·fx/(uL−uR)`）；多帧/多视角再用 `triangulatePoint3`（要求 ≥2 个相机位姿，否则 `TriangulationUnderconstrainedException`）。官方 `_large` 示例**并未**调用 `triangulatePoint3`，而是读入已三角化的相机系 `(X,Y,Z)` 再 `transformFrom` 到世界系——那是 toy/offline 路径，online 应换成上述 API。[`StereoCamera.cpp` backproject](https://github.com/borglab/gtsam/blob/2f3e56c0ddbd3a1aa54ed043643b553d26a069f6/gtsam/geometry/StereoCamera.cpp)、[`triangulation.h` `triangulatePoint3`](https://github.com/borglab/gtsam/blob/2f3e56c0ddbd3a1aa54ed043643b553d26a069f6/gtsam/geometry/triangulation.h)
- **符号**：采用 `Symbol('x', k)` / `Symbol('l', j)`（`_large` 与 Kimera 一致）；小示例用裸整数 key，不宜照搬。[`StereoVOExample_large.cpp`](https://github.com/borglab/gtsam/blob/2f3e56c0ddbd3a1aa54ed043643b553d26a069f6/examples/StereoVOExample_large.cpp)、[Kimera `VioBackend-definitions.h`](https://github.com/MIT-SPARK/Kimera-VIO/blob/ce8c59b7b273ab5ac29db7e5572e1623760e19c7/include/kimera-vio/backend/VioBackend-definitions.h)
- **外参**：`GenericStereoFactor` 支持可选 `body_P_sensor`；若优化变量是 body（IMU）位姿，必须传入 left-cam（rect）外参。Kimera 把 `B_Pose_leftCamRect_` 交给 smart factor / 状态预测；phad M2.3 若状态是 left-cam 或已把姿态定义在左目，可省略该参数（identity）。[`StereoFactor.h`](https://github.com/borglab/gtsam/blob/2f3e56c0ddbd3a1aa54ed043643b553d26a069f6/gtsam/slam/StereoFactor.h)、[Kimera `VioBackend.h`](https://github.com/MIT-SPARK/Kimera-VIO/blob/ce8c59b7b273ab5ac29db7e5572e1623760e19c7/include/kimera-vio/backend/VioBackend.h)
- **Cheirality**：默认 `throwCheirality_=false`；失败时 Jacobian 置零并返回 `Vector3::Constant(2.0 * K_->fx())` 大残差。测试可开 `verboseCheirality`；生产勿默认 throw。Kimera 对 smart factor 同样 `throwCheirality = false`，并有 `cleanCheiralityLmk` 删除坏 landmark——显式因子场景应在优化后/失败时 drop 该 `l`，而非抄 smart-factor 槽位逻辑。[`StereoFactor.h` evaluateError](https://github.com/borglab/gtsam/blob/2f3e56c0ddbd3a1aa54ed043643b553d26a069f6/gtsam/slam/StereoFactor.h)、[Kimera `setSmartStereoFactorsParams`](https://github.com/MIT-SPARK/Kimera-VIO/blob/ce8c59b7b273ab5ac29db7e5572e1623760e19c7/src/backend/VioBackend.cpp)
- **Frontend↔backend 缝**：Kimera 前端送 `StatusStereoMeasurements` +（VIO 时）PIM；**backend 自持** `FeatureTracks` / smart-factor map。phad 前端已拥有 per-frame `FrameTracks` + 稳定 `LandmarkId`——M2.3 宜让 **estimator 独占图与 Values**，只消费帧观测快照，不要再在 backend 另建一条无限增长的 track 表（Kimera 自己也标注 `feature_tracks_` “grows unbounded”）。[Kimera `BackendInput`](https://github.com/MIT-SPARK/Kimera-VIO/blob/ce8c59b7b273ab5ac29db7e5572e1623760e19c7/include/kimera-vio/backend/VioBackend-definitions.h)、[Kimera `VioBackend.h` L511–512](https://github.com/MIT-SPARK/Kimera-VIO/blob/ce8c59b7b273ab5ac29db7e5572e1623760e19c7/include/kimera-vio/backend/VioBackend.h)、[phad `stereo_tracks.hpp`](../../phad/frontend/stereo_tracks.hpp)
- **窗口策略**：VINS-Fusion / Kimera / OpenVINS 均用固定滞后 + **边缘化或协方差更新** 保留信息。M2.3 明确 **drop**——更接近“每步重建窗口图再 LM”，不要抄 `MarginalizationFactor` / `IncrementalFixedLagSmoother`。新帧位姿初值可借 VINS 的 **PnP（已知 3D）** 或恒速/上一帧外推；ORB-SLAM3 Local BA 的 “fixed KF 锚定” 在概念上对应 gauge/边界固定，但实现是 g2o，不直接移植。
- **刻意不抄**：Kimera smart stereo + ISAM2 fixed-lag；VINS Ceres 边缘化与逆深度状态；OpenVINS MSCKF（特征多数不进状态）；ORB-SLAM3 共视图 Local BA + 地图点生命周期（M2.3 无窗口丢弃即可）。

## Detailed notes

### GTSAM official StereoVO examples

- Links
  - [`examples/StereoVOExample.cpp` @ 4.3a1](https://github.com/borglab/gtsam/blob/2f3e56c0ddbd3a1aa54ed043643b553d26a069f6/examples/StereoVOExample.cpp)
  - [`examples/StereoVOExample_large.cpp` @ 4.3a1](https://github.com/borglab/gtsam/blob/2f3e56c0ddbd3a1aa54ed043643b553d26a069f6/examples/StereoVOExample_large.cpp)
  - gtbook notebook：[`StereoVOExample_large.ipynb`](https://github.com/gtbook/gtsam-examples/blob/c1268c4bfdac726a0b7d358d1691da6529681d7c/StereoVOExample_large.ipynb)
  - Doxygen：[`GenericStereoFactor`](https://gtsam.org/doxygen/a05511.html)、[`triangulatePoint3`](https://gtsam.org/doxygen/a00458.html)
- Relevant files / APIs
  - Factors: `graph.emplace_shared<GenericStereoFactor<Pose3,Point3>>(StereoPoint2(uL,uR,v), model, poseKey, landmarkKey, K)`
  - Calib: `Cal3_S2Stereo(fx, fy, s, u0, v0, b)`
  - Gauge (small): `NonlinearEquality<Pose3>(1, Pose3())` at origin
  - Gauge (large): `NonlinearEquality<Pose3>(Symbol('x',1), first_pose)` + comment *“forces … QR rather than Cholesky”*
  - LM: default ctor；large 设 `LevenbergMarquardtParams::orderingType = Ordering::METIS`
  - Landmark init in large: file provides camera-frame `(X,Y,Z)` → `camPose.transformFrom(Point3(X,Y,Z))`；**not** `triangulatePoint3`
- Patterns
  - Toy：2 poses × 3 landmarks，手写初值，batch 一次优化即退出——可验证 API，不可当 online VO。
  - Large：离线读 KITTI-like 因子文件，仍是 **单次 batch**，无滑窗 / 无边缘化。
  - gtbook 复述同一 gauge/QR 注释，确认这是官方教学立场而非过时注释。
- Implications for phad M2.3
  - 因子与优化器可原样落地；online 路径需自建：每帧插入 `x(k)`、对新 `LandmarkId` 三角化、对窗口内观测加 factor、滑出时 **erase keys + rebuild or surgically remove**、保留单一 `PriorFactor` 在窗口 oldest 或全局首帧（需对齐决策，见 Open questions）。
  - 大图时 METIS ordering 值得保留；小窗口可先用默认。

### Kimera-VIO (MIT-SPARK)

- Links
  - Repo / README：[`MIT-SPARK/Kimera-VIO` @ `ce8c59b7`](https://github.com/MIT-SPARK/Kimera-VIO/blob/ce8c59b7b273ab5ac29db7e5572e1623760e19c7/README.md)
  - [`VioBackend-definitions.h`](https://github.com/MIT-SPARK/Kimera-VIO/blob/ce8c59b7b273ab5ac29db7e5572e1623760e19c7/include/kimera-vio/backend/VioBackend-definitions.h)
  - [`VioBackend.h`](https://github.com/MIT-SPARK/Kimera-VIO/blob/ce8c59b7b273ab5ac29db7e5572e1623760e19c7/include/kimera-vio/backend/VioBackend.h)
  - [`VioBackend.cpp`](https://github.com/MIT-SPARK/Kimera-VIO/blob/ce8c59b7b273ab5ac29db7e5572e1623760e19c7/src/backend/VioBackend.cpp)
- Relevant files
  - FE→BE：`BackendInput` 含 `status_stereo_measurements_kf_`（`StatusStereoMeasurements`：tracker status + stereo measurements）、`pim_`、raw IMU（初始化用）。
  - Backend owns：`FeatureTracks`、`LandmarkIdSmartFactorMap` / `SmartFactorMap`、`IncrementalFixedLagSmoother`（`#define INCREMENTAL_SMOOTHER`）。
  - Symbols：`kPoseSymbolChar='x'`, `kLandmarkSymbolChar='l'`（另有 `v`/`b` 给 VIO）。
  - Vision factors：`SmartStereoProjectionPoseFactor` + `Cal3_S2Stereo` stereo cal；构造时带 `B_Pose_leftCamRect_`。
  - Gauge / init：`addInitialPriorFactors` 对首帧加 `PriorFactor`（pose / vel / bias），**不是** `NonlinearEquality`。
  - Cheirality：`smart_factors_params->throwCheirality = false`；优化异常路径调用 `cleanCheiralityLmk` 删 landmark。
- Patterns (borrow vs not)
  - **Borrow**：清晰的“前端给测量 + 相对运动提示，后端独占图”；外参 `B_Pose_leftCamRect` 合同；强 `PriorFactor` 锚定；cheirality 不抛异常而是剔除。
  - **Not copy**：structureless smart factors（与 M2.3 “显式 landmark” 相反）；fixed-lag smoother / marginalization；backend 内二次维护 track 表且注释承认 unbounded；IMU 整条路径。
- Implications for phad M2.3
  - 接口形状可简化为：`FrameTracks` + stereo cal + `T_B_C`（若需要）→ estimator。
  - Landmark 生命周期用显式 `Values` 中的 `Point3` + `GenericStereoFactor`，滑出即删——比 Kimera smart-factor slot bookkeeping 简单一个数量级，符合 meter-level 出口。

### VINS-Fusion

- Links
  - [`estimator.cpp` @ `be55a937`](https://github.com/HKUST-Aerial-Robotics/VINS-Fusion/blob/be55a937a57436548ddfb1bd324bc1e9a9e828e0/vins_estimator/src/estimator/estimator.cpp)
  - [`feature_manager.cpp` @ `be55a937`](https://github.com/HKUST-Aerial-Robotics/VINS-Fusion/blob/be55a937a57436548ddfb1bd324bc1e9a9e828e0/vins_estimator/src/estimator/feature_manager.cpp)
- Relevant patterns
  - **Keyframe measurement seam**：tracker 输出 `map<feature_id, vector<(cam_id, xyz_uv_vel)>>`；`FeatureManager::addFeatureCheckParallax` 决定是否关键帧（M2.3 每帧都是 KF，此门控可忽略，但测量包形状可参考）。
  - **Pose init**：`initFramePoseByPnP` 用已三角化特征的世界点 + 当前帧观测，`cv::solvePnP` 得新帧位姿（无 IMU 时尤其重要）。
  - **Landmark init**：`STEREO && is_stereo` 时在 **start_frame** 用左右目投影矩阵 DLT（`triangulatePoint3` 风格手写 SVD）；深度 ≤0 则回退 `INIT_DEPTH`。
  - **Window**：`WINDOW_SIZE` 满后 `optimization()`（Ceres）再 `slideWindow()`；`MARGIN_OLD` 路径构建 `MarginalizationFactor`，并对特征 `removeBackShiftDepth`——**与 M2.3 drop 相反**。
  - **Gauge**：`double2vector` 在 `USE_IMU` 时把优化后的位姿对齐回 `Ps[0]` 位置与 yaw；无 IMU 分支则直接写回 para，不显式锁 SE3 gauge（依赖问题设定 / 边缘化先验）。纯双目 M2.3 **不能**依赖该 IMU gauge 技巧，应显式 `PriorFactor<Pose3>`。
- Implications for phad M2.3
  - 借：新帧 PnP 初值；首个有效立体观测即三角化；失败深度的显式回退/跳过。
  - 不借：边缘化、逆深度参数化、Ceres residual 布局。

## Open questions for alignment

1. **优化坐标系**：`X(k)` 是 body（IMU）还是 left-camera（rect）？若 body，是否统一经 `GenericStereoFactor(..., body_P_sensor=T_B_C)` 注入？（architecture 写 body pose；M2.2 前端在 rect 图像上测像素。）
2. **Gauge 锚点**：prior 钉死 **全局首帧**（轨迹不漂但窗口需持续带上 `x0` 或把结果链式存出），还是钉死 **当前窗口 oldest**（每滑窗重定 gauge，导出轨迹需累积相对位姿）？
3. **窗口长度 N** 与每帧全是 KF 时的实时预算（MH_01 @ ~20 Hz）？
4. **新帧位姿初值**：PnP（VINS 风格）vs 恒等/恒速外推 vs 仅依赖 LM 从差初值拉回？
5. **Landmark 插入时机**：第一个 `StereoStatus::kValid` 即 `backproject`，还是要求 track `length≥2` / 最小视差？（Kimera smart factor 要求 ≥2 obs；VINS stereo 允许单帧。）
6. **滑出丢弃规则**：仅丢 `x` 离开窗口的 pose，还是同时丢“最后一次观测已离开窗口”的 `l`？跨窗口仍被跟踪的 id 是否在重新进入时重新三角化？
7. **`PriorFactor` 噪声**：近似 equality 的对角 sigma（Kimera `initialPositionSigma_=1e-5` 量级是否可接受）？
