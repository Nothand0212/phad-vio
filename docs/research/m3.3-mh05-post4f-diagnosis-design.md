## 3. 数据流与步骤

```text
④f/④b est.tum ── phad_traj_eval --gt-euroc <seq> --errors-csv ──► errors.csv
④f/④b diag.csv ── join on timestamp_ns ────────────────────────────────┤
④f/④b summary/meta ── 身份与汇总 ──────────────────────────────────────┤
                                                                        ▼
                                                         一次性 Python 对照
                                                                        ▼
                                      docs/research/m3.3-mh05-post4f-diagnosis.md
```

1. **身份核对**：两边 `meta.json` 的 commit / `config_hash` / 相对增量键；
   确认 summary ATE 与基线一致（④f ≈3.057，④b ≈3.449）。
2. **逐位姿误差**：对两边 `est.tum` 跑
   `phad_traj_eval --est … --gt-euroc <MH_05> --max-dt-ms 2.5 --errors-csv …`
   （与 bench 同 SE3 ATE 语义）；**不**手写对齐。
3. **时间线对照**：`errors.csv` ⋈ `diag.csv`，比较平移误差分叉、
   `reproj_rms_after(_cull)`、`outliers_culled`、`num_cheirality`、
   `pnp_success` / inliers、`segment_id`、`low_connectivity`；重点看
   - i≈425 大剔 + ④f `drops_skipped` 之后；
   - 是否仍有「高 RMS / culled≈0」平台；
   - 相对 ④b 谁先分叉、谁有二次自救。
4. **事件表**：分叉点与 cull / skip-drop 峰值帧簇，用数字支撑假说。
5. **收敛**：笔记末唯一推荐刀 + 否决；不足则写清升级 B 的缺口。

临时文件放 `/tmp` 或未跟踪目录；不提交 `errors.csv` / 一次性脚本
（除非事后要求入库）。

若 `phad_traj_eval` 未在 `build/`，先
`cmake --build build --target phad_traj_eval` 再跑。

## 4. 诊断笔记格式

1. 元信息：日期、状态、对照身份、关联文档 / #24  
2. 汇总表：ATE/RPE、culled、reopt、cheirality、pnp、seg/re/failed、
   `drops_skipped`（④f）  
3. 分叉时间线与关键帧簇表（含 skip-drop / 大剔前后）  
4. 假说检验（每条 **支持 / 反对 / 不足**）：  
   - 末轮 Huber 遮罩外点；  
   - mean-cull 盲区（高图 RMS、单点毒、culled≈0）→ 观测级 / max 判据；  
   - skip-drop 后仍丢二次自救 / 连通性不足（相对 ④b）；  
   - 前端跟踪质量 / PnP 外点（非 estimator cull）；  
   - 其它（写清）。  
5. **结论（必填）**：唯一推荐下一刀；否决项；或 B 升级清单  

### 缺口处理

- GT / `est.tum` 对不齐或 match rate 异常 → 先修关联，不硬猜。  
- 仅靠 18 列 diag 无法区分假说 → 结论写「升级 B」，不假装选定机制。
