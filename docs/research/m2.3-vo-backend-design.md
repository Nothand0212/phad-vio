# M2.3 VO 后端设计

日期：2026-07-31  
状态：已审阅，决策见 §2  
相关：[roadmap M2.3](../roadmap.md)、[architecture](../architecture.md)、[conventions](../conventions.md)、[开源对照](m2.3-vo-backend-open-source-refs.md)

## 1. 目标与非目标

### 目标

在已有双目前端（`FrameTracks`）之上接入 GTSAM 显式 landmark 固定窗口 batch BA，使 `MH_01_easy` 产出完整 `T_W_B` 轨迹（TUM），ATE 有限且米级即可；该数字作为后续里程碑基线。

### 非目标

- 关键帧策略；`findEssentialMat` / `solvePnPRansac` 几何验证与位姿初值（M3）
- IMU、preintegration、`V`/`B` 状态（M4）
- 边缘化 / fixed-lag smoother（M6）
- Smart factor、多线程、回环
- 精度优化或 MH_02–05 门控

两处刻意越过「最小」的地方，理由记录在此以免被后续误读为 scope creep：

- **恒速位姿初值**只用上两个已接受帧的相对位姿外推，不解 PnP、不接触 OpenCV，
  因此不属于 M3 的「几何验证」范围；MH_01 在 20 Hz 下 body 速度可达 1–2 m/s，
  零运动初值配合无 robust kernel 是最典型的发散组合。
- **Huber kernel** 是噪声模型的一个参数，不是外点剔除算法；前端目前只有前后向
  一致性与极线/视差/深度门限，缺少运动模型层面的剔除，单个漂移的 LK 点在 1 px
  sigma 下足以掰弯整个窗口。M3 的 RANSAC 相对该配置测收益。

## 2. 已锁定决策

| 项 | 决策 |
|---|---|
| 关键帧 | 每帧都进 estimator |
| Seam | App/glue 将 `FrameTracks`（仅 `kValid`）组装为 `KeyframeMeasurement`；类型属 `phad::estimator`；frontend 不引入关键帧 API |
| `LandmarkId` | 上移到 `phad::common`；`phad::frontend` 与 `phad::estimator` 都 alias 它，estimator 仍不依赖 frontend |
| Pose 初值 | 恒速外推 `T_prev · (T_prevprev⁻¹ · T_prev)`；只有一个已接受帧时退化为 `T_prev`。开关 `use_constant_velocity_init`，默认开，基线数字注明取值 |
| Gauge | 单一强 `PriorFactor<Pose3>` 钉在**当前窗口最老帧**；滑窗时迁移（均值取该帧当前估计） |
| 窗口 | 可配置，默认 `10` |
| 状态定义 | `X(k)` = body pose；`GenericStereoFactor` 传 `body_P_sensor = T_B_left_rectified` |
| 外参来源 | **`RectifiedStereoCalibration::T_B_left_rectified()`**，与 `Cal3_S2Stereo` 同源；构造函数不再单独收外参 |
| Landmark 初值 | 首次 `kValid` 观测用 `StereoCamera::backproject`，再变到世界系 |
| Landmark 入图门限 | 窗口内 **≥2 次观测**才建 factor；单次观测的点精确可解、对位姿零信息 |
| 图维护 | **每步重建**窗口内 factor graph + Values，再 LM；候选帧先入临时窗口，LM 成功才提交 |
| 视觉噪声 | 各向同性 `Isotropic::Sigma(3, 1.0)` px on `(uL, uR, v)`，外包 `noiseModel::Robust` + `mEstimator::Huber(k = 3.0)` |
| Prior sigma | 旋转 `1e-4` rad、平移 `1e-4` m 的对角先验（近似 equality 但不触发 QR） |
| 输出语义 | 每步只写出**最新帧**位姿；窗口内旧帧被重新优化但不回写已导出的轨迹点 |
| 出口应用 | `phad_stereo_vo_probe`（无窗口验收）+ `phad_euroc_runner`（可视化） |
| Gauge 因子类型 | `PriorFactor`（不用 `NonlinearEquality`，避免强制 QR） |
| GTSAM 接入 | `find_package(GTSAM 4.3 REQUIRED)`，本机已装 4.3.0；安装步骤写进 README |

### 2.1 外参必须取校正后的左目

这一条单列，因为取错不会崩溃，只会把一个常量误差烧进基线。观测是校正后的像素，
`Cal3_S2Stereo` 也来自 `RectifiedStereoCalibration`，因此 `body_P_sensor` 对应的
sensor 系是**校正后**的左目。它与 `StereoImuCalibration::T_B_left_camera()` 差一个
`stereoRectify` 的 `R1`：

```text
T_B_left_rectified.R = R_B_left · R1ᵀ
T_B_left_rectified.t = t_B_left
```

取未校正的 `T_B_left_camera()` 相当于给每个 pose 右乘一个常量误差。右乘的常量
**吸收不进 Umeyama 对齐**，会表现为正比于角速度的杆臂误差。EuRoC 的 `R1` 约零点
几度，米级出口照样通过——正因如此它会安静地成为 M2.3 基线的一部分，直到 M3 追
厘米时才发作。构造函数只收 `RectifiedStereoCalibration`，不给这个不一致留接口。

## 3. 模块边界

### 3.1 `phad::estimator`

CMake target：`phad_estimator`（alias `phad::estimator`）。

| 拥有 | 不拥有 |
|---|---|
| `KeyframeMeasurement` / `StereoObservation` / `VioEstimate` / `VioUpdateResult`（M2 无 `pim`） | 图像、路径、数据集字段名 |
| 固定窗口：pose、landmark、窗口内观测缓存 | 关键帧决策、feature track 生命周期 |
| GTSAM 图重建、`Cal3_S2Stereo`、`body_P_sensor`、LM | 边缘化、smart factor、IMU |
| 诊断：重投影、cheirality、共视连通性 | ATE（`phad::eval`） |

**依赖**：`phad::common`、`phad::sensor`、`phad::camera`、GTSAM。  
**不依赖** `phad::frontend`（由 apps/glue 连接，避免库环依赖）。GTSAM 只出现在
`.cpp` 与 PIMPL 内，不进公开头文件，因此 `PRIVATE` 链接。

结果类型沿用 architecture.md §2.5 / §3.4 的目标命名（`VioEstimate` /
`VioUpdateResult`），M4 加入 `V`/`B` 时字段扩展、名字不变；类名 `StereoVoEstimator`
则标注 M2 的纯视觉现状，可在 M4 改名，不以抽象基类预留。

### 3.2 公开 API（草）

```cpp
namespace phad::estimator
{

  using common::LandmarkId;

  struct StereoObservation
  {
    LandmarkId      id;
    Eigen::Vector2d left_pixel;    // rectified left
    double          disparity_px;  // must be > 0
  };

  struct KeyframeMeasurement
  {
    common::Timestamp              timestamp;
    std::vector<StereoObservation> observations;
  };

  struct EstimatorOptions
  {
    int    window_size                = 10;
    int    min_landmark_observations  = 2;   // in-window, to enter the graph
    int    min_shared_landmarks       = 10;  // below this: low-connectivity flag
    double stereo_sigma_px            = 1.0;
    double huber_k_px                 = 3.0;
    double prior_rotation_sigma_rad   = 1e-4;
    double prior_translation_sigma_m  = 1e-4;
    bool   use_constant_velocity_init = true;
  };

  enum class UpdateStatus : std::uint8_t
  {
    kOk       = 0,
    kRejected = 1,
    kFailed   = 2
  };

  struct VioEstimate
  {
    common::Timestamp timestamp;
    Eigen::Isometry3d T_W_B;
  };

  struct UpdateDiagnostics
  {
    std::uint32_t num_observations;
    std::uint32_t num_landmarks;      // in the graph
    std::uint32_t num_shared;         // observed by the new frame and the window
    std::uint32_t num_cheirality;
    std::uint32_t lm_iterations;
    double        reproj_rms_before_px;
    double        reproj_rms_after_px;
    double        max_window_pose_shift_m;  // 已导出位姿被重新优化的幅度
    bool          low_connectivity;
  };

  struct VioUpdateResult
  {
    UpdateStatus               status;
    std::optional<VioEstimate> estimate;  // only when kOk
    UpdateDiagnostics          diagnostics;
    std::string                message;  // non-empty when not kOk
  };

  class StereoVoEstimator
  {
  public:
    explicit StereoVoEstimator( camera::RectifiedStereoCalibration calibration,
                                EstimatorOptions options = {} );
    ~StereoVoEstimator();

    StereoVoEstimator( const StereoVoEstimator& )            = delete;
    StereoVoEstimator& operator=( const StereoVoEstimator& ) = delete;
    StereoVoEstimator( StereoVoEstimator&& ) noexcept;
    StereoVoEstimator& operator=( StereoVoEstimator&& ) noexcept;

    [[nodiscard]] VioUpdateResult update(
        const KeyframeMeasurement& measurement );

  private:
    struct Impl;
    std::unique_ptr<Impl> m_impl;
  };

}  // namespace phad::estimator
```

`LandmarkId` 从 `phad::frontend` 上移到 `phad::common`。此前两个 namespace 各定义
一个 `std::uint64_t` 别名，靠注释维系「数值合同一致」，写反了静默编译通过；上移后
两边 alias 同一个类型，estimator 依然不依赖 frontend。

## 4. 数据流与每步算法

### 4.1 内部状态（私有）

- 有序窗口队列：每帧 `{timestamp, T_W_B, observations}`
- `LandmarkId → Point3`（世界系），仅保留窗口内仍被观测的 id
- 最近两个**已接受**帧的位姿，供恒速外推
- 诊断用：`LandmarkId →` 观测过的时间戳列表（不参与优化）

### 4.2 `update` 步骤

1. **校验输入**：时间戳严格递增；观测非空（首帧也要求至少一观测才初始化）；
   视差 > 0；像素有限。标定合同已在构造期通过。
2. **首帧**：`T_W_B = I`；对每个观测 `backproject(StereoPoint2)` 得左相机系点，
   经 `T_W_B · T_B_left_rectified` 到世界系，插入 landmark。
3. **后续帧**：pose 初值按 §2 恒速外推；未见过的 id → `backproject`；已见 id 沿用
   当前 landmark 估计作初值。统计 `num_shared` = 本帧观测中已在窗口 landmark 表里
   的 id 数。
4. **候选入窗**（临时，未提交）；若超过 `window_size`：弹出最老帧；删除窗口内已无
   观测的 landmark。被删除的 id 若日后重新被跟踪到，按「未见过」重新 `backproject`。
5. **重建图**：
   - Symbols：`x(k)` / `l(j)`（`j` 由稳定 `LandmarkId` 映射）
   - 只有窗口内观测数 `≥ min_landmark_observations` 的 landmark 入图。单次观测的点
     有 3 个测量对 3 个未知量，精确可解，对位姿零信息，只会把变量数从 10 个 pose
     撑到几百。
   - 每个入图观测：`GenericStereoFactor<Pose3,Point3>` + 共享 `Cal3_S2Stereo`
     + `body_P_sensor`，噪声模型为 Huber-robust 的各向同性 1 px
   - 最老帧：`PriorFactor<Pose3>`（强先验，均值 = 该帧当前估计）
6. **`LevenbergMarquardtOptimizer`**。
7. **提交**：仅当 LM 正常结束才把结果写回窗口 pose 与 landmark。抛
   `IndeterminantLinearSystemException` 等异常时丢弃候选帧，内部状态保持
   调用前的样子——每步重建图的设计让这一步天然是事务性的，不会毒化后续帧。
8. **返回**最新帧 `VioEstimate` + 诊断。

### 4.3 观测到 `StereoPoint2` 的换算

GTSAM 的 `StereoCamera::project` 给出 `uL − uR = fx·b / Z`。前端在
`phad/frontend/stereo_tracker.cpp` 的定义一致：

```cpp
const double disparity = static_cast<double>( left_pts[ index ].x -
                                              right_pts[ index ].x );
// ...
const double depth_m = calibration.fxPixels() * calibration.baselineM() /
                       disparity;
```

因此

```text
StereoPoint2( uL = left_pixel.x(),
              uR = left_pixel.x() - disparity_px,
              v  = left_pixel.y() )
```

右目行坐标在校正后与左目对齐，前端已用 `max_epipolar_px` 门限过，故只传左目的
`v`。这是整个 slice 里符号错误最容易藏身的一行，配 §6.1 的往返单测。

### 4.4 标定映射

从 `RectifiedStereoCalibration` 构造 `Cal3_S2Stereo(fx, fy, s = 0, cx, cy, baseline)`。  
`body_P_sensor` 取同一个对象的 `T_B_left_rectified()`，理由见 §2.1。

### 4.5 连通性退化

若新帧与窗口内已有 landmark 的共视数很低，它的位姿就欠约束；共视为 0 时完全自由，
因为它自己的新 landmark 恰好被自己的观测唯一确定，对位姿零信息。LM 会把它留在初值
上并报告一个很小的 error，即一次静默的假成功。规则：

- `num_shared` 永远进诊断与 probe CSV；
- `0 < num_shared < min_shared_landmarks` → 仍然优化，置 `low_connectivity`；
- `num_shared == 0` → `kRejected`，理由为连通性；此时任何输出都是虚构。

## 5. 错误与诊断

| `UpdateStatus` | 含义 |
|---|---|
| `kOk` | LM 成功，带 `T_W_B` |
| `kRejected` | 输入/合同非法（空观测、坏视差、时间戳倒退），或 `num_shared == 0` |
| `kFailed` | 优化异常或不可接受的失败；附原因字符串 |

约束：禁止用 identity / 上一帧冒充 `kOk`。

### 5.1 拒帧后的状态机

`kRejected` 与 `kFailed` 走同一条恢复路径，语义必须写死，否则「下一帧的初值是谁」
和「轨迹是否留洞」会散落到 app 里：

- 该帧**不进窗口**；窗口、landmark 表、最近两个已接受位姿全部保持调用前的样子；
- 下一帧的恒速外推使用最近两个**已接受**帧，跳过被拒帧；
- 不写轨迹点，`estimate` 为 `nullopt`；
- probe CSV 照常写一行，`status` 列区分，便于事后统计；
- 失败不累积：估计器没有「已损坏」终态，下一帧照常尝试。

因此 roadmap 出口里的「完整轨迹文件」定义为：轨迹覆盖序列的完整时间跨度，写出的
位姿数等于 `kOk` 帧数，且被拒帧数与原因分布被显式报告。**基线记录必须带上拒帧
比例**，否则「ATE 很好」可能只是因为丢掉了难的那些帧。

**Cheirality**：factor 默认不 throw；计数 `num_cheirality`；优化后丢弃仍在相机后方的
landmark（下一步重建图时它自然不再入图），不中止序列。单测覆盖显式报告。

**Probe 诊断 CSV（列）**  
`timestamp_ns, status, num_obs, num_landmarks, num_shared, low_connectivity,
window_size, prior_key, reproj_rms_before_px, reproj_rms_after_px, num_cheirality,
lm_iterations, max_window_pose_shift_m`

**按 id 汇总 track**：诊断结构或测试 helper 能按 `LandmarkId` 列出完整观测时间戳。

### 5.2 输出语义

每步只导出最新帧的位姿。窗口内的旧帧会被后续优化继续修正，但已写出的轨迹点不回改
——这是 odometry 式输出。另一种做法（每步重写最后 N 个位姿）会给出不同的 ATE，选前者
是为了让 M2.3 的数字与 M6 fixed-lag 之后可比。`max_window_pose_shift_m` 记录旧帧被
改动的幅度，用来判断这个选择带来多大损失；该值若很大，说明窗口内信息还在剧烈重排，
是 M3 的输入信号。

## 6. 测试与验收

### 6.1 单元（合成，`-L unit`）

1. `StereoPoint2` 往返：已知深度的世界点 → `project` → `backproject` 回到原点，
   并断言 `uL − uR = fx·b/Z`。锁住 §4.3 的符号约定。
2. **外参是 body 而非左目**：构造 `R1 ≠ I`、`t_B_left ≠ 0` 的合成标定，生成一段
   带旋转的运动，断言恢复出的是 `T_W_B` 而不是 `T_W_leftcam`。这是 §2.1 那个
   bug 的回归测试。
3. 扰动初值后 pose / landmark 误差下降。
4. 优化后重投影 RMS 下降（`reproj_rms_after_px < reproj_rms_before_px`）。
5. Behind-camera → `num_cheirality` 计数正确，序列不中止。
6. **错误外参可被诊断发现**：用外参 A 生成观测、构造时喂外参 B，断言优化后
   `reproj_rms_after_px` 仍高于阈值且位姿误差显著。
   注意错误外参**不会**返回 `kFailed`——它不违反任何合同，只产出貌似合理但错的
   轨迹，所以判据是残差信号而不是状态码。
7. 连通性：构造与窗口零共视的一帧，断言 `kRejected` 且窗口状态不变。
8. Landmark 入图门限：窗口内只被观测一次的 id 不出现在图里。
9. 拒帧恢复：一次 `kRejected` 之后，下一帧的恒速外推跳过被拒帧，且结果与该帧
   从未出现过时一致。
10. 按 landmark id 汇总 feature track。
11. 窗口大小与 prior 始终在最老帧；滑出帧不在 Values。
12. Huber 生效：注入一个大幅偏移的观测，断言它对最终位姿的影响显著小于纯高斯
    噪声模型下的影响。

### 6.2 集成出口

- `MH_01_easy`：`phad_stereo_vo_probe` 跑完不崩，写出完整 TUM  
- `phad_traj_eval`：ATE 有限、米级；连同**拒帧比例、`low_connectivity` 帧数、
  重投影 RMS 分布**一起记录为 M2.3 基线，单独一个 ATE 数字不足以支撑 M3 的对比  
- Runner：轨迹形状目视合理（人工）；agent 不擅自弹窗

### 7.1 GTSAM 接入

`find_package(GTSAM 4.3 REQUIRED)`。本机 `/usr/local/lib/cmake/GTSAM` 已有 4.3.0，
`thirdparty/gtsam-4.3a1/` 是它的源码与构建目录但被 gitignore，所以**安装步骤要写进
README**，不能默认别人机器上有。

这是本 slice 时间风险最大的一步，建议单列为第 0 个任务：链接 GTSAM 并跑通一个只
构造 `gtsam::Pose3` 的冒烟测试，再动业务代码。三个已知的坑：

- 仓库对自己的 target 开了 `-Wall -Wextra -Wpedantic -Wconversion -Wsign-conversion`，
  GTSAM 头文件会刷屏。PIMPL 已经把 GTSAM 挡在公开头文件外，因此 `PRIVATE` 链接，
  必要时把它的 include 目录标成 SYSTEM。
- GTSAM 的 Eigen 必须和 `Eigen3::Eigen` 3.4 是同一份。`GTSAMConfig.cmake` 里是
  `find_dependency(Eigen3 REQUIRED)`，正常情况下一致，但 GTSAM 若曾用自带 Eigen
  构建就是 ODR 隐患，冒烟测试要覆盖一次 Eigen 类型的往返。
- 若该 GTSAM 是带 `-march=native` 构建的，跨机器分发会有对齐/ABI 问题；本里程碑
  只在本机跑，记录一笔即可。

### 9.1 已知的遗留风险

- 窗口 10 帧 @ 20 Hz 只跨 0.5 s，运动基线很短；深度主要来自双目而非运动视差。
  若 MH_01 的 ATE 差到不可解释，先调窗口长度再怀疑因子栈。
- 每帧全是关键帧，每步重建约 10 pose × 数百 landmark 的图并做完整 LM。实时率不是
  M2.3 出口（M7 才要求 ≥1x），但若单帧耗时到秒级会拖慢迭代，届时 `Ordering::METIS`
  是第一个开关。
- 噪声与 Huber 的取值没有一手实测依据（见开源对照笔记末尾的 Unverified 一节），
  它们是待标定的起点，不是承诺值。
