# M4.4 VIO bias transition 合同修复设计

日期：2026-08-09
状态：A 已实现并完成 MH_01；合同修复保留，但 M4.4 出口 FAIL
范围：默认 IMU-on estimator 的 bias transition；不改变 keyframe schedule

本文档描述当前约定，不是绝对约束，会随项目开发修订。

## 1. 目标与当前红灯

最终目标不是“IMU 已接入”，而是默认 VIO 在同一轨迹 support 上同时优于 VO：

```text
VIO ATE translation RMSE < VO ATE translation RMSE
VIO RPE translation RMSE < VO RPE translation RMSE
```

`scripts/vio_vo_common_support.py` 对 MH_01 的 exact timestamp intersection 给出稳定
红灯（重复 4 次一致）：

| 指标 | VIO | VO（共同 support） | VIO - VO |
|---|---:|---:|---:|
| poses | 3240 | 3240 | 0 |
| matched | 3218 | 3218 | 0 |
| ATE RMSE / m | 0.122337 | 0.0831874 | +0.0391496 |
| RPE RMSE / m | 0.0229568 | 0.0183341 | +0.0046227 |

因此“VIO 只因少了开头 442 帧而比较吃亏”已被证伪。100-pose 窗口中，
common index `2700..2799` 是稳定强坏窗（ATE/RPE delta
`+0.0212963/+0.0244193 m`），而 `2100..2199` 是少数双指标胜窗
（`-0.0024908/-0.0023701 m`）。

## 2. 事实、推断与证据缺口

### 2.1 已确认事实

1. `PreintegrationCombinedParams` 已用 `imu_acc_rw²`、`imu_gyr_rw²` 设置
   `biasAccCovariance` 与 `biasOmegaCovariance`。
2. 当前每个连续 IMU transition 同时加入：
   - 一个 `gtsam::CombinedImuFactor(Xi, Vi, Xj, Vj, Bi, Bj, pim)`；
   - 一个零增量 `BetweenFactor<ConstantBias>(Bi, Bj, rw·sqrt(dt))`。
3. GTSAM 4.3a1 的官方 header 明确说明 `CombinedImuFactor` 内部以这两个
   covariance 建模 bias random walk；[固定 revision header]
   (https://github.com/borglab/gtsam/blob/2f3e56c0ddbd3a1aa54ed043643b553d26a069f6/gtsam/navigation/CombinedImuFactor.h#L195-L209)。
4. 同一 revision 的实现把 `Between(bias_j, bias_i)` 作为 6 维 `fbias`，与
   9 维 preintegration residual 拼成 15 维 factor residual；[固定 revision
   implementation]
   (https://github.com/borglab/gtsam/blob/2f3e56c0ddbd3a1aa54ed043643b553d26a069f6/gtsam/navigation/CombinedImuFactor.cpp#L185-L248)。
5. 官方 `CombinedImuFactorsExample` 只把 `CombinedImuFactor` 加入图，没有再加入
   bias `BetweenFactor`；[固定 revision example]
   (https://github.com/borglab/gtsam/blob/2f3e56c0ddbd3a1aa54ed043643b553d26a069f6/examples/CombinedImuFactorsExample.cpp#L238-L245)。
6. `scripts/vio_bias_probe.py` 在 estimator `status=ok` rows 上，以 2.5 ms
   tolerance 对齐 EuRoC bias ground truth。32 个 100-pose 桶的相关性为：

   | 两列 | Pearson r |
   |---|---:|
   | ATE delta vs acc bias RMS error | +0.459 |
   | RPE delta vs acc bias RMS error | +0.470 |
   | ATE delta vs gyro bias RMS error | +0.651 |
   | RPE delta vs gyro bias RMS error | +0.552 |

   最坏 RPE 桶 27 的 acc/gyro bias RMS error 分别为
   `0.516948 m/s²`、`0.00515447 rad/s`。
7. 窗口填满后 `prior_key` 基本逐帧推进；当前 batch window 每次丢弃旧图并以旧状态
   重新设头部 pose/velocity/bias priors，没有 marginal factor。

### 2.2 推断

- **高置信**：额外 `BetweenFactor` 重复表达了 `CombinedImuFactor` 已包含的 bias
  evolution；这违反当前 GTSAM 类型合同，应删除。
- **中等置信**：bias 误差是 MH_01 退化的重要伴随量；相关性支持继续沿 bias/state
  路径排障，但不证明单一因果。
- **中等置信**：逐帧移动的 batch window 丢弃旧信息可能继续驱动 bias/state 漂移，
  即使删除重复 factor 也未必足够。

### 2.3 仍缺的证据

- 尚无 A/B run 证明删除重复 factor 会提升精度；重复约束也可能暂时抑制 bias
  漂移，合同修复后指标可能变差。
- 现有 diag 不输出 velocity、factor residual 分解或 marginal covariance，无法把
  bias 漂移唯一归因于初始化、窗口丢信息或视觉/IMU observability。
- 旧 `dbg_*` run 没有可恢复的精确源码差异，不作为本设计证据。

## 3. 已对齐的 A→B 顺序

### A（本次）：去掉重复 bias transition factor

只保留 `CombinedImuFactor` 内部的 bias random-walk 模型。删除 estimator 中额外
`BetweenFactor<ConstantBias>`、对应 sigma 构造与无用 include。

这一刀不增加 feature flag。它是单一类型合同修复，不保留旧路径，也不提供
runtime fallback。

### B（A 不足时）：先分离 PIM prediction 与 posterior

A 未使 VIO 同时优于 VO后，不直接实现 fixed-lag。当前窗口填满后 `prior_key` 几乎
逐帧推进，缺少 contemporaneous no-advance control；现有相关性不足以证明
`rebuild-and-reprior` 是因果。B 先以只读 sidecar 记录同 timestamp 的 one-step PIM
prediction 与最终 posterior state：

- prediction 已先偏离 GT：转 initialization / IMU model；
- prediction 较好、posterior correction 持续拉远：转视觉 factor / window；
- posterior 退化与 prior-target movement 呈独立异常签名：才设计 fixed-lag / 显式
  marginalization。

B 的接口和验收另见 `m4.4-vio-state-probe-design.md`。

## 4. 模块边界

- `phad::estimator` 继续独占 GTSAM 与 IMU factor graph；public PIMPL 接口不变。
- 生产修改只在 `phad/estimator/stereo_vo_estimator.cpp`：每个连续 IMU interval
  对应恰好一个 `CombinedImuFactor`。
- `scripts/vio_vo_common_support.py` 是离线验收门，只比较 exact common timestamps。
- `scripts/vio_bias_probe.py` 是只读诊断工具，只消费 `diag.csv` 与 EuRoC ground
  truth，不反向注入 estimator。
- 不改变 apps composition、keyframe selector、config schema/hash 或 raw artifact
  schema。

## 5. 数据流

```text
raw IMU [ti, tj]
  → PreintegratedCombinedMeasurements(biasHat = Bi)
      params.biasAccCovariance   = imu_acc_rw² I
      params.biasOmegaCovariance = imu_gyr_rw² I
  → CombinedImuFactor(Xi, Vi, Xj, Vj, Bi, Bj)
      residual = [R/p/v preintegration error; bias evolution error]
  → LM batch solve
  → write optimized X/V/B back to window
```

保持不变：头部 X/V/B priors、IMU gap weak priors、preintegration biasHat、视觉
stereo factors、outlier/cheirality 流程和 window eviction。

删除的数据流只有第二份：

```text
Bi,Bj → BetweenFactor(zero bias increment, rw·sqrt(dt))  # 删除
```

## 6. 错误与诊断

- factor 构建仍沿用现有 gap 判断；无有效相邻 IMU state 时不构建
  `CombinedImuFactor`，弱 prior 行为不变。
- `vio_vo_common_support.py --assert-vio-better`：合同/输入错误返回 2；VIO 未双指标
  胜出返回 1；通过返回 0。
- `vio_bias_probe.py`：schema、非有限数、非单调时间或 ground-truth span 内超过
  tolerance 返回 2；span 外 estimator rows 显式计为 `dropped_outside_gt`。
- dirty 实验只称 probe evidence，不称正式 baseline；不隐藏失败 run。

### 7.2 MH_01 预注册门

固定 control：

```text

VO   run: b9da3bf_dirty/imuoff_regression_a5a403b0
```

- 完整性硬门：`segments/reanchors/failed = 1/0/0`；completion/coverage 不低于
  当前 VIO control；
- 机制门：重新生成 bias probe，报告全程与坏窗 2700 的 bias error，不预设它必降；
- A 可保留门：共同 support 的 ATE 与 RPE 都严格优于当前 VIO control，且完整性门
  通过；

  `< 0.0183341 m`，即同时严格优于 VO。

若 A 改善但未达里程碑出口，保留 A 并进入 B 设计；若任一质量指标恶化或完整性退化，
记录失败并用 `apply_patch` 撤销 A 的生产改动，再进入 B，不用调参掩盖结果。
