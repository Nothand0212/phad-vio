## 1. 一句话结论

M3.2 基线里 4 条序列的低 completion **不是精度问题，而是一个吸收态**：估计器
一旦因 `num_shared == 0` 拒帧，窗口与 landmark 表被事务回滚冻结，而前端重新
检测会发放全新 `LandmarkId`，于是之后每一帧都 `num_shared == 0`，永久拒帧直到
序列结束。V1_03 上**一帧**异常废掉了随后 1906 帧。

## 3. 机制

拒帧发生在 `update()` 的早退分支：

```515:526:phad/estimator/stereo_vo_estimator.cpp
    if ( m_impl->initialized && num_shared == 0 )
    {
      result.status  = UpdateStatus::kRejected;
      result.message = "zero shared landmarks with window";
```

该分支之后（以及所有 `kRejected` / `kFailed` 路径）走事务回滚，`window`、
`landmarks_W`、`last_accepted_T_W_B` 全部还原。回滚本身是对的——问题在于
**没有任何路径能让窗口重新对上新的 id 空间**：

1. 前端在跟踪断裂后由 `detectNewTracks` 补点，`next_id++` 单调递增、永不复用；
2. 估计器的 `landmarks_W` 只含断裂前的旧 id；
3. `num_shared` 是两者的交集大小，交集一旦为空就永远为空；
4. 于是 `initialized && num_shared == 0` 恒成立 → 吸收态。

## 5. 右目匹配失败是全局常态，不是 MH_02 专属

`phad_stereo_frontend_probe` 全序列汇总对照：

| 指标 | MH_01_easy（ATE 0.150 m） | MH_02_easy（completion 0.131） |
|---|---:|---:|
| `mean_tracks` | 199.9 | 199.96 |
| `min_tracks` | — | 183 |
| `valid_rate` | 0.732 | 0.721 |
| `no_right_match_rate` | 0.246 | 0.259 |
| `invalid_disparity_rate` | 0.0217 | 0.0206 |
| `epipolar_median_px` | 0.120 | 0.111 |
| `epipolar_p95_px` | 7.96 | 11.40 |

两条序列几乎一致：**约 25% 的 track 每帧都拿不到右目匹配**，这是全局常态，
MH_01 在这个基础上仍能跑出 0.150 m。因此右目匹配加固是独立的精度/鲁棒性切片，
**不是崩溃主因**；崩溃主因是第 3 节的吸收态。

## 6. `matchRight` 的种子中毒

坏视差在 epipolar 门限**之前**就被写回下一帧的搜索种子：

```255:265:phad/frontend/stereo_tracker.cpp
        const double disparity = static_cast<double>( left_pts[ index ].x -
                                                      right_pts[ index ].x );
        track.last_disp_px =
            static_cast<float>( disparity );  // seed next frame even if rejected

        if ( abs_dy > options.max_epipolar_px )
        {
          track.status = StereoStatus::kInvalidDisparity;
```

左右 LK 收敛到错行（`abs_dy` 30–68 px）时只要通过了 FB 检查，这个明显错误的
视差就成为下一帧的种子，形成自维持的失败。这与 MH_02 该段 `no_right_match`
长时间高位吻合，但因果方向尚未单独验证（属 Slice ② 的待验项）。

另外，`matchRight` 对**新检测**的 track 用 `last_disp_px = 0` 作种子，即在右图
同一像素起搜；EuRoC 上典型视差 10–50 px，全靠金字塔层数兜。

## 8. 给设计的输入

1. **必须去掉 `num_shared == 0` 的拒帧门**，改为「重叠断裂即以新 id 重建窗口」；
   固定窗口 + 最老帧硬 prior 的架构下，这必然等价于把新窗口的 prior 打在最后一个
   被接受的位姿上（re-anchor）。
2. **初始化与 re-anchor 共用一个最小观测数门限**；不满足时该帧 `kRejected`，
   不写位姿，让 `completion_rate` 诚实。
3. 断裂点必须可观测（哪一帧、第几段、累计几次），否则 bench 表上分不清
   「算法变好」与「re-anchor 变多」。
4. 右目匹配（25% 失败率、种子中毒、新 track 零种子）与单帧 LK 全灭属后续切片，
   目标是**减少 re-anchor 次数**与提高每帧观测数，不是修崩溃。
