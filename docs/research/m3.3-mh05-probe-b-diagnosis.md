## 4. 机制链（探针 B 证实）

```text
i=425 大剔 32 + reopt + skip-drop
    → 前端保留 culled tracks（drops_skipped=1）
    → lifetime_culled 记入 32 ids
i=426+  zombie_track_n=32 且 rejected_block_n 高
    → 同一批 id 不能复生入图，却仍占前端 track
    → shared / 可 PnP 集合相对 ④b 变稀（自 427）
i=426 已 shift≈5.3 m；429 lm=100 + shift≈2.94 → 误差平台锁 ~3 m
    → 之后 reproj 很低（自洽漂移），外点族无杠杆
```

这把 post4f §4 的「疑似 zombie×block、未直接证实」升级为 **已证实的主机制**。

## 6. 结论（出口）

### 唯一推荐下一刀

**skip-drop × block 交互修复：大剔 `drops_skipped` 之后，对被 cull 的
track id 做精确 drop（消除长期 zombie），保留 `block_culled_rebirth` 与
skip-drop 的「同帧不连锁抽空」意图。**

落地语义（机制片再对齐细节，本笔记只定刀口）：

1. i=425 仍可 skip 同帧 `dropTracks`（保住 ④f 相对 ④e 的软门收益）；
2. **不得**让 32 个 culled id 以 zombie 身份跨数十帧占前端；
   随后帧（或同帧末、或再下一帧）对**本批** `culled_ids` 精确 drop；
3. **不**整批关掉 `block_culled_rebirth`，**不**整批关掉 skip-drop，
   **不**把已 cull landmark 重新放回图（那是关 block，否决作首选）。

验收指向：MH_05 上 i=426+ `zombie_track_n` 对 425 cull 集应迅速归零；
427–429 `shared` / PnP 连通相对 ④b 缺口应收窄；ATE 在不回归 ④e 高 RMS
平台的前提下继续压。机制片编号（④g+）按此刀开口，不占探针片号。

### 否决项（本轮不打）

| 项 | 原因 |
|---|---|
| 单独「末轮去 Huber」 | 429 残差已低；无遮罩平台 |
| 单独观测级 / max 判据 | 无高 RMS/`culled≈0` 平台 |
| 再拧 `max_outlier_reopts` | 无第二次 `culled≥4` |
| 关掉整个 `block_culled_rebirth` | 会撤销 ④c 防复生；证据要的是去 zombie，不是放坏点 |
| 关掉整个 skip-drop | 会回归 ④e 灾难平台；要修的是交互，不是撤软门 |
| 窗口大位移门 / 重种子作首选 | 截 429 症状；根在 425→426 zombie×block |
| 直接开 Slice ⑤ | 与 M4 耦合；本债已有机制出口 |
| 无新证据改默认阈值蒙混 &lt;1 m | 与前序债纪律一致 |
