## 1. 目标

引入关键帧选择策略，使 estimator 滑窗只包含稀疏的关键帧（而非所有帧），从而：
- 延长窗口时间跨度（10 个关键帧 ≈ 1.5–2.5s vs 当前 10 帧 ≈ 0.5s），给 landmark
  更多帧积累观测
- 直接缓解 V1_03/V2_02 的前端重置问题——窗口内保留更久的关键帧意味着单帧 track
  丢失不再导致 `shared=0`
- 为 M4 IMU 预积分预备帧边界（关键帧 = preintegration boundary）

## 2. 已对齐决策

| 决策点 | 结论 |
|---|---|
| 关键帧选择标准 | 组合：视差 > 30 px OR track 存活率 < 60% OR 距上个关键帧 > 0.5s |
| 非关键帧处理 | Track-only：PnP 估计位姿，不进窗口 BA，不 seed 新 landmark |
| IMU 预积分边界 | 关键帧 = 边界；非关键帧 IMU data 在 M4 merge 进上一段（VINS-Fusion） |
| 窗口管理 | `window_size=10` 不变，但窗口只含关键帧 |
| 前置关键帧数 | 前 2 帧总是关键帧（初始化窗口） |

## 3. 模块边界

关键帧选择逻辑放在 **apps/session 层**（`offline_vo_session`），不在 estimator。

```
┌──────────────────────────────────────┐
│        apps/offline_vo_session       │
│                                      │
│  StereoTracker ──→ FrameTracks       │
│       │                              │
│       ▼                              │
│  isKeyframe(last_kf, current) ──→？  │
│       │                              │
│    ┌──┴──┐                           │
│   YES    NO                          │
│    │      │                          │
│    ▼      ▼                          │
│  estimator   const-velocity PnP      │
│  ::update()  (track-only)            │
│    │      │                          │
│    ▼      ▼                          │
│  window  prev_accepted_T_W_B update  │
│                                      │
└──────────────────────────────────────┘
```

职责划分：

| 层 | 职责 |
|---|---|
| session | 维护 `last_keyframe_tracks`、计算视差/track 率、决定是否关键帧 |
| estimator | 不变：`update()` 接口不变。窗口管理不变（仍 `window.push_back` + `pop_front`），只是推入的频率由 session 控制 |
| frontend | 不变：每帧产生 `FrameTracks` |

estimator 改动最小——只需新增一个 public method 用于非关键帧的 track-only 处理
（或复用 `update()` 的一个 mode flag），不改变 `buildGraph`、`tryPnpInit`、cull、
reanchor 等核心逻辑。

### 为什么不在 estimator 内做关键帧选择

- estimator 看不到前端 track 的像素级信息（视差计算需要像素坐标，当前
  `KeyframeMeasurement` 只有 `StereoObservation`）
- 关键帧选择的输入（上一关键帧的 track 集合、当前帧的像素坐标）天然在 session/
  frontend 侧
- VINS-Fusion 和 ORB-SLAM3 都在 tracking 层决策关键帧
- 保持 estimator 的单一职责——给定 measurement 和 mode flag，优化并返回位姿

## 4. 关键帧选择算法

### 4.1 输入的维护

session 维护：

```
last_keyframe_tracks:  map<LandmarkId, pixel_coord>  ← 上一关键帧的左目像素
last_keyframe_timestamp: Timestamp
```

每次关键帧被送入 estimator 后，session 保存其 `FrameTracks` 的左目像素坐标。

### 4.2 判断逻辑

```
function isKeyframe(current_tracks, last_kf_tracks, last_kf_ts, current_ts):
    // 规则 1：前 2 帧总是关键帧
    if total_keyframes < 2: return true

    // 规则 2：时间兜底（> 0.5s = 10 帧 @ 20Hz）
    if (current_ts - last_kf_ts) > 0.5s: return true

    // 规则 3：track 存活率
    common_ids = intersect(current_tracks.ids, last_kf_tracks.ids)
    if len(common_ids) < 0.6 * len(last_kf_tracks): return true

    // 规则 4：平均视差
    parallax_sum = 0
    for id in common_ids:
        p_cur = current_tracks.left_pixel[id]
        p_kf  = last_kf_tracks.left_pixel[id]
        parallax_sum += ||p_cur - p_kf||
    avg_parallax = parallax_sum / len(common_ids)
    if avg_parallax > 30.0 px: return true

    return false  // 非关键帧
```

### 4.3 阈值来源

| 参数 | 值 | 来源 |
|---|---|---|
| 视差阈值 | 30 px | VINS-Fusion 10 px × 放宽 3×（纯 VO 不含 IMU，需更多关键帧补偿无惯性预测） |
| Track 存活率 | 60% | ORB-SLAM3 refRatio 0.75 的放宽版 |
| 时间兜底 | 0.5s | ORB-SLAM3 / VINS-Fusion 共识值 |
| 前置关键帧数 | 2 | VINS-Fusion 前 2 帧策略 |

阈值不进 `config_hash`——作为 session 的内部常量，不作为 estimator 的配置项。
后续通过 `phad_vo_bench` 全表效果决定是否暴露为可配置参数。

## 5. 非关键帧的 Track-Only 处理

### 5.1 接口

在 estimator 新增一个轻量 public method：

```cpp
// 仅做 PnP 位姿估计 + 更新 last/prev_accepted，不修改窗口/landmark/graph。
// 诊断字段只填 segment_id、pnp_success/inliers、num_shared。
VioUpdateResult trackOnly(const KeyframeMeasurement& measurement);
```

`trackOnly()` 的内部逻辑是 `update()` 的一个子集：
1. 与 landmarks_W 计算 `num_shared`
2. 若有足够 shared，运行 `tryPnpInit()` 估计位姿
3. 若 PnP 成功，更新 `last_accepted_T_W_B` / `prev_accepted_T_W_B`
4. 若 PnP 失败，退回恒速预测（仍更新 last/prev，保持链不断）
5. **不** modify `window`、`landmarks_W`、`track_times`、`culled_ids_`
6. **不** run graph optimization
7. 返回值不带 `estimate` 字段（非关键帧不产出轨迹位姿）

### 5.2 轨迹输出

非关键帧的位姿**不写** `est.tum`。roadmap 已预警「⑤ 会改 `est.tum` 输出语义」——
est.tum 现在只输出关键帧的优化后位姿，不再逐帧输出。这意味着 est.tum 的行数会
从 `total_image_frames` 变为 `total_keyframes`。

评估脚本（`phad_traj_eval`）的时间关联以 nearest-neighbor 匹配，关键帧位姿与
真值之间的时间差可能略大（平均 0.1s vs 当前 0.025s），但对 ATE/RPE 的影响在
统计噪声范围内。

如果需要非关键帧的位姿用于诊断，可在 diag.csv 增加 `track_only_pnp_success` 和
`track_only_pose_*` 列，但不进标准输出。

### 5.3 非关键帧对 reanchor 的影响

非关键帧也可能遇到 `shared=0`（前端重置发生在一串非关键帧之中）。处理方式：

- 如果非关键帧 `shared=0` → 标记为 `kRejected`，不更新 last/prev
- 直到下一个关键帧出现，如果该关键帧 `shared=0` → 触发 reanchor（现有逻辑）
- 如果非关键帧持续 rejected，恒速预测链路断掉，下一个关键帧的 guess 可能不准
  → PnP 需要承担 init 角色

这种"非关键帧 rejected 但关键帧 reanchor"的模式实际上比当前"每帧都可能 reanchor"
更优——减少了不必要的 reanchor，因为单帧 track 丢失在关键帧之前就会被"过渡"掉。

## 6. 与 M4 IMU 的耦合

### 6.1 关键帧 → IMU 预积分边界

```
                    keyframe_i               keyframe_{i+1}
                         │                         │
  ────┬─────┬─────┬─────┼─────┬─────┬─────┬─────┼────
      │                   │                   │
   non-kf               non-kf              non-kf
      │                   │                   │
      └─ IMU merge ──────┴─ IMU merge ────────┘
        进上段预积分        进上段预积分
```

预积分 `PreintegratedCombinedMeasurements` 在两个相邻关键帧之间。非关键帧的 IMU
数据通过 `push_back()` merge 进当前预积分。

### 6.2 M4 需要改动的地方

当 M4 加入 IMU 时：
1. `StereoPairSynchronizer` 开始产出 `StereoImuPacket`（而非 `StereoFrame`）
2. session 将每帧的 IMU buffer 传给 estimator
3. 关键帧时：estimator 构造新的 `PreintegratedCombinedMeasurements`，插入
   `ImuFactor`
4. 非关键帧时：IMU 数据 merge 进当前预积分（与 VINS-Fusion `slideWindow` 逻辑相同）
5. 以上改动集中在 session + estimator，不涉及关键帧选择逻辑本身

纯 VO 阶段不实现任何 IMU 代码——只在关键帧决策中预留语义边界。

## 7. 错误与诊断

### 7.1 新增诊断字段

在 `diag.csv` 新增 1 列：

| 列 | 含义 |
|---|---|
| `is_keyframe` | 1 = 关键帧（进 estimator window），0 = track-only 非关键帧 |

非关键帧在 diag.csv 中仍有行，但 `status` = `ok`（track-only）或 `rejected`（PnP失败）。
非关键帧的 `reproj_rms_*` 等优化相关列填 0。

`summary.json` 新增：

| 字段 | 含义 |
|---|---|
| `total_keyframes` | 关键帧总数 |
| `total_track_only_frames` | 非关键帧（track-only）总数 |

### 7.2 关键帧选择的诊断日志

首次运行新关键帧策略时，session 输出一行 info：

```
[info] keyframe selection: parallax=30.0px track_ratio=0.6 max_interval=0.5s
```

每帧不输出关键帧决策日志（避免刷屏）。

## 9. 不做

- 不修改 `estimator::update()` 的内部逻辑（PnP、cull、reopt、cheirality、reanchor）
- 不改变 config hash（关键帧阈值不进 flattenConfig）
- 不实现 IMU 预积分代码
- 不移除或关闭 `drop_culled_tracks`/`skip_drop_min_culled`/`zombie_drop_age`/
  `block_culled_rebirth`

- 不做关键帧剔除（keyframe culling）——那是 M6 边缘化后才考虑的
