## 0. 摘要

V1_02 的 ATE 轨迹 `0.768 → 2.617 → 2.026 → 0.522` 的因果链已用数据验证并**修正**:

- **触发**: V1_02 有两段快速旋转(原始 IMU |gyro| 峰值 **2.47 rad/s**,p95=1.12),
  GT state 四元数平滑后只剩 0.65 rad/s——**必须用 raw IMU 才能看到真实强度**。
  V1_01 峰值 0.94 rad/s,从未超过 **~1.0 rad/s 临界值**(57°/s)。
- **机制(修正后)**: 快旋转段 → ⑤c 前端(quality 0.01 / pyramid 3 / 无 CLAHE /
  无中值流 / 无 F-RANSAC)track ID 大规模轮换 → 关键帧更新开始 `kFailed`(BA 阶段,
  回滚事务)→ **新 GFTT ID 永远无法入图** → map overlap 衰减(110→1)→ 失败自持
  (88-141 帧)→ accepted 链冻结 → re-anchor 锚 = 冻结链的 CV 外推(陈旧)→
  新 segment 永久偏移,BA 局部收敛无法修复。
- **原 §6 假说(非关键帧 PnP 失败 → CV 链污染)对 V1_02 不成立**: 非关键帧 PnP
  失败仅 15 帧(0.9%),157 个失败帧**全部是关键帧**。原假说来自 V2_02(corridor,
  d94f57b 时代代码),两条链不同。
- **Level B 贡献矩阵**: CLAHE(0.522→2.308)≫ pyramid 4(→1.832) ≈ quality 0.003
  (→1.632) ≈ 中值流(→0.917) ≈ 机制组 > F-RANSAC(→0.577,可忽略)。**单项关掉
  任何一个都会在第二旋转段失败**;只有全开配置两个旋转段都存活。
- **glue 通道独立贡献**: 同样的 ⑤c 前端,glue 树(2.617→1.498,−43% ATE,
  re-anchors 2→1);glue + ⑥ 前端 = 0.522。

### 1.3 四个断言的判定

**断言 1(非关键帧 PnP 失败触发链)—— ❌ 否决**

⑤c V1_02: 非关键帧 `pnp_success=0` 仅 **15 帧(0.9%)**;157 个 failed 帧
**全部是关键帧**(KF 内 failed=157,非 KF 内 0)。非关键帧只有 10 帧 rejected
(⑤b gate: `num_shared < min_pnp_inliers`)。真实触发是**关键帧更新失败**:

- 失败段 1: frames 597-737(t≈29.9-36.9s),num_shared 110→1,obs 稳定 115-145
- 失败段 2: frames 880-895(t≈44.0-44.8s),num_shared 116→2
- 全部失败帧 `is_keyframe=1`。原因:KeyframeSelector 的 Rule 1b(obs<10)和
  Rule 3(survival<60%)在 track 衰减时**强制每帧为关键帧**——快旋转段 30px
  视差规则本身几乎不触发(旋转补偿后视差≈0),是"track 衰减 → 强制 KF"。

**断言 2(reproj RMS 在 PnP 失败段递增)—— ❌ 否决**

16 个 PnP 失败段中仅 2 段 RMS > 段前 1.5×(0.54→0.97px 量级)。failed 帧
`reproj_rms_after_cull_px=0`(不进诊断)。没有 reproj 散开信号——失败不是
"guess 漂移导致重投影散开",而是**优化器级失败**(见 §1.4)。

**断言 3(re-anchor 锚陈旧 → 永久偏移)—— ⚠️ 修正支持**

- 支持: re-anchor 锚 = `poseInitialValue()` = `T_prev * (T_prevprev⁻¹ * T_prev)`
  (CV 外推),而失败帧全部事务回滚,**accepted 链冻结 141 帧(7.1s,GT 位移 ~7m)**
  后 CV 外推必然陈旧。E0 实验中 est.tum 在 re-anchor 前有 7.1s 的轨迹断档
  (1461 点=仅 accepted 帧,失败窗口无输出,最大缺口 7.100s ≈ 141×0.05s;
  冻结发生在 estimator 内部的 last/prev accepted 链,不是输出 hold)。
- 否决部分: "起始 RMS 高、BA 硬扯"——重锚后 rms 正常收敛(0.29→0.5px),
  num_shared 立即恢复 100+。偏移来自 anchor 的绝对位姿错误,BA 在偏的锚上
  正常局部收敛,偏移不可观测、无法修复。

**断言 4(V1_01 无 re-anchor 无信号)—— ✅ 支持(附修正)**

V1_01 ⑤c: failed=0, reanchors=0,无 num_shared 衰减段,PnP 失败段最长 9 帧。
但 V1_01 ⑤c 的 ATE 也退化(0.173→0.514)——**这是另一条更轻的链**: 前端质量
退化(无失败、无 re-anchor),⑥ 前端把它修到 0.092(比 baseline 还好)。
V1_01 的退化与 re-anchor 机制无关。

**A7(baseline 无失败信号)—— ✅ 支持**

baseline: failed=0, reanchors=0,segments=1。baseline 的 `pnp_success=0` 也有
146 帧(8.5%,启动段+分散短段)——**PnP 失败本身不致命**。关键差异:
baseline 每帧成功 → 前端 churn 的新 ID 每帧入图 → map 不塌;
⑤c 一旦出现第一个失败 → 回滚 → 新 ID 永远进不了图 → 失败自持。
(baseline 的 pnp=0 帧不进 BA 的机制与 ⑤c 不同:baseline 全关键帧无 eviction。)

### 1.4 失败机制(代码路径)

⑤c 的 `kFailed` 路径(仅关键帧走 BA):
`non-finite pose initial value`(2 处)→ LM optimizer `IndeterminantLinearSystemException`
/ 其它异常 → `missing window pose` / `non-finite optimized pose` / `non-finite landmark`。

失败段内 pnp 常成功(pnp=1)且 obs 稳定 → 失败发生在 BA 阶段。最可能的路径:
窗口图随 map overlap 衰减而病态 → LM 奇异 → kFailed → 回滚。确切异常消息
未记录在 diag.csv 中(待验证,见 §7 未决问题)。

## 2. 旋转临界条件(V1_01 vs V1_02)

### 2.1 数据: 必须用 raw IMU,不能用 GT state

| 指标 | V1_01 | V1_02 |
|---|---:|---:|
| GT state 四元数差分 | max 0.65 rad/s | max 0.65 rad/s |
| **raw IMU |gyro|** | **max 0.94, p99=0.73** | **max 2.47, p99=1.42** |
| > 1.0 rad/s 采样 | 0 (0.0%) | 1716 (10.0%) |
| > 1.5 rad/s 采样 | 0 | 103 |
| 每秒峰值 top | 0.94 | 2.47 / 1.82 / 1.51 |

EuRoC 官方 GT state 的 200Hz 四元数是平滑+量化的(每 5ms 采样旋转 ~1e-4 rad,
低于量化噪声,中位数=0),**完全掩盖了 V1_02 的快速旋转**。原始 IMU 陀螺
(t=30.5-31.5s 峰值 1.8-2.47 rad/s;t=40-44.5s 持续 1.0-1.5 rad/s)才是真实输入。

### 2.2 临界阈值

- **|gyro| > ~1.0 rad/s(57°/s)是 ⑤c 前端的失败临界**: V1_01 从不超
  (0 失败、0 re-anchor);V1_02 两段失败时间与 >1.0 rad/s 时段吻合
  (失败段 1: t≈29.9s 起,恰在 1.26 rad/s 升速段;失败段 2: t≈42.5-44.8s 持续段)。
- V1_02 两段的失败表现不同: 段 1 是尖峰(2.47 rad/s,0.5-1s)加上之后的
  缓降——⑤c 在尖峰前就开始失败;段 2 是持续 3-4s 的 1.0-1.5 rad/s。
- ⑥ 前端能扛住段 1 的尖峰(0 失败),但在段 2 持续旋转仍失败(19 帧,855-873);
  只有全开配置(⑦最终)两段都存活。

### 2.3 对"纯 stereo VO 在 V1 上的天花板"的定量说明

前端能力边界: 在 ~1.0 rad/s 以上,LK 跟踪 + 立体匹配对 track 存活的保持能力
成为瓶颈;此时**零视差悬挂(glue)与 track 存活数量**比"跟踪精度"更关键。
>1.0 rad/s 时像素运动 ~1.5°/帧 + 平移混合,3 层金字塔 + 无初始猜的 LK
不足以维持 ID 稳定。

### 3.2 结论

1. **单项贡献排序(V1_02)**:
   **CLAHE(2.308)≫ pyramid 4(1.832) ≈ quality 0.003(1.632) ≈ 机制组
   (E7 1.637) ≈ 中值流(0.917) > F-RANSAC(0.577,可忽略)**。
2. **生存关键项 = CLAHE / quality 0.003 / pyramid 4**: 关掉任何一个 → 第二旋转段
   (持续 1.0-1.5 rad/s)失败 + re-anchor。CLAHE 最重: 关掉后连第一段(2.47 尖峰)
   也失败(138 帧),且在 t≈17.4s 出现**单帧突发 churn**(num_shared 152→1,
   obs 稳定——光照/对比度边界处全部 track 重检,CLAHE 的对比度归一化作用)。
3. **中值流是精度项**: 关中值流无失败、无 re-anchor,但 ATE +76%——旋转段
   的 LK 初始猜改善位姿质量,不决定存活。
4. **F-RANSAC 可忽略**: +11%。
5. **非线性交互(E0 vs E1 反转)**: E0(全关,1.498)反而好于 E1(仅关 CLAHE,
   2.308)——"全退"比"单退"少一次 re-anchor。原因: E1 的 quality 0.003+
   pyramid 4 在无 CLAHE 时产生更多 track,churn 面更大;E0 的少而强的 track
   反而更稳。**不能做简单的线性叠加归因**,单项贡献排序仅在同一起点下有效。
6. **glue 通道的独立贡献(跨树分解)**:
   - 真 ⑤c(无 glue)+ ⑤c 前端 = 2.617(157 fail, 2 reanch)
   - glue 树 + ⑤c 前端(E0)= 1.498(141 fail, 1 reanch)
   → **glue 单独回收 −43% ATE、−50% re-anchors**,即便前端照旧。

## 4. 推荐配置

**保持默认(402d1925,即 slice-7 最终定案)**: CLAHE(2.0/16×16) + 中值流 +
F-RANSAC + quality 0.003 + pyramid 4 + glue(悬挂门 1.0m + far-refresh 6.0px)。
理由:

- V1_02 0.522,0 失败,0 re-anchor;MH_01 gate 0.081 ≤ 0.0988 PASS(硬门验证,
  见 slice-7 checkpoint,e13comp 全序列)。
- 任何单项回退都导致 V1_02 旋转段失败或精度退化;F-RANSAC 是唯一可裁项
  (+11%),但裁掉它的收益(每帧一次 F 矩阵 RANSAC 的算力)尚未量化,
  **不建议现在动**——它的算力成本也在 MH 系列的开销里,gate 已过。
- 归因开关(`--no-clahe` 等)保持 CLI-only,不进 config hash,不构成生产配置面。

## 5. 与 ⑦ glue 通道的因果衔接

- glue 通道(零视差悬挂 track + 悬挂距离门 1m + far-return 投影一致性刷新)
  直接作用于本条链的**下游**: 它让 num_shared 在旋转段不再塌到 0——
  悬挂 track 保持 ID 存活,map overlap 不衰减,`overlap_broken` 不触发,
  re-anchor 归零(E_ref failed=0, reanchors=0)。
- 但 glue **不能替代前端**: E0(glue 树 + ⑤c 前端)仍有 141 帧失败、1 次
  re-anchor(ATE 1.498)。glue 只救"零视差但可见"的 track;剧烈旋转段
  (2.47 rad/s)LK 直接丢 track(不可见),glue 无从挂起。**前端(尤其 CLAHE)
  保住 track 可见性,glue 保住 track 存活性**,两者正交互补:
  E0(glue 无前端)= 1.498,前端无 glue(⑥)= 2.026,两者都有 = 0.522。

## 6. 对后续计划的影响

- **pre-M4 可做**:
  1. diag.csv 增加失败消息字段(`result.message`),让 kFailed 路径可观测——
     本报告 §1.4 的"BA 病态"仍是推断(未记录确切异常)。
  2. 旋转段 RPE 审计: 中值流(0.917)与默认(0.522)的差距在旋转段的
     RPE/位姿连续性上,值得用 rpe 分段分析定位(旋转段 vs 平移段)。
  3. 前端算力剖面: F-RANSAC 的帧成本 vs +11% 精度——若预算紧张可裁。
  4. 失败自持段的"新 ID 无法入图"是回滚事务的直接后果——可评估
     "失败帧仍允许 seed 新 landmark(不推进 pose)"的变体(但 ⑦ 已绕开
     该路径,收益有限,低优先级)。
- **留给 M4(IMU)**:
  - >1.0 rad/s 旋转段的 pose 链由 IMU 预积分承载后,旋转段不再依赖
    前端 track 存活维持位姿;V1_02 的 0.522 天花板有望进一步下降。

    存活仍是前端问题,CLAHE 等不变。
- **不做**: 调 quality 0.001/0.005、pyramid 5 等参数微调(根因已明,收益
  由前端机制提供而非参数)。
