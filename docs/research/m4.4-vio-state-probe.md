## 1. 问题与单变量

Combined-only A 纠正了重复 bias transition 合同，但 MH_01 仅改善约
`1.27e-6 m` ATE，仍显著劣于纯 VO。B 不改 estimator 决策，只记录同一 accepted
state 的两条状态：

```text
上一 accepted posterior + 当前完整 IMU interval
  → pre-LM one-step PIM prediction
  → 当前视觉/IMU factor graph + LM
  → final posterior
```

它回答“PIM prediction 已经先错，还是 optimizer correction 把较好的 prediction
拉错”。它不是从 t0 递归到底的 IMU-only trajectory，也不能单独测绝对 gravity tilt。

production delta 仅包括：

- `UpdateDiagnostics::nav_state` Eigen/POD snapshot；
- apps `VioStateProbe` strict CSV writer；
- CLI-only `--vio-state-probe <path>`；
- 离线 `scripts/vio_state_probe.py`。

sidecar 不进入 config/hash，不回写 estimator、keyframe selector、tracker 或主产物。

## 3. 实现与错误合同

- estimator 在 first seed 与 regular `imuPredict` 后、任何本帧 LM 前保存 prediction；
  只在最终 accepted IMU-on transaction 上附加 posterior velocity/state key；
- 42 列 CSV 只写 `status=kOk`，以 `max_digits10` 输出；writer 强校验 pose、finite、
  unit quaternion、IMU interval 以及 timestamp/state key 单调性，并逐行 flush；
- rejected/failed/IMU-off 不写假状态；accepted gap 以
  `prediction_valid=false` 显式保留；
- CLI 与 `--no-imu` 冲突，open/write/flush/schema invariant 失败升级为明确
  session error；
- analyzer 强校验完整 schema；EuRoC ground-truth 范围外 rows 单列计数，不静默
  截断原始 sidecar，不把不足 22 poses 的尾桶伪装成可算 RPE。

  `phad_traj_eval` 构建通过；

## 5. PIM prediction 与 posterior

`phad_traj_eval` 对同一 3218-pose GT support 分别执行 SE(3) alignment；1 秒 RPE
pairs 均为 3198：

| metric | PIM prediction | posterior | posterior − prediction |
|---|---:|---:|---:|
| ATE translation RMSE / m | 0.122469 | 0.122336 | **−0.000133** |
| RPE translation RMSE / m | 0.0235555 | 0.0229567 | **−0.0005988** |

同一 3218 rows 上，posterior 相对 prediction 的 correction RMS：

| correction | RMS |
|---|---:|
| pose translation | `0.001959997 m` |
| pose rotation | `0.03363646 deg` |
| velocity | `0.01001306 m/s` |
| gyro bias | `0.000646981 rad/s` |
| accel bias | `0.005649906 m/s²` |

32 个完整 100-pose buckets 中：

- posterior ATE 优于 prediction：`32/32`；
- posterior RPE 优于 prediction：`31/32`；唯一反例 bucket 30 仅恶化
  `+0.0000221 m`；
- 已知坏窗 bucket 27 的 prediction/posterior ATE 为
  `0.0450692 / 0.0441319 m`，RPE 为 `0.0559517 / 0.0544340 m`；
- 尾桶只有 18 poses，只报告 correction，不计算 ATE/RPE。

每个 bucket 独立 SE(3) 对齐，因此这些数字回答局部 shape/correction，不回答
世界系绝对 roll/pitch 或 gravity direction 是否正确。

## 7. 事实、推断与证据缺口

### 事实

- probe-on 与 A 的主三文件逐字节相同；选刀证据没有改变被测系统；
- PIM prediction 与 posterior 都显著劣于 VO；
- optimizer correction 全局及几乎全部局部桶都在改善 PIM prediction，而不是把
  一个更好的 prediction 拉坏；
- correction 量级远小于 VIO 相对 VO 的约 `3.9 cm` ATE 差距。

### 推断

- **高置信**：不应把 fixed-lag、窗口丢信息或视觉 correction 作为下一刀；B 的
  contemporaneous control 与该方向相反；
- **中高置信**：误差在本帧 LM 前已经存在，下一步应先审计 initialization truth
  与 IMU model（初始 `R/v/bg/ba`、gravity magnitude/direction、静止窗统计）；
- **不能推断**：当前日志尚不能区分初始化绝对 tilt、v0、acc bias、标定/时间或
  noise model 中哪一项是主因。

### 证据缺口

- one-step prediction 每帧都从上一 posterior 出发，不是独立递归 IMU-only control；
- per-bucket SE(3) alignment 会吸收常量姿态 gauge，不能测初始化绝对 gravity tilt；
- 尚未记录通过静止门的 raw mean/std、初始化 `R_W_I0/v0/bg0/ba0/g`，也未与 EuRoC
  t0 ground truth 做同一坐标系对比；
- MH_01 单序列选刀不证明跨序列收益。

## 8. 下一片建议

下一片应是 read-only initialization truth audit：记录最终被采用的静止窗口边界与
raw acc/gyr mean/std、`R_W_I0`、`v0`、`bg0`、`ba0`、gravity magnitude/direction，
并在离线端用 EuRoC t0 ground truth 核验。先让日志区分 `R/v/b/g` 哪个在进入第一条
PIM 前已经错，再设计最小 production fix。

当前不支持直接替换成 online joint alignment，也不支持 fixed-lag；这两者都需要
上述 truth audit 提供新的机制证据后另行设计与对齐。
