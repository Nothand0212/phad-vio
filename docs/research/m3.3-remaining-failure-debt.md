## 0. 修订说明(2026-08-07)

初版(2026-08-05)分析的是 PnP 仲裁 era 的 run(`afe3829/config_773ea011`),
当时的结论是"三条序列根因相同: 前端光流在困难段全丢 → LandmarkId 完全
失配 → reanchor 振荡"。本次按 slice-7 官方 run 重做数据层分析后,该结论
**部分推翻**:

| 初版结论 | 修订后 |
|---|---|
| V2_03 根因是"前端跟踪极限 + 初始 224 帧零 landmark" | **数据侧**: cam1 曝光不足 → 立体 SAD 匹配失败 → disparity=0;cam0 缺 414 帧 → 10Hz 段。前端 track 数量全程正常(obs 127-181),**不是跟踪丢失** |
| V1_03 "72 failed 分 3 簇 / 14 rea / ATE 3.353" | 官方 run 已降到 **6 failed / 5 rea / ATE 4.960**(⑤⑥⑦ 的 glue + 前端收益);残量是算法侧: 6 帧短自持 + re-anchor 锚误差 |
| V2_02 "36 failed / 3 rea / ATE 2.192" | **0 failed / 0 rea / ATE 0.853** — 已清理;残余为精度债(立体观测稀疏) |
| V2_03 "1011 rejected, 52.6%" | 913 rejected(47.5%),841 为 KF(92%)——**rejected 洪泛是 KF 的 seed/re-anchor 门自持,不是非 KF 门** |

关键修正: **"前端跟踪极限"不能解释 V2_03**。obs(左目 track 数)在 rejected
窗口保持 127-181 正常;失效的是 **disparity** 层——`countStereoObservations`
与 `num_shared` 只统计 `disparity_px > 0` 的观测(estimator:855-870),而
cam1 过暗 → `matchRight` 的非归一化 SAD 基本失败。pre-M4 实测(cbb4505,
`num_disparity` 列):启动段 0-152 每帧 200 条 track 中**仅 1-7 条产出
视差**(≈1-3%,非字面 0)→ 无任何单 track 能积累 `min_seed_observations=10`
帧的视差观测 → seed 饿死 → shared=0 → 门拒绝。track 活着,但"立体深度
观测"基本死了。

### 0.1 pre-M4 小片实测(2026-08-07, cbb4505 双路径代码)

链 A/B1 的**候选修复被实测否决**。实现 Census(5×5 窗 24bit Hamming,
matchRight 双路径: SAD 主路径 + Census 兜底, 仅 SAD 被拒时触发)后:

| 配置 | V2_03 ATE | 覆盖 | 锚跳(>5m) | MH_01 ATE |
|---|---:|---:|---:|---:|
| SAD-only(=`enable_census=false`, 与 slice-7 同行为) | **3.6278** | 0.758 | 0 | **0.0810** |
| Census 兜底 on | 7937 | 0.99 | 225(均 236m) | 0.0915(+13%) |

Census 兜底把暗帧视差从 1-7/帧提升到 ~11/帧(启动段累计 1633 vs 296),
但**提升的部分是错误匹配**(暗帧 Hamming 平顶、噪声驱动)——错误视差进
PnP → pose 被污染 → 反复丢跟踪 → 重建锚错 → 全局 ATE 7937m。SAD 在暗帧
"少产视差"反而是保护:估计器只消费健康匹配,重建次数少(10)且锚定正确。

**结论**: 链 A/B1 的匹配器替换路线(NCC/Census)不通。剩余候选:
(a) 帧级曝光归一化(对 cam1 整帧做亮度补偿后仍用 SAD);(b) 接受数据侧
限制(0.758 覆盖, ATE 3.628 已持平 ORB-SLAM3 的 7.0× 差距, 见 §1.5);
(c) 暗帧视差低可信度标记(估计器侧感知, 而非前端强修)。Census 代码保留
(`--tracker-enable-census`), 默认关闭。

### 1.2 机制链 A: 启动段 0-152(153 帧 rejected)

cam1 从第 0 帧就暗(≈57)→ `matchRight` SAD 每帧 200 条 track 中仅 1-7 条
产出视差(≈1-3%, pre-M4 `num_disparity` 实测)→ 无单 track 连续 10 帧
视差观测 → `min_seed_observations` 饿死 → `num_shared`=0 → seed 门拒绝。
i=153 首次 `ok`(re-anchor 帧,shared=0 不设门限),154 起 shared=4-6 缓慢
积累。

**关键证据**: rejected 帧的 `num_obs` = 127-181(**track 数量完全正常**)。
初版"前端无法建立 landmark"错误——前端建立了 track,但只有 ~1-3% 能
产出立体深度。这是**立体匹配层的失效,不是跟踪层的失效**。
**Census 兜底已实测否决(§0.1)**: 强行提升视差数量引入错误匹配,ATE
7937m。

### 1.3 机制链 B: rejected 洪泛(913 帧,841 为 KF)

rejected 连续段: (0-152,153), (696-792,97), (1007-1065,59), (1155-1299,
145), (1503-1554,52), (1600-1611,12), (1627-1920,294)。

- **B1 曝光段**: 696-792 / 1155-1299 / 1627-1920 — cam1 过暗(1.1 表) →
  SAD 全败 → shared=0 → 自持
- **B2 10Hz 缺帧段**: 698-778 / 1154-1249 / 1508-1546 / 1604-1609 等 —
  cam0 帧间隔 0.1s(正常 0.05s)→ 帧间运动翻倍 → LK/SAD 更难收敛
- 两个异常**重叠出现**在同一窗口,机制叠加

**与 V1_02 的关键区别**: V1_02 的 rejected 是**非 KF 门**(`num_shared <
min_pnp_inliers=10`);V2_03 的 rejected **92% 是 KF**(841/913)——KF 只走
seed/re-anchor 路径: shared=0 → overlap_broken → re-anchor → seed 需要
disparity>0 的观测,而 cam1 暗 → seed 空转 → 下一帧 shared 仍为 0 →
rejected。**自持环在立体匹配层,不在地图层**。

### 1.4 机制链 C: failed 40 帧 @536-574 + 576(曝光正常)

- cam0 118-164 / cam1 120-158,亮度正常 → **不是数据问题**
- gyro > 1.0 rad/s 旋转段(与 V1_02 归因同款)→ BA kFailed → 事务回滚 →
  seed 阻塞 → shared 衰减 → 自持 39+1 帧
- 这是 V1_02 链 C 的完整复刻,唯一的算法侧失败簇(40 帧中 40 帧)

### 1.5 外部对照(数据难,对所有系统)

|---|---:|---:|
| ORB-SLAM3(表内其**最差**序列) | 0.521 | 1.0× |

## 2. V1_03(算法侧主靶)

### 2.1 数据干净

cam0=cam1=2149,10Hz 缺帧 **0 帧**,健康段曝光 ±5——**数据侧无异常**。
ATE 4.960 完全由算法侧承担。

### 2.2 6 failed @1320-1325: 短自持

```
i     status  shared  obs   pnp   kf
1318  ok      1       116   0     1
1319  ok      2       135   0     1
1320  failed  2        48   0     1
1321  failed  1       133   0     1
1322  failed  2       138   0     1
1323  failed  1       125   0     1
1324  failed  1       164   0     1
1325  failed  1       173   0     1
1326  ok      0       165   0     1   ← re-anchor
```

- shared=1-2 微小但非零 → PnP 无法求解(pnp=0)→ BA 数值失败 → failed
- obs 48-173 正常 → 又是"track 在、深度观测在衰减"的模式,但这里是
  **地图层衰减**(seed 阻塞),不是立体匹配层
- V1_02 88-141 帧自持的微缩版(6 帧)——程度轻,模式同款

### 2.3 5 次 re-anchor: 4 次瞬时单点 + 1 次后置

| 位置 | 前序共享数 | 类型 |
|---|---:|---|
| i=243 | 26-48(健康) | **瞬时单点**(shared 40→0) |
| i=330 | 41-44(健康)→ 3 帧 rejected | 短簇 |
| i=1326 | 6 failed 簇之后 | **后置**(失败驱动) |
| i=1344 | 59-88(健康) | **瞬时单点** |
| i=2031 | 58-74(健康) | **瞬时单点** |

seg3 仅 18 帧(i=1326-1343)——re-anchor 后来不及积累又触发下一次。
re-anchor 锚 = CV 外推(基于回滚冻结的 last/prev accepted 链),一旦锚偏,
新 segment 局部收敛但偏移不可观测(V1_02 归因 §1.5 同款机制)。

### 2.4 ATE 4.960 = 81× ORB-SLAM3(全表最差 ratio)

| 系统 | V1_03 ATE | phad ratio |
|---|---:|---:|
| ORB-SLAM3 | 0.061 | **81×** |
| SVO | 0.070 | 71× |
| OV²SLAM no LC | 0.17 | 29× |
| phad-VIO | 4.960 | — |

V1_03 数据对 ORB-SLAM3/SVO 都是简单序列(0.061/0.070);phad 的 81× 是
**纯算法侧差距**,全表 11 序列中 ratio 最大的一个。误差来源: 6 failed

seg3 仅 18 帧,锚陈旧度最高)。

## 3. V2_02(确认清理)

| 指标 | afe3829(初版) | e77ee5d(官方) |
|---|---:|---:|
| failed | 36 | **0** |
| rejected | 13 | 80 |
| reanchors | 3 | **0** |
| ATE | 2.192 | 0.853 |

glue + ⑥ 前端已把 failure 清零。残余是**精度债**:
- `shared/obs` 中位 0.169(V1_02 对照 0.525),`num_shared` 中位 28(对照 87)
- corridor 场景远距低视差 → 有效立体观测(disparity>0)稀疏 → BA 约束少
- ATE 0.853 = 30× ORB-SLAM3 0.028,但结构稳定(单 segment,0 断档)

这不是 failure 债,是立体几何信息量的问题,留给 M4 IMU + 深度/尺度
约束,不在本次范围。

## 4. 结论

### 4.1 优先级

| 序列 | 判定 | 依据 |
|---|---|---|
| **V1_03** | **值得修(算法侧)** | 数据干净,81× 全表最差 ratio,失败模式已完全理解(6 帧自持 + 5 re-anchor 锚误差) |
| **V2_03** | 前端鲁棒性候选 | 数据侧为主(7× ratio 且 ORB-SLAM3 也退化),链 C 是唯一纯算法侧失败 |
| **V2_02** | 记录 | 已清理,精度债非 failure |

### 4.2 VO 侧可做(pre-M4,零门控风险)

1. ~~**matchRight 归一化/Census**~~ **已实测否决**(2026-08-07, §0.1):
   Census 兜底在 V2_03 引入错误匹配 → ATE 7937m(225 次锚跳)。替代候选:
   **帧级曝光归一化**(cam1 整帧亮度补偿后仍走 SAD, 不换匹配核)——未试,
   优先级中;或接受数据侧限制(§0.1 结论 c)
2. **LK pyramid 5**: 10Hz 段帧间运动翻倍,当前 4 层金字塔位移上限不足
   (V2_03 链 B2 候选修复)——未立项
3. **diag 增加 `num_disparity` 列** ✅(2026-08-07 完成): 本次诊断花在
   "区分 track 死 vs 视差死"上的时间直接变成一行诊断输出,下轮诊断免费
   (`reject_reason` 字段未做, `num_disparity`+`num_shared`+`num_obs` 三列
   联立已足够区分所有已知拒绝路径)

### 4.3 不做

- **不为 V2_03 调参**(min_seed_observations / 门限): 数据侧问题,调参
  只能刷分不能修根,且 MH_01 门控已定
- 不改 seed/re-anchor 门逻辑: 链 B 的自持是数据异常(disparity=0)的
  正确反映,门逻辑本身在健康序列上无回归证据
- 不做 "failed 帧 seed" 变体: V1_02 归因 §6-4 已判低优先级

### 4.4 门控

本诊断**零代码改动**;MH_01 硬门(0.0988)与全表 record-only 状态不受影响。
若 4.2 的匹配核改动立项,单独开片并全表重测。
