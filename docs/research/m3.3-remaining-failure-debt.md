## 1. 结论先行

三条残余 failure 序列的根因不是 PnP 仲裁、cull 策略或 estimator 缺陷，而是
**前端光流跟踪在困难段一次性丢失全部 track，导致 `LandmarkId` 完全失配**。

前端维持 200 个 track 的 ID 池，estimator 以相同 ID 识别 landmark。当前端因
快速旋转/低纹理/运动模糊而将所有 LK track 丢失时，下一帧 GFTT 重新检测会发放
全新 ID。estimator 的窗口里有大量 landmark，但没有一个 ID 与新帧的 track 匹配
→ `shared=0` → 触发 reanchor。reanchor 重建窗口和 landmark 表，但如果前端再次
丢失全部 track，循环重复。

这跟 M3.3 Slice ① 的原始吸收态（`num_shared==0` 硬拒）不同：Slice ① 修复后，
`shared=0` 时系统正确地 reanchor 而不是永久拒帧。但 reanchor 需要时间重建 landmark
（需要 `min_seed_observations=10` 帧），如果前端持续不能维持 track，就会出现
一连串极短 segment（V1_03 seg=7 仅 3 帧）。

**三条序列在 PnP 仲裁前后均未恶化**（V1_03 failed 从 185 降至 72，V2_02 持平，
V2_03 持平），证明回归不在 estimator 侧。

## 2. 逐序列分析

### 2.1 V1_03_difficult（15 seg / 14 rea / 72 failed / ATE 3.353 m）

**PnP 仲裁 vs zombie-age**：failed 185→72（−61%），rejected 不变，PnP fallback
421→326，low_connectivity 279→201。仲裁显著**改善**了该序列。

**Failed 帧特征**（72 帧，分 3 簇）：
- 主簇 i=186–242（57 帧）：`shared=4–15`、`pnp=0`（PnP 求解失败）、
  `low_connectivity` 交替。有共享 landmark（4–15 个），但 3D-2D 对应质量不足以
  支持 PnP RANSAC 找到 10+ inlier
- 这些帧并非完全没有 landmark，而是 landmark 的投影噪声太大，PnP 无法收敛

**Reanchor 特征**（14 次）：
- **典型模式**（seg=0→1, seg=1→2 等）：前 1–3 帧 `shared` 逐步降至 0→1，
  随后 rejection→reanchor。前端 track 自然衰减 + 关键时刻全部丢失
- **异常模式**（seg=8→9 i=1344, seg=9→10 i=1377）：前序帧完全健康
  （`shared=133`、`pnp=1`、`inl=102`、`rmsA=0.53`），下一帧 `shared=0`。
  这是前端**瞬时全 track 重置**——某一帧光流跟踪全部失败，GFTT 补点生成 200 个
  全新 ID，estimator 地图中 178 个 landmark 无一匹配
- seg=7 仅 **3 帧**（i=1327–1329）——reanchor 后来不及积累足够 landmark，下一轮
  重置即来

**判定**：V1_03 的困难段（快速旋转+低纹理）超出当前前端跟踪能力。PnP 仲裁
已改善 situation，剩余 72 failed 是前端跟踪极限。

### 2.2 V2_02_medium（4 seg / 3 rea / 36 failed / ATE 2.192 m）

**PnP 仲裁 vs zombie-age**：所有计数几乎不变（failed 36↔36, rejected 13↔13,
segments 4↔4, PnP fallback 283→280）。仲裁对此序列几乎无影响。

**Failed 帧特征**（36 帧，分 2 簇各 18 帧）：
- 簇 1（i=542–559）：18 帧，`shared` 降至 1–2，`pnp=0`
- 簇 2（i=765–782）：18 帧，同样模式

**Reanchor**（3 次）：
- seg=0→1（i=561）、seg=1→2（i=783）：经典的前端 track 衰减→`shared→0`→reanchor
- seg=2→3（i=1592）：与前两次不同。前序帧全部健康（`shared=15–26`，PnP 成功），
  然后 i=1592 `shared=0`。这是 V1_03 型的瞬时全 track 重置，但 V2_02 在整段
  序列中**仅发生一次**

**判定**：三条序列中最稳定。两次小 failure 簇 + 一次意外重置。frontend 在
V2_02 corridor 中表现远优于 V1_03。

### 2.3 V2_03_difficult（12 seg / 11 rea / 40 failed / 1011 rejected / ATE 7.671 m / completion 0.453）

**PnP 仲裁 vs zombie-age**：所有计数几乎不变。仲裁对此序列无影响。

**主导问题：52.6% rejected**。

首 224 帧（i=0–223）全部 rejected，且此期间 `window_size=0`、`landmarks=0`。
前端无法建立任何 landmark：
```
i=220: rejected shared=0 obs=5  lm=0 win=0
i=221: rejected shared=0 obs=9  lm=0 win=0
i=222: rejected shared=0 obs=7  lm=0 win=0
i=223: rejected shared=0 obs=7  lm=0 win=0
i=224: ok       shared=0 obs=11 lm=0 win=1  ← 第一个 ok 帧
i=225: ok       shared=5 obs=11 lm=5 win=2  ← 开始积累
```

i=224 虽然 `shared=0`，但返回 `ok`——这是 reanchor（或首帧初始化）帧，不设
shared 门限。随后 landmark 逐步积累（i=228 达到 21 个 landmark、PnP 首次成功）。

**初始 224 帧为何零 landmark**：V2_03 在 M3.2 已知 `drop_right=415`（右目 415
帧无配对左目）。虽然 synchronizer 只发射配对帧，但初始段的图像质量、特征数量
或运动模式可能使前端无法在最初几百帧产生跨帧持久 track。

后续周期性的 rejection 簇（i=412–449、i=696–792 等）与 V1_03 的 reanchor 循环
模式相同。

**判定**：V2_03 是数据质量（M3.2 立体配对不均衡）+ 前端跟踪极限的组合。52.6%
rejection 率主要由初始无 landmark 段驱动；一旦系统建立 landmark，可维持数百帧
的稳定跟踪。

## 3. 根因机制（统一模型）

```
困难运动段（快速旋转 / 模糊 / 低纹理）
        │
        ▼
┌───────────────────────────────┐
│  前端 LK 光流全部跟踪失败      │
│  GFTT 补点 → 200 个全新       │
│  LandmarkId                    │
└───────────────────────────────┘
        │
        ▼
┌───────────────────────────────┐
│  estimator 窗口有 100+ 个      │
│  landmark，但没有一个 ID 与     │
│  新帧 track 匹配               │
│  → shared = 0                 │
└───────────────────────────────┘
        │
        ▼
┌───────────────────────────────┐
│  reanchor：prior 打在最后一个  │
│  被接受的位姿上，重建窗口       │
│  和 landmark 表                │
└───────────────────────────────┘
        │
        ▼
    ┌───────┐    前端再次丢全部 track    ┌───────────────┐
    │ 正常   │ ←─────────────────────→ │ reanchor 循环  │
    │ 跟踪   │    (3–627 帧后)          │ (seg=3/7/14帧) │
    └───────┘                          └───────────────┘
```

reanchor 后，窗口需要时间重建：
- `min_seed_observations=10`：landmark 需≥10 帧观测才能进入种子池
- `min_landmark_observations=2`：landmark 需在≥2 帧被观测才能加入图
- `window_size=10`：窗口满 10 帧后才滑出最老帧

如果在窗口重建完成前前端再次丢 track，segment 就极短（V1_03 seg=7 仅 3 帧）。
稳定 tracking 恢复后（如 V1_03 seg=3 的 627 帧），系统正常工作。

## 4. Failed 帧的二级分类

| 类型 | 特征 | V1_03 | V2_02 | V2_03 |
|---|---|---|---|---|
| **shared=0 型** | 无共享 landmark → rejected | 48 帧 | 17 帧 | 1023 帧 |
| **shared>0 但 PnP 挫败型** | 有共享但 3D-2D 噪声大 → PnP RANSAC 无充足 inlier → CV guess → 优化数值失败 → failed | 72 帧 | 36 帧 | 40 帧 |

第二类是新现象：landmark 存在（5–15 shared），但对应质量太差，PnP 无法工作，
而 CV guess 在该帧也退化（快速运动使恒速预测不准），导致 LM 优化失败。

## 5. 修复方向

### 不推荐

- 降低 `min_seed_observations` 或 `min_shared_landmarks`：会让低质量 landmark
  更快进图，在健康序列上引入回归风险（MH_01 已验证）
- 调整 session/cull 参数：根因不在 estimator
- 修改 PnP 仲裁判据：三条序列与 zombie-age 持平或改善，仲裁无责

### 推荐方向

按优先级：

1. **Slice ⑤ 关键帧策略**（已在 roadmap 中挂起）：关键帧不滑出窗口可延长时间窗口，
   给 landmark 更多帧积累观测，降低瞬时前端重置的破坏力。窗口内保留更多"锚帧"
   意味着一帧的 track 丢失不再导致 `shared=0`——因为前面几帧的关键帧 landmark
   仍然与新帧有重叠

2. **前端 track 持久化**：当前前端在 LK 跟踪失败时立即丢弃 track。可考虑
   "zombie track"（保留 track ID 但标记为"不可靠"，几帧后如果 LK 恢复则复用
   同一 ID）——这会减少 LandmarkId 的完全失配

3. **TrackId ≠ LandmarkId**（AGENTS.md 中已确认的中期债）：将前端 track 标识
   与 estimator landmark 标识解耦，在中间层做匹配。前端 track 重置不会导致
   estimator `shared=0`

4. **接受为前端跟踪极限**：某些 EuRoC 序列的运动模式就是超出了基于 LK 光流的
   前端能力。后续 M4（IMU）会通过惯性预测改善位姿初值，间接帮助前端（更好的
   位姿→更准的 epipolar 搜索→更少的 track 丢失）

### 立即可做

- **V2_03**：`drop_right=415` 是已知数据侧限制。考虑在 benchmark 中将 V2_03
  标记为"已知数据质量问题"，不作为算法门控序列

## 7. 后续
