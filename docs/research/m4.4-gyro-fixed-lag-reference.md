# M4.4 gyro-only fixed-lag / marginalization 对照调研

> 日期：2026-08-10
>
> 状态：research，不是已确认设计
>
> 作用域：已撤销 full-B5，当前仅保留 gyro-only pose + shared gyro bias + stereo rolling batch
>
> 外部资料检索日：2026-08-10；所有源码链接均锁定 commit

## 1. 结论先行

推荐下一片先做 **contract probe → read-only shadow**，不直接把生产 rolling batch 换成
`IncrementalFixedLagSmoother`。原因不是 GTSAM 缺少这个类，而是当前状态模型与
fixed-lag 的真实生命周期尚未对齐：

1. **版本事实**：本机安装的不是题设中的 `4.3a1`，而是 `4.3a0`
   (`3ad4b4c3cb28394c9597f48fa02dad361c8450e3`)。但 fixed-lag 相关的 8 个核心文件在
   `4.3a0` 与 `4.3a1`
   (`2f3e56c0ddbd3a1aa54ed043643b553d26a069f6`) 间 blob id 逐个相同，因而本文对
   `4.3a1` 的 API 结论也适用于本机实际库。
2. **库归属**：`IncrementalFixedLagSmoother` 已在稳定头
   `<gtsam/nonlinear/IncrementalFixedLagSmoother.h>` 中，实现符号由 `libgtsam`
   导出。`gtsam_unstable` 下的同名头只是带 warning 的转发头，新代码不应再依赖它。
3. **shared bias 可以“不被删”，但不等于可安全长期优化**：每次只刷新同一
   bias key 的 timestamp（不再插入 value）可把它留在 lag 内；但它一旦成为被边缘化
   pose 的 separator，GTSAM 会把它加入 `fixedVariables_`，之后不再重线性化。这只与
   B3 当前“已对齐、强 prior 冻结”的 bias 勉强相容，不能作为未来在线 bias
   模型。
4. **显式 landmark 不能朴素跨窗刷新**：长寿命 landmark 也会成为边缘化的
   separator，从而被固定线性化点。更严重的是，用 `factorsToRemove` 提前删掉某
   landmark 的最后一个 factor 后，ISAM2 会删掉无用 value，但 `FixedLagSmoother`
   保留该 key 的 timestamp；后续它到期时可直接抛异常。当前 mean-cull / cheirality /
   reopt 依赖“删点后全图重建”，不能只改 optimizer 类型。
5. **成熟 VIO 实现没有采用一个永久 shared bias**：Kimera-VIO、VINS-Fusion、
   ORB-SLAM3 和 Basalt 都将 bias 放在每帧/每 keyframe 的状态中，用 IMU / random-walk
   因子连接相邻 bias。它们的 landmark 处理也是 structureless factor、显式 Schur
   prior、局部固定 keyframe 或独立 landmark database，没有可直接搬过来的“同一
   explicit point key 无限刷新 timestamp”模式。
6. **API 可用 ≠ 当前生命周期可安全接入**：稳定头、主库符号和 basic pose
   marginalization 均已可用；但当前 post-opt cull/rebuild 要求能撤销坏 landmark 的全部
   历史贡献，linear marginal prior 则不可逆。现有固定 revision 参考中，没有一个支持
   “phad 当前 shared bias + explicit point + post-cull 语义不变”的最小 production
   fixed-lag 模式。

**决策建议**：fixed-lag 值得继续试，但当前只应作为生命周期探针，不应作为
M4.4 立即的 production accuracy candidate。否则会同时改变 solver、marginalization、bias
及 landmark 语义，无法判断 VIO/VO 精度变化来自哪一层。

## 3. `IncrementalFixedLagSmoother` 的公开 interface 与生命周期合同

### 3.1 公开 interface

`4.3a1` 的公开面包括：

| interface | 合同 |
|---|---|
| `IncrementalFixedLagSmoother(double lag, const ISAM2Params&)` | `lag` 与 caller 提供的 timestamp 同单位；默认打开 `findUnusedFactorSlots` |
| `update(newFactors, newTheta, timestamps, factorsToRemove)` | 追加 factor/新 key 初值，更新 key timestamp，按 factor slot 删 factor，然后自动边缘化 |
| `calculateEstimate()` / `calculateEstimate<T>(key)` | 取当前全量/单 key 估计；最新帧应按确切 `X(frame_index)` 读，不应依赖 key 字典序 |
| `timestamps()` | 只读当前 key→timestamp 表 |
| `getFactors()` | 取 ISAM2 内部 factor graph；包含空 slot，删除前需 `exists(slot)` |
| `getISAM2Result()` | 取上一次 `isam_.update()` 的 `newFactorsIndices`等结果 |
| `getISAM2()` | 只读 ISAM2，可检查 `valueExists()` / `getFixedVariables()` |
| `marginalCovariance(key)` | 计算当前 key 边缘协方差 |

来源：
[`IncrementalFixedLagSmoother.h`](https://github.com/borglab/gtsam/blob/2f3e56c0ddbd3a1aa54ed043643b553d26a069f6/gtsam/nonlinear/IncrementalFixedLagSmoother.h#L34-L141)、
[`FixedLagSmoother.h`](https://github.com/borglab/gtsam/blob/2f3e56c0ddbd3a1aa54ed043643b553d26a069f6/gtsam/nonlinear/FixedLagSmoother.h#L33-L130)、
[`ISAM2.h`](https://github.com/borglab/gtsam/blob/2f3e56c0ddbd3a1aa54ed043643b553d26a069f6/gtsam/nonlinear/ISAM2.h#L119-L220)。

`FixedLagSmoother::Result` 在 incremental 实现中仍是占位型结果：实现固定写
`iterations=1`、`error=0`，源码也保留了 `TODO: Fill in result structure`。因此不能用它作
accuracy / convergence 诊断；需读实际 estimate、factor error 或 `getISAM2Result()`。
[实现位置](https://github.com/borglab/gtsam/blob/2f3e56c0ddbd3a1aa54ed043643b553d26a069f6/gtsam/nonlinear/IncrementalFixedLagSmoother.cpp#L126-L136)

### 3.2 一次 `update()` 的精确顺序

`4.3a1` 实现的顺序是：

1. 先将 caller 给出的 timestamp 写入/更新双向表；
2. 取整张 timestamp 表的最大值作为 `current_timestamp`；
3. 选中所有 `timestamp < current_timestamp - smootherLag` 的 key；
4. 给可边缘化 key 分 group 0，其他**已跟踪 timestamp**的 key 分 group 1；
5. 调用 `isam_.update(newFactors, newTheta, factorsToRemove, ...)`；
6. 将选中 key 作为 Bayes tree leaf 边缘化；
7. 最后才从 timestamp 表删除已边缘化 key。

来源：
[`IncrementalFixedLagSmoother.cpp`](https://github.com/borglab/gtsam/blob/2f3e56c0ddbd3a1aa54ed043643b553d26a069f6/gtsam/nonlinear/IncrementalFixedLagSmoother.cpp#L45-L120)、
[`FixedLagSmoother.cpp`](https://github.com/borglab/gtsam/blob/2f3e56c0ddbd3a1aa54ed043643b553d26a069f6/gtsam/nonlinear/FixedLagSmoother.cpp#L46-L119)。

由此得到以下合同：

- cutoff 是严格小于；恰好等于 cutoff 的 key 仍保留。
- 没有“timestamp 必须单调”的显式检查，但 current 由全表最大值决定。新增一个过时
  key 可在同次 update 被立即边缘化；向已经边缘化的 key 添 factor 则没有可用 value。
  phad 应保持 accepted-state epoch 单调，被拒/失败帧不推进 graph time。
- timestamp 是 `double`。不应把 `int64` 纳秒 epoch（约 `1e18`）直接 cast 后作 lag
  运算；对齐现有帧数窗口时，应用 accepted `frame_index` 的 `double`，或使用相对起点秒。
- `newTheta` 只能包含 `newFactors` 中首次出现的新 key；已在系统中的 key 不得重复插值。
  [ISAM2 明示合同](https://github.com/borglab/gtsam/blob/2f3e56c0ddbd3a1aa54ed043643b553d26a069f6/gtsam/nonlinear/ISAM2.h#L119-L158)
- `timestamps` 可以只包含需要刷新的已有 key；`updateKeyTimestampMap()` 会替换旧值。
- 没有 timestamp 的 key 永远不会被 smoother 主动选中，但在约束排序中，未出现在
  group map 的 key 默认属于 group 0，而不是“永久 separator”。
  [Ordering 合同](https://github.com/borglab/gtsam/blob/2f3e56c0ddbd3a1aa54ed043643b553d26a069f6/gtsam/inference/Ordering.h#L158-L184)

### 3.3 factor slot 与删除合同

`factorsToRemove` 是 **factor graph slot index**，不是 key，也不是“本次 newFactors 中的下标”。
默认 `findUnusedFactorSlots=true`，空 slot 会被复用，因而 caller 必须：

1. 按稳定顺序插入 factors；
2. 用当次 `getISAM2Result().newFactorsIndices` 记录每个 factor 的真实 slot；
3. 删除前验证 `getFactors().exists(slot)`；
4. 边缘化后允许 slot 失效/被复用，不得以“曾经的 slot”作永久身份。

GTSAM 本身只在 `ISAM2Result` 中返回用户新加 factor 的 slot；
`IncrementalFixedLagSmoother` 调用 `marginalizeLeaves()` 时没有对外返回新生 linear marginal
factor 的 slot。用户账本应只管自己插入且需替换的 factor。

Kimera-VIO 也将 smart factors 放在 `newFactors` 最前，再按
`newFactorsIndices[i]` 回写 slot，并在旧 slot 已经因超出 horizon 消失时删掉其跟踪账本。
[替换逻辑](https://github.com/MIT-SPARK/Kimera-VIO/blob/ce8c59b7b273ab5ac29db7e5572e1623760e19c7/src/backend/VioBackend.cpp#L1049-L1120)、
[`newFactorsIndices` 回写](https://github.com/MIT-SPARK/Kimera-VIO/blob/ce8c59b7b273ab5ac29db7e5572e1623760e19c7/src/backend/VioBackend.cpp#L1712-L1761)。

### 3.4 异常与事务性

`IncrementalFixedLagSmoother::update()` **没有 strong exception guarantee**：

- timestamp 表在 `isam_.update()` 前已被修改；
- `marginalizeLeaves()` 的 debug 检查在发现非 leaf 时明示抛出“ISAM2 已处于不一致
  状态，不应继续使用”。
  [ISAM2 实现](https://github.com/borglab/gtsam/blob/2f3e56c0ddbd3a1aa54ed043643b553d26a069f6/gtsam/nonlinear/ISAM2.cpp#L487-L523)

因而生产 seam 必须在每次 update 前备份**整个 smoother + factor/timestamp ledger**，任何
异常都恢复完整 snapshot 并显式返回失败，不能 catch 后继续使用可疑状态。
Kimera-VIO 在调用前复制 smoother，对 indeterminate system 重试前及 cheirality 清理前都恢复
backup，但它的 factor `shared_ptr` 仍共享，所以也假定 factor 本身不在 update 期间就地修改。
[备份/异常处理](https://github.com/MIT-SPARK/Kimera-VIO/blob/ce8c59b7b273ab5ac29db7e5572e1623760e19c7/src/backend/VioBackend.cpp#L1383-L1573)。

## 4. pose + landmark + shared/global bias 能否直接使用

### 4.1 pose：可用，且与 newest-state 输出相容

每个 accepted frame 使用唯一 `X(frame_index)`，并给它一次 accepted epoch timestamp，是
`IncrementalFixedLagSmoother` 的正常模式。边缘化的旧 pose 被移出活动图，其信息以
linear marginal factor 留给窗口内 separator。

phad 现在对外每次 `update()` 只返回当前 newest pose；TUM 轨迹在当帧已追加，不回写
历史行。因此 fixed-lag 不需要对外暴露整窗口，也不应追溯改写旧输出；只需按确切
`X(candidate.frame_index)` 取 newest estimate。内部仍需将活动窗口 pose 回写到现有
`window`，否则 PnP、reprojection cull 和 `last_stereo_pose_W` 会使用不一致的旧值。

### 4.2 shared gyro bias：可存活，但会固定线性化点

三种 timestamp 策略的结果不同：

| 策略 | 结果 | 结论 |
|---|---|---|
| 从不给 `W(0)` timestamp | 不会按 lag 删除，但排序时默认在 group 0 | 不可作为永久 separator 合同 |
| 只在首次给 timestamp | 到期后与旧 pose 一起被边缘化 | 后续 gyro factor 将引用不存在的 key |
| 每次用 current epoch 刷新，不重复插 value | 始终在 group 1，不被 lag 删除 | 唯一可行的 shared-key 存活方式 |

但“存活”后仍有线性化合同。ISAM2 边缘化旧 pose 后，会为生成的每个 linear
marginal factor 遍历幸存 key，并把它们全部放入 `fixedVariables_`。
[源码](https://github.com/borglab/gtsam/blob/2f3e56c0ddbd3a1aa54ed043643b553d26a069f6/gtsam/nonlinear/ISAM2.cpp#L669-L720)；
[公开文档也明示说明幸存 key 的线性化点会固定](https://github.com/borglab/gtsam/blob/2f3e56c0ddbd3a1aa54ed043643b553d26a069f6/gtsam/nonlinear/ISAM2.h#L182-L202)。

本机用 `Point2` 作为可视化的 global separator 做了最小实验：lag=`1.5`，每次刷新
`B(0)` timestamp，并连接所有新 pose。输出为：

```text
update  B_timestamp_present  B_is_fixed
1       1                    0
2       1                    1
3       1                    1
```

第一个旧 pose 超过 lag 后，global key 立即成为 fixed variable。这与源码完全一致。

**对 B3 的边界结论**：当前 bias 在 staged alignment 后用非常强的 prior 冻结，所以
fixed linearization 不一定立即改变产品语义；但这必须由 shadow 的 `bias_delta` /
objective 证明，不能由“数值应该很小”代替。一旦要在线估 bias，应改为每状态
bias + random-walk/equality factor，让旧 bias 随旧 pose 一起边缘化。

### 4.3 explicit landmark：不可直接套用同一个长期 key

对 `L(id)` 按“最后一次真实 stereo factor 的 accepted epoch”刷新 timestamp，能让它在可见
期留在窗内；但当最旧 observation pose 被边缘化时，这个 point 也会成为 marginal
factor 的 separator，随即进入 `fixedVariables_`。后续观测能继续改变 delta，但不会在新
线性化点重新线性化旧 marginal prior。这与当前每帧 LM 全图重线性化的语义不同。

提前 cull 还有一个可复现的 key/timestamp 失配：

1. 插入 `X(0)` 及它的 prior，记录 factor slot；
2. 通过 `factorsToRemove` 删掉唯一 factor；
3. ISAM2 删掉无用 `X(0)` value，但 smoother 的 `timestamps()` 仍有 `X(0)`；
4. 插入 `X(1)` 推进 current time，使残留 timestamp 超过 lag。

本机 `4.3a0`（与 `4.3a1` 相关 blob 相同）输出：

```text
after_remove ts=1 value=0
caught=Index out of requested size range
```

`FixedLagSmoother` 没有公开 key/timestamp 删除 interface；`eraseKeyTimestampMap()` 是 `protected`。
因此现有 cull 不能翻译为“删掉该 landmark 的所有 factor slot”就结束。生产实现
必须先选定一套完整生命周期，例如：

- 让 graph landmark 只自然到期，cull 只阻止新 factor，不提前删最后 factor；或
- 把地图身份与 graph generation 分开，当一代 factor 寿命结束时重建明确的新 graph key；或
- 采用已验证的 structureless / explicit Schur 生命周期。

这三者都是新的设计决策，不应在“换 smoother”时隐式选定。

### 4.4 当前 post-opt cull/rebuild 与 marginal prior 的不可逆冲突

这是比 stale timestamp 更基本的 production blocker。

当前 rolling batch 的语义是：先优化当前完整窗口，再根据 post-opt reprojection
residual 决定 mean-cull / cheirality；删掉坏 landmark 及其窗口观测后，重建 graph
并 reopt。重建后的目标中不再包含该 landmark 的任何贡献，所以这是一个可撤销的
trial optimization。

fixed-lag 的时序不同：`update()` 先加新 factor 和求解，然后在同次调用内边缘化
超窗 pose。若坏 landmark 的 observation factor 连到该 pose，其线性化信息已经被压进
`LinearContainerFactor` marginal prior。后续即使：

- 删掉仍可见的原始 factor slot；
- 删掉 landmark value；
- 从 domain `landmarks_W` / window observations 中删除它；

也无法从已生成的 marginal prior 中按 landmark 身份减去它的历史信息。
`IncrementalFixedLagSmoother` 没有返回“某个用户 factor 被吸收到哪个 marginal factor”的可逆
provenance；它在内部删原 factor、加 linear marginal factor 的过程见
[`ISAM2::marginalizeLeaves`](https://github.com/borglab/gtsam/blob/2f3e56c0ddbd3a1aa54ed043643b553d26a069f6/gtsam/nonlinear/ISAM2.cpp#L669-L720)。

因而下列两个目标无法由一次最小类型替换同时满足：

```text
A. 保留当前 post-opt residual 决策 + 删点后全目标重建语义
B. 每帧立即将超 lag 信息压进不可逆 incremental marginal prior
```

要兼容 A，只有三类更深的设计：

1. 在生成 prior **之前**完成一切 residual 选择，如 VINS-Fusion/Basalt 自己管理
   residual 集和 marginalization；
2. 保留可重放的原始观测/checkpoint，cull 后从未污染的 checkpoint 重建整个
   smoother 与 prior；
3. 不使用不可逆 marginal prior，继续局部 batch + fixed anchor，这与 ORB-SLAM3 更接近。

1/2 都不是当前 M4.4 的最小 gyro-only production slice；3 实际上支持继续使用现有
rolling batch，而不是引入 fixed-lag。Kimera 的方式是在 update 前替换仍存在的 smart
factor，当旧 factor 已被 horizon 清掉时就删除 track；它也没有提供“从已生成
prior 中撤回后来才判为 outlier 的 landmark”模式。

**结论**：固定 revision 的成熟实现支持“先定义完整 marginalization lifecycle，再做持久
solver”，不支持当前 lifecycle 不变的最小 production swap。所以本切片的正确边界是
probe/shadow，不是产品 estimate handoff。

## 5. 成熟实现如何处理窗口生命周期

### 5.1 横向对照

| 实现 | 状态 / bias | 旧状态 | landmark | 可借鉴 | 不可直接搬 |
|---|---|---|---|---|---|
| GTSAM `IncrementalFixedLagSmoother` | caller 自定 key/timestamp | 按 timestamp 自动线性边缘化 | caller 自负生命周期 | 稳定库、slot 结果、自动 Bayes-tree marginalization | 不提供 landmark/cull 策略，也不提供 update 失败回滚 |
| Kimera-VIO | 每 keyframe 一组 `x/v/b` | frame id 作 timestamp，fixed-lag | smart stereo factor；新观测到来时删旧 slot/加新 factor；超 horizon 后删 track | factor slot 账本、更新顺序、smoother backup | 它无 explicit point key；不是 shared bias；它的 smart-factor 生命期不等于 phad |
| VINS-Fusion | 每窗口位一组 pose/vel/acc-bias/gyro-bias | 手写 Schur complement prior，可删 oldest 或 second-newest | 视觉 residual 中显式 drop anchor/feature，滑窗时 shift depth | “边缘化的是一个整体状态语义” | Ceres 参数块地址映射、inverse-depth anchor 与 phad 不同 |
| ORB-SLAM3 | 每 keyframe 的 pose/vel/gyro-bias/acc-bias + bias RW edge | 不做 fixed-lag prior；取最近时序 keyframes 优化，窗外一帧及共视帧固定 | global MapPoint 持久化，每次只选 local observations | newest temporal set + fixed anchor，地图与当次 graph 分离 | 这是 local batch BA，不是 GTSAM marginalization |
| Basalt | 每 timestamp 一个 pose/vel/bias state | 非keyframe 整体删；旧 keyframe 可仅保 pose、边缘化 vel/bias；保留 square-root prior | 独立 landmark DB，按 keyframe/lost-landmark 集合删除 | 状态分层、明确 keep/marg index、nullspace 检查 | 是自研 square-root marginalizer，不是一个 GTSAM 类的替换 |

## 6. 对 phad 的最小可行 seam

### 6.1 外部 seam 不变

保留现有 `StereoVoEstimator::update(measurement, keyframe)` 作唯一外部 seam。不新增
`Smoother` adapter、不暴露 GTSAM key/timestamp/slot，也不让 `apps/` 管 marginalization。这些都应局限
在 estimator PIMPL 内，否则 caller 必须学习一整套 GTSAM 生命周期，模块会变浅。

内部可替换 seam 位于：

```text
已通过 gate 的 candidate
  → 完成现有 window / landmark / cull 事务决策
  → [当前：buildGraph + LM + reopt]
  → 回写活动 window / landmark / newest result
```

fixed-lag 只能替换方括号中的 graph-state implementation，不能跨过前面的事务决策。
测试仍经过 `StereoVoEstimator::update()` 的真实 seam。

### 6.2 timestamp 与窗口对齐

- pose timestamp 使用 accepted `frame_index`；拒绝/失败帧不推进。
- 当前 gyro-active 窗口是“只 pop oldest，同时约束 total ≤ 10、keyframes ≤ 7”，不是一个
  固定 lag 数值。可在加入 candidate 后先算出现有规则要保留的 `oldest_frame_index`，再将
  `smootherLag = current_frame_index - oldest_frame_index`。由于 cutoff 是严格 `<`，恰好处于
  `oldest_frame_index` 的 key 会保留。
- pre-activation / IMU-off 的视觉窗口允许删中间 keyframe/优先删非keyframe，timestamp fixed-lag
  只会删时序前缀，不能直接表达这一规则。因此不能在 gyro 激活前就无条件替换
  全部 VO graph；这也是先 shadow 的原因。

### 6.3 最小内部账本

生产 fixed-lag 至少需在 PIMPL 内拥有：

- pose key ↔ accepted epoch；
- graph landmark generation ↔ domain `LandmarkId` ↔ 最后一个真实 stereo-factor epoch；
- 每个可替换/可删用户 factor 的 slot，以及 slot 是否仍 `exists`；
- shared bias key 的 current timestamp 刷新（仅限当前 frozen-bias probe）；
- smoother 与上述账本的同一事务 snapshot。

zero-disparity observation 没有创建 stereo factor，不应只因 domain track 仍在就刷新 graph
landmark timestamp。否则会创造没有新图约束的“假存活”。

segment seed / re-anchor 本来就清窗并重建 landmark 表；对持久 smoother 应定义为一个显式
graph reset event，重建新 smoother 与账本。这是 domain lifecycle，不是出错后的静默 fallback。

## 7. 不可直接迁移的模式

1. **“将 `LevenbergMarquardtOptimizer` 替换为 `IncrementalFixedLagSmoother`”**：这同时改变
   solver iteration、relinearization、prior 语义和 factor 寿命，不是等价重构。
2. **Kimera smart-factor 账本照搬**：Kimera 没有 explicit `L(id)` value，超 horizon 后直接删
   track；phad 的持久 `landmarks_W`、far-return refresh、rebirth block 合同不同。
3. **VINS/Basalt 手写 marginal prior 照搬**：它们的 residual parameterization、FEJ/线性化点、
   nullspace 和 landmark anchor 都是系统级设计，不是 M4.4 gyro-only 的小修。
4. **ORB-SLAM3 的 fixed anchor 当 marginal prior**：ORB-SLAM3 做的是 local batch BA，老 pose 仍作
   fixed vertex 参与当次 graph，没有把它消元成 prior。
5. **永久 shared bias 当作成熟 VIO bias model**：四个参考实现都是每状态 bias 链；当前
   shared bias 只能是 frozen-calibration 过渡语义。
6. **catch 异常后继续用原 smoother**：源码没有事务保证，必须恢复备份并显式失败。
7. **删掉 landmark 最后 factor 即视为 key 已完整删除**：ISAM2 value 和 smoother timestamp 会
   脱节，本机已复现后续到期异常。

## 8. 建议的下一 vertical slice

### 8.1 Phase P0：先写 installed-library contract probe

用仓库 C++ test target 经稳定头和 `gtsam` target 验证，不改产品输出：

1. cutoff 严格 `<`，等于 cutoff 的 pose 保留；
2. 已有 shared key 只刷 timestamp，不重复插 value，可跨 lag 存活；
3. 首次 pose marginalization 后 shared key 进入 `getFixedVariables()`；
4. `newFactorsIndices` 与插入顺序对应，空 slot 可复用；
5. 删最后 factor 后复现 `timestamp present && !valueExists`，下次到期必须显式失败；
6. 人工制造 update 异常，恢复 smoother + ledger snapshot 后下一个合法 update 仍成功。

P0 的价值是把本文的本机临时实验变成仓库内可回归合同，防止后续 GTSAM 升级时
静默改变行为。

### 8.2 Phase P1：MH_01 read-only shadow

P0 全绿后，复用现有 CLI-only probe 通道，在 `StereoVoEstimator::update()` 内运行一份不参与
prediction、gate、LM 初值或返回 pose 的 shadow graph。建议 sidecar 至少记录：

```text
frame_index, current_epoch, cutoff_epoch,
batch_window_n, smoother_pose_n, smoother_landmark_n,
bias_present, bias_fixed, bias_delta_norm,
user_factor_n, missing_owned_slot_n, timestamp_without_value_n,
marginalized_pose_n, shadow_update_ok, shadow_exception,
newest_rot_delta_rad, newest_trans_delta_m
```

运行合同：

- shadow 异常必须使 probe/run 明确失败，不能静默 reset 后继续冒充成功；
- segment seed / re-anchor 可按已定义的 lifecycle 显式 reset，并记录 reason；
- rejected/failed frame 的 current epoch 不得前进；
- active pose set 必须与 gyro-active 现有 oldest-prefix window 一致；
- timestamp 表与 `valueExists()` 必须没有孤儿；
- newest delta 的首要门是 finite 且无突变；LM 与 iSAM2 不保证 bit-identical，不应在 probe
  阶段伪造为零差异验收。

### 8.3 production candidate 的前置门

只有同时满足以下条件，才把 shadow estimate 切到产品路径：

1. 明确 bias 是“永久 frozen calibration”还是“每状态 bias chain”；后者才是长期模型。
2. 明确 landmark 的 graph generation、timestamp 刷新、cull 和 rebirth 合同，并消除
   `timestamp_without_value`。
3. 所有 factor slot 都由局部账本拥有，边缘化/复用后不持有 stale slot。
4. MH_01 shadow 全程无异常、key/factor 数有界、newest delta 无发散；再进一步做 product
   candidate。
5. product candidate 仍必须通过 M4 核心出口：成对 MH_01 上 VIO 精度严格优于 VO。
   不通过则先停在 MH_01 诊断，不扩到 11 序列。

## 9. 待后续设计确认的问题

以下不是本文已决定项：

- frozen shared bias 是否只用于一个 fixed-lag probe，还是直接转每状态 bias chain；
- graph landmark 采用 generation key、自然到期，还是 structureless factor；
- pre-activation 视觉图是否保持 rolling batch，gyro activation 时做一次明确 graph handoff；
- iSAM2 的 relinearization / wildfire 参数取值；本调研只确认了默认 interface，未做精度调参。

在 P0/P1 日志之前回答这些问题，证据不足；因此当前最小且可证伪的下一刀就是
contract probe，而不是 production swap。
