## 1. 旋转补偿视差（V1_01 +268% 的关键修复方向）

**核心发现**：raw 像素视差混淆了平移与旋转；旋转导致的"视差"不可三角化（无
baseline）。所有严肃系统都做旋转补偿——除了已发布的 VINS 代码（补偿行被注释）。

| 系统 | 做法 | 细节 |
|---|---|---|
| VINS-Mono (T-RO 2018) | 平均特征视差 ≥ 10 px（`10/460` 归一化）或 <20 track | 论文明确说纯旋转会夸大视差需 IMU 预积分补偿；**但发布代码中 `p_i_comp = p_i`（补偿行注释）** |
| DSO (PAMI 2018) | mean squared flow + **rotation-removed flow** + brightness | 旋转补偿项检测平移变化；纯旋转补偿后 flow 小 → 不触发关键帧 |
| Pirchheim ISMAR 2013 | 旋转检测 r=β/γ>0.2 → 3DOF panorama keyframe | 纯旋转下特征不可三角化（"infinite features"），标准视差滤波导致 "mapping starvation and tracking failure" |
| RD-VIO (TVCG 2024) | RANSAC 检测纯旋转帧 → R-frame：延迟三角化、bearing-only 残差、位置正则化 | **规则：最后一个关键帧永远是 N 帧；旋转帧绝不做关键帧** |

**我们的情况**：30 px 阈值是 VINS 10 px 的 3 倍——匀速直线时安全（MH 改善），
但快速旋转时 raw 像素视差轻易超 30 px → 旋转触发关键帧 → (a) 无三角化 baseline
(b) 滑窗驱逐结构上有价值的关键帧 → 关键帧泛滥 + 退化几何。

## 2. 关键帧密度：太稀太密都伤

| 来源 | 结论 |
|---|---|
| RL-SVO ablation (arXiv:2407.15626) | 关键帧惩罚移除 → 几乎每帧都是关键帧 → 精度下降；高惩罚 → ~2× 更少关键帧 → MH03/MH04 track loss。两个极端都伤；快速/旋转运动需要足够关键帧 |
| DKB-SLAM (Robotics 2025) | 运动状态加权自适应视差阈值 w_θ, w_t；**旋转时阈值降低（10≤T≤30 px）使关键帧插入更容易**；旋转 >45° 帧间重叠不足 |
| Kimera2 (ISER 2023) | max_disparity_since_lkf 消融：**更小阈值普遍更好**；推荐 75–100；最差 vs 最好设置误差差一个数量级 |
| Kim 2020 自适应阈值 | 最优阈值随平均特征跟踪长度变化；固定阈值被证明次优 |

## 3. 非关键帧位姿质量

| 来源 | 做法 |
|---|---|
| VINS-Mono | **camera-rate refinement**：30Hz 轻量 motion-only visual-inertial 优化（~5ms vs >50ms 全优化），比单帧 PnP 平滑得多 |
| VINS marginalization | 非关键帧视觉观测丢弃但 IMU 预积分继续跨过它（MARGIN_SECOND_NEW） |
| Usenko RSS 2019 | 长关键帧间隔时 IMU 预积分信息少；Non-Linear Factor Recovery 提取边际化先验中的高频运动信息 |
| Basalt | 7 KF + 3 temporal frames；非关键帧 aging out 时边际化，优化便宜所以非关键帧跟踪质量高 |
| IMU 传播误差 | 0.1s 时 0.0027m → 10s 时 0.9329m（arXiv:1909.03423） |

## 4. 关键帧判据对照表

| 系统 | 判据 | 阈值 |
|---|---|---|
| VINS-Mono/Fusion | 平均特征视差 OR 跟踪数 | 10 px 或 <20 track |
| OKVIS (IJRR 2015) | 匹配点覆盖面积比 | <50-60% |
| Basalt | 未映射新点比例 + 最小间隔 | <70% connected 且 ≥5 帧 |
| Kimera2 | optical-flow disparity OR 时间 | 75-100 px |
| DSO | rotation-compensated flow, raw flow, brightness | adaptive |
| DKB-SLAM | 运动加权自适应视差 | 10-30 px, Θ_max 45°, t_max 10m |
| ORB-SLAM3 | 视角变化 + 跟踪质量 + 冗余 | heuristic |

**我们的三判据对照**：视差 30 px ≈ 3× VINS（太激进）；track 存活率 <60% ≈ Basalt
30%-new-features（合理）；时间 >0.5s ≈ Kimera2/Basalt 时间兜底（合理但走廊慢速
运动也会触发）。

## 5. 走廊 / 低纹理（V2_02 灾难）

- 点特征 VIO 在低纹理走廊被记录失败：LK 光流前端退化，VIO-only 挣扎，高漂移或
  发散（NTNU 隧道实验）
- 前向平移 → 特征靠近 epipole 微小视差 + 远处"infinite"点 → **30 px 视差判据
  永不触发** → 只有 0.5s 时间规则产生固定间隔关键帧，baseline 近零 → 深度/
  尺度估计塌陷
- 缓解（文献验证）：点+线融合（PL-VIO/PL-VINS/Trifo-VIO）、延迟三角化
  （RD-VIO 防近零 baseline 垃圾深度）、绝对位移触发（DKB-SLAM t_max）

## 6. 行动建议（按影响力排序）

1. **视差项旋转补偿**（V1_01 最高影响修复）——把上一关键帧观测旋转到当前帧再
   阈值化（VINS 公式 `p_i_comp = ric^T · Rs[r_j]^T · Rs[r_i] · ric · p_i`；
   无 IMU 时可用两关键帧间相对位姿近似）
2. **关键帧最小间隔**（Basalt 5 帧）——防旋转关键帧泛滥驱逐窗口
3. **视差阈值降到 10-15 px**（旋转补偿后；VINS 10 / VGGT 15 / Kimera2 更小更好）
4. **旋转帧不做关键帧**（RD-VIO 规则：最后关键帧永远是 N 帧）
5. **非关键帧位姿：VINS 式 camera-rate motion-only refinement**（~5ms）而非
   裸 PnP/恒速
6. **走廊：绝对位移触发**（DKB-SLAM t_max）让慢速前进仍有 baseline

## 6. 开源实现全对比（源码验证，2026-08-05）

对 VINS-Fusion / ORB_SLAM3 / Kimera-VIO / Basalt / DSO / OKVIS 的 master 源码
浅克隆验证（ROVIO 来自 IJRR'17 论文）：

| 系统 | 非关键帧位姿来源 | 轨迹输出 | 关键机制 |
|---|---|---|---|
| VINS-Fusion | **窗口 BA 状态**（无 PnP-only 帧）| 每帧 | MARGIN_SECOND_NEW 只改边际化对象；最新帧永远在 BA；PnP 只是初始化器（失败保持 IMU 传播值） |
| Basalt | **窗口 BA 状态** | 每帧 | frame_states 含所有帧（pose+vel+bias）全是优化变量；landmark 收集所有帧观测；关键帧只控制 landmark hosting + 边际化顺序（保留最近 2 帧，DSO 式距离分数） |
| Kimera-VIO | **frontend 位姿**（KLT+RANSAC：2pt mono w/ IMU 旋转 prior、5pt mono、1pt stereo、3pt stereo、stereo PnP）| **仅关键帧**（链式增量轨迹）| 因子图 keyframe-only（`StereoImuPipeline.cpp:101` gate `is_keyframe_`）；非 KF 位姿仅作下个 KF 的 guess + between-factor；输出为 keyframe rate |
| ORB-SLAM3 | **PoseOptimization**（g2o pose-only LM，RANSAC 后）| 每帧（stereo/RGBD）| `Optimizer::PoseOptimization`（Optimizer.cc:814）：4×10 迭代，Huber sqrt(5.991)px，外点重掩码——让每帧位姿达到 ATE 级 |
| DSO | 直接法帧位姿 | 每帧 | — |
| OKVIS | 窗口状态 | 每帧 | — |
| ROVIO | 滤波状态 | 每帧 | — |

**不输出非关键帧位姿的**：只有 Kimera-VIO（keyframe rate）和 ORB-SLAM 单目模式
（拒绝 SaveTrajectoryTUM）。其余全部每帧输出。

**ATE 评估约定**：keyframe-only 轨迹用 evo/ate 在关键帧时间戳上评估（时间戳
关联，evo 插值）；TUM 约定是 all-frames CameraTrajectory.txt。**没有系统在
关键帧之间插值**——它们都用各自机制产生每帧位姿。

### 对我们的启示

1. **VINS/Basalt 路线**：非 KF 进 BA（窗口语义重构，改动大）
2. **ORB-SLAM3 路线**：非 KF 用 RANSAC 后 pose-only LM 精修（轻量，改动中，
   保持关键帧窗口语义）——agent 明确推荐「missing piece vs ORB-SLAM3 is a
   pose-only nonlinear refinement after RANSAC」
3. **Kimera 路线**：KF-only 图 + frontend 位姿输出（与我们当前最像，但 Kimera
   的非 KF 位姿有 IMU 旋转 prior 的 RANSAC 多假设，质量远高于我们的裸 PnP）
