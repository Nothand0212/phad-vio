## 2. 债的形态（④f 仍在）

大剔 i=425 skip 后（probe-b）：

| i | zombie | shared |
|---:|---:|---:|
| 426–435 | 32 | 13→83（相对无 zombie 路径更窄） |
| 440 | 26 | 79 |
| 450 | 7 | 142 |

zombie 会自然衰减，但 **426–429 窗口**正是 pose 大位移段；slot 被僵尸占用
（`max_tracks`）+ `block_culled_rebirth` 拒复生 → shared/PnP 变稀。  
整批 drop 能清 zombie，但把 ATE 打回 4.565。

## 3. 三个候选

### 候选 A — 子集 drop（推荐先探针）

**想法**：skip 当帧仍不 drop；仅对 `culled_landmark_ids` 的**子集**在后续
某处 `dropTracks`（例如仅 cheirality 子集、或 mean-cull 中残差最差的 K 个），
避免 32 全集触发 ④e 等价类。

| 利 | 弊 |
|---|---|
| 直接对准「slot 占用」；可扫 K / 子集定义 | 子集选错仍可能塌向 ④e；需新诊断计数 |
| 仍保留 skip 软门与 block | 多一次 MH_05 探针矩阵（成本中） |

**探针建议（未编码前可 CLI 覆写）**：K∈{0,4,8,16,32} 或
`cheirality-only` vs `mean-cull-only`，只看 MH_05 ATE + i=426–430
`zombie`/`shared`/`shift`；K=0=④f，K=32≈④e。

### 候选 B — 多帧条件 drop（图已变后再清）

**想法**：完整集不在 i+1 清；仅当 id **仍**以 zombie 存活 ≥N 帧（如 N=5～10）
且（可选）`num_shared` 低于阈值时，再精确 drop 残余。

| 利 | 弊 |
|---|---|
| postmortem 留口：跨更多帧且 track 图已变时，可能逃出 ≡④e | N 过小塌向 ④g；N 过大≈④f（无收益） |
| 对准「长期 zombie」而非「刚 cull 的连通」 | 调参面大；426–429 伤害可能已铸成 |

### 候选 C — 非 `dropTracks` 的 slot 让路

**想法**：不调用 `dropTracks`；在 frontend / session 让 skip-cull 集在
`max_tracks` 预算里**最低优先**，新 GFTT 可挤掉僵尸槽位（或 glue 层剥离
zombie obs 但不删 track——后者对 slot 无帮助，不推荐单独做）。

| 利 | 弊 |
|---|---|
| 避免 ④e 已知的 drop 语义 | 触及 frontend 优先级/检测补点路径，边界重于 A/B |
| 保留 block；僵尸随挤出自然消失 | 需新合同与单测；行为更难对拍 |

## 4. 暂不纳入本轮

| 项 | 原因 |
|---|---|
| 完整集一帧 / 多帧无条件 drop | ④g 已证伪（或高度风险） |
| 关 skip / 关 block / Huber / 观测级 / ⑤ | 既有否决 |
| 先全序列再定刀 | 可并行，但不替代「不清整批」下的机制候选 |

## 5. 推荐节奏

1. **先选候选**（本笔记对齐）。
2. 若选 **A**：先做 MH_05 探针矩阵（可最小 CLI / 一次性补丁），用数字否决
   「任何非空子集都 ≡④e」或锁定可用 K；再开正式设计片。
3. 若选 **B/C**：直接进设计对齐（模块边界 → 数据流 → 验收），仍要求
   MH_01 硬门 + MH_05 不毁 3.057。

**作者推荐**：候选 **A**（子集 drop + 廉价探针），因为用最少产品面验证
「部分清 slot 是否能在 3.06 与 4.565 之间插值」，再决定是否值得做 B/C。
