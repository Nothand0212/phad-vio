## 1. 结论先行

MH_02 的首次发散不是 re-anchor，也不是 GTSAM 随机数值故障。根因是一个跨
PnP 与 landmark 生命周期的**错误授权链**：

1. `tryPnpInit()` 只用左目 2D RANSAC 的 inlier 数判定成功，没有用实际 stereo
   objective 或恒速 guess 复核候选位姿；
2. source i=364 因而接受了相对恒速 guess 偏离约 **11.149 m / 2.960 rad** 的
   PnP proposal，尽管同帧 PnP 路径的优化前 stereo RMS 是 **180.552 px**，关闭
   PnP 时只有 **2.121 px**；
3. LM₁ 后，`dropCheiralityLandmarks()` 以这个尚未收敛的当前位姿 `x364` 判定三个
   landmark 在相机后方，并立即从 `landmarks_W`、整个 window 与未来复生集合中
   永久删除；随后的 LM₂ 虽把当前输出位姿拉回健康轨迹，却不会重验或恢复已删点；
4. 其中 `LandmarkId=6719` 是唯一没有同时被 mean-cull 命中的点。删除它使 i=365
   的 shared 由 17 降为 16、PnP inliers 由 12 降为 11，并把 PnP proposal 从
   **0.004804 m / 0.005849 rad** 的小修正翻成约
   **166951 m / 1.259 rad** 的灾难解；该帧仍返回 `kOk`；
5. 后续 cheirality/cull 继续抽空因子。i=370 末尾 `x370` 的 stereo degree 从
   11 变成 0，i=371 的失败 reopt 仍提交了这个 post-cull 状态，i=372 构图后
   GTSAM 精确报 `Leftover keys after elimination: x370`；
6. 连续失败让 shared 逐步降至 0，i=389 才触发 re-anchor。因此 re-anchor 只是
   下游恢复路径，不参与首次发散。

一句话根因：**一个只通过左目 inlier 数的 PnP proposal，在通过 stereo/final-pose
验证前就间接授权了不可逆 cheirality 删除；LM₂ 修正位姿却无法撤销由错误中间状态
作出的生命周期决定。**

## 3. 最小化结果

### 3.1 判定准则

根因 prefix 以 source i=372 裁尾，必须同时保持：

1. 首个 `max_window_pose_shift_m > 0.5` 恰为 source i=366；
2. 首个 `kFailed` 恰为 source i=372；
3. i=372 的完整异常 message 与 outer reference 相同。

不同 index、不同 message 或更早的其它 failure 均判为
`GREEN_OR_DIFFERENT`，避免把另一种崩溃误当原问题。

## 6. 事实、推断与剩余未知

### 已证事实

- i=364 PnP proposal 与 CV 相差 `11.149 m / 2.960 rad`，且其 stereo RMS 比
  no-PnP 路径高两个数量级；
- `dropCheiralityLandmarks()` 在 LM₁ 后立即同时修改 `landmarks_W`、window
  observations 与 `culled_ids_`；LM₂ 不会恢复这些 id；
- `6719` 在输入 i=363..368 连续出现，像素和 disparity 平滑；i=364 仅在当前
  `x364` 下被判到相机后方；
- 只改变 i=364 对这个 lifecycle 分支的处理即可 3/3 消除完整异常链；
- i=370/i=371 post-cull graph 的 `x370` degree=0，直接解释 i=372 的 GTSAM
  leftover key；
- 当前 `max_window_pose_shift_m` 有意排除了本帧，所以没在 i=365 报出当前 pose
  的 `1e5 m` 跳变。

### 有证据支持的推断

- `6719` 不是靠大 residual 混入的普通外点：若不走 cheirality 专用删除，它不会
  被 mean-cull，LM₂ 后还能作为 i=365 的第 12 个 PnP inlier，并使 proposal 回到
  4.8 mm 量级；但本诊断没有 ground-truth landmark 坐标，故不把“它绝对是正确点”
  写成事实；
- i=364 的 PnP 错解本身在 Slice ③ 尚可被后端恢复；真正把暂态变成吸收式灾难的
  是“未经 stereo/final-pose 复核的 proposal → 不可逆 lifecycle mutation”；
- i=372 的 optimizer exception 是确定的图结构后果，不是浮点随机性。

### 仍未确认但不阻塞归因

- OpenCV 在 i=364 选择该 PnP basin 的具体数值分支；修复不应依赖复现其内部迭代；
- `6719` 的 EuRoC ground-truth 3D 点身份；当前合同只需要证明 lifecycle 决策相对
  final accepted state 已过时；
- 同一缺陷在其余发散序列的触发频率。下一修复片完成 MH_02 诊断门后，才按既有
  MH_01/MH_05→全序列顺序验证，不能由本单序列外推。

## 7. 唯一推荐修复切片

### PnP stereo-consistency arbitration

下一片只修**最早授权边界**：把 `solvePnPRansac` 结果从“inlier 数够就直接采用并
掩码”改为 proposal；在修改 `candidate.observations`、backproject 新点或进入任何
永久 cull 前，用与 backend 一致的 shared stereo 约束比较 PnP proposal 与现有
CV/上一帧 guess。只有 proposal 有限、stereo score 不劣于 guess 且支持集足够时才
采用；否则完整 fallback 到 guess，并且不应用该 PnP inlier mask。

选择这个切片而不是直接关闭 PnP、关闭 cull或调阈值的原因：

- 它修复的是 Slice ③ 设计中明确写下、现已被证据推翻的
  “PnP↔guess 一致性不加门限（YAGNI）”假设；
- 它在 i=364 的**最早错误状态**之前截断链条，保留健康场景的 PnP 收益；
- 它使用实际 stereo objective 做相对仲裁，不以 MH_02 专用米制/角度 magic
  threshold 拟合一个样本；
- 它不改变 public API、session feedback、`config_hash` 或数据格式；若确需新增
  对外选项或诊断列，必须按项目合同另行对齐，不能在实现中顺带加入。

已暴露但不与主修复混打的安全债：`buildGraph()` 会给每个 window pose 无条件插值，
而 post-cull 可以把某 pose 的 factor degree 清到 0；reopt failure 还可能提交该状态。
修复片应把“所有非 prior window pose 均与 prior 连通”做成测试/内部断言证据；若
PnP 仲裁后 MH_02 不再命中该路径，再单独决定是否开 transactional-cull hardening，
不要借本片同时重写整个 cull 状态机。

### 明确否决

| 不作为下一片 | 原因 |
|---|---|
| `enable_pnp_init=false` 产品化 | 只是诊断臂，会回退 Slice ③ 已有收益 |
| 放宽 `pnp_reproj_px` / `min_pnp_inliers` | i=364 已有 26 inliers；数量门无法表达 stereo objective 一致性 |
| 直接关闭 cheirality/mean-cull | 会保留真实坏点；全程 no-cheirality 臂已有高 RMS sentinel |
| 调 `max_outlier_reopts` | no-reopt 仍有首异；问题发生在错误 proposal 已授权 lifecycle 之前 |
| 修改 zombie/drop/block | 固定 estimator trace 已复现根因，且 allow-rebirth 不消除首异 |
| 把 re-anchor 提前 | 只会更早消费污染 anchor，不能修首次错误状态 |
| 直接开 Slice ⑤/M4 | 与本根因无关，违反当前债务顺序 |

## 8. 下一片回归 seam 与验收

临时 2.6 MB raw trace 和 replay harness 已清理，不把诊断基础设施伪装成产品代码。
修复片应先新增持久 RED 测试，再实现：

1. estimator 单测构造“左目 PnP inliers 足够、但 disparity/stereo score 明显劣于
   CV guess”的小场景；断言 fallback、`pnp_success=false`、不应用 PnP mask；
2. 保留现有干净 PnP 成功用例，防止实现退化成总是 fallback；
3. 对 cull 后 graph 加定向测试：任何写入 `Values` 的 window pose 不能为 degree=0
   或与 prior 断连；先用现有行为证明 RED，再决定最小失败语义；
4. 临时恢复本诊断的 estimator-only seam 或等价 fixture，验证 MH_02 i=0..372：
