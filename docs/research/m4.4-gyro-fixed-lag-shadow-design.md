# M4.4 gyro fixed-lag read-only shadow 设计

日期：2026-08-10

状态：**B/P1 实施设计；read-only，不是 production handoff**

本文档描述当前约定，不是绝对约束，会随项目开发修订。

## 1. 目标与证据边界

P0 已确认 installed GTSAM 的 cutoff、global separator、factor slot、timestamp orphan 与
snapshot rollback 合同。P1 只回答下一层问题：

> 把当前 gyro-active rolling batch 的 causal、post-cull graph events 送入一份持久
> fixed-lag shadow 后，状态/factor 是否有界、生命周期是否无 orphan/slot 错配、newest
> estimate 是否 finite 且不发生结构性失控？

P1 不改变 `StereoVoEstimator::update()` 返回的 pose、bias、status 或现有 diagnostics；
shadow 不参与 prediction、PnP、cull、keyframe selection、window eviction、gyro alignment 或
任何下一帧输入。它只在显式 CLI probe path 下启用，默认 runtime 不构造 smoother。

shadow 每帧的新 pose/landmark 初值、landmark retirement 与 cull 决策来自 production batch。
因此一旦 shadow pose 与 batch pose 分离，后续 shadow 仍在消费 batch 驱动的 graph events；
它不是“如果上一帧已经 handoff 会怎样”的有效反事实。P1 可以证伪生命周期和数值稳定性，
不能用 shadow ATE 宣称 production 精度会提高。真实 VIO<VO 仍必须由后续单路径 candidate
run 验证。

## 2. 外部 seam 与模块边界

外部 estimator seam 保持不变：

```text
StereoVoEstimator::addImuMeasurement(...)
StereoVoEstimator::update(KeyframeMeasurement, is_keyframe)
```

新增的 public POD 仅是可选诊断：

```cpp
struct FixedLagShadowDiagnostics
{
  bool active;
  bool reset;
  FixedLagShadowReset reset_reason;
  std::uint64_t current_epoch;
  std::uint64_t cutoff_epoch;
  // bounded-state / factor ownership / newest delta fields...
};
```

`EstimatorOptions::enable_fixed_lag_shadow` 默认 false，只由 composition root 在
`--fixed-lag-shadow-probe <path>` 非空时设置，不进入 config snapshot/hash。GTSAM smoother、
timestamps、factor slots、landmark generation 全部留在 estimator PIMPL；apps 只序列化 POD，
不管理 graph。

新增独立 `FixedLagShadowProbe` CSV writer，避免改变既有 69-column `vio_state.csv`。writer
open/write/flush/schema 错误升级为 session error；与 `--no-imu` 同用是参数错误。

## 3. Shadow graph 数据流

### 3.1 激活与 bootstrap

只对本次实际使用 `FusionMode::kGyroVisual` 且 `kOk` 的 update 执行 shadow。pure visual
warm-up 与 gyro alignment commit update 只输出 `active=false`；下一次 production 真正建
AHRS graph 时才 bootstrap。

bootstrap 从该 update 已完成 mean-cull/cheirality/reopt 后的 clean active window 构造：

- 每个 window pose `X(frame_index)`；
- 一次 oldest pose prior；
- shared frozen gyro bias `W(0)` 与一次 bias prior；
- contiguous、无 gap 的 `PoseAhrsFactor`；
- 达到 `min_landmark_observations` 的显式 Point3 与真实 stereo factors；
- 初值使用 production 当帧最终 pose/bias/landmark，只用于 shadow 线性化起点。

所有 pose timestamp 使用 accepted `frame_index`；`W(0)` timestamp 使用 current epoch；
landmark timestamp 使用最后一个实际加入的 positive-disparity factor epoch。zero-disparity
observation 不建 factor，也不刷新 timestamp。

### 3.2 后续 add-only delta

每个后续 gyro-active accepted update 只添加尚未提交的：

- newest pose value；
- 新 graph landmark generation 的 Point3 value；
- 新 contiguous AHRS edge；
- 新 pose↔landmark stereo observation factor。

一个 landmark 在第二个 active-window stereo observation 到来后才满足 graph admission；此时
一次补入仍在 active window 内的第一和第二 observation。每个用户 factor 以语义 owner
去重，并用 `newFactorsIndices` 记录真实 slot。

P1 固定 `ISAM2Params.relinearizeThreshold=0`、`relinearizeSkip=1`，采用 GTSAM 官方 fixed-lag
example 的“每次考虑重线性化”诊断设置；不扫参数。`FixedLagSmoother::Result::error` 是占位值，
不得用于判定。

### 3.3 dynamic lag 与 active pose set

gyro-active production window 只从时序前缀 `pop_front`，但同时受 total≤10、keyframe≤7
约束。shadow 每次将：

```text
lag = current_frame_index - production_window.front().frame_index
```

由于 GTSAM cutoff 是严格 `<`，front epoch 恰好保留，更老 pose 被边缘化。成功 update 后，
shadow 中 `X` key 的集合必须与 production active window 一致；不一致是 probe failure，
不通过静默 reset 掩盖。

## 4. Landmark、cull 与 generation 合同

### 4.1 graph generation

domain `LandmarkId` 与 shadow GTSAM key 分离。每次 domain landmark 从 `landmarks_W` 消失，
其当前 graph generation 退休；同一 `LandmarkId` 后续重新播种时分配新 key。旧 generation
不再刷新 timestamp，自然随 lag 到期。这避免已经边缘化/仍待到期的 `L(id)` key 被错误
复用。

### 4.2 cull 是本探针唯一有意不同的语义

current rolling batch 可以在 post-opt cull 后重建整窗目标，撤销该 landmark 在窗口内的
全部贡献；fixed-lag prior 无法 unbake 已边缘化历史。P1 明确采用一个可观察而非伪等价的
shadow 语义：

1. 本帧 final production graph 已删除的 landmark 不向 shadow 添加本帧或补历史 factor；
2. 已提交的 factor 不用 `factorsToRemove` 追删，不制造 timestamp orphan；
3. generation 退休、停止新 factor/timestamp，旧信息按 fixed-lag 自然到期；
4. 每帧报告 `retired_landmark_n` 与累计 retirement，供 MH_01 判断差异规模。

这近似“边缘化前冻结当时的 outlier 决策”，只属于 read-only shadow。它既不声称保留当前
cull 语义，也不自动成为 production 方案。

### 4.3 factor ledger reconciliation

ledger 只拥有 caller 插入的 prior/AHRS/stereo factor。每次 update 前后检查：

- slot 不存在且至少一个 owner key 已边缘化：expected expiry，删除 ledger entry；
- slot 不存在但所有 owner keys 仍存在：`missing_owned_slot_n++`，本帧失败；
- `getFactors().exists(slot)` 后才允许视为 owned；
- internal `LinearContainerFactor` 不进 ledger；
- 新 slot 即使复用了旧编号，也按 `newFactorsIndices` 覆盖为新 owner。

## 5. Shared bias 与事务

P1 延续 B3 的 frozen shared bias，只用于诊断：首次插入 `W(0)`，后续只刷新 timestamp，
不重复放进 `newTheta`。每帧报告 `bias_present`、`bias_fixed` 与 shadow-vs-batch
`bias_delta_norm`。第一次 pose marginalization 后 `bias_fixed=true` 是预期事实，不是 online
bias 模型通过。

每次 shadow update 使用：

```text
candidate = accepted shadow smoother + generation map + factor ledger
```

所有增量、update、marginalization、estimate 与 invariant 检查只作用于 candidate；全部成功
才 swap commit。任何异常或 invariant 失败：丢弃 candidate，production update 也返回显式
`kFailed`/reason，使 probe run 失败；不得 catch 后 reset 继续冒充完整 shadow。

segment/re-anchor 是唯一允许的显式 lifecycle reset：当 production `segment_id` 改变时，
从该段 post-cull active graph 重新 bootstrap，并报告 `reset_reason=segment`。首次进入
gyro graph 报 `bootstrap`。

## 6. Sidecar 合同

每个 accepted IMU-on update 写一行；warm-up 行 `active=0`，gyro shadow 行 `active=1`。至少
包含：

```text
timestamp_ns,state_key,fusion_mode,active,reset,reset_reason,
current_epoch,cutoff_epoch,batch_window_n,smoother_pose_n,
smoother_landmark_n,bias_present,bias_fixed,bias_delta_norm,
user_factor_n,missing_owned_slot_n,timestamp_without_value_n,
marginalized_pose_n,retired_landmark_n,new_landmark_generation_n,
shadow_p_x,shadow_p_y,shadow_p_z,shadow_q_x,shadow_q_y,shadow_q_z,shadow_q_w,
newest_rot_delta_rad,newest_trans_delta_m
```

完整 shadow pose 只用于定位 jump/bucket，不作为有效 handoff 反事实。writer 验证单调
timestamp/state key、finite/SE(3)、inactive 零状态、active count/invariant 与 reset enum。

## 7. TDD 与验收

### 7.1 合成 seam

测试只通过 `StereoVoEstimator::update()`：

- disabled 时 diagnostics absent；enabled 的 warm-up accepted rows 为 inactive；
- gyro activation 下一 update bootstrap，pose set 与 window 相等、bias present；
- 超过 lag 后 pose count 始终有界，shared bias 进入 fixed set且无 orphan/missing slot；
- landmark 消失/同 ID 重播种分配新 generation，不复用旧 GTSAM key；
- shadow on/off 的 production status/pose/bias/factor count sequence 一致；
- overlap break 只产生显式 segment reset；
- writer 的 schema、单调性、invalid diagnostics、I/O failure 与 transaction 都有测试；
- CLI path 不改 config hash，且 `--no-imu` 明确拒绝。

### 7.2 MH_01 结构门

P1 run 使用 recovery 相同代码配置与 `--fixed-lag-shadow-probe`：

1. `est.tum`、`kf.tum`、`diag.csv` 与
   `m44_gyro_only_recovery_b3a1c0de` 逐字节相同，config hash 仍 `f6808356`；
2. sidecar accepted row 数与主轨迹一致；gyro-active support 与 B3 的 1680 rows 对齐；
3. shadow failure、timestamp orphan、missing owned slot 均为 0；
4. active pose set 每行等于 batch window，state/factor/landmark 数有界；
5. bootstrap/segment reset 数与 production segment lifecycle 一致；
6. newest delta 全 finite，报告分位数、最大值与固定时间桶，不预设无证据的精度阈值。

任一 1–5 失败，P1 否决并停在 MH_01；不通过 silent reset、放宽 invariant 或跳过坏行继续。

## 8. P1 之后

P1 通过只说明 fixed-lag shadow 的最小生命周期可运行。下一步必须依据日志另写 production
handoff 设计，至少决定：

- frozen shared bias 是否先保持，还是在 handoff 前转每状态 bias chain；
- shadow 的 frozen-cull retirement 是否能成为产品合同，或需先重做 factor admission；
- graph events 改由 candidate 自己产生后，PnP/cull/landmark 初值如何闭环；
- 单路径 candidate 如何失败回滚而不保留 batch compatibility mode。

只有单路径 MH_01 paired run 的 ATE/RPE 都严格优于 VO，才扩 MH_05/11；P1 本身不完成
M4.4。
