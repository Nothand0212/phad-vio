## 1. 目标与非目标

**Slice ① 的唯一目标**：消除「重叠断裂 → 永久拒帧」的吸收态，让 M3.2 基线里
completion 0.03–0.13 的四条序列能跑完，并保证 MH_01 的健康路径逐字节不变。

不做（属后续切片或后续里程碑）：

- 前端右目匹配加固、单帧 LK 全灭的缓解（Slice ②）；
- RANSAC 几何验证与 PnP 位姿初值（Slice ③）；
- 优化后 chi2 外点剔除与 landmark 生命周期（Slice ④）；
- 关键帧策略（Slice ⑤，会改输出语义且与 M4 边界耦合）；
- 边缘化（M6）、IMU（M4）、place recognition / 段间闭合（M8）；
- 分段 ATE 与 `phad::eval` 的任何改动。

## 2. 已对齐的决策

| 决策点 | 结论 | 依据 |
|---|---|---|
| 触发形式 | **去掉 `num_shared == 0` 的拒帧门**，重叠断裂即以新 id 重建窗口；不引入失败检测器与计时器 | Basalt 的 `connected0/(connected0+new) < 0.7 → take_kf`；VINS 后端无重叠门 |
| gauge | 新段最老帧 prior 打在**最后一个被接受的位姿**上（re-anchor），输出仍是单条连续 TUM | 本仓库无 marg prior / 无 IMU，零重叠时无任何跨断裂约束；这是「不设门」在该架构下唯一的单轨迹落地 |
| 不采用分段 | 拒绝 ORB-SLAM3 的 Atlas 路线 | 其前提是 BoW 能把段接回来（本仓库要到 M8）；其导出路径靠丢弃未 merge 的段回避 gauge 问题 |
| anchor 位姿 | **复用现有 `use_constant_velocity_init` 的位姿初值规则**，不写第二套外推 | 开启即恒速外推一个 Δt，关闭即沿用上一位姿 |
| prior 噪声 | 沿用 `prior_rotation_sigma_rad` / `prior_translation_sigma_m`（1e-4） | 它是 gauge 而非信息；段间只在全局 SE3 对齐后比较 |
| seed 门限 | 新增 `min_seed_observations`，**初始化与 re-anchor 共用**；不满足则该帧 `kRejected`、不写位姿 | 避免「1 个观测建窗口」（V2_03 现状）与「输出等于 anchor 的假位姿」把 completion 刷高 |
| 归属 | 决策在 `StereoVoEstimator::update()` 内部，`num_shared` 只有它能算 | 契约仍是「喂测量、拿位姿」，不新增两步协议 |
| 状态枚举 | `UpdateStatus` **不加新值**，re-anchor 帧就是 `kOk` | 它确实产出了估计；段边界由 `segment_id` 跳变表达 |
| 诊断可观测性 | `UpdateDiagnostics.segment_id`；`diag.csv` 加列 `segment_id`；`summary.json` 加 `robustness.reanchors` 与 `trajectory.segments` | bench 表若看不见断裂，就分不清「算法变好」与「re-anchor 变多」 |
| 评估口径 | ATE 仍为整条轨迹单次 SE3 对齐，`phad::eval` 不动 | 与历史基线可比；分段 ATE 属 YAGNI |
| 出口门控 | Slice ① 只门控 completion 与 MH_01 不回归；**ATE 只记录不门控** | 跨 coverage 的 ATE 不同量：MH_02 从评估 13% 变成评估 100%，ATE 必然上升 |
| 配置身份 | 两个新字段进 `flattenConfig()`，`config_hash` 从 `0885385a` 变更，新产物落新目录 | 配置变了就该换目录；`enable_reanchor=false` 用于复现旧行为做 A/B |

## 3. 模块边界

不新增库。改动集中在三处，依赖方向不变：

```text
phad::estimator   StereoVoEstimator  ← 段生命周期与 re-anchor 决策（本切片主体）
                  EstimatorOptions   ← enable_reanchor / min_seed_observations
                  UpdateDiagnostics  ← segment_id
        ↓ （只读诊断）
apps/offline_vo_session               ← 记录 segment_id 进 diag.csv、统计 segments/reanchors
        ↓
apps/phad_vo_bench                    ← flattenConfig 新字段；summary 新字段
        ↓
phad::bench       RunSummary          ← robustness.reanchors / trajectory.segments
```

`phad::frontend` 本切片**不动**。`phad::eval` 本切片**不动**。

## 4. 数据流与状态机

`update()` 的判定顺序：

```text
入参校验（空观测 / 非有限像素 / 非正视差 / 时间戳倒退）
   └→ kRejected（原样，不触碰状态）

计算 num_shared = |measurement.ids ∩ landmarks_W|

┌ 未初始化 ─────────────────────┐
│ initialized 且 num_shared > 0 │→ 正常路径（含 low_connectivity 标记）
└ initialized 且 num_shared == 0 → 重叠断裂
                                    │
                                    ├ !enable_reanchor → kRejected（旧行为，A/B 用）
                                    │
                                    └ num_obs >= min_seed_observations ?
                                        否 → kRejected（不污染状态，下一帧再试）
                                        是 → seedSegment(anchor)
```

`seedSegment(anchor)` 的语义（初始化与 re-anchor 共用同一函数）：

| 项 | 初始化（首段） | re-anchor（新段） |
|---|---|---|
| anchor 位姿 | `Isometry3d::Identity()` | 现有 CV 位姿初值规则的输出 |
| `window` | 清空后只放本帧 | 同 |
| `landmarks_W` | 空 → 由本帧 backproject 填 | **清空**（旧 id 已不可达）后由本帧 backproject 填 |
| `track_times` | 累积 | **继续累积**（本来就跨 prune 存活） |
| `next_frame_index` | 从 0 | **继续单调**（保证 `prior_key` 在图里唯一） |
| prior | 打在本帧，sigma 照旧 | 同 |
| `segment_id` | 0 | `++segment_id` |
| backproject 失败 | 整帧 `kRejected` + 回滚 | 同 |

事务回滚不变：任何 `kRejected` / `kFailed` 都还原 `window`、`landmarks_W`、
`track_times`、`last_accepted_T_W_B`、`prev_accepted_T_W_B`、`next_frame_index`、
`initialized`，新增还原 `segment_id`。

re-anchor 帧的位姿是**预测值**（等于 anchor），不是测量值：新段窗口只有一帧，
其 prior 与由该帧 backproject 得到的 landmark 初值自洽，优化不会移动它。
这一帧仍记 `kOk`，靠 `segment_id` 跳变让下游知道它是段首。

## 5. 接口草图

```cpp
// phad/estimator/types.hpp
struct EstimatorOptions
{
  int    window_size                = 10;
  int    min_landmark_observations  = 2;
  int    min_shared_landmarks       = 10;  // 仍只驱动 low_connectivity 标记
  int    min_seed_observations      = 10;  // 初始化与 re-anchor 共用的种子门限
  double stereo_sigma_px            = 1.0;
  double huber_k_px                 = 3.0;
  double prior_rotation_sigma_rad   = 1e-4;
  double prior_translation_sigma_m  = 1e-4;
  bool   use_constant_velocity_init = true;
  bool   enable_reanchor            = true;  // false 复现 M3.2 的永久拒帧行为
};

struct UpdateDiagnostics
{
  // …既有字段不变…
  std::uint32_t segment_id = 0;  // 每次 re-anchor 递增；0 为首段
};
```

`min_seed_observations` 默认取 10，与既有 `min_shared_landmarks` 同量级；开源侧
量级从 5（Kimera `minNrStereoInliers_`）到 50（SVO `quality_min_fts`）不等，故该值
本身是可调旋钮而非定论，进 `config_hash` 后可用 bench 扫。

## 6. 错误与诊断

**日志**（沿用 M3.2 sync 的做法）：首次 re-anchor warning 一次，结束时一条 summary
（段数、re-anchor 次数、因 seed 门限被拒的帧数）。不每帧刷屏。

**`diag.csv`**：在既有 13 列尾部追加 `segment_id`，成为 14 列。这是有意的契约变更，
需同步 `phad/estimator/README.md`、`apps/AGENTS.md` 与 `tests/apps` 的字节格式用例。
`est.tum` 格式**不变**（不加段号列，保持 evo 可直接读）。

**`summary.json`**（`schema_version` 保持 1，只加字段）：

```json
{
  "robustness": { "rejected": 0, "failed": 0, "low_connectivity": 0,
                  "cheirality": 0, "reanchors": 0 },
  "trajectory": { "…": "…", "segments": 1 }
}
```

`segments = reanchors + 1`（有首段时）。两个都写出来，便于人眼校验而不必心算。

## 7. 测试与验收

### 单元测试（`tests/estimator/`）

| 用例 | 断言 |
|---|---|
| 重叠断裂后恢复（吸收态回归锁） | 正常跑 N 帧 → 喂一帧 id 全新且观测充足 → `kOk`、`segment_id == 1`、位姿等于 CV 预测的 anchor；**再喂若干正常帧仍为 `kOk`** |
| seed 门限拒帧不污染状态 | 断裂帧观测数 < `min_seed_observations` → `kRejected`、无 estimate；下一帧观测充足 → 成功 seed |
| 旧行为可复现 | `enable_reanchor = false` → 断裂后永久 `kRejected`（与 M3.2 行为一致） |
| 初始化门限 | 首帧观测数 < `min_seed_observations` → `kRejected`；补足后成功 |
| anchor 与 CV 规则一致 | `use_constant_velocity_init` 开 → anchor 为外推位姿；关 → anchor 为上一位姿 |
| 既有用例不回归 | 窗口上限、Huber、cheirality、`low_connectivity`、`observationTimestamps` 全绿 |

### 契约测试

- `tests/apps/`：`diag.csv` 14 列表头与浮点字节格式；
- `tests/bench/`：`summary.json` 的 `reanchors` / `segments` 序列化。

### 真序列验收（M3.1 bench，11 条 EuRoC）

| 项 | 门控 |
|---|---|
| MH_01_easy | `segments == 1`、`reanchors == 0`；`est.tum` 与 `4780660/default_0885385a/est.tum` **逐字节相同**；ATE 仍 0.150155 m |
| MH_02 / V1_03 / V2_02 / V2_01 | `completion_rate` 显著上升（具体门控数字待首轮跑完后写入 roadmap） |
| V2_03_difficult | 不作为门控：sync 丢 415 右帧是数据事实，且场景本身退化 |
| ATE | **只记录不门控**；跨 coverage 不可直接比较 |
| 对照表 | `bench_table.py` 出「`4780660` 基线 vs 新 commit」两列表 |

MH_01 的字节相同是「没动到健康路径」的证明：该序列全程 `num_shared > 0`，
新代码路径不应被触发。

## 8. 后续切片边界

| 切片 | 边界（不写实现） |
|---|---|
| ② 前端右目匹配加固 | 目标是**减少 re-anchor 次数**并提高每帧观测数，不是修崩溃。三个已知洞：约 25% 的 `no_right_match` 全局常态；坏视差在 epipolar 门限之前就写回 `last_disp_px` 造成种子中毒；新 track 以 `last_disp_px = 0` 起搜。校正后左右应是行对齐的，值得考虑沿 epipolar 行的一维搜索替代二维 LK |
| ③ RANSAC + PnP | 详见 [`m3.3-slice3-pnp-design.md`](m3.3-slice3-pnp-design.md)：estimator 内 `solvePnPRansac` 初值 + 本帧 inlier 掩码；失败回退恒速；默认 `pnp_reproj_px=2.0`（勿直接抄 VINS F / Kimera stereo 阈值单位） |
| ④ / ④b / ④c / ④d / ④e 外点剔除与 landmark 生命周期 | ④ mean-cull（MH_05 不够）→ ④b LM₂（仍不够）→ ④c 拒复生+dropTracks（MH_01 健康 OK、ATE 硬门不够）→ ④d [`m3.3-slice4d-cull-threshold-design.md`](m3.3-slice4d-cull-threshold-design.md) 默认阈值 **4.0**（MH_01 硬门通过；MH_05 仍 ~4.56；见基线 §9）→ ④e [`m3.3-slice4e-multiround-reopt-design.md`](m3.3-slice4e-multiround-reopt-design.md) `max_outlier_reopts=3`（MH_01 不回归；MH_05 **持平** 4.565 → 停全序列；多轮预算未动用；见基线 §10）。下一刀建议去 Huber 末轮 / 观测级外点续片 |
