注：obs = 每帧前端 track 数（max_tracks=200）；shared = 与窗口 landmark 交集。

## 2. 核心结论

V 系列退化的**直接原因**是前端跟踪能力崩溃：

- V2_02 观测中位只有 **46 个**（MH 的 1/3），56.8% 帧 <50 个 track
- V2_03 观测中位只有 **4 个**，97.1% 帧 <50 个，68.9% 帧 shared<10
- 观测不足 → PnP 无法运行 / shared 太少 → rejected/failed 激增
  （V2_03 rejected 1058 帧，completion 0.44）

**后端公式不是主因**——同样的 7KF+3temporal BA + Huber 在 MH 系列工作良好，
V 系列喂给后端的数据就少一个量级。

## 3. 当前前端缺陷（对照公开系统）

| 缺陷 | 当前 | ORB-SLAM3 / SVO |
|---|---|---|
| CLAHE 光照均衡 | **无** | ORB-SLAM3 明确使用（论文原文） |
| 特征类型 | GFTT 角点 | ORB 描述子（可宽基线重定位） |
| max_tracks | 200 | ORB-SLAM 1000-1500 |
| 宽基线重定位 | 无（LK 丢即丢） | ORB 描述子匹配找回 |
| guided matching | 无 | TrackReferenceKeyFrame |
| 三角化 | 单帧立体 backproject | 多帧三角化（ORB-SLAM） |

V 系列特征：手持快速旋转（V1）、走廊低纹理（V2）、光照变化（V1_03/V2）。
这些场景**正是** CLAHE + 描述子重定位 + 多特征数量擅长的。

## 4. 待调研确认（3 个 subagent 进行中）

1. 前端鲁棒性 trick（CLAHE / ORB / 特征数量 / guided matching）
2. 三角化与深度估计（多帧三角化 vs 单帧 backproject）
3. 滑动窗口与鲁棒估计（Huber / RANSAC 阈值 / 观测覆盖）

## 5. 预期修复方向（待调研后定）

- **低成本高收益**：CLAHE 预处理 + max_tracks 增大（纯工程，数小时可试）
- **中等成本**：多帧三角化替代单帧 backproject
- **高成本**：ORB 描述子 + 宽基线重定位（前端重构）
