## 1. 目标

修复 Slice ⑤ 关键帧策略的全序列恶化（5 改善 / 6 恶化，V2_02 +5400% 灾难）。
根因已定位（见诊断文档 §6）：非关键帧 PnP 位姿质量差 + 关键帧选择对旋转不敏感
+ 位姿链污染。本片按 ORB-SLAM3 与 VINS 的验证做法修复，两步：

1. **A. 非关键帧 pose-only 精修**（ORB-SLAM3 `PoseOptimization` 模板）：
   RANSAC 后对 inlier 集跑 Huber 加权 LM，位姿质量从"裸 PnP"提升到"ATE 级"
2. **B. 关键帧选择修复**（VINS/DKB 模板）：
   旋转补偿视差 + 低 track 强制关键帧 + snapshot 条件更新 + 空观测级联修复

## 2. 背景与根因回顾

### 2.1 全序列结果（`d94f57b`）

| 组 | 序列 | 症状 |
|---|---|---|
| 改善 | MH_01/02/05, V1_02, V2_01 | 匀速直线，非 KF PnP 稳定 |
| 恶化 | MH_03/04, V1_01, V1_03 | 快速旋转，非 KF PnP 噪声大 |
| 灾难 | V2_02/03 | corridor 低纹理 + 视差判据失效 |

### 2.2 根因链（逐帧验证）

```
旋转段 LK 丢 track → num_shared ∈ [1,9]（< min_pnp_inliers=10）
  → 非关键帧 PnP 从不尝试 → 纯 CV 外推被无门控接受为 kOk
  → CV 链被 guess 自喂（速度冻结）→ 误差单调增长
  → 关键帧 BA 从坏初值 → 坏局部极小 → 灾难位姿写 est.tum
```

### 2.3 开源证据

| 系统 | 非 KF 位姿机制 | 可借鉴 |
|---|---|---|
| ORB-SLAM3 | RANSAC 后 pose-only LM（g2o，4×10 迭代，Huber √5.991/√7.815，外点重掩码）| **方案 A 模板** |
| VINS | 最新帧永远在窗口 BA；PnP 只是初始化器（失败保持传播值）；旋转补偿视差；低 track 强制关键帧 | **方案 B 模板** |
| DKB-SLAM | 旋转时视差阈值自适应降低（10-30 px）| 方案 B 参考 |
| RD-VIO | 旋转帧不做关键帧 | 方案 B 参考 |

## 3. 方案 A：非关键帧 pose-only 精修

### 3.1 机制

非关键帧路径（`update(keyframe=false)`）在 PnP RANSAC 之后、写 est.tum 之前，
对 inlier 集跑轻量 pose-only LM：

```
solvePnPRansac → proposal + inlier mask（现有）
        │
        ▼
pose-only LM：只优化新帧位姿，landmark 固定
  - 目标：Σ Huber( stereo reprojection residual ) over inlier 集
  - Huber δ ≈ √5.991 px（2-DOF χ² 95%）——ORB-SLAM3 mono 值
  - 3 轮迭代（ORB 4×10 是 g2o 内部迭代；我们 GTSAM LM 一次收敛即可）
  - 每轮后用 Huber 权重重掩码外点
        │
        ▼
精修后位姿 → 写 est.tum + 更新 last/prev 链
```

### 3.2 实现位置

`phad/estimator/stereo_vo_estimator.cpp` 非关键帧路径（当前 `:1243-1276`）：

```cpp
// 非关键帧：PnP RANSAC 后 pose-only 精修
if ( !keyframe )
{
  // 1. 若 PnP 成功（已有 proposal + inlier mask）
  //    → pose-only LM 精修 candidate.T_W_B
  // 2. 若 PnP 失败或 shared < min_pnp_inliers
  //    → 保持恒速 guess（但见方案 B 的门控：低 shared 时强制关键帧，
  //      或拒绝该帧不写 est.tum）
  // 3. 更新 last/prev + estimate
}
```

### 3.3 关键设计决策

| 决策点 | 结论 | 依据 |
|---|---|---|
| 优化器 | GTSAM `LevenbergMarquardtOptimizer`，只含新帧 pose 变量 | 与主路径一致，PIMPL 已藏 GTSAM |
| 因子 | `GenericStereoFactor` over inlier 集（复用现有 factor 构造）| 与 `buildGraph` 一致 |
| Huber | `Huber::WithChiSquared(5.991)`（mono 2-DOF）；stereo 用 7.815？——**对齐项目惯例**：主路径 `huber_k_px=3` 是线性阈值，此处保持 `huber_k_px` 一致性 | 不新增配置 |
| 迭代 | LM 默认收敛（`optimizer.optimize()`）| 不限制轮数；pose-only 图小（1 变量 + N 因子），收敛快 |
| 外点重掩码 | 精修后 RMS > `outlier_avg_reproj_px` 的点标记，但**不**删 landmark（非 KF 无生命周期）| 只影响该帧位姿质量 |
| 失败处理 | LM 异常（indeterminant）→ 回退 PnP 原始位姿 | 非 KF 不返回 kFailed，保持 kOk |

### 3.4 性能

pose-only 图：1 个 pose 变量 + ~10-50 个 stereo factor。LM 收敛通常 <10 次迭代。
与主路径 BA（10 pose + 数百 factor）相比可忽略。非关键帧占 ~80% 帧，整体
RTF 影响预计 <5%。

### 3.5 测试

- `NonKeyframeRefineImprovesRms`：合成数据，PnP 位姿带噪声 → 精修后 stereo RMS
  下降
- `NonKeyframeRefineKeepsInliers`：精修后 inlier 集不减少（Huber 掩码语义）
- `NonKeyframeRefineFailureFallsBack`：奇异图（landmark 共线）→ 回退 PnP 位姿
- 现有 62 个 estimator 测试不回归

## 4. 方案 B：关键帧选择修复

### 4.1 旋转补偿视差

当前视差是 raw 像素位移（`offline_vo_session.cpp:88-99`）——旋转时夸大，导致
旋转触发无 baseline 的关键帧（V1_01 根因）。

修复：用**最近两关键帧的相对旋转**把上一关键帧观测投影到当前帧，再测平移视差：

```cpp
// 旋转补偿视差
// R_lastkf_current = 从上一关键帧到当前帧的估计旋转
// p_comp = R_lastkf_current * p_lastkf   （把上一 KF 观测旋转到当前帧方向）
// parallax = mean || p_cur - p_comp ||
```

旋转估计来源（无 IMU，纯 VO）：

| 来源 | 精度 | 成本 |
|---|---|---|
| 恒速模型外推旋转（`poseInitialValue()` 的旋转部分）| 中 | 零 |
| 上一关键帧 BA 后位姿旋转（`last_accepted` 的旋转）| 高 | 零 |
| 两关键帧间恒速外推 | 中 | 零 |

选择：**用 `last_accepted_T_W_B` 的旋转**（上一接受帧的 BA/PnP 精修后旋转）——
已有、稳定、无新增计算。

```
parallax_compensated = mean over common tracks of
    || p_cur - R_prev_to_cur * p_lastkf ||
```

### 4.2 低 track 强制关键帧

VINS 规则：`last_track_num < 20 → 关键帧`。我们改为：

```cpp
// 在 isKeyframe 的 Rule 1 后插入（或 Rule 3 前）：
// 当前帧观测数 < min_pnp_inliers（10）→ 强制关键帧
if ( tracks.observations.size() < min_pnp_inliers ) return true;
```

依据：观测 <10 意味着 PnP 无法运行 → 非关键帧必退化 → 强制关键帧让 BA 处理。

### 4.3 snapshot 条件更新

当前 `updateKeyframeSnapshot` 无条件执行（`offline_vo_session.cpp:399-400`）——
estimator 拒绝关键帧时 snapshot 仍推进，导致时间兜底被重置、视差基线失同步。

修复：

```cpp
if ( is_kf && update.status == kOk )
{
  updateKeyframeSnapshot( tracks, tracks.timestamp );
}
```

### 4.4 空观测级联修复

当前 0 观测帧：survive=0/1=0 → 关键帧 → 被拒 → snapshot 仍更新 → 循环。

修复（配合 4.3）：

```cpp
// 空观测帧不更新 snapshot；且不触发关键帧（交给 estimator 拒绝）
if ( tracks.observations.empty() ) return false;  // 非关键帧 → 被拒
```

或：空观测帧仍尝试关键帧，但 snapshot 条件更新（4.3）已打破循环。

### 4.5 dt 归一化（恒速外推）

`stereo_vo_estimator.cpp:498-518` 的恒速外推无 dt 缩放：

```cpp
// 当前：predicted = T_prev * (T_prevprev⁻¹ * T_prev)
// 修复：predicted = T_prev * (T_prevprev⁻¹ * T_prev) 的 rotation/translation
//        按 (t_cur - t_prev) / (t_prev - t_prevprev) 缩放
```

这需要 pose 的插值/外推（SE(3) 对数域插值）。GTSAM 无直接 API，用 Eigen：
- 旋转：`Eigen::Quaterniond::slerp`（按 dt 比例）
- 平移：线性插值

注意：主路径（关键帧）的恒速外推也用它——**dt 归一化同时改善关键帧初值**。
但这是行为变更，需要谨慎（可能影响 MH_01 硬门）。**本片先不改主路径**，只在
非关键帧路径的门控中避免长间隙外推（见 §5 门控）。

### 4.6 测试

- `RotationCompensatedParallax`：纯旋转（无平移）→ 补偿后视差 ≈ 0 → 非关键帧
- `LowTrackForcesKeyframe`：观测 < 10 → 关键帧
- `SnapshotOnlyOnAccept`：estimator 拒绝 → snapshot 不更新
- `EmptyTracksNotSpuriousKeyframe`：0 观测 → 非关键帧（配合 4.3/4.4）
- 现有 KeyframeSelectionTest 7 个测试更新（视差语义变化）

## 5. 非关键帧门控（止损）

配合方案 A/B，非关键帧失败路径：

```
非关键帧：
  shared >= min_pnp_inliers 且 PnP 成功
    → pose-only 精修 → kOk（写 est.tum）
  shared >= min_pnp_inliers 但 PnP 失败
    → 恒速 guess + 精修（无 inlier 集 → 精修跳过）→ kOk（写 est.tum）
  shared < min_pnp_inliers
    → 方案 B 已强制关键帧（观测 <10）→ 此路径应罕见
    → 若仍进入：kRejected（不写 est.tum，不更新链）
```

关键行为变更：**shared < min_pnp_inliers 的非关键帧被拒绝**（当前是 kOk + CV guess）。
这直接修复审计发现 1-2（无门控接受 + 链自喂）。

| 风险 | 缓解 |
|---|---|
| pose-only 精修改变 MH_01 数字 | 硬门兜底；MH_01 非 KF 少（16%），影响小 |
