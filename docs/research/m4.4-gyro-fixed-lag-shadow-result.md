## 1. 结论

P0 与 P1 已完成预定范围：本机 GTSAM 的 cutoff、separator、factor slot、timestamp
orphan 与 full-snapshot rollback 合同均由定向测试锁定；持久 fixed-lag shadow 在完整
MH_01 gyro-active suffix 上保持 pose/factor/state 有界，没有 missing owned slot、timestamp
orphan、异常或 silent reset，并且不改变 production 主产物。

这只证明 **lifecycle vertical slice 可运行**。P1 不能晋级为 production handoff：

- shadow 的新 pose/landmark 初值、track/schedule 与 graph admission 仍来自 production
  rolling batch，不是闭环候选；
- newest shadow-vs-batch translation delta 随时间扩大，p50/p95/max 为
  `0.208/0.606/0.643 m`；rotation 为 `0.0310/0.0554/0.0620 rad`；
- active suffix 只有 5 次 production mean-cull，retirement 与 translation delta 相关系数
  为负且很弱，现有证据不支持把差异归因于 cull；
- shared bias delta 最大仅 `1.95e-8 rad/s`，但首次 marginalization 后 bias 有 1674 行处于
  fixed set；这证明 P1 的 frozen-bias 语义按设计发生，不证明 online bias 模型成立；
- 直接把该 newest pose 交给 production 会把尚未闭环验证的差异写入下一帧 PnP、cull、
  selector 与 landmark 初值，当前没有证据授权。

因此 P1 通过、direct handoff 否决。下一片若继续 fixed-lag，应先让 candidate 自己拥有
递归 pose/landmark state 与 graph events，并保持 read-only；不得把本 sidecar 拼成
“shadow ATE”冒充有效反事实。

## 2. 实现范围

### 2.1 P0 installed-library contract probe

`tests/estimator/fixed_lag_contract_test.cpp` 固定五类 installed GTSAM 行为：

1. cutoff 严格 `<`，front epoch 恰好保留；
2. 每帧刷新 timestamp 的 shared separator 存活，并在相邻 pose marginalization 后进入
   `ISAM2::fixedVariables_`；
3. `newFactorsIndices` 是 caller factor 的真实 slot，允许 unused slot 复用；
4. 删除某 key 的最后一个 factor 会留下 timestamp orphan，后续到期可抛异常；
5. candidate update 失败后，复制的 smoother+ledger snapshot 能完整恢复 accepted state。

### 2.2 P1 estimator shadow

`StereoVoEstimator` PIMPL 内新增默认关闭的 shadow state：

- `IncrementalFixedLagSmoother`、timestamp、factor-slot ledger 与 landmark generation 不
  越过 estimator 边界；
- bootstrap 消费第一次真实 gyro graph 的 post-cull active window；后续只添加新 pose、
  AHRS、stereo observation 与递增 `q` generation；
- AHRS factor owner 精确登记 `X_i/X_j/W(0)` 三键；
- lag 动态取 `current_epoch - window.front().frame_index`，成功后 pose key set 必须与
  production window 完全相同；
- shared `W(0)` 只刷新 timestamp；landmark 消失或 value 到期时 retirement，重播种分配
  新 generation；
- 每帧深拷贝 accepted smoother+ledger，在 candidate 上完成 update、slot/orphan、pose-set
  与 finite 检查后才 swap；异常使 production update 显式 `kFailed`；
- 首次 gyro graph 报 `bootstrap`；re-anchor 是唯一允许的 `segment` reset；segment 首帧
  可合法为 `pose=1, landmark=0`，下一帧重新 admission Point3。

### 2.3 composition root 与离线分析

`--fixed-lag-shadow-probe <path>` 是 CLI-only path：writer 成功打开后才设置
`EstimatorOptions::enable_fixed_lag_shadow`；与 `--no-imu` 同用时报参数错误；路径不进入
`config_hash`。30 列 CSV writer 验证单调 timestamp/state key、mode/reset、bounded pose
set、bias/factor、slot/orphan、SE(3) 与 finite；I/O 或 schema 错误升级为 session error。

`scripts/gyro_fixed_lag_shadow_probe.py` 再独立校验同一合同，输出 canonical JSON、
p50/p95/p99/max 与固定 10 s bucket。它不读取 GT、不计算 shadow ATE。

### 4.4 cull/churn 归因边界

同 timestamp 连接 active sidecar 与 production `diag.csv`：

```text
production mean-cull: sum=5, nonzero rows=3
retirement:           sum=3172, nonzero rows=1183
new generation:       sum=3222, nonzero rows=692
retirement without same-row cull: 1180 rows
corr(translation delta, retirement/new/cull) = -0.130 / -0.114 / -0.011
```

事实是 visible-track/window 生命周期产生大量 generation churn，而 production mean-cull
在 active suffix 极少；最大 delta 行也没有 same-row cull。由此只能排除“当前差异主要由
same-row mean-cull 驱动”的简单解释，不能证明 history prior、schedule feedback 或闭环
candidate 中的真正因果。

## 6. 决策

P0/P1 的推荐刀完成，结论不是“fixed-lag 已可替换 batch”，而是：

1. installed API 与最小持久 lifecycle 可用；
2. frozen shared bias 与 bounded graph 按设计发生；
3. production 零扰动门通过；
4. batch-driven shadow 与 rolling batch 的 newest estimate 发生持续、显著分离；
5. 因 shadow 不是闭环反事实，不评估其 ATE，也不直接 handoff。

下一片需要单独对齐。推荐先做 **candidate-owned read-only closed-loop shadow**：沿用 frozen
`W(0)`，让 candidate 自己递归产生 pose/landmark estimate 与 graph admission，并记录独立
trajectory；仍不反馈 production selector。若该层结构/健康不过门，停止 fixed-lag 路线；
若通过，再设计单路径 production candidate 与 paired MH_01 门。

备选是直接 production handoff（风险最高，当前证据不支持），或停止 fixed-lag、回到
local-batch 的其他模型改动。无论选择哪一项，M4.4 的最终门仍是 paired exact-common
ATE 与 1 s RPE 都严格 `VIO < VO`；P1 本身不完成 M4.4。
