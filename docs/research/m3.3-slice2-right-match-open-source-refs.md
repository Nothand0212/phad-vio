## 1. 要回答的问题

Slice ② 的目标是把 `no_right_match` 的 25% 全局常态压下去。设计稿把原因归为三个洞：
坏视差写回 `last_disp_px` 造成种子中毒、新 track 以 `last_disp_px = 0` 起搜、
单帧 LK 全灭。开工前要回答的是：**参考实现给右目搜索什么初值、什么范围，
以及它们是否维护「上一帧视差」这种 per-track 记忆。**

## 2. 先修正本仓库的现状描述

`matchRight()` 里 `right_seed`（由 `last_disp_px` 构造）**当前不生效**：

```215:217:phad/frontend/stereo_tracker.cpp
      cv::calcOpticalFlowPyrLK( left, right, left_pts, right_pts,
                                forward_status, forward_error, win,
                                options.lk_pyramid_levels );
```

`cv::calcOpticalFlowPyrLK` 的签名是
`(prevImg, nextImg, prevPts, nextPts, status, err, winSize = Size(21,21),
maxLevel = 3, criteria = …, flags = 0, minEigThreshold = 1e-4)`。调用只给到第 8 个
实参，`flags` 取默认 `0`；未置 `OPTFLOW_USE_INITIAL_FLOW` 时 OpenCV 会在迭代前把
`prevPts` 拷进 `nextPts`，把调用方写好的初值覆盖掉。

因此诊断文档第 6 节的两个洞需要改写：

- **种子中毒目前是惰性的**：坏视差确实被写回 `last_disp_px`，但从未影响过搜索。
  它是「一旦启用初值就会立刻变成真 bug」的隐患，不是 MH_02 崩段的现行成因。
- **「新 track 零种子」实际是「所有 track 零种子」**：每个 track 每帧都从左目同一
  像素坐标在右图起搜，EuRoC 上典型视差 10–50 px 全靠 3 层金字塔兜。

这条同时说明：25% 的 `no_right_match` 不能归因于种子，得另找解释。

## 3. 逐项目结论

### 3.1 VINS-Fusion —— 与本仓库现状完全同型

`feature_tracker.cpp` 里时序 LK 与右目 LK 用了不同策略。时序 LK 在有预测时用初值，
并在成功数 `< 10` 时退回无初值重试：

```cpp
// vins_estimator/src/featureTracker/feature_tracker.cpp:117
if(hasPrediction)
{
    cur_pts = predict_pts;
    cv::calcOpticalFlowPyrLK(prev_img, cur_img, prev_pts, cur_pts, status, err,
        cv::Size(21, 21), 1,
        cv::TermCriteria(cv::TermCriteria::COUNT+cv::TermCriteria::EPS, 30, 0.01),
        cv::OPTFLOW_USE_INITIAL_FLOW);
    …
    if (succ_num < 10)
       cv::calcOpticalFlowPyrLK(prev_img, cur_img, prev_pts, cur_pts, status, err,
                                cv::Size(21, 21), 3);
}
```

注意用初值时金字塔降到 **1 层**，无初值时才用 3 层——初值与金字塔层数是互相替代的
两种覆盖搜索范围的手段。

右目匹配则**没有任何初值**，和本仓库现状一模一样：

```cpp
// :216
cv::calcOpticalFlowPyrLK(cur_img, rightImg, cur_pts, cur_right_pts, status, err,
                         cv::Size(21, 21), 3);
// reverse check cur right ---- cur left
cv::calcOpticalFlowPyrLK(rightImg, cur_img, cur_right_pts, reverseLeftPts,
                         statusRightLeft, err, cv::Size(21, 21), 3);
```

`cur_right_pts` 每帧从零重算，**不存在 per-track 视差记忆**。反向检查阈值同为
FB 距离，失败即丢弃该右点（左目 track 存活）。

### 3.2 lk-vio —— 用 3D 重投影作初值

时序与右目两处都置了 `OPTFLOW_USE_INITIAL_FLOW`（11 px 窗、**5 层**）。右目初值
不是视差记忆，而是把已三角化的地图点投影到右相机：

```cpp
// src/lk_vio/frontend.cpp:367
auto pt_in_map = feat->map_point_.lock();
if ( pt_in_map )
{
  Eigen::Vector2d p = right_camera_->world2pixel( pt_in_map->getPosition(),
      current_frame_->getRelativePose() * reference_kf_->getPose() );
  right_cam_kps.push_back( cv::Point2f( p.x(), p.y() ) );
}
else
{
  right_cam_kps.push_back( feat->kp_position_.pt );   // 退回左目像素，即视差 0
}
```

即：**有 3D 就用几何，没 3D 就用视差 0**。代价是前端要读后端的地图点。

### 3.3 Basalt —— 唯一「有视差记忆」的，但形式不同

Basalt 不是每帧重做左右匹配。`processFrame()` 对**每个相机**独立做时序跟踪：

```cpp
// include/basalt/optical_flow/patch_optical_flow.h:157
for (size_t i = 0; i < calib.intrinsics.size(); i++) {
  trackPoints(old_pyramid->at(i), pyramid->at(i),
              transforms->observations[i], new_transforms->observations[i]);
}
```

左右匹配只在**新点诞生时**做一次，初值是左目位置（等价视差 0）：

```cpp
// :339 addPoints()
if (calib.intrinsics.size() > 1) {
  trackPoints(pyramid->at(0), pyramid->at(1), new_poses0, new_poses1);
```

`trackPoints` 内部自带 FB 检查（`optical_flow_max_recovered_dist2 = 0.09`，
即 0.3 px），金字塔 `optical_flow_levels = 3`。

于是右目点的每帧初值是**上一帧该点自己的右目位置**——这是「视差记忆」的最强形式，
但它由一条独立的右目 track 承载，而不是一个标量 `last_disp_px`。配套的纠错是
`filterPoints()`：每帧用 essential matrix 的 epipolar error
（`optical_flow_epipolar_error = 0.005`，归一化平面）复检，超限的点从**左右两侧
同时删除**。

### 3.4 Kimera-VIO —— 无初值，搜索范围由最小深度导出

不用 LK，用沿 epipolar stripe 的模板匹配。范围是显式算出来的：

```cpp
// src/frontend/StereoMatcher.cpp:219
// dimension of the search space in right camera is defined by min depth:
// depth = fx * b / disparity => max disparity = fx * b / minDepth;
int stripe_cols =
    std::round(fx * baseline / stereo_matching_params_.min_point_dist_) +
    stereo_matching_params_.templ_cols_ + 4;  // 4 is a tolerance
```

参数默认 `templ_cols_ = 101`、`templ_rows_ = 11`、`stripe_extra_rows_ = 0`、
`min_point_dist_ = 0.1 m`、`max_point_dist_ = 15 m`。stripe 只铺在左特征 x 的
**左侧**（因为 `disparity = left.x - right.x > 0`），`matchTemplate` 用
`CV_TM_SQDIFF` 全范围穷举取最小，再 `cornerSubPix` 亚像素。`stripe_extra_rows_ = 0`
意味着默认**只搜同一行**，完全信任校正。

无 per-track 记忆；`getRightKeypointsRectified()` 每帧对所有左特征重算。
源码注释里 `TODO(Toni): Here we could perform bidirectional checking...`——连
反向检查都没有。

### 3.5 ORB-SLAM3 —— 无初值，视差范围 `[0, fx*b/baseline]`

`Frame::ComputeStereoMatches()`：先按 y 建右目关键点的行索引表（半径
`2 * scaleFactor[octave]`），再在视差范围内按描述子距离选候选：

```cpp
// src/Frame.cc:841
const float minZ = mb;          // 最小深度 = 基线长度
const float minD = 0;
const float maxD = mbf/minZ;
…
const float minU = uL-maxD;
const float maxU = uL-minD;
```

选中后在该 octave 的金字塔图上做 **±5 px 滑窗 SAD**（`w = 5` 的 11×11 块，
`L = 5`），命中边界（`bestincR == ±L`）即放弃，再抛物线拟合取亚像素
（`deltaR` 超出 ±1 即放弃）。最后一道是**全局中位数剔除**：

```cpp
// :968
const float median = vDistIdx[vDistIdx.size()/2].first;
const float thDist = 1.5f*1.4f*median;
```

超过 `thDist` 的匹配整批作废。无 per-track 记忆。

### 3.6 SVO Pro —— 场景级逆深度先验，非 per-track

`StereoTriangulation` 只对**新特征**调 `findEpipolarMatchDirect`，传的是一组
场景级常量而不是 per-track 历史：

```cpp
// svo/include/svo/stereo_triangulation.h:15
double mean_depth_inv = 1.0/3.0;
double min_depth_inv  = 1.0/1.0;
double max_depth_inv  = 1.0/50.0;
```

搜索沿 epipolar 线按 `epi_length_pyramid_ / 0.7` 步（上限
`max_epi_search_steps = 500`）做 ZMSSD patch 打分。已三角化的点靠时序直接法与
`reprojector` 维护，不再重做左右匹配。

## 4. 对照汇总

| 项目 | 右目匹配方式 | 搜索初值 | 搜索范围的来源 | per-track 视差记忆 | 坏匹配的纠正 |
|---|---|---|---|---|---|
| **本仓库现状** | 每帧左→右 2D LK（21 px / 3 层） | **无**（`flags = 0`，初值被覆盖） | 隐式，金字塔层数 | 字段存在但不生效 | FB 0.5 px + epipolar 1.5 px 门限 |
| VINS-Fusion | 每帧左→右 2D LK（21 px / 3 层） | 无 | 隐式，金字塔层数 | 无 | 反向 LK 检查 |
| lk-vio | 每帧左→右 2D LK（11 px / 5 层） | **地图点重投影**；无地图点则视差 0 | 隐式 | 无（用 3D 几何替代） | 无独立复检 |
| Basalt | 右目**独立时序** patch LK；左→右只在新点做一次 | **上一帧该点的右目位置** | 隐式，3 层 | **有**（以右目 track 承载） | 每帧 essential-matrix epipolar 复检，超限左右同删 |
| Kimera-VIO | 沿 epipolar stripe 模板匹配（101×11） | 无 | **显式**：`fx*b/min_point_dist`（0.1 m） | 无 | 无（连双向检查都没有） |
| ORB-SLAM3 | 行索引 + 描述子，再 ±5 px 滑窗 SAD | 无 | **显式**：视差 ∈ `[0, fx*b/baseline]` | 无 | SAD 距离全局中位数 ×2.1 剔除 |
| SVO Pro | epipolar 线 ZMSSD 搜索，只对新特征 | 场景级 `mean_depth_inv = 1/3 m` | **显式**：逆深度 `[1/1, 1/50] m` | 无 | — |

## 5. 结论

1. **「per-track 上一帧视差作 LK 初值」在参考实现里没有先例。** 六个项目分成两条路线：
   要么不记忆、每帧重算（VINS / Kimera / ORB-SLAM3 / SVO），要么根本不每帧重做左右
   匹配（Basalt / SVO 对已三角化点）。`last_disp_px` 这个字段本身是本仓库的自造物。
2. **显式视差范围比初值更普遍。** Kimera 与 ORB-SLAM3 都从深度下限反推最大视差并
   把搜索限制在 `[0, fx*b/min_depth]` 的一维区间。本仓库有 `min_depth_m` /
   `max_depth_m`，但只用作**事后门限**（算完 disparity 再判），没有约束搜索本身——
   2D LK 可以收敛到右图任意位置，包括视差为负或跨行的地方。
3. **行约束是被普遍信任的。** Kimera 默认 `stripe_extra_rows_ = 0`（只搜同一行），
   ORB-SLAM3 的行索引半径按 octave 只有几像素。本仓库用 2D LK 允许 y 自由漂移，
   再用 `max_epipolar_px = 1.5` 事后拒绝——这等价于「先让它走错，再扔掉」，
   直接解释了为什么 `epipolar_p95` 能冲到 8–68 px 而 `no_right_match` 稳定在 25%。
4. **有记忆就必须有每帧复检。** 唯一有记忆的 Basalt 配了 `filterPoints()` 的
   essential-matrix 复检，且失败时左右观测同删。若本仓库要启用初值记忆，必须同时
   决定「坏匹配如何不污染下一帧」，否则就是把惰性隐患变成真 bug。
5. **lk-vio 的重投影路线在本仓库不可用**：它要求前端读后端地图点，与
   `docs/architecture.md` 的单向依赖（estimator 不依赖 frontend，frontend 也不
   依赖 estimator）冲突。记录在此以说明排除理由。

## 6. 给设计的输入

按「改动量 / 与参考实现的距离」排序的三条可选路线：

| 路线 | 内容 | 最接近的参考 | 代价 |
|---|---|---|---|
| **R1 一维化** | 保留每帧左→右匹配，但把搜索约束到 epipolar 行与 `[fx*b/max_depth, fx*b/min_depth]` 的视差区间；用块匹配（SAD/NCC）+ 亚像素取代 2D LK | Kimera + ORB-SLAM3 | 换匹配器；`last_disp_px` 直接删除 |
| **R2 右目时序 track** | 给每个 track 维护右目像素，右目做时序 LK；左→右只在新 track 诞生时做一次；每帧 epipolar 复检，失败即左右同删 | Basalt | 结构性改动，`LiveTrack` 增右目状态 |
| **R3 启用初值 + 加固** | 置 `OPTFLOW_USE_INITIAL_FLOW`，把 `last_disp_px` 写回移到门限之后，新 track 用邻域中位视差 | 无先例（最接近 lk-vio 的退化形式） | 最小；但等于自造机制 |

R1 与 R3 正交：R1 解决「搜索范围不受约束」，R3 解决「初值」。R2 同时覆盖两者但
改动最大。三者都能用 `phad_stereo_frontend_probe` 的 `valid_rate` /
`no_right_match_rate` / `epipolar_p95_px` 前后对照来测量。
