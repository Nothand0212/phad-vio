## 3. 关键发现

### 3.1 ④g ≡ ④e（bit-identical）

| 产物 | ④g vs ④e |
|---|---|
| `diag.csv`（2273 行） | **逐行相同** |
| `est.tum`（2268 poses） | **逐 pose 相同**（`max‖e−g‖=0`） |

结论：**对 MH_05 这条序列，④g 的「skip 当帧 + 下帧 process 前 flush」与 ④e 的「当帧立即 drop」观测等价。**

循环结构解释：

```text
④e: process(i) → estimate(i) → dropTracks(culled) → … → process(i+1)
④g: process(i) → estimate(i) → pending ∪= culled → … → flush/drop → process(i+1)
```

相对 `process(i+1)`，两者都在其前清掉同一批 track；MH_05 仅一次大剔 skip（i=425），故全局轨迹坍缩到同一条。

## 4. 假说判定

| 假说 | 判定 | 理由 |
|---|---|---|
| H1 延后一帧仍太早 | **否决（作为独立机制）** | 一帧延后 ≡ 立即 drop（对下一 `process`）；再「晚一点但同批 drop」不会逃出该等价类，除非跨过更多帧且改变 track 图 |
| H2 drop 本身伤 ATE | **成立** | 同一 32-id 集在 `process(426)` 前被 drop → ④e 灾难；④f 永不 drop → ATE 3.06 |

补充：Probe B「zombie×block 导致 i=429 低残差大位移」在 ④f 上仍成立（zombie 持续、shared 更窄），但 **全局 ATE 仍优于清 zombie 的 drop 路径**。清 zombie ≠ 改善 ATE。

## 5. 对 Probe B §6 出口的修正

§6 推荐「skip 后对完整 `culled_landmark_ids` 精确 `dropTracks`」在机制上已实现（④g），且 zombie 归零，但 **ATE 软门失败并 bit-collapse 到 ④e**。

因此该出口应降级为：**已证伪作为 ATE 改善刀**；保留其诊断价值（证明一帧 defer ≡ immediate drop）。
