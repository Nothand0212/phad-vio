# M4.4 VO/VIO common support 与误差分解上游对照

日期：2026-08-09

状态：**一手资料调研完成；common-support/bias 只读 probe 已回填；支持下一刀只保留
`CombinedImuFactor`；未修改 production**

本文档描述当前约定，不是绝对约束，会随项目开发修订。

## 1. 结论先行

1. **三方 common timestamp support 已排除“只是 coverage 不同”的解释。** MH_01
   exact common support 有 `3240` poses；在共同 GT support 上实际 matched `3218`、
   1 秒 RPE pairs `3198`。VIO/VO ATE 为 `0.122337 / 0.0831874 m`，RPE 为
   `0.0229568 / 0.0183341 m`，仍为 **FAIL**。初始化缺失的 442 帧仍应作为独立启动
   指标，但不是当前 post-init 精度差距的充分解释。
2. **common support 只消除了比较混杂，没有给出根因。** 后续完整误差分解仍应输出：
   首个短窗口冻结 alignment 后的 suffix drift、相对首帧 drift，以及不用于校正的
   Sim(3) scale diagnostic。stereo 的主指标不得用 Sim(3) 修正。
3. **最可直接迁移的日志模式来自 Kimera：同一 timestamp 同时记 posterior
   `pose/velocity/bias` 和 PIM-only predicted `pose/velocity`。** 两者之差就是视觉/图
   优化对惯性外推的 correction，可把“IMU 模型先预测错”与“图优化/视觉把状态拉错”
   分开。再配合 EuRoC GT 的 velocity、gyro bias、acc bias，可直接检查初始化和
   post-init 漂移，而不必先扫参数。
4. **初始化不能只看最终 ATE。** Kimera、VINS 与 ORB-SLAM3 都把 gyro bias、gravity、
   velocity（monocular 时再加 scale）作为显式初始化量或质量门。phad-vio 当前静止
   初始化由同一个 `mean_acc` 同时决定 roll/pitch 与 acc bias，存在可观测性混淆；
   `V=0` 也只是静止假设。若 Combined-only 候选仍不够，后继诊断应直接记录并对 GT
   检查 `gravity angle / v0 / bg0 / ba0`，而不是先改变初始化器。
5. **当前源码存在已经确认的 factor-model 重复约束。**
   `CombinedImuFactor` 已在 15 维联合协方差中包含 bias random walk；GTSAM 的
   Combined 示例不再加 bias `BetweenFactor`，普通 `ImuFactor` 示例才加。phad-vio
   当前两者并用且使用同一组 RW 参数，相当于对同一个 bias increment 再施加一次独立
   约束。本地核对也确认两者消费相同 RW 与同一 bias increment。**这足以支持下一刀
   删除显式 `BetweenFactor`、只保留 `CombinedImuFactor`，以恢复 GTSAM Combined
   模型合同。** 它是否改善 ATE/RPE 仍须由隔离 A/B 验证，不能把“模型修正有依据”
   等同于“M4.4 已过门”。
6. **当前“固定窗”不是成熟实现常见的 marginalization history。** phad-vio 每次删除
   最老状态后重建整图，并以新窗头当前 `X/V/B` 重新置 prior；VINS-Fusion 显式携带
   marginalization factor，Kimera 使用 `IncrementalFixedLagSmoother`。后继 probe 应
   记录 `prior_key` 变化、窗头 prior target、PIM/posterior correction 与 factor cost。
   没有独立于共同时间趋势的证据时，不应把 drift 归因于重锚。

因此 P0a（common support + GT bias 对齐）已经给出足够的选刀证据：M4.4 下一刀建议
进入**单变量 factor-model 修正**，只移除显式 bias `BetweenFactor`，保留 Combined
内部 bias RW，不同时扫 noise/prior、不改初始化与 window policy。本文后半仍保留
完整 P0/P1 日志合同，供该候选未过门时继续定位。

## 2. 本仓库问题定义

### 2.1 已有事实

MH_01 当前锚点如下。数值来自现有 checkpoint；本轮没有重跑 benchmark。

| 路径 | ATE trans RMSE (m) | RPE trans RMSE (m) | coverage | 输出/输入帧 |
|---|---:|---:|---:|---:|
| pure VO | `0.080964` | `0.017781` | `1.0` | 全序列 |
| VIO | `0.1223373968` | `0.0229567901` | `0.8799239336` | `3240 / 3682` |

VIO 的 `442` 个 rejected frame 全部位于初始化前缀；post-init 有 `3240` 个输出，
`segments/reanchors/failed=1/0/0`，且此前 shadow probe 已确认 post-init IMU evidence
连续有效。详见 [M4.4 checkpoint](../benchmark/m4.4/README.md) 与
[fixed-epoch shadow 结果](m4.4-keyframe-shadow-probe.md)。

随后只读 common-support probe 使用两个 run 的 exact pose timestamps 取交集，并把
两条裁剪后 trajectory 交给同一个 `phad_traj_eval`：

| support | common poses | GT matched | RPE pairs | VIO ATE / RPE (m) | VO ATE / RPE (m) | verdict |
|---|---:|---:|---:|---:|---:|---|
| post-init exact common | 3240 | 3218 | 3198 | `0.122337 / 0.0229568` | `0.0831874 / 0.0183341` | **FAIL** |

ATE/RPE delta 分别为 `+0.0391496 m`、`+0.0046227 m`（VIO−VO）。22 个 common
pose 位于 GT 可评估范围外，两条路径共同丢弃；因此 metric inputs 与 endpoint count
一致。该结果确认 VIO 的 post-init 退化不是 VO 完整前缀单独造成的。

GT bias 只读 probe 在同一可评估 support 上得到 3218 个样本；分箱 bias error 与轨迹
退化存在中等相关，但两者都有显著时间自相关，不能据此单独确定因果方向。它支持继续
检查 bias evolution constraint，不支持直接把 acc/gyro bias 初始化宣布为唯一根因。

### 2.2 本轮要回答的问题

- 初始化前缀缺失对 VO/VIO 数值差多少；
- post-init 第一个状态是否已有 gravity、scale、velocity、gyro/acc bias 误差；
- 误差是早期常量偏差，还是随时间增长的 drift；
- 惯性外推本身错，还是 posterior correction 把正确外推拉错；
- `IMU noise / bias prior / bias RW` 的权重是否与实际 residual 一致；
- 误差是否与窗头 prior 迁移同步，从而支持“rebuild-and-reprior”归因。

### 2.3 非目标

- 不把缺失的 442 帧插值成 VIO 成功输出；
- 不用 Sim(3) 把 stereo 尺度误差从主指标中消掉；
- 不先实现 VINS/ORB 的初始化器；
- 本研究文件本身不改 factor；下一独立 slice 可只删除 bias `BetweenFactor`，但不得
  同时改 noise/prior 或 window policy；
- 不把相关性当因果；若 P0 只有相关证据，再单独设计只读 counterfactual shadow。

### 4.2 GTSAM：先保留 PIM prediction，再看 posterior；Combined 已包含 bias walk

GTSAM Combined 示例的模式是：

1. 由传感器 noise density 与 bias RW 设置 `PreintegratedCombinedMeasurements`；
2. 用上一 posterior state/bias 调 `predict()` 得到新状态初值；
3. 加 `CombinedImuFactor` 与外部 correction，优化后再更新 state/bias；
4. 在 correction timestamp 同时输出 estimate 与 reference。

证据：

- [noise 与 bias RW L99-L132](https://github.com/borglab/gtsam/blob/2f3e56c0ddbd3a1aa54ed043643b553d26a069f6/examples/CombinedImuFactorsExample.cpp#L99-L132)
- [state/bias priors L153-L199](https://github.com/borglab/gtsam/blob/2f3e56c0ddbd3a1aa54ed043643b553d26a069f6/examples/CombinedImuFactorsExample.cpp#L153-L199)
- [Combined factor、PIM prediction 与 posterior L238-L296](https://github.com/borglab/gtsam/blob/2f3e56c0ddbd3a1aa54ed043643b553d26a069f6/examples/CombinedImuFactorsExample.cpp#L238-L296)

`CombinedImuFactor` 的 15 维 residual 顺序是 rotation、position、velocity、
accelerometer-bias increment、gyro-bias increment；其 covariance 同时传播 bias RW
并保留 preintegration 与 bias 的相关性：

- [Combined factor 合同 L195-L209](https://github.com/borglab/gtsam/blob/2f3e56c0ddbd3a1aa54ed043643b553d26a069f6/gtsam/navigation/CombinedImuFactor.h#L195-L209)
- [bias covariance 传播 L95-L160](https://github.com/borglab/gtsam/blob/2f3e56c0ddbd3a1aa54ed043643b553d26a069f6/gtsam/navigation/CombinedImuFactor.cpp#L95-L160)
- [15 维 residual 组装 L187-L248](https://github.com/borglab/gtsam/blob/2f3e56c0ddbd3a1aa54ed043643b553d26a069f6/gtsam/navigation/CombinedImuFactor.cpp#L187-L248)

官方 Combined 示例只加 `CombinedImuFactor`；相反，普通 `ImuFactor` 不含下一时刻
bias，因此其示例另加 bias `BetweenFactor`：

- [ordinary ImuFactor + BetweenFactor L253-L263](https://github.com/borglab/gtsam/blob/2f3e56c0ddbd3a1aa54ed043643b553d26a069f6/examples/ImuFactorsExample.cpp#L253-L263)

**可迁移模式：** 同 timestamp 保留 `PIM prediction` 与 `posterior`；记录 factor 的
raw residual 和总 Mahalanobis cost。

**重要限制：** Combined 的 full covariance 有 cross-block correlation。把 whitening
后的 15 个分量机械切成 R/P/V/Ba/Bg 并分别求和，不再具有严格的物理分块含义。probe
应记录：

- raw 15-vector 及五个 raw block norm；
- full `rᵀΣ⁻¹r`；
- 如需分块标准化，只能记 `r_kᵀΣ_kk⁻¹r_k`，并明确它忽略 cross-correlation、各块
  不可相加成 full cost。

## 5. 与 phad-vio 当前实现的逐项对照

### 5.1 初始化

当前静止初始化在 0.5 秒窗口逐轴检查 gyro/acc std，随后：

- `gravity_dir = normalize(mean_acc)`；
- 用该方向决定 roll/pitch；
- `ba0 = mean_acc - configured_g * gravity_dir`；
- `bg0 = mean_gyro`；
- `v0 = 0`。

对应源码见
[`runStaticInitDetection()`](../../phad/estimator/stereo_vo_estimator.cpp#L754-L844)。

**已确认事实：** `ba0` 与 `gravity_dir` 由同一 `mean_acc` 构造，且该 `ba0` 必然平行
于 `mean_acc`。单个静止窗口不能同时独立观测 gravity tilt、完整三轴 acc bias 与
未知线加速度。

**工程推断：** 如果 EuRoC GT 显示初始化窗口确实静止，而 `ba0` 的 gravity-tangent
分量仍明显错误，则这更符合 tilt/acc-bias 混淆；若窗口内 GT velocity 或 bias-corrected
specific force 明显变化，则先归因于静止假设被破坏。两者都不能只靠最终 ATE 区分。

### 5.2 post-init 图与换窗

当前实现：

1. 用上一 posterior `X/V/B` 进行 PIM prediction；
2. IMU-on 时只 `pop_front()` 保持 IMU segment 连续；
3. 每次从当前 window 全量重建 graph；
4. 对新窗头当前 `X/V/B` 重新加 prior；
5. 每个有效 interval 同时加 `CombinedImuFactor` 和 bias `BetweenFactor`。

证据：

- [PIM prediction](../../phad/estimator/stereo_vo_estimator.cpp#L691-L751)
- [窗头 priors 与 IMU factors](../../phad/estimator/stereo_vo_estimator.cpp#L1244-L1344)
- [IMU `pop_front()` 与 rebuild](../../phad/estimator/stereo_vo_estimator.cpp#L2267-L2349)

**术语约定：** 本文把它称为 `rebuild-and-reprior`，避免与携带 Schur complement
历史信息的 fixed-lag marginalization 混为一谈。现有 `segments/reanchors=1/0` 只说明
没有 estimator segment re-anchor，不代表窗头 prior 没有移动。

### 5.3 现有日志能看见什么、看不见什么

`diag.csv` 已有 `prior_key` 与 posterior bias 三轴，但没有 velocity、PIM-only state、
初始化统计、factor cost/residual、prior target 或 GT state error：

- [row 组装](../../apps/offline_vo_session.cpp#L672-L699)
- [CSV schema](../../apps/offline_vo_session.cpp#L762-L800)

因此仅凭现有 `diag.csv` 无法回答：

- bias 是初始就错，还是优化后逐渐走错；
- acc noise 太松/太紧，还是 acc bias prior/RW 太紧；
- PIM prediction 错，还是视觉 correction 错；
- `prior_key` 变化是否伴随状态跳变；
- Combined 与显式 Between 各贡献多少 cost。

### 5.4 Combined + Between 已确认重复；性能影响仍待 A/B

**事实：** phad-vio 给 Combined 的 `biasAccCovariance/biasOmegaCovariance` 与显式
Between 的 `sigma=rw*sqrt(dt)` 来自同一组选项；Combined 自身 residual 已含同一个
bias increment。

**已确认结论：** 这会重复惩罚 bias motion；在忽略 Combined cross-correlation 的简单
近似下相当于把同一 diagonal information 加了两次。真实效果还受 R/P/V 与 bias
相关项、视觉因子和窗头 prior 影响，不能直接换算成“有效 sigma 除以 `sqrt(2)`”。

**已补证据：** GT bias probe 已显示 bias error 与轨迹退化存在中等相关；common
support 仍 FAIL。结合 GTSAM factor 合同，这足以支持“只保留 Combined”作为单变量
修正，而不是继续保留两条同语义路径。

**仍有证据缺口：** 目前没有 removal A/B 的 MH_01 ATE/RPE，也没有每个 factor 的
pre/post cost。因此不能声明重复约束就是全部 `+0.0391496 m` ATE gap 的根因，更不能
预先声称删除 Between 后一定胜过 VO。

## 6. 建议的 P0 只读 probe 合同

### 6.1 行为隔离硬门

建议沿用 M4.4 B1 shadow 的隔离方式：

- CLI-only `--vio-error-probe <sidecar-dir>`，默认关闭，不进 `config_hash`；
- production `est.tum`、`kf.tum`、`diag.csv`、summary/meta 必须与 control 逐字节相同；
- sidecar 只读取本次已经构造出的 samples、initial values、optimized values、factors，
  不回写 estimator state；
- probe 失败应使本次 probe run 明确失败，不静默吞掉或伪造空数据；
- 第一阶段不运行第二个 optimizer，不改变 LM 次数和 factor graph；
- 所有 schema 带 `schema_version`、code identity、config hash、dataset identity 与时间
  单位，浮点非有限值直接报错。

建议分两层产物：

1. estimator sidecar：`init.json` + `state.csv` + `factor.csv`；
2. offline analyzer：读取 VO/VIO 两个 run、EuRoC GT 与 sidecar，生成
   `common.csv` + `summary.json` + plots。

### 6.2 common timestamp support 的确定性算法

优先用两次 run 的原始 `timestamp_ns`，不要先把纳秒 round-trip 成 TUM `double`：

1. 从 VO/VIO `diag.csv` 读取 image timestamp axis，并只保留实际出现在各自
   `est.tum` 的 successful pose；
2. 若两个 estimate 来自同一 image axis，取 exact-ns intersection；
3. 只有输入确实异步时才使用 `eval.max_dt_ms=2.5` 的一对一最近邻，匹配过的 sample
   不得复用；
4. 对 common timestamp 插值或关联到**同一个** GT sample；禁止 VO、VIO 各自选不同
   最近 GT row；
5. 不外推 GT；每个丢弃原因分别计数；
6. RPE 只使用两端都在 common support 的同一 interval pair。

定义：

```text
C = timestamps with VO pose, VIO pose, and one shared GT state
P = input timestamps before first C timestamp
```

必须报告：

- `n_input / n_vo / n_vio / n_common`；
- `n_prefix_missing`、prefix duration 与 first common timestamp；
- exact match 数、tolerance match 数、最大/中位 `|dt|`；
- GT 不可用、duplicate、out-of-tolerance 各自计数；
- common RPE endpoint pair 数，而不只报 pose 数。

### 6.3 同一 common support 上的四种视图

| 视图 | alignment | 回答的问题 | 不能回答的问题 |
|---|---|---|---|
| A. conventional | VO、VIO 分别在**同一 C** 上拟合 SE(3)，禁止 scale correction | 最佳刚体对齐后的轨迹 shape 谁更准 | 常量 world-frame tilt/yaw/translation |
| B. frozen-prefix | 只用 C 的首 2 秒拟合各自 SE(3)，冻结后评估余下 suffix | 初始化附近校准后，后续 drift 多快 | 首 2 秒内被拟合吸收的误差 |
| C. start-relative | 各轨迹与 GT 都转成相对第一个 common pose，不再全段 refit | 相对初态的 translation/rotation drift | 初始绝对 gravity attitude |
| D. scale diagnostic | 单独拟合 Sim(3) 的 `s_fit`，但不用于 A/B/C 主指标 | metric motion 是否有整体尺度偏差、是否随时间变 | 不能证明应在 stereo production 中加 scale state |

初始化绝对 roll/pitch 不靠 ATE alignment 猜，而由 `init gravity direction ↔ GT gravity
in body` 的夹角单独给出；yaw 是 gauge，单列且不作 gravity init 失败条件。

每个视图至少输出：

- VO、VIO 的 APE translation/rotation time series；
- 同 timestamp 的 paired delta `error_vio(t) - error_vo(t)`；
- 1 秒 RPE translation/rotation，endpoint pairs 完全相同；
- post-init elapsed `[0,1) / [1,3) / [3,5) / [5,10) / [10,end]` 分箱；
- first/last 10% RMSE、robust median/P95、error-vs-time slope；
- `s_fit` 的首 2 秒、全段与 rolling-window 曲线。

### 6.4 `init.json`：直接检查初始化假设

建议字段如下：

| 类别 | 字段 |
|---|---|
| 窗口 | start/end ns、duration、sample count、first accepted image、rejected prefix count |
| 原始统计 | mean/std acc xyz、mean/std gyro xyz、`norm(mean_acc)-configured_g`、每个 gate margin |
| 初始化输出 | `R_W_I0`、gravity direction/magnitude、`v0`、`bg0`、`ba0` |
| GT 同步 | GT pose/velocity/bg/ba at init、最大 interpolation gap、frame convention id |
| 派生误差 | gravity angle、roll/pitch/yaw error、velocity error、bg error xyz/norm、ba error xyz/norm |
| 可观测性 | GT speed range、bias-corrected gyro norm、bias-corrected specific-force residual range |

EuRoC GT velocity 是 world-frame 量，应使用与 trajectory 相同的固定 rotation 转换后再
比较；bias 是 IMU/body-frame 量，只有在确认 phad body 与 EuRoC IMU axis、单位、符号
一致后才能逐轴比较。frame contract 不匹配时 probe 必须报错，而不是自动猜符号。

为区分 gravity tilt 与 acc bias，另把 `ba_error` 分解为相对 GT gravity-in-body 的
parallel 与 tangent 分量：

- 大 gravity angle、tangent ba error 大，且窗口真实静止：支持 tilt/ba 混淆；
- gravity angle 小而 ba error 大：更支持 bias 初始化本身错误；
- 两者都小但 `v0` 与 GT 差大：更支持 zero-velocity 假设错误。

### 6.5 `state.csv`：Kimera 式 posterior/PIM 双轨

每个 post-init successful state 一行，至少包含：

| 分组 | 字段 |
|---|---|
| identity | timestamp ns、frame index、accepted index、keyframe、window size、prior key、anchor changed |
| posterior | pose、velocity xyz、bg xyz、ba xyz |
| PIM-only | predicted pose、velocity、biasHat、segment dt/sample count/gap |
| correction | `Log(R_pred⁻¹R_post)`、`p_post-p_pred`、`v_post-v_pred`、`b_post-b_prev` |
| window anchor | old/new prior key、prior target pose/velocity/bias、实际 sigma |
| GT | common-support pose/velocity/bg/ba error；无 GT 时显式 null |
| visual context | observation/landmark/shared count、reprojection before/after、max pose shift |

“PIM-only”必须从上一轮已经提交的 posterior state/bias 和本 interval 原始 samples 得到，
并在任何本轮视觉 optimization 之前保存；否则它不是独立的 inertial prediction。

### 6.6 `factor.csv`：按 factor 记录 pre/post cost

每个 graph update 至少聚合：

- Combined factor count、总 raw residual norm、总 `error(values)`，pre/post 各一份；
- 每个 interval 的 raw R/P/V/Ba/Bg block norm；
- full Combined Mahalanobis cost；
- bias Between 的 raw increment 与 Mahalanobis cost；
- X/V/B prior 的 target、raw residual、Mahalanobis cost；
- stereo factor cost/reprojection residual；
- total graph error 与 LM iterations。

额外不变量：同一 interval 中 Combined 的 raw Ba/Bg increment 与显式 Between raw
increment 应只差既知符号/排列；不成立就说明 layout 或 factor association 有 bug。

### 6.7 换窗诊断

用已有 `prior_key` 检测窗头移动，但不能简单按 `anchor_changed` 二分。当前 window
填满后几乎每个 successful state 都会 `pop_front()`，GT bias probe 的固定 100-frame
分箱在 warm-up 后也基本都是 `prior_advances=100`；缺少同时期的
`anchor_changed=0` control frames。应改为记录连续量：窗头 pose/velocity/bias target
移动幅度、prior cost、PIM→posterior correction，并检查它们与误差 derivative 的
lag/correlation。

检查下列量是否在边界显著跳变：

- frozen-prefix APE derivative 与 start-relative RPE；
- PIM→posterior position/rotation/velocity correction；
- B prior、V prior、Combined、Between cost；
- newest/oldest state shift 与 reprojection cost。

由于 anchor 几乎逐帧移动，仅凭相关性不能识别因果。只有 target movement/correction
出现可重复的异常幅度，且 PIM raw residual 与视觉观测质量不足以解释时，才把
`rebuild-and-reprior` 升为候选；否则必须降级。

P0 不做第二个 solve。若边界签名成立，P1 再设计行为隔离的 counterfactual shadow：
例如保留 eviction 前 window，仅求一个不回写的 shadow posterior。不能在没有 P0
证据时直接实现 marginalization production 改造。

## 7. 诊断判别矩阵

| 假设 | 支持该假设的组合证据 | 反证/降级条件 | 后续最小实验 |
|---|---|---|---|
| 初始化 gravity/roll-pitch 错 | init gravity angle 大；yaw-free orientation error 从首帧即大；relative drift 早期可平 | gravity angle 与首帧 orientation error 都小 | 只读检查 static window/axis/sign，暂不改 optimizer |
| metric scale 错 | `s_fit` 明显偏 1，rolling scale 近似稳定；translation error 随路程成比例 | `s_fit≈1` 或只在后段变化 | 检查 stereo calibration、IMU units；不启用 Sim(3) 主指标 |
| gyro bias init 错 | `bg0-GT` 大；visual/PIM rotation residual 经当前 bg 修正后仍大；yaw/rotation drift 近线性 | bg 与 residual 都小 | 只读 gyro residual；有证据后再设计 bias init A/B |
| acc bias init/tilt 混淆 | gravity-tangent `ba0-GT` 大；ΔV/ΔP raw residual 与 velocity drift 从早期增长 | ba/gravity 都接近 GT | 检查静止假设；再决定 joint gravity/velocity/ba init |
| zero velocity 假设错 | GT `v0` 非零；PIM/posterior 首段需大 velocity correction | GT `v0≈0` | 只读延长/移动 init window 对照，不先改默认 |
| acc/gyro white noise 不匹配 | raw residual 随 motion 合理但 full Mahalanobis 长期系统性过大/过小；bias/prior error 不主导 | 只在 anchor change 或视觉退化时异常 | 固定轨迹与状态后做单参数 replay probe |
| bias prior/RW 过紧 | GT bias error 可下降但 posterior bias 被钉住；B prior/Between cost 与 visual correction 持续竞争 | bias 能跟随 GT、cost 正常 | 先分清 Combined 与 Between，再做单因子 ablation |
| Combined + Between 重复约束 | 上游合同与本地构图已确认同一 RW/Δb 被施加两次；GT bias error 与退化相关 | A/B 只能反证其性能贡献，不能改变重复语义 | 单变量删除 Between；保留 Combined 内部 RW，跑隔离门 |
| rebuild-and-reprior | prior-target movement/correction/cost 的异常幅度与 error derivative 同步；PIM/视觉不能解释 | 逐帧 anchor 下只有共同时间趋势、无独立签名 | P1 no-write counterfactual window shadow |
| 视觉前端/关键帧主导 | PIM prediction 与 GT 接近，但 posterior correction 把它拉远；同时 reprojection/track/KF event 异常 | PIM 已先偏离 GT | 回到视觉/KF evidence，不继续扫 IMU 参数 |
| timestamp/calibration 错 | camera/PIM dt residual、gyro visual/PIM residual 随角速度呈系统模式；轴向误差稳定 | dt/axis checks 全通过 | 先修 data contract；不以 noise 掩盖 |

单个信号不足以定案。例如“bias 变化很小”既可能是真实 bias 稳定，也可能是 prior 过紧；
必须同时看 GT bias error、factor cost 与 PIM/posterior correction。

## 8. P0 验收与决策出口

### 8.1 Probe 正确性门

1. probe off 与 control 逐字节一致；probe on 的 production 主产物仍逐字节一致；
2. common timestamp 数能从输入集合恒等式复算，所有 RPE endpoints 属于 C；
3. VO/VIO 每个 common row 指向同一个 GT timestamp/interpolated state；
4. state/factor sidecar timestamp 单调、有限、frame/accepted/prior transaction 自洽；
5. PIM sample `sum_dt` 与 state interval 相符；
6. Combined/Between bias increment layout 不变量通过；
7. 报告同时给出 initialization prefix 与 post-init common-support 指标，不能只留一个
   更好看的 RMSE。

### 8.2 P0 必须交付的数字

- common support 上 VO/VIO 的 A/B/C 三种 ATE/RPE 与 paired delta；
- prefix 442 帧的数量、时长、占比；
- `gravity angle / v0 error / bg0 error / ba0 error`；
- first 2s、2–5s、5s+ 的 pose/velocity/bias error；
- PIM-only 与 posterior 各自对 GT 的误差，以及 correction magnitude；
- Combined、Between、X/V/B priors、stereo factor 的 pre/post cost；
- prior-target movement/correction/cost 与 error derivative 的时序关系；若逐帧换锚无法
  构造 contemporaneous control，必须明确报告不可识别。

### 8.3 下一步选择规则

- **本轮实际选择：** common support 仍 FAIL，bias error 与退化相关，加上已确认的
  factor 合同重复，下一刀只移除显式 bias Between，保留 Combined 内部 RW；
- **初始化量首帧已错，之后 slope 不大：** 下一刀转 joint initialization/质量门；
- **初始化接近 GT，但 PIM-only 持续漂：** 转 IMU model/noise/bias evolution；
- **PIM-only 接近 GT，posterior 被拉远：** 转视觉因子/关键帧/窗口信息；
- **只在 prior-key 边界跳：** 转 marginalization/reprior counterfactual；
- **Combined-only A/B 仍 FAIL：** 模型合同修正可以保留，但不得据此继续盲扫 RW/prior；
  回到 PIM/posterior 与 initialization state probe 选下一刀；
- **common support 后 VIO 已不劣于 VO：** 先修正式评估口径，同时把 442 帧 startup
  latency 作为独立 M4.4 债；不能宣称全里程碑完成。

## 9. 事实、工程推断与证据缺口汇总

### 9.1 已确认事实

1. 原 VO/VIO headline metrics 使用不同 output coverage；exact common-support 复算后
   VIO ATE/RPE 仍分别差 `0.0391496 / 0.0046227 m`，结论仍 FAIL。
2. 主流评估代码提供 pairwise association；本轮未发现现成的 VO/VIO/GT 三方 support
   合同。
3. Kimera 直接记录 posterior state 与 PIM-predicted navstate，并显式记录初始化 IMU
   对照。
4. VINS 与 Kimera 的 window 实现保留 marginalization history；phad-vio 当前重建 graph
   并给新窗头重新加 X/V/B priors。
5. GTSAM Combined factor 已包含 bias evolution residual/covariance；其官方 Combined
   示例不再加 bias Between，普通 ImuFactor 示例才加。phad-vio 两条路径消费相同 RW
   与同一 bias increment，重复约束已经确认。
6. VINS-Fusion 和 ORB-SLAM3 在 stereo 模式不把 scale 当自由变量；monocular scale
   初始化不能直接移植。
7. GT bias error 与退化存在中等相关，但时间自相关与其他 state/factor 尚未排除。

### 9.2 工程推断

1. common support 已排除 coverage 混杂；frozen-prefix drift 与 posterior/PIM 双轨仍是
   Combined-only 候选不够时信息增益最高的后继 probe。
2. Combined+Between 会重复约束 bias evolution；只保留 Combined 是符合上游合同的
   最小修正。它改善精度的幅度仍是待测量推断。
3. `rebuild-and-reprior` 可能丢失窗口外历史信息，但只有换窗边界签名或 counterfactual
   才能证明它解释了当前误差。
4. current static `mean_acc` 初始化很可能混淆 gravity tangent 与 acc bias，但 EuRoC GT
   能在不改 production 的情况下直接检验。
