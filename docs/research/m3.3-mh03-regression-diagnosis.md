## 1. 结论先行

MH_03 ATE 回归（1.121→1.336 m，+19.2%，无 failed/reanchor）的根因是 **PnP 仲裁
在 i=1388 正确拒绝了 PnP proposal（358 px stereo RMS），但恒速 guess（6.7 px RMS）
经 LM 收敛到的局部最小值在绝对位姿上更差**。这不是仲裁判据的逻辑错误——proposal
确实比 guess 差两个数量级——而是帧级 RMS 比较的内在局限：一个在图像空间"糟糕"的
PnP proposal 可能位于正确的位姿盆地，而"干净"的 guess 可能停在错误的盆地。

该回归应被视为 PnP 仲裁的**已知权衡**（MH_02 ATE 5.3e5→0.092 m、MH_05 2.456→
0.472 m、V1_02 8.41→0.77 m 等），不推荐为单序列放宽 `stereo_sigma_px` 或修改
仲裁判据。

## 5. i=1388 事件链（逐帧）

### 5.1 分叉前（i=1385–1387）：完全一致

健康状态：PnP 总是成功，RMS ~0.5–0.6 px，无外点剔除。

### 5.2 i=1388：分叉点

```
           pnp_success   pnp_inliers   rms_before   rms_after   culled
zombie         1             58         358.080      132.709       0
pnp arb        0              0           6.657        4.082       0
```

- zombie-age：左目 inlier 数≥10 → 直接采用 58-inlier PnP proposal。该 proposal
  的 stereo RMS 高达 **358.08 px**（正常帧 ~0.5 px），LM 后降为 132.71 px（仍极高）
- PnP arb：`solvePnPRansac` 成功，但 proposal RMS（358 px）远超 guess RMS（6.66 px）
  + `stereo_sigma_px`（1 px）→ **拒绝**，回退恒速 guess。LM 后 RMS=4.08 px

仲裁行为**完全正确**：358 px vs 6.7 px，proposal 明显更差。`outliers_culled=0`
说明 per-landmark 平均（跨帧）未触发 4.0 px 门限。

- PnP arb：恒速 guess 驱动 LM 收敛到一个 RMS ~4.4 px 的状态，且因 PnP 仍成功
  （inlier 数足够），无拒帧——就这样稳在 ~4 px 误差连续 **7 帧**
- zombie-age：从 i=1388 的 132.71 px RMS_after 出发，i=1389 的恒速 guess 却
  只产生 0.56 px RMS_before——**那个 132.71 px RMS 的"烂位姿"实际上比 PnP arb

这就是图像空间误差与绝对位姿误差的脱耦：

132.71 px RMS 的位姿竟然产生更准确的恒速预测！这说明 zombie 的 PnP→LM 路径虽然
产生巨大的图像误差（132 px），但收敛到的绝对位姿比 guess→LM 路径（4 px RMS）更
接近真实相机运动。

## 6. 根因机制

```
                        zombie-age 路径
i=1388 PnP proposal ──→ accept (左目 inlier≥10)
  (358 px RMS)              │
                            ▼
                       LM optimization
                      132 px RMS_after
                            │
                            ▼
                      i=1389 CV guess: 0.56 px ← 位姿好！
                            │
                            ▼
                      后续帧 rms ~0.5 px（正常）
                      ATE = 1.12 m ✓


                        PnP arb 路径
i=1388 PnP proposal ──→ reject (358 ≪ 6.7+1)
  (358 px RMS)              │
                            ▼
                      CV guess: 6.7 px
                            │
                            ▼
                       LM optimization
                      4.1 px RMS_after
                            │
                            ▼
                      i=1389 CV guess: 4.25 px ← 位姿差！
                            │
                            ▼
                      8 帧连续 rms ~4.4 px（局部最小）
                      ATE = 1.34 m ✗
```

根本原因：LM 是一个局部优化器。两个不同的初始位姿（PnP proposal vs CV guess）
可能收敛到不同的局部极小值。PnP proposal 虽然图像误差巨大，但位于"正确"的
收敛盆地；CV guess 虽然图像误差小，但位于"错误"的盆地。仲裁只看当前帧 RMS，
无法判别哪个盆地更好。

这跟在 MH_02 上的修复不矛盾：MH_02 i=364 的 PnP proposal（180 px RMS / 11.149 m
偏移）确实在错误的盆地，仲裁正确地阻止了它。MH_03 i=1388 的 PnP proposal（358 px
RMS / 0.025 m 偏移）在正确的盆地，仲裁却阻止了它——**但仲裁没有跨帧信息来做这个
区分**。

## 8. 推荐

**接受 MH_03 回归作为已知权衡。** 不改判据、不调 `stereo_sigma_px`、不增加
二次验证或多假设跟踪。

理由：

1. **判据本身正确**：358 px vs 6.7 px，任何帧级比较都会拒绝。问题不在判据，而在
   LM 收敛到不同局部极小值——这是 LM 的本质限制，不是仲裁的 bug。
2. **无低成本修复**：可行的"两个盆地都试"方案（对 proposal 和 guess 都跑 LM 后
   比较 RMS_after）在本帧仍会拒绝 proposal（132.71 vs 4.08 px），不能改变结果。
   跨帧决策（看下一帧的 RMS 再回退）涉及 estimator 架构变更，不在 M3.3 范围。
3. **净收益压倒性**：MH_02 6 个数量级的改善 + 其他 6 条序列 —— 不应为 0.215 m
   回归风险仲裁本身。
4. **与约束一致**：roadmap 明确「不用调 session/cull 阈值或任意放大
   `stereo_sigma_px` 代替诊断」。诊断完成——根因是局部极小值而非判据错误，不构成
   修复依据。

### 不做

- 放宽 `stereo_sigma_px`（MH_01 已验证会回归）
- 对 proposal 和 guess 都跑 LM 后比较 RMS_after（本帧无效 + 双倍计算）
- 跨帧 rollback（架构变更，不在 M3.3）
- 为 MH_03 单独开关仲裁（破坏 config identity）
- 多假设跟踪或 filter 级决策（M7 范围）
