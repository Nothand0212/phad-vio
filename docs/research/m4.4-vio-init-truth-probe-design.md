## 2. 模块与 interface

### 2.1 estimator 一次性事件

`phad::estimator` 在已有 `UpdateDiagnostics` 增加只读 POD：

```cpp
struct ImuInitDiagnostics
{
  std::uint32_t     imu_sample_count;
  std::int64_t      imu_t_i_ns;
  std::int64_t      imu_t_j_ns;
  double            imu_dt_s;
  Eigen::Vector3d   gyro_mean;
  Eigen::Vector3d   gyro_std;
  Eigen::Vector3d   acc_mean;
  Eigen::Vector3d   acc_std;
  Eigen::Isometry3d T_W_B0;
  Eigen::Vector3d   velocity_W;
  Eigen::Vector3d   bias_gyro;
  Eigen::Vector3d   bias_acc;
  double            acc_mean_norm;
  double            gravity_model_magnitude;
  double            gyro_std_limit;
  double            acc_std_limit;
};

std::optional<ImuInitDiagnostics> imu_init;
```

`imu_init` 只在 `InitPhase::kCollecting → kReady` 的那一次 update 上存在。即使同一
update 随后因视觉播种被拒，它仍保留，因为它描述已经提交的初始化状态机事件；
后续 update 不重复。public interface 只含 Eigen/POD，GTSAM 类型继续留在 PIMPL。

### 2.2 apps 单行 sidecar module

```cpp
class VioInitProbe
{
public:
  explicit VioInitProbe(const std::filesystem::path& path);
  void write(const estimator::VioUpdateResult& update);
};
```

module 隐藏 33 列 CSV schema、数值/pose/interval 校验、单事件 transaction、
`max_digits10` 与 I/O。caller 每帧只调用 `write(update)`；没有 snapshot 时无操作，
第二个 snapshot 是明确错误。

`OfflineVoSessionOptions::vio_init_probe_path` 与 bench
`--vio-init-probe <csv>` 是 CLI-only seam；空路径关闭，不进入 config/hash。
它要求 IMU-on，不改变现有 42 列 `vio_state.csv`。

### 2.3 offline analyzer module

```text
python3 scripts/vio_init_probe.py \
  <vio_init.csv> <euroc-sequence> [--output <report.json>]
```

analyzer 隐藏 EuRoC 17 列 GT 解析、bracket/SLERP 时间关联、identity `T_BS`
核验、quaternion/rotation 数学和派生误差。输入是一行实际 production snapshot；
禁止从 raw IMU 重新实现 initializer 后把重算结果称作实际状态。

这是一个文件 adapter，不为唯一实现增加 interface hierarchy。

## 3. 数据流

```text
init_imu tail window
  → production mean/std + static gates
  → production R_W_B0 / v0 / bg0 / ba0 / g
  → ImuInitDiagnostics（同一检测 transaction）
  → apps::VioInitProbe 单行 CSV
  → Python + EuRoC GT at t0
  → report.json / stdout
```

raw CSV 列分组：

- interval：`imu_t_i_ns/imu_t_j_ns/imu_sample_n/imu_dt_s`；
- raw statistics：gyro/acc mean 与 population std xyz；
- gates：gyro/acc std limit；
- initialization：`q_W_B0`、`v0`、`bg0`、`ba0`、`acc_mean_norm` 与实际
  PIM 使用的 `gravity_model_magnitude`。二者禁止都命名为 gravity estimate。

translation 不记录：静止 IMU 初始化的绝对位置不可观，当前恒为 gauge zero。

EuRoC analyzer 只在 groundtruth 与 IMU `sensor.yaml` 的 `T_BS` 都为 identity 时逐轴
比较。本仓库 body=IMU；GT header 的 `q_RS` 解释为 `R_W_B`，velocity 以 W 表达，
bias 以 B 表达。t0/t1 必须由左右 GT row bracket；姿态用 shortest-path SLERP，
velocity/bias 线性插值，禁止外推，且 bracket span 不超过 7.5 ms。

派生量：

- yaw-invariant gravity angle：`R_W_B0ᵀ e_z` 与 `R_W_B_gtᵀ e_z` 的夹角；
- GT t0/window speed、window orientation change 与 `Δv/Δt`；
- `bg0/ba0` 逐轴与 norm error；
- `ba_error` 沿 GT body-up 的 signed parallel 分量与 tangent norm；
- `g_est-g_nominal`；
- 静止模型 residual：raw gyro mean−GT bg、raw acc mean−
  `(g_nominal·body_up_gt + GT ba)`。

## 4. 错误与诊断

- C++ writer open/header/row/flush 失败：session 明确失败；
- snapshot 的 sample count `<2`、非正/不匹配 duration、非有限值、负 std、
  非正 gate/gravity、非刚体 `T_W_B0`：拒绝，不写部分行；
- 同一 estimator 出现第二个 init event：`logic_error`，不静默覆盖；
- `--no-imu` 与 `--vio-init-probe`：参数错误；
- Python 缺列、多行/零行、非有限、非单位 quaternion、时间/interval 不变量失败：
  返回 2；
- GT/IMU `T_BS` 非 identity、header 不符、t0 超出 GT 或 bracket span >7.5ms：返回 2，
  禁止自动猜 frame/sign；
- probe off/on 的 `est.tum`、`kf.tum`、`diag.csv` 必须逐字节相同，否则先修隔离。

## 6. 选刀规则与非目标

- gravity angle 与 tangent `ba` error 同时大、GT 窗口近静止：设计 joint
  gravity/ba initialization，不扫 RW/prior；
- gravity angle小、`ba` error 大：先修 bias initializer；
- `|v_gt(t0)|` 大：设计 velocity-aware/online alignment；
- static-model residual 出现轴/符号级错误：先修 frame/measurement contract；
- R/v/bg/ba/g 都接近 GT：转 calibration/timestamp 或连续 IMU model probe。

本片不实现 online alignment、fixed-lag、factor-cost probe、noise 调参或第二个
optimizer；不运行 sentinel/11/11，直到日志支持并验证一个 production fix。
