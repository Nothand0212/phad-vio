## 1. 目标

修复 V 系列退化（0.5-8.8 m vs 公开 LK 系统 0.02-0.09 m）。三份调研确认主因是
**前端跟踪崩溃**（V2_03 观测中位仅 4 个）而非后端。本片实施前端加固（LK 初始
猜预测 + CLAHE + 几何校验 + 参数微调），⑥b 再做深度加固。

## 2. 已对齐决策

| 决策点 | 结论 |
|---|---|
| LK 初始猜 | 常速中值流预测 + `OPTFLOW_USE_INITIAL_FLOW` |
| 预处理 | CLAHE（左右目各一次，clip 3.0, tile 8x8）|
| 几何校验 | F 矩阵 RANSAC（LK 后、FB 前）|
| quality_level | 0.01 → 0.003（保守，VINS/Kimera 0.001 区间）|
| 金字塔 | 3 → 4 层 |
| 特征数量 | 保持 200（SVO/VINS 同级，非主因）|
| 修改范围 | `phad/frontend/stereo_tracker.{hpp,cpp}` + 选项默认值 |
| 框架外 | ORB 描述子、宽基线重定位（不做）|

## 3. Task 1：LK 初始猜预测

### 3.1 机制

当前 LK 从上一帧位置起步（`calcOpticalFlowPyrLK` 无初始猜）。快速偏航时帧间
位移超出收敛域 → track 全灭。

修改：用**上一帧对的中值光流**作为本帧所有 track 的初始猜：

```cpp
// Impl 新增：
std::optional<cv::Point2f> median_flow;  // 上一帧对的中值光流

// process() 中，LK 前：
std::vector<cv::Point2f> guess_pts;
if ( median_flow.has_value() ) {
  guess_pts.reserve( prev_pts.size() );
  for ( const auto& p : prev_pts )
    guess_pts.push_back( p + *median_flow );
}

cv::calcOpticalFlowPyrLK(
    prev_left, left, prev_pts, curr_pts, forward_status, forward_error,
    win, options.lk_pyramid_levels,
    cv::noArray(),
    guess_pts.empty() ? cv::noArray() : cv::_InputArray( guess_pts ),
    win, /*useInitialFlow=*/true );
```

等等——`calcOpticalFlowPyrLK` 的签名：`(prevImg, nextImg, prevPts, nextPts,
status, err, winSize, maxLevel, criteria, flags, minEigThreshold)`。初始猜通过
`nextPts` 传入 + `flags |= cv::OPTFLOW_USE_INITIAL_FLOW`。所以：

```cpp
cv::calcOpticalFlowPyrLK(
    prev_left, left, prev_pts, curr_pts, forward_status, forward_error,
    win, options.lk_pyramid_levels,
    cv::TermCriteria( cv::TermCriteria::COUNT + cv::TermCriteria::EPS, 30, 0.01 ),
    cv::OPTFLOW_USE_INITIAL_FLOW,
    1e-4 );
```

其中 `curr_pts` 预填 guess（中值流预测位置），`OPTFLOW_USE_INITIAL_FLOW`
让 LK 从 guess 起步。

### 3.2 中值流计算

FB 检查通过后，收集所有幸存 track 的位移 `(curr - prev)`，取中值：

```cpp
// FB 检查后：
std::vector<cv::Point2f> flows;
flows.reserve( survivors.size() );
for ( survivors ) flows.push_back( curr - prev );
// 按 x+y 排序取中值（或分别取 x,y 中值）
```

**用中值而非均值**：抗单 track 异常。流为空（全部丢失）时清空
`median_flow`（下帧无预测）。

### 3.3 无 IMU 的预测合理性

常速模型假设帧间运动恒定。V 系列高加速度段预测会偏，但**预测只是 LK 的
初始猜**（收敛域内都 OK），不引入 BA 偏差——与 ORB-SLAM motion model 一致。

## 4. Task 2：CLAHE 预处理

`process()` 入口对左右目各做一次 CLAHE：

```cpp
const cv::Mat left_raw  = toGrayMat( rectified.left );
const cv::Mat right_raw = toGrayMat( rectified.right );
cv::Ptr<cv::CLAHE> clahe = cv::createCLAHE( 3.0, cv::Size( 8, 8 ) );
cv::Mat left, right;
clahe->apply( left_raw, left );
clahe->apply( right_raw, right );
```

好处（一次改动修三处）：
- **GFTT**：角点响应在曝光不均时衰减 → CLAHE 恢复
- **LK**：亮度恒常假设被曝光突变破坏 → CLAHE 对齐灰度分布
- **SAD**：左右目亮度不一致直接打爆原始绝对差 → CLAHE 对齐

注意：`prev_left` 也必须存 CLAHE 后的图（否则前后帧预处理不一致）。

## 5. Task 3：F 矩阵 RANSAC（几何校验）

LK + FB 之后、右目匹配之前，对幸存 track 做 F 矩阵 RANSAC：

```cpp
// 收集幸存 track 的 prev/curr 点对
std::vector<cv::Point2f> prev_pts_f, curr_pts_f;
for ( survivors ) { prev_pts_f.push_back( prev ); curr_pts_f.push_back( curr ); }
cv::Mat F;
std::vector<uchar> geo_status;
if ( prev_pts_f.size() >= 8 ) {
  F = cv::findFundamentalMat( prev_pts_f, curr_pts_f, cv::FM_RANSAC,
                              3.0, 0.99, geo_status );
}
// 仅保留 geo_status 为 1 的 track
```

依据：VINS（F 矩阵 RANSAC）、Kimera（1/2 点 RANSAC）都在 FB 之后做几何校验。
模糊帧上 FB 对"两边都糊但一致"的错误 track 无效，几何校验砍掉它们。

## 6. Task 4：参数微调

`stereo_tracker.hpp` 选项默认值：

| 项 | 现状 | 改为 | 依据 |
|---|---|---|---|
| quality_level | 0.01 | 0.003 | Kimera 0.001 区间；模糊帧角点响应衰减 |
| lk_pyramid_levels | 3 | 4 | Kimera `klt_max_level: 4`；可收敛位移翻倍 |

保持：max_tracks 200、lk_window_px 21、forward_backward_px 0.5。

注意：这些进 config_hash（`flattenConfig`）——**会改变 config hash**，属预期。
