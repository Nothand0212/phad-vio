## 1. 要回答的问题

Slice ③ 目标（roadmap / 设计稿）：用 `solvePnPRansac` 取代
`StereoVoEstimator::poseInitialValue()` 的恒速初值，并用几何验证剔除时序外点。
设计稿已点名的参考阈值：VINS `F_THRESHOLD = 1.0 px`、Kimera
`ransac_threshold_stereo_ = 1.0`、置信度 0.99。

开工前要分清两件常被混称的事：

1. **位姿初值**：用历史 3D landmark + 当前 2D 观测求 `T_W_C` / `T_W_B`，喂给后端优化；
2. **几何验证 / 外点剔除**：用 RANSAC（或 pose-only BA 的 chi2）决定哪些
   track / 观测进图、哪些从 frontend 或 estimator 里扔掉。

二者可以同一次 PnP-RANSAC 完成，也可以拆开（前端 2D-2D / 3D-3D，后端单独
PnP）。各系统归属不同。

本仓库现状（对照用）：

```312:331:phad/estimator/stereo_vo_estimator.cpp
    [[nodiscard]] Eigen::Isometry3d poseInitialValue() const
    {
      …
      if ( !options.use_constant_velocity_init ||
           !prev_accepted_T_W_B.has_value() )
      {
        return *last_accepted_T_W_B;
      }
      …
      const Eigen::Isometry3d  predicted =
          T_prev * ( T_prevprev.inverse() * T_prev );
```

即：有两帧历史则恒速外推一帧，否则沿用上一接受位姿；**无几何验证、无外点剔除**。

## 2. 先澄清设计稿里的阈值单位

| 名称 | 出处 | 实际用途 | 单位 / 含义 |
|---|---|---|---|
| `F_THRESHOLD = 1.0` | VINS-Fusion yaml `F_threshold` | 前端 `findFundamentalMat` 的 RANSAC 阈值 | **像素**（归一化到虚拟焦距平面后再比） |
| `ransac_threshold_stereo_ = 1.0` | Kimera `TrackerParams` / EuRoC yaml | 前端 **3D-3D Arun** RANSAC | OpenGV `PointCloudSacProblem` 阈值（**非像素**；与 PnP 重投影不是同一量） |
| `ransac_threshold_pnp_ = 1.0` | Kimera `TrackerParams` | 前端可选 **2D-3D PnP** RANSAC | **像素**，再换成角阈值 `1-cos(atan(√2·e/f))` |
| `ransac_probability` / `0.99` | Kimera `0.995`；VINS `0.99`；ORB reloc `0.99` | RANSAC 成功概率 | 无量纲 |

结论：设计稿把 VINS 的 **2D-2D F 阈值** 与 Kimera 的 **3D-3D 阈值** 并列为
「几何验证阈值」可以作数量级参考，但 **不能直接当作 `solvePnPRansac` 的
`reprojectionError` 参数**。与 PnP 同型的是 Kimera `ransac_threshold_pnp_ = 1.0 px`
与 VINS loop closure 的 `10.0/460 ≈ 0.022`（归一化平面）。

## 3. 逐项目结论

### 3.1 VINS-Fusion —— 与 Slice ③ 目标最接近的「后端 PnP 初值」

**归属：estimator（`FeatureManager`），frontend 的 F-RANSAC 在热路径上被关掉。**

纯双目 / 无 IMU 的非线性路径每帧：

```537:546:vins_estimator/src/estimator/estimator.cpp

            f_manager.initFramePoseByPnP(frame_count, Ps, Rs, tic, ric);
        f_manager.triangulate(frame_count, Ps, Rs, tic, ric);
        optimization();
        …
        outliersRejection(removeIndex);
```

`initFramePoseByPnP`（`feature_manager.cpp:259`）：

- 收集 `estimated_depth > 0` 的历史三角化点 → 世界系 3D；
- 当前帧归一化平面 2D；
- 用 **上一帧相机位姿** 作 `useExtrinsicGuess`；
- 调用 **`cv::solvePnP`（非 Ransac）**，`K = I`（点已在归一化平面）；
- 最少 **4** 点；失败则 **不写** `Rs/Ps[frameCnt]`。

```215:254:vins_estimator/src/estimator/feature_manager.cpp

{
    …

    …
    pnp_succ = cv::solvePnP(pts3D, pts2D, K, D, rvec, t, 1);

```

注释掉的 `solvePnPRansac` 阈值是 `8.0/focalLength`、置信度 `0.99`——说明作者一度
想用 RANSAC，但主干留下的是带初值的迭代 PnP。

**失败回退**：`slideWindow()` 在上一轮末已把 `Ps/Rs[WINDOW_SIZE]` 拷成上一帧
（`estimator.cpp:1357-1359`）；PnP 失败时该拷贝保留 → **零运动（沿用上一帧）**，
不是恒速模型。有 IMU 时非线性路径根本不调 PnP，靠预积分传播。

**几何验证 / 外点**：

| 机制 | 位置 | 状态 | 效果 |
|---|---|---|---|
| `rejectWithF()` | frontend | **热路径注释掉**（`feature_tracker.cpp:169`） | `findFundamentalMat(..., F_THRESHOLD, 0.99)`，失败则 `reduceVector` 删 track |
| PnP inliers | estimator | **无**（非 RANSAC） | 不 cull |
| `outliersRejection()` | estimator 优化后 | **开着** | 平均重投影 `ave_err * FOCAL_LENGTH > 3` px → 永久删 landmark，并 `featureTracker.removeOutliers` |

`F_threshold: 1.0` 在全部官方 yaml（含 `euroc_stereo_config.yaml:48`）一致；但默认
**不跑**。真正在剔除外点的是优化后的 3 px 平均重投影，属 Slice ④ 形态。

**对 PHAD**：VINS 证明「用已三角化 landmark 做后端 PnP 种子、失败则沿用上一帧」
在纯双目滑窗里可跑；但它 **没有** 用 RANSAC 做时序外点剔除——那部分被关掉了。

### 3.2 Kimera-VIO —— 前端几何验证主力；PnP 可选且 EuRoC 默认关

**归属：frontend 做 RANSAC 剔点 + 相对位姿；backend 只消费 pose guess / between factor。**

关键帧路径（`StereoVisionImuFrontend.cpp:349-399`）在 `useRANSAC_=true` 时顺序：

1. **Mono 2D-2D**（Nister 5pt 或 2pt+已知旋转）→ `removeOutliersMono`（landmark id 置 `-1`）；
2. 稀疏双目重建后 **Stereo 3D-3D Arun** → `removeOutliersStereo`（右点标
   `FAILED_ARUN`、深度清零）；
3. 可选 **PnP 2D-3D**（`use_pnp_tracking_`）。

默认参数（`VisionImuTrackerParams.h` / EuRoC `FrontendParams.yaml`）：

| 参数 | 默认 / EuRoC |
|---|---|
| `minNrMonoInliers_` | 10 |
| `minNrStereoInliers_` | 5 |
| `min_pnp_inliers_` | 10（EuRoC yaml 写成 20） |
| `ransac_threshold_mono_` | `1e-6`（bearing / OpenGV） |
| `ransac_threshold_stereo_` | `1.0` |
| `ransac_threshold_pnp_` | `1.0` px |
| `ransac_max_iterations_` | 100 |
| `ransac_probability_` | **0.995**（不是 0.99） |
| `use_pnp_tracking_` | **EuRoC = 0（关闭）** |
| `pnp_algorithm_` | EPNP |

PnP 实现（`Tracker.cpp:1122+`）：OpenGV absolute-pose RANSAC，把像素阈值换成
角阈值；成功且 inliers `> min_pnp_inliers_` 才 `TrackingStatus::VALID`。
**明确不删外点**：

```159:165:src/frontend/VisionImuFrontend.cpp

    status_pnp->first = TrackingStatus::VALID;
    …
    // TODO(Toni): remove outliers from the tracking?
```

Backend pose guess（`VioBackend.cpp:812-860`）由 `pose_guess_source_` 选择；
EuRoC `BackendParams.yaml`：`pose_guess_source: 0` → **`PoseGuessSource::IMU`**。
PnP / Stereo / Mono 失败时日志 `"Using IMU for pose guess"`。`addBetweenStereoFactors`
在 EuRoC 也是 0——3D-3D 相对位姿默认**不加** between factor，主要贡献是
**前端剔点**。

**对 PHAD**：Kimera 把「几何验证 cull tracks」和「PnP 位姿种子」拆开；EuRoC
默认只开前者（2D-2D + 3D-3D），PnP 关、pose guess 走 IMU。本仓库无 IMU、且
frontend↔estimator 单向依赖，不能照搬「frontend 读 backend landmarks_map_ 做
PnP」（`Tracker::pnp` 锁 `landmarks_map_`）。

### 3.3 ORB-SLAM3 —— 跟踪用运动模型 + pose-only BA；PnP-RANSAC 只服务重定位

**归属：Tracking 线程（前端兼局部地图跟踪），不是独立滑窗 estimator 的 init。**

正常 `OK` 状态（`Tracking.cc:1945-1956`）：

- 无速度或刚重定位后 2 帧 → `TrackReferenceKeyFrame()`（BoW 匹配，位姿种子 =
  `mLastFrame`，然后 `Optimizer::PoseOptimization`）；
- 否则 → `TrackWithMotionModel()`：`mCurrentFrame.SetPose(mVelocity * mLastFrame.GetPose())`
  （恒速 SE3），`SearchByProjection`，再 pose-only BA；失败则退回 reference KF。

`TrackWithMotionModel` **不用 PnP**。外点在 `PoseOptimization` 后按
`mvbOutlier` 从 `mvpMapPoints` 断开（本帧关联断开，不是立刻毁地图点）。
纯双目成功门限：`nmatchesMap >= 10`（`Tracking.cc:2946`）。

`Relocalization()` 才上 **MLPnP + RANSAC**（`Tracking.cc:3656-3658`）：

```text
SetRansacParameters(0.99, /*minInliers*/10, /*maxIts*/300,
                    /*minSet*/6, /*epsilon*/0.5, /*th2*/5.991)
```

内点判据：重投影误差² `< σ² · 5.991`（`MLPnPsolver::CheckInliers`）。随后再
`PoseOptimization`；需要 `nGood >= 50` 才算重定位成功。失败则
`RECENTLY_LOST` / `LOST`（见既有 M3.3 对照笔记）。

**对 PHAD**：ORB 的日常跟踪路径 = **恒速（或上一帧）种子 + 投影匹配 +
pose-only 鲁棒 BA**，与本仓库「恒速 → 窗口 BA」同型；`solvePnPRansac` 是
**丢跟踪后的恢复工具**，不是每帧初值。Slice ③ 若每帧 PnP-RANSAC，更接近
VINS/Kimera-PnP，而不是 ORB 热路径。

batch 窗口一个更好的线性化点，不是 Basalt 路线的必需品。

### 3.5 SVO Pro —— 直接法对齐取代 PnP；外点在 pose optimizer

**归属：frontend `FrameHandler*`。**

双目热路径（`frame_handler_stereo.cpp`）：`sparseImageAlignment()`（层级 KLT /
直接法相对位姿）→ `projectMapInFrame()` → `optimizePose()`（重投影 pose-only，
阈值 `poseoptim_thresh` 默认 **2.0 px**，`svo_factory.cpp:71`）。
`PoseOptimizer::run` 结束后 `removeOutliers` 按重投影阈值删观测
（`pose_optimizer.cpp:63-69`）。

特征不足时强制关键帧三角化恢复，**不跑 PnP-RANSAC**（见既有对照笔记）。
opengv RANSAC 出现在 loop closing / map alignment，不在帧间 VO 初值。

**对 PHAD**：SVO 用直接法对齐当「几何初值」，等价角色不是
`solvePnPRansac`。可借鉴的是「pose-only 后再按 px 阈值 cull」，更偏 Slice ④。

### 3.6 OpenVINS —— 前端 F-RANSAC；位姿靠 IMU 传播

**归属：`ov_core` tracker 剔点；MSCKF 状态靠 IMU clone。**

`TrackKLT.cpp:873`：KLT 后对 undistort 点


阈值 ≈ **2 px / f**（归一化平面），置信度 **0.999**。Descriptor 路径用

IMU 传播。

**对 PHAD**：无 IMU 时 OpenVINS 路线不适用；其 F-RANSAC 是 frontend 时序外点
剔除的干净先例，阈值与 VINS `1.0 px`（虚拟焦距平面）同量级。

## 5. 结论（跨系统模式）

1. **「每帧 PnP 当 VO 初值」几乎只有 VINS 纯双目后端在做**；且主干是
   `solvePnP` + 上一帧外参初值，**不是** `solvePnPRansac`。设计稿选 RANSAC 是
   合理加固（VINS 自己注释里就留过 RANSAC 版本），但不要误以为开源热路径已经
   普遍如此。
2. **「几何验证剔时序外点」在开源里通常是 frontend 的 2D-2D F / essential /
   3D-3D**，与 PnP 初值是两条线。VINS 的 `F_THRESHOLD=1.0` 与 Kimera
   `ransac_threshold_stereo_=1.0` **不是同一物理量**；和 `solvePnPRansac` 同型的
   像素阈值是 Kimera `ransac_threshold_pnp_=1.0` 或 ORB `√5.991 ≈ 2.45 px`（×σ）。
3. **失败回退几乎从不是「拒绝整帧」**：沿用上一帧（VINS）、IMU（Kimera）、
   换参考 KF / 丢跟踪（ORB）、强制建 KF（SVO）。PHAD 已有 re-anchor 与
   `min_seed_observations`；PnP 失败应落在「退回恒速/上一帧」而非新的吸收态。
4. **RANSAC 若只求位姿、不掩码观测，就没有完成「剔时序外点」**——这是 VINS
   现状与 Slice ③ 文案之间最大的缺口；Kimera 对 PnP 也留了 `TODO: remove
   outliers`，说明他们清楚二者该耦合却没做。
5. **本仓库模块边界**排除 lk-vio / Kimera 那种「frontend 读地图点做重投影 /
   PnP」。Slice ③ 的自然落点是 `StereoVoEstimator`：用已有 `landmarks_W` +
   当前 `StereoObservation` 做 3D-2D，写 `poseInitialValue`，并用 inlier 掩码
   决定本帧哪些观测进 GTSAM（frontend track 表可先不动，留给 Slice ④）。

## 6. PHAD 可借鉴点 / 需回避点

### 可借鉴

1. **VINS `initFramePoseByPnP` 数据流**：已三角化世界点 + 当前归一化/像素观测 +
   上一帧位姿作 `useExtrinsicGuess`；成功则覆盖恒速初值。最贴 Slice ③「取代恒速」。
2. **把 RANSAC 加回去（VINS 注释版本 / Kimera PnP / OpenCV `solvePnPRansac`）**：
   置信度 `0.99`–`0.995`；像素阈值从 **1.0–3.0 px** 起扫（对齐 Kimera pnp
   `1.0` 与 VINS 事后 `3 px`，不要直接抄 `ransac_threshold_stereo_=1.0`）。
3. **失败 fallback = 上一帧或现有恒速**（VINS / 本仓库现状），保持
   `use_constant_velocity_init` 为后备开关，便于 A/B。
4. **优化前用 inlier 掩码丢本帧外点观测**（Kimera mono/stereo、ORB pose BA），
   这样 Slice ③ 的「几何验证」才有可测效果（`reproj_after`、reanchors）。
5. **最少对应数门限**：VINS 4（PnP 最小集）、Kimera pnp 10–20、ORB reloc 10 /
   跟踪 10——与现有 `min_seed_observations` 对齐时，PnP 路径应
   `max(min_pnp_correspondences, min_seed_observations)`，避免 4 点碰巧通过种子门。

### 需回避

1. **不要把 VINS `F_THRESHOLD` 或 Kimera `ransac_threshold_stereo_` 未经换算写进
   `solvePnPRansac` 的 `reprojectionError`**——单位与模型都不同。
2. **不要为了「跟 Kimera」在 frontend 做 PnP**：会破坏单向依赖，且 EuRoC 默认
   根本没开 PnP。
3. **不要学 VINS 只跑无 RANSAC 的 `solvePnP` 却宣称完成了几何验证**——外点仍会
   进 GTSAM，Slice ③ 与 ④ 边界会糊掉。
4. **不要学 ORB 把每帧 PnP-RANSAC 当跟踪主路径**：ORB 热路径是运动模型；每帧
   RANSAC 的成本与失败语义是重定位级的。
5. **不要在 PnP 失败时引入新的永久拒帧门**：与 Slice ① 去掉吸收态的方向相反；
   失败应退回恒速/上一帧，让窗口 BA 自己消化（或靠后续 Slice ④ chi2）。
6. **不要在 Slice ③ 同步做「永久删除 frontend track」**（VINS
   `removeOutliers`）：那是跨模块生命周期，设计稿划给 Slice ④。

### 给设计稿的输入（仅问题，不定案）

| 待对齐项 | 选项提示 |
|---|---|
| PnP API | OpenCV `solvePnPRansac`（与 roadmap 字面一致）vs 自研/OpenGV EPNP |
| 对应点表达 | 像素 + `K` vs 归一化平面 + `K=I`（VINS） |
| 外点作用域 | 仅本帧观测掩码 / 同步标 landmark 坏点 / 动 frontend |
| 与恒速关系 | PnP 优先、失败 fallback；或 inliers 不足时根本不调用 PnP |
| 阈值与门控 | `reproj_px`、`confidence`、`min_inliers` 是否进 `config_hash` |
| 诊断 | `diag.csv` 是否增加 `pnp_inliers` / `pnp_success`（对标 Kimera ransac CSV） |
