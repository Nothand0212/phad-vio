## 1. 目标

补上"只用立体视差定深度"的结构缺陷：对**立体匹配失败但运动视差好**的 track，
用**多帧三角化**（两帧 DLT）获取深度——这是 SVO/ORB-SLAM2 在 V2 低纹理走廊
成功的核心机制。

## 2. 背景与数据

### 2.1 瓶颈实锤

| 序列 | 右目成功率 | valid track | ATE |
|---|---:|---:|---|
| V2_02 | 22% | 38 | 1.405 |
| V2_03 | 9% | **10** | 2.892 |

V2 低纹理 → SAD 无区分度 → 立体视差缺失 → estimator 饿死。但 V2 帧间平移
0.3-1m >> 立体基线 0.11m——**运动视差条件远好于立体**，多帧三角化可行。

### 2.2 为什么 ⑥b 的 seed 门限失败

⑥b 尝试"track ≥2/3 帧才 seed"（`min_track_observations_for_seed`），A/B 证明
无效（V2_03 无改善）。原因：**门限只延迟了 seed，没有提供新深度来源**——延迟
后仍用单帧立体 backproject。多帧三角化才是本质修复。

## 3. 设计

### 3.1 核心机制

对**新 landmark**（不在 `landmarks_W`），seed 深度来源从"单帧立体 backproject"
改为"**立体优先，多帧三角化补充**"：

```
新 landmark seed 深度获取：
  1. 立体视差可用（disparity_px > 0 且通过门限）
     → 单帧 backproject（现有，质量好时直接用）
  2. 立体失败（无右目匹配，track 无视差）
     → 多帧三角化：在窗口内找该 landmark 的 ≥2 帧观测
       （含本帧），用对应位姿做两帧 DLT 三角化
  3. 两者都不可用 → 不 seed（现有行为）
```

### 3.2 关键点：观测数据从哪来

`KeyframeMeasurement.observations` 是**当前帧**的观测（含无视差的 track——前端
`StereoObservation` 的 `disparity_px` 可能为 0 或负？需确认）。多帧三角化需要
**历史帧的同一 landmark 观测**：

- 窗口 `WindowFrame.observations` 存了每帧观测（含历史）✓
- 同一 `LandmarkId` 在多帧窗口中出现（前端 track 跨帧持续）✓
- 每帧的位姿 `frame.T_W_B`（BA 优化后）✓

**问题**：`StereoObservation` 的 `disparity_px` 为 0 时（无右目匹配），观测是否
仍存进 `WindowFrame.observations`？检查 glue/session 是否过滤。若被过滤（只存
valid），多帧三角化需要改观测收集（允许无视差观测进入，或前端补发）。

**已确认（2026-08-06）**：`toKeyframeMeasurement`（`apps/stereo_vo_glue.hpp`）
**过滤了 `status != kValid`**——无右目匹配的 track（`disparity_px` 无值）被
丢弃，不进 estimator。多帧三角化需要**数据通道改造**：

```cpp
// 改造：让左目跟踪正常但右目匹配失败的 track 也进 estimator
// （带 disparity_px = 0 标记，表示"立体失败，可用多帧三角化"）
for ( observation : tracks.observations ) {
  if ( observation.status == kValid ) {
    push( { id, left_pixel, disparity_px } );      // 立体可用
  } else if ( observation.status == kNoRightMatch && track.length >= 2 ) {
    push( { id, left_pixel, 0.0 } );                // 立体失败 → 多帧三角化候选
  }
}
```

`StereoObservation.disparity_px` 语义扩展：`0` = 无立体视差，可多帧三角化。

### 3.3 两帧 DLT 三角化

对 landmark `id` 在帧 i、j（位姿 `T_i`、`T_j`，左目像素 `p_i`、`p_j`）：

```cpp
// 两帧左目观测的线性三角化（DLT）
// 每帧提供 2 个方程：u = fx*x/z + cx, v = fy*y/z + cy（相机系）
// 用 SVD 解齐次方程
Eigen::Vector3d triangulateTwoView(
    const gtsam::Pose3& T_W_left_i, const Eigen::Vector2d& p_i,
    const gtsam::Pose3& T_W_left_j, const Eigen::Vector2d& p_j );
```

GTSAM 有现成工具：`gtsam::triangulatePoint3`（`gtsam/geometry/triangulation.h`）。
它接受两个 Pose3（相机位姿）+ 两个 Point2（归一化或像素？需确认 API），返回
Point3。

**质量门限**：
- 两帧的视角差（视差角）≥ 1°（ORB-SLAM2 的 1.15° 门限）——运动视差太小则
  三角化病态，回退立体或不 seed
- cheirality：三角化点在两帧相机前方
- 重投影误差 ≤ 门限（如 3px）

### 3.4 触发时机

在**关键帧 seed 新 landmark 时**（`keyframe` 分支的 backproject 循环），对
`disparity_px <= 0`（无立体视差）的观测走多帧三角化。**非关键帧仍不 seed**（⑤c
语义不变）。

## 4. 已对齐决策

对齐结论（2026-08-06 实现前确认；门控后修订见 §8）：

| 决策点 | 结论 |
|---|---|
| 深度来源 | 立体优先，多帧三角化补充 |
| 三角化方法 | 两帧 DLT（GTSAM `triangulatePoint3`）|
| 帧选择 | 当前帧 + 窗口内视差角最大的历史帧（逐历史帧尝试，通过门限的最大视差对胜出）|
| 视角差门限 | ≥1°（ORB-SLAM2 1.15°）|
| 重投影门限 | 两帧左目重投影 RMS ≤ 3px |
| cheirality | 两帧前方检查 |
| 诊断字段 | `num_triangulated_seed` 进 diag.csv（**门控后移除**，见 §8）|
| seed 门计数 | keyframe seed 的 track 长度门（⑥b `min_track_observations_for_seed`）计**所有观测**（含零视差帧）|
| 触发 | 关键帧 seed 时，立体失败的新 landmark |
| 非关键帧 | 仍不 seed（⑤c 不变）|
| 立体正常时 | 保持单帧 backproject（质量好）|
| 零视差观测 | 不进 BA 因子、不计入 `countObservations`/PnP 支撑集/cheirality 判定（门控阶段逐项发现并修正，见 §8）|

## 5. 待确认（对齐时讨论）—— 结案

1. **观测收集需改造** ✓ 已实施：glue 新增 `kNoRightMatch` + `track.length>=2`
   通道（`disparity_px=0` 标记）；buildGraph 过滤 `disparity_px > 0` 才建
   StereoFactor（退化右目像素防御，落地）
2. **GTSAM triangulatePoint3 API** ✓ 确认：接受 `vector<Pose3>` + `sharedCal` +
   `Point2Vector` + `rank_tol` + `optimize`；返回 world 系 `Point3`；cheirality
   违规抛 `TriangulationCheiralityException`。实现后随三角化一并门控禁用
3. **性能** ✓ 可控（仅立体失败触发）；门控后无实际运行
4. **与 reanchor 交互** ✓ 已处理：seedSegment（重建窗口）无窗口历史，零视差
   观测直接跳过，靠后续关键帧再 seed
5. **min_seed_observations** ✓ 门控阶段修正：init/re-anchor 门改用
   `countStereoObservations`（只数立体）——原"数所有观测"使 V2_03 灾难性膨胀
   （20.3 m），见 §8 机制 5

## 6. 实施顺序

```text
Task 1: glue 通道改造 — kNoRightMatch track 进 estimator（disparity_px=0 标记）
Task 2: buildGraph 过滤 disparity_px=0 观测（不进 BA 因子，仅三角化用）
Task 3: GTSAM triangulatePoint3 接入（两帧 DLT + cheirality + 视角差门限）
Task 4: 关键帧 seed 分支：立体失败 → 多帧三角化
Task 5: 单测（合成：纯平移运动 + 立体失败 → 多帧三角化恢复深度）
Task 6: 门控（MH_01 不回归 + V2_02/V2_03 右目成功提升 → ATE 下降）
Task 7: 全序列
Task 8: 文档收口
```

## 7. 风险

| 风险 | 缓解 |
|---|---|
| 多帧三角化引入病态点（视角差小）| 1° 门限 + cheirality + 重投影门限 |
| MH_01 回归（立体正常时也走三角化）| 立体优先，三角化仅立体失败时 |
| 观测收集改动影响现有行为 | 保持 `disparity_px>0` 过滤兼容，新增无视角差通道 |
| 性能 | 仅 V2 类序列触发，开销小 |

门控实为**逐步证伪**。最终采用 **E13 composed g1**（悬挂距离门 1m +
左目投影一致性刷新 6px），完整实验链见

### 8.3 机制结论（逐位验证）

1. **悬挂机制是全部效应唯一载体**（E10）：零视差观测只提供窗口存活，本身不进 BA。
2. **效应 = far-return 时图初始值 + 存活本身**：V2_01/V2_02/V2_03 的效应是
   stale-3D vs fresh-backproject 的初值选择（方向相反、随距离/一致性分布重叠不可
   静态分离）；**MH_03 是反例**——三种 3D 策略（keep / 刷新一致 / 刷新漂移）全部
   ≈0.15–0.17，只有整组 drop（=ck）有效，损伤是悬挂存活本身（id 连续/图内存在）。
3. **E12a 的"机制 = 3D 初值 100% 坐实"作废**（prune-gate 早返回 bug 使 E12a/c/d
   循环全是死代码）；E13 的逐位验证（g=5 在 3 序列逐位 = e9 ⇒ 门从未触发）坐实
   距离度量真实生效。

### 8.4 落地形态

- `hanging_landmark_gate_m = 1.0`（默认）：悬挂 landmark 距其最近立体观测位姿移动
  >1m 即丢弃（真实距离簿记 `last_stereo_pose_W`，超出窗口存续）
- `far_return_refresh_px = 6.0`（默认）：far-return 的陈旧 3D 投影到当前左目像素
  >6px（或 cheirality 违规）时刷新为当前 backproject
- 多帧三角化（GTSAM 两帧 DLT）保持实现但门控禁用（`min_track_observations_for_seed`
  路径不触发）；`num_triangulated_seed` 诊断字段已移除
